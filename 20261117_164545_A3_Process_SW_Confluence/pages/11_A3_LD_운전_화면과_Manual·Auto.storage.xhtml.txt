<h2>1. 화면을 읽는 목적과 현재 기준</h2>
<p>운전 화면은 “어떤 값을 입력했는가”뿐 아니라 “지금 어느 기판에 어떤 값이 적용되어 있는가”를 확인하는 도구다. Recipe 편집값, Main의 현재 표시, 준비된 Station snapshot, Controller 실행값과 결과 파일은 시점과 소유자가 다르다. 화면에 보이는 값 하나만으로 실제 가공값까지 바뀌었다고 판단하지 않는다.</p>
<p>이 페이지는 9a43c709 원본의 정적 확인을 기반으로 운전 확인 순서를 정리한다. 현장 버튼 위치·권한·Mode 전환 조건은 배포 화면과 승인된 장비 절차를 함께 확인한다. 문서의 확인 순서는 신규 인원 교육과 인수인계용이며 미검증 장비 동작을 실행하도록 승인하는 절차가 아니다.</p>

<h2>3. Auto 전 확인 순서</h2>
<ol><li><strong>기준을 기록한다.</strong> 배포 Commit 또는 배포본 식별자, Recipe ID/버전, I/F map, Calibration과 적용 Offset 파일을 확인한다. 현장 파일 경로와 승인된 기준은 인수인계 담당자가 실제 배포 자료로 채운다.</li><li><strong>기판을 연결한다.</strong> 현재 Glass ID, 모델, 선택 PPID/EQ Recipe가 같고 진행 중인 다른 작업과 섞이지 않았는지 확인한다.</li><li><strong>가공 대상을 확인한다.</strong> 사용 Cell·Head, 담당 영역, DOE/원빔 구성, Masking·Round·Chess 제외, 총 Shot 수와 검사 Sampling을 Preview와 준비 계획에서 비교한다.</li><li><strong>상대 장치 준비를 확인한다.</strong> PLC/Stage, Review, Optic, Automation1의 연결상태와 실제 Ready, 원신호의 최신값을 확인한다. 연결됨과 가공 허가는 따로 확인한다.</li><li><strong>기존 세션을 확인한다.</strong> 이전 Start/Complete, 미완료 검사·0선 후속 cleanup, 정지 확인과 남은 요청이 해소되어야 다음 요청을 새 작업으로 해석할 수 있다.</li><li><strong>준비 결과를 확인한다.</strong> DoReady로 구성된 frozen parameter·Script·Head/Task mapping이 화면의 편집 의도와 같은지 확인한다. 실행 중의 Recipe 편집을 현재 Script 변경으로 간주하지 않는다.</li><li><strong>실행과 결과를 구분해 읽는다.</strong> Task 실행 완료, 가공 완료 신호, Review 판정, 파일 저장과 CIM 보고는 각각 해당 완료 근거를 확인한다.</li></ol>

<h2>5. Review 화면에서 특히 구분할 것</h2>
<p>생산 코드의 REVIEW DATA에는 결과 Load, 재검사, KEY IN/COPY 편집, RESULT SAVE와 OFFSET APPLY 경로가 있다. COPY는 다른 Shot의 결과 후보를 편집하는 기능이며 대상의 새 촬영도, 현재 보정 snapshot 복사도 아니다. 저장한 EDIT 결과가 적용 후보가 되는지는 RESULT_SOURCE 열이 있는지에 따라 다르므로 <ac:link><ri:page ri:content-title="08. A3 LD Align·Review·검사·보정"/><ac:plain-text-link-body><![CDATA[검사·보정 페이지]]></ac:plain-text-link-body></ac:link>의 형식 경계를 함께 읽는다.</p>
<p>산포도의 표시 범위는 그리기 설정이다. 기존 지도 초록은 결과 존재를, 산포도 색은 Judge를 표현할 수 있으므로 지도 색과 품질 판정을 같게 해석하지 않는다. 원측정과 작업 편집, MEASURED/INTERPOLATED/EDITED, raw/변환 오차, 미측정과 실제 0을 구분해야 한다.</p>
<p>11월 16일 교육용 Review 작업공간 HTML은 지도·표·산포도와 측정/보정 조작을 교육·검토하기 위한 별도 산출물이다. 그 HTML의 originalMeasurement 보존, 대표 최종 F 복사, “이동 후 측정 &amp; 보정” 검증 Gate는 해당 HTML의 검증 결과다. 생산 C#에 동일하게 이식·현장 검증된 기능이라는 의미가 아니다.</p>

<p>SDK 형식 프로젝트의 기본 항목에 편입되는 구조와 호출·배포·실행 성공은 별개다. 이번 문서 작성에서는 정식 빌드와 장비 UI 실행을 하지 않았다.</p>
<h2>7. 인수인계 실습과 완료 기준</h2>
<ol><li>동일한 가상 Shot을 Main Preview, 준비 계획, Script, Review 결과에서 식별자로 찾아 설명한다.</li><li>가상 Recipe 값을 바꾸고 현재 표시와 이미 준비된 실행 snapshot의 차이를 설명한다.</li><li>측정 NG, 수동 EDIT OK, 미측정, 실제 0의 자료를 구분하고 보정 가능 여부를 설명한다.</li><li>재검사 Revision을 만들기 전후 원본과 변경 행을 비교하고 Offset Apply를 별도 단계로 설명한다.</li><li>증상이 생겼을 때 <ac:link><ri:page ri:content-title="15. A3 LD 장애대응과 미결사항"/><ac:plain-text-link-body><![CDATA[장애대응 페이지]]></ac:plain-text-link-body></ac:link>의 자료 묶음을 만들어 담당 개발자에게 전달한다.</li></ol>
<p>이 실습표는 학습 확인 기준이며 실제 수행·통과 기록은 아니다. 장비 권한, 담당자 연락 경로, 배포본 위치와 정상 화면 예시는 현장 인수인계 시 해당 장비의 승인 자료로 확정한다.</p><h2>실제 코드로 읽는 처리 흐름</h2><p>결과 등급 계산과 화면 연결은 서로 다른 구현 단계다. 아래는 등급 계산 함수의 실제 내용으로, 화면에 연결되었거나 설정이 저장된다는 증거로 확대하지 않는다.</p><h3>CReviewResultLevelSettings.cs · ST_REVIEW_RESULT_LEVEL_SETTINGS.Resolve</h3><p><strong>코드 위치명:</strong> <code>CReviewResultLevelSettings.cs</code> · 본문에서 읽는 실제 구현 발췌</p><ac:structured-macro ac:macro-id="90ed5c1e-1e55-58ab-80ad-fac9503c72f7" ac:name="code" ac:schema-version="1"><ac:parameter ac:name="language">csharp</ac:parameter><ac:parameter ac:name="title">CReviewResultLevelSettings.cs · ST_REVIEW_RESULT_LEVEL_SETTINGS.Resolve</ac:parameter><ac:parameter ac:name="linenumbers">false</ac:parameter><ac:plain-text-body><![CDATA[    public EN_REVIEW_RESULT_LEVEL Resolve(double resultX, double resultY)
