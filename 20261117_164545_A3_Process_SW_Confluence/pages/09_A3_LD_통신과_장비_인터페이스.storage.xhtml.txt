<h2>1. 통신을 이해하는 출발점</h2>
<p>A3 Process는 Stage, Vision, Automation1과 광학 장치를 같은 목적에 사용하지만 하나의 프로토콜로 묶지 않는다. 설정에 장치를 등록하는 일, 네트워크나 Serial 연결을 여는 일, 명령을 보내는 일, 상대가 수락한 일, 실제 동작이 끝난 일은 서로 다르다. 장애 분석은 “통신 NG”라는 한 문장 대신 모듈·장치번호·명령·실패 단계·마지막 정상시각을 먼저 정하는 데서 시작한다.</p>
<p>현재 기준은 A3Drilling Commit 9a43c709다. CInterfaceManager, CComm, 주요 Serial Driver와 CInterfaceFile은 dfa5920e CodeRef와 바이트가 동일함을 확인했다. 아래 설명은 실제 소스를 읽은 구조이며 현장의 모든 주소·배율·연결·복구 시험을 완료했다는 뜻은 아니다.</p>
<h2>2. 요청이 실제 통신에 도달하는 경로</h2>

<h2>3. 등록과 연결을 점검하는 순서</h2>
<p>CComm은 CCommBase 하위 타입의 CCommTypeAttribute를 읽어 InterfaceType과 DeviceName에 맞는 구현을 고른다. 장치명이 구체적인 등록이 일반 등록보다 우선한다. 일치하는 타입이 없으면 CReadyOnlyComm이 만들어지며 Live not ready 오류를 남긴다. 객체 생성에 성공하거나 화면에 행이 나온다는 사실만으로 실제 Driver 지원을 판단하지 않는다.</p>
<ol><li>실행 PC가 읽는 Interface 파일과 버전을 확인한다. CInterfaceFile은 JHMI_INTERFACE.csv의 경로를 만들므로 비슷한 이름의 현장 복사본이 자동 선택된다고 가정하지 않는다.</li><li>모듈·번호·NickName·InterfaceType과 연결 옵션을 확인한다. 이름이 중복되면 모듈+번호로 구별하며, 코드의 중복 이름 오류를 빈 응답으로 바꾸지 않는다.</li><li>대상 장치의 모델·펌웨어·통신매체·Serial 속도/Parity/종단문자 또는 SDK 버전을 공식 자료와 대조한다.</li><li>Online, Offline, Simulation을 구분하고 LastSent·LastReceived·LastError·상태 변경시각을 함께 기록한다.</li><li>먼저 승인된 조회 명령으로 응답 형식과 단위를 확인하고, 동작 명령은 해당 설비의 운전·인터락 절차에 따라 별도 검증한다.</li></ol>
<h2>4. MELSEC 맵은 주소표 이상의 계약이다</h2>
<p>한 항목은 논리 ID, 장치번호, Use, IN/OUT, 읽기/쓰기 권한, 주소, Word 수, signed 여부, 배율, 유효범위를 함께 가진다. 같은 숫자 1도 원시 1인지 배율을 거친 논리 1인지 다를 수 있다. Stage Distortion ABLE/COMPLETE의 현재 정의에는 IN DWord·2Word와 읽기 0.0001/쓰기 10000 표현이 있으므로 실제 PLC와 원시값·논리값을 함께 대조해야 한다.</p>
<p>값이 마지막으로 정상이었다는 것과 지금도 유효하다는 것은 다르다. Snapshot의 값·읽기 시각·오류 상태·읽기 회차를 함께 보고, 상태가 정상이어도 허용 시간보다 오래된 캐시를 새 수신으로 사용하지 않는다. 실제 쓰기 이후에 얻은 readback인지도 확인한다. Heartbeat는 값이 1인지만 보는 대신 갱신 주기·변화·Timeout·PC별 감시 주체를 계약해야 한다.</p>
<p>MELSEC 장치에 일반 ExecuteFunction 문자열을 보내는 경로는 현재 코드가 거부한다. 새 I/F는 기존 CMelsec의 typed API·중앙 연결·Queue를 재사용하고 독립적인 두 번째 PLC 접속이나 UI의 직접 polling으로 소유권을 나누지 않는다. 주소 정의의 존재와 현장 배선·Device Map 일치는 별도의 검수 항목이다.</p>
<h2>5. ACK·Busy·Complete와 실행 식별자</h2>
<p>ACK는 요청 수락, Busy는 진행, Complete는 계약에서 정한 완료를 뜻하도록 명확히 정의한다. 어느 신호도 이름만으로 물리 이동·품질 합격·결과 저장·Host 보고를 모두 대표하지 않는다. 신호의 ON 조건·OFF 조건·상대 수신 확인·재시도·중복 요청·Timeout·재기동 시 초기화 주체를 표로 고정해야 한다.</p>
<p>가능하면 로그는 Glass/Run, Recipe, 모듈·Head·Cell·Shot, 메시지/요청 식별자, 송수신시각을 연결해 읽는다. 현재 모든 외부 프로토콜이 이런 필드를 전송한다고 가정해 새 wire 형식을 만들지는 않는다. 필드가 없는 경로는 로컬 실행 문맥과 시간 근거의 한계를 기록하고 계약 보완 항목으로 남긴다. 이전 기판의 늦은 결과를 현재 기판의 완료로 합치는 문제가 특히 중요하다.</p>
<p>Vision은 1001~1003 메시지 이름만 외우기보다 각 메시지의 송신 주체·Payload·배열 개수·ACK·최종 수집 조건을 코드와 합의서에서 확인한다. 결과가 도착했는지, 요구한 점 수만큼인지, 값이 유효한지, 품질 판정이 통과했는지는 각각 확인한다. 좌표 단위·Flip·보정 소비는 <ac:link><ri:page ri:content-title="07. A3 LD Scanner·MOF·Automation1"/><ac:plain-text-link-body><![CDATA[좌표·보정 설명]]></ac:plain-text-link-body></ac:link>으로 이어진다.</p>
<h2>6. 잠금·취소·재연결의 의미</h2>
<p>Automation1Comm은 통신 잠금과 상태 조회 잠금을 구분하고 Buffered feed 중 읽기 전용 상태 경로를 허용한다. 새 코드를 넣을 때 잠금 순서를 뒤집거나 상태 조회가 실행 Queue를 점유하게 하면 정지와 진단이 서로 기다릴 수 있다. Task Fault는 연결 끊김과 다르게 처리되는 분기가 있으므로 화면 문구도 구분한다.</p>
<p>Serial에는 자동 재접속 회수·간격·수동 억제 상태가 있고 명령은 SerialLock으로 직렬화된다. 재연결은 연결 복구이며 앞선 물리 명령을 다시 실행해도 된다는 허가가 아니다. Timeout 후에는 명령 미수신·실행 중·완료 후 응답 유실을 구분할 수 있는지 확인하고 계약 없이 이동·출사 명령을 반복하지 않는다.</p>
<p>CancellationToken 취소나 Station 스레드 정지가 모든 외부 장치의 즉시 정지를 보장하지 않는다. Controller Task, Stage, 출력과 정리 신호가 실제로 어떤 상태인지 확인해야 한다. 화면 응답이 빨라졌다는 사실과 안전 정지 완료를 같은 검증 결과로 세지 않는다.</p>
<h2>7. 현장 장애 확인 절차</h2>
<ol><li>발생시각, 화면/모드, 활성 기판과 Recipe, 장치번호, 명령·응답·오류를 보존한다. 재시작으로 로그와 상태가 지워지기 전에 증거를 확보한다.</li><li>설정 파일을 잘못 읽었는지, 장치가 미등록인지, fallback Comm인지부터 확인한다.</li><li>연결 오류와 프로토콜 오류를 나눈다. 포트가 열려도 데이터 형식·종단문자·주소·배율이 틀리면 기능은 실패할 수 있다.</li><li>송신 전부터 멈췄는지, 송신 후 ACK를 기다리는지, 실제 완료를 기다리는지, 결과 저장에서 실패했는지 구분한다.</li><li>Snapshot 시각과 readback, 상대 PC의 같은 회차 로그를 대조한다. 캐시 정상값이나 시간 근접만으로 같은 요청이라고 확정하지 않는다.</li><li>승인된 복구 절차에 따라 미완료 출력·Task·기판 상태를 확인한다. 중복 동작 가능성이 남으면 무조건 재전송하지 않는다.</li><li>원인, 조치, 바뀐 설정·소스, 회귀 시험과 재현 여부를 남긴다. 근거가 없으면 원인 미확정으로 관리한다.</li></ol>
<h2>8. 통합시험과 인수 시 남길 증거</h2>
<p>정상 한 번 연결되는 시험 외에 미등록·중복 NickName, 잘못된 타입, 늦은/빈/잘린 응답, 순서 변경, 네트워크 단절·재연결, 중복 요청, stale 캐시, Write 이후 readback 지연, 재시작 중 미완료 거래를 평가한다. 기대 출력·실제 출력·시각·원시/공학값·환경·소스 Commit을 기록한다. Simulator 통과와 실 PLC/Vision/광학 장치 시험을 구분한다.</p>
<p>코드 찾기는 CComm.Create, CInterfaceDevice.ExecuteFunction, CInterfaceManager.ExecuteDeviceFunction, CMelsec, CAutomation1Comm, CSerialComm, CVisionComm부터 시작한다. 고객이 확정할 주소·허용 지연·완료/복구 정책과 실제 시험 증거가 없으면 인수 완료로 올리지 않는다.
