A3Drilling 전용 오프라인 코딩 도구

A3 Pi Studio 0.5.1

온라인에서 한 번 준비하고, 현장에서는 자연어로 코드 조사와 수정을 요청합니다.

1. 기존 앱 종료 후 새 폴더에 압축 해제

트레이에서 기존 A3 스튜디오를 종료한 뒤, Windows x64 실행 ZIP을 풀어 App 폴더 전체를 유지하세요. EXE 하나만 복사하지 않습니다. 이전 버전 폴더는 보관해도 됩니다.

2. 인터넷이 되는 곳에서 준비

App\Setup-A3.cmd를 실행합니다. 필요한 Git, A3Drilling/master 최신 사본, 모델 연결, 코드 색인, 기준 빌드 확인을 순서대로 진행합니다. 기존 모델이 있으면 재사용하고 없으면 기본 Qwen3-8B Q4_K_M 약 5GB를 받습니다.

3. 준비 상태 확인 후 채팅

화면 위 코드 연결 상태에서 실제 경로·Commit·C# 반영 수를 확인합니다. 현장에서는 App\시작하기.cmd를 실행하고 요청을 입력하세요.

Review 좌표를 계산하고 Vision에 전달하는 코드를 찾아, 현재 흐름을 실제 파일 근거로 설명해줘.

업데이트와 다른 노트북

인터넷이 연결된 곳에서 Setup-A3.cmd를 다시 실행하면 최신 master를 별도 폴더로 준비합니다. 앱이 만든 깨끗한 사본은 자동 연결하며 이전 폴더는 그대로 남습니다. 직접 수정한 작업은 자동으로 덮어쓰지 않습니다.

다른 노트북도 전체 App 폴더를 복사한 다음 온라인 준비를 한 번 실행합니다. 완전 오프라인 반입은 승인된 코드·모델·자료를 포함해 해당 PC에서 사전에 준비 상태를 확인해야 합니다. 공개 ZIP에는 장비 소스·내부 자료·모델·사용자 상태가 없습니다.

저장 공간이 부족한 PC는 충분한 공간이 있는 드라이브에서 준비하세요. 필요하면 관리자가 A3_STUDIO_STATE_ROOT 사용자 환경변수에 절대 경로를 지정할 수 있습니다. 이 고급 설정은 프로젝트나 모델을 자동 이동시키지 않습니다.

소스 검증 역할지도

Review·Vision 조사에서는 좌표 이동, Vision 송신, 로컬 CSV 저장을 구분하는 검증 근거를 함께 제공합니다. 원문 파일 전체 SHA가 확인한 버전과 일치하는 경우에만 사용하고, 파일이 바뀌면 해당 메모를 제외합니다. 일반적인 Review→Vision 좌표 흐름 질문은 검증된 한국어 5단계와 실제 소스 근거로 바로 조회합니다. 답변 첫 줄에서 이 조회와 LLM 추론을 구분합니다. 원인 진단·코드 수정·다른 리뷰 모드·상세 요청은 로컬 모델 경로를 사용합니다. 현재 버전에 대해 확인한 구조 메모이며 모델 가중치 학습이나 모든 변경의 자동 검증을 뜻하지 않습니다.

검증 범위와 제한

소스 누락과 검색 실패, 모델 답변 오류는 구분해야 합니다. 이 버전은 검색·연결·실제 질문 응답을 별도로 검증합니다. 작은 모델이 모든 복잡한 로직을 정확히 분석한다고 보장하지 않습니다. 중요한 변경은 파일 근거와 빌드·시험으로 확인하세요. 검색·스타일 갱신은 모델 가중치 학습과 다릅니다. 기존 A3 전체 빌드의 Log 관련 오류 및 실장비 검수는 별도입니다.
