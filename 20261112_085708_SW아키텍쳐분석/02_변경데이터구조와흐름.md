# 변경된 데이터 구조와 흐름

## 1. 데이터가 맡는 역할

| 데이터 | 역할 | 이번 변화 |
| --- | --- | --- |
| JHMI_RCP.csv / Recipe CSV | 입력 항목 정의와 Recipe별 값 | 정의 형식 유지, test0929의 저장 값 대량 변경 |
| Setting.csv | 장비 공통 설정 | 분해능·0선·FollowUp·Wapage 공차 변경 |
| Review Plan | 어디를 어떤 Beam으로 검사할지 | ShiftOffsetX/Y를 명시적으로 보유하고 목표 좌표에 적용 |
| ReviewResult CSV | 측정 결과와 검사 조건 | SHIFT_OFFSET_X/Y 추가, 기존 RESULT_SOURCE 사용과 재검사 Revision 저장 |
| Review Offset CSV | 다음 가공에 더할 보정값 | 5열 형식 유지, 엄격 로드·고유 파일 저장·적용 이력 추가 |
| AppliedSources.csv | 어떤 결과를 어떤 Offset 파일로 적용했는지 | 날짜별 이력 신규 도입 |
| LastSuccessfulMof.json | 마지막 성공 수동 MOF의 Shift | CompletedAt/ShiftOffsetX/ShiftOffsetY 신규 저장 |
| Product Active/History | 기판 진행 상태와 리뷰 결과 | 저장 구조 변경 없음; 새 Revision과의 자동 동기화는 별도 확인 |

`Cell`은 기판 영역, `Model/Shot`은 배치의 점과 순서, `Beam`은 해당 Shot에서 선택한 광점, `Head`는 실제 가공 스캐너입니다. 같은 Cell/Shot도 Beam과 Shift·측정 세대가 다르면 같은 관측값으로 취급하면 안 됩니다.

## 2. Recipe와 Setting

test0929는 **43,376행의 3열 키 구조**와 키 집합을 유지합니다. 값 변경42,840개 중 Align X21,410·Align Y21,413·8Head Default X/Y16·가공횟수1입니다. 기존0이던 저장 Align 값이 대규모로 다시 들어갔습니다. 이는 코드 계산식 변경과 별도로 다음 좌표를 바꾸므로 시험 기준 Recipe와 현장 Recipe를 대조해야 합니다.

| Setting 항목 | 이전 | 현재 | 의미 |
| --- | --- | --- | --- |
| RUNOPTION_ZERO_DEFENCE_USE | 0 | 1 | 0선 시퀀스 활성화 |
| RUNOPTION_FOLLOWUP_USE | 0 | 1 | 후속 검사 활성화 |
| Review_Camera_Resolution | 1 | 0.05 | 같은 pixel 입력의 mm 환산이 이전 대비1/20; 실제 수신 단위 확인 필요 |
| Wapage_AlignBase_Tolerance | 0.1 | 0.2 | 기준 허용값 변경, 현장 기준 승인 필요 |

근거: [Setting.csv:52](https://github.com/kjuws10-rgb/A3Drilling/blob/5aee8e58439c9b455cae7c9593c9be986c3e682e/Config/Setting/Setting.csv#L52-L104). Review Align Key Pos X/Y의 Setting 이관은 이 diff에 없습니다. 현재 Recipe 항목과 장비 설정을 혼동하지 않습니다.

## 3. Shift와 검사 결과

일반 결과의 저장 열에 `SHIFT_OFFSET_X`, `SHIFT_OFFSET_Y`가 추가됐습니다. 기존 `RESULT_SOURCE`는 재검사 출처를 판단할 때도 사용합니다. writer의 열 수는 일반30→32, Fine42→44, Rough32→34, Beam Inspection57→59입니다. 재검사 Revision은 BASE 헤더를 유지합니다. 과거 파일의 기존 형식도 읽기 경로에서 고려합니다. 모든 과거 데이터가 자동으로 새 형식으로 변환된 것은 아닙니다. 실제 파일별 열·행 수 요약은 [schema-summary.json](schema-summary.json)에 있습니다.

근거: [CReviewResultFile.cs:12](https://github.com/kjuws10-rgb/A3Drilling/blob/5aee8e58439c9b455cae7c9593c9be986c3e682e/Drilling.File/ReviewResult/CReviewResultFile.cs#L12-L48), [CReviewResultFile.cs:79](https://github.com/kjuws10-rgb/A3Drilling/blob/5aee8e58439c9b455cae7c9593c9be986c3e682e/Drilling.File/ReviewResult/CReviewResultFile.cs#L79-L98), [CReviewResultFile.cs:434](https://github.com/kjuws10-rgb/A3Drilling/blob/5aee8e58439c9b455cae7c9593c9be986c3e682e/Drilling.File/ReviewResult/CReviewResultFile.cs#L434-L484).

재검사는 원본을 읽고 성공적으로 완료된 선택 측정값을 반영해 `_REINSP_시간.csv`를 새로 만듭니다. 기존 파일을 그대로 덮는 방식은 아닙니다. 새 실측과 이전에 남은 결과의 출처 구분은 보정에 사용할 때 중요합니다. 기존 ResultType이 AUTO/FINE이면 전체 결과를 보간에 다시 사용할 수 있어, 재검사하지 않은 이전 값까지 재적용되는지 확인해야 합니다.

## 4. 보정 적용 이력

```text
Config/RECIPE/<Recipe>/_reviewoffset/
  yyyyMMdd_HHmmss_fff_reviewoffset.csv
  Rollback/...
  _apply/yyyy/MM/dd/AppliedSources.csv
```

| 열 | 뜻 |
| --- | --- |
| SOURCE_RESULT_FILE | 정규화한 원본 결과 경로 |
| OFFSET_FILE | 이 적용으로 생성한 Offset 파일명 |
| APPLIED_AT | 적용 시각 |

경로는 파일 내용 hash가 아닙니다. 조회는 현재 날짜의 이력 파일에 한정됩니다. 결과 파일 이름/폴더를 바꾸거나 자정을 넘긴 뒤 적용하면 기존 적용과 같다고 판단하지 않을 수 있습니다. [CReviewOffsetFile.cs:30](https://github.com/kjuws10-rgb/A3Drilling/blob/5aee8e58439c9b455cae7c9593c9be986c3e682e/Drilling.File/ReviewOffset/CReviewOffsetFile.cs#L30-L45), [CReviewOffsetFile.cs:129](https://github.com/kjuws10-rgb/A3Drilling/blob/5aee8e58439c9b455cae7c9593c9be986c3e682e/Drilling.File/ReviewOffset/CReviewOffsetFile.cs#L129-L211).

Offset은 임시파일을 쓴 뒤 충돌하지 않는 이름으로 Move합니다. 이력 쓰기 실패 시 새 Offset을 제거하는 보상 처리가 있습니다. 그러나 여러 파일을 아우르는 데이터베이스 트랜잭션이나 프로세스 간 전체 계산 잠금으로 확장해 해석하면 안 됩니다. [CReviewOffsetFile.cs:213](https://github.com/kjuws10-rgb/A3Drilling/blob/5aee8e58439c9b455cae7c9593c9be986c3e682e/Drilling.File/ReviewOffset/CReviewOffsetFile.cs#L213-L260).

## 5. 수동 MOF 성공 이력과 Product

```json
{"CompletedAt":"완료 시각","ShiftOffsetX":0.0,"ShiftOffsetY":0.0}
```

위는 형식을 설명하는 예시입니다. `LastSuccessfulMof.json`에는 RecipeId·GlassId·Head 목록이 없습니다. 이전 기판의 성공 Shift를 현재 리뷰에서 선택할 수 있으므로 사용자가 기판/Recipe를 확인해야 합니다. 이력 저장 실패 시 성공 가공 자체를 실패로 되돌리지 않고 오류 메시지를 남깁니다. [CStationProcess.cs:3576](https://github.com/kjuws10-rgb/A3Drilling/blob/5aee8e58439c9b455cae7c9593c9be986c3e682e/Drilling.Common/Station/CStationProcess.cs#L3576-L3597), [CStationProcess.cs:3722](https://github.com/kjuws10-rgb/A3Drilling/blob/5aee8e58439c9b455cae7c9593c9be986c3e682e/Drilling.Common/Station/CStationProcess.cs#L3722-L3761), [CStationProcess.cs:5853](https://github.com/kjuws10-rgb/A3Drilling/blob/5aee8e58439c9b455cae7c9593c9be986c3e682e/Drilling.Common/Station/CStationProcess.cs#L5853-L5857).

Product는 `Data/Product/ActiveProduct.csv`와 History의 기존 compact 형식을 사용합니다. Shift·적용 이력의 새 열을 Product까지 확장하는 변경은 없습니다. Review 결과 저장과 Product 진행 상태 갱신은 서로 다른 경로이며, 새 재검사 Revision 저장을 곧 Product 교체로 보면 안 됩니다. [CProductFile.cs:142](https://github.com/kjuws10-rgb/A3Drilling/blob/5aee8e58439c9b455cae7c9593c9be986c3e682e/Drilling.File/Product/CProductFile.cs#L142-L178), [CProductFile.cs:258](https://github.com/kjuws10-rgb/A3Drilling/blob/5aee8e58439c9b455cae7c9593c9be986c3e682e/Drilling.File/Product/CProductFile.cs#L258-L266).
