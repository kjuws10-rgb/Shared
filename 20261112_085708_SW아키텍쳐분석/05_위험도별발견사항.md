# 위험도별 발견사항과 검증 순서

아래 등급은 이번 정적 분석의 우선순위 제안입니다. 실장비 고장 발생이나 고객 사양 확정을 뜻하지 않습니다.

| --- | --- | --- | --- |
| 높음 | 기존 Log/CLogManager 누락으로 정식 빌드19오류 | 신규 File/UI 코드까지 정상 컴파일됐다고 판단할 수 없음 | 누락 원본을 정식 복구하고 clean clone Release 전체 빌드; 스텁으로 합격 처리하지 않음 |
| 높음 | 기본 Vision loopback/MELSEC SIMUL=1 | 현장 실제 통신과 다른 조건으로 구동될 수 있음 | 시작 전 모든 장치의 REAL/SIMUL·주소·포트·수신 갱신을 현장 승인본과 비교 |
| 높음 | 적용 이력은 당일/경로 단위 | 날짜 변경·복사/재검사 새 경로는 동일 결과 재누적 가능 | 같은 파일·복사본·자정 전후·Revision을 차례로 적용해 최종 Offset과 이력 대조; 측정 세대/해시/기준 Offset Revision 설계 |
| 중간 | 재검사/저장 중 다른 결과 선택·LOAD의 경합 후보 | 이전 비동기 완료가 새 화면/취소상태에 영향을 줄 수 있음 | 지연 측정/저장 중 트리 선택·Refresh·LOAD·새 측정 연속 조작; 작업 세대 식별과 완료 후 전환 보장 |

## 최소 검증 시나리오

1. **기본 I/F**: 현장 주소·REAL/SIMUL을 확인하고 Vision 정상/NG/미수신을 각각 주입합니다. 장치별 응답과 화면 표시가 일치해야 합니다.
2. **Shift**: 같은 Recipe와 Shot에서 0→(+0.1,−0.2)→같은 값 재적용→0 순서로 목표를 비교합니다. X는+0.1, Y는Stage 방향×−0.2이며 중복 누적이 없어야 합니다.
3. **결과 Revision**: 여러 Cell에서 OK/NG 섞어 재측정하고 다른 Beam도 선택합니다. 원본 hash는 유지되고 새 파일에서 선택 행만 바뀌어야 합니다. 원본 값은 보존하되 파생 결과를 Apply할 때 이미 소비한 오차를 새 측정으로 재누적하지 않아야 합니다. 출처/적용 계보 정책을 명시합니다.
4. **중복**: 동일 결과2회, 다른 이름 복사, 다음 날짜, 새 Revision을 각각 Apply합니다. 사용자 의도와 현재 구현의 허용/차단 차이를 수치로 기록합니다.
5. **복원/실패**: Offset과 이력 파일 쓰기를 각각 실패시키고 Rollback을 연속 수행합니다. 유효한 최신 파일·이력의 짝이 유지되는지 확인합니다.
6. **경합**: 재검사 또는 저장을 지연시키고 결과를 바꿉니다. 이전 작업이 새 데이터/CTS/카메라를 건드리지 않아야 합니다.
7. **실기**: 0선·FollowUp·Masking 경계·Trigger 누락·혼합DOE/원빔 평가를 별도 수행합니다. 이 보고서 작성 중에는 장치나 레이저를 구동하지 않았습니다.

각 항목의 정확한 caller와 줄 근거는 [영향 분석](03_가공Review영향분석.md) 및 [검증 기록](06_분석근거와검증.md)에 연결했습니다.
