# Review 결과·누적 보정 변경 분석

분석 대상은 `kjuws10-rgb/A3Drilling`의 `master`, 비교 범위는 `a1162209220fd31caa68cbf82b5a98db9588af39` → `5aee8e58439c9b455cae7c9593c9be986c3e682e`이다. 별도 분석 Clone의 HEAD와 Push URL `DISABLED`를 읽기 전용으로 확인했다. 이 담당 검토에서는 소스 수정, 프로그램 실행, 빌드, 장비 시험, Commit 및 Push를 하지 않았다. 아래의 위험은 소스 호출 관계를 추적한 정적 분석이며, 실장비에서 재현된 장애라는 뜻이 아니다.

## 1. 먼저 알아둘 결과

이번 변경으로 **AUTO와 수동 보정 모두 어떤 결과 파일을 적용했는지 이력을 남긴다.** AUTO는 같은 파일이 이미 적용된 경우 실패와 알람으로 처리하고, 수동 화면은 재적용 확인을 받는다. 이전 분석의 “AUTO 결과를 다시 수동으로 적용해도 아무 이력이 없는 문제”에 직접 대응하는 변경이다. 다만 같은 파일의 판단 기준은 **오늘자 이력에 기록된 파일 경로**다. 이전 날짜, 파일 복사본, 새 재검사 파생 파일까지 묶어 판단하는 전역 중복 방지는 아니다. [AUTO 적용](https://github.com/kjuws10-rgb/A3Drilling/blob/5aee8e58439c9b455cae7c9593c9be986c3e682e/Drilling.Common/Review/CAutoFineReviewCoordinator.cs#L94-L166) [수동 적용](https://github.com/kjuws10-rgb/A3Drilling/blob/5aee8e58439c9b455cae7c9593c9be986c3e682e/Drilling.UI/Menu/Menus/CMenuCorrection.cs#L2250-L2311) [이력 식별](https://github.com/kjuws10-rgb/A3Drilling/blob/5aee8e58439c9b455cae7c9593c9be986c3e682e/Drilling.File/ReviewOffset/CReviewOffsetFile.cs#L565-L602)

가장 먼저 검증해야 할 잔여 경로는 **이미 보정에 사용한 결과를 일부 재검사한 뒤 새 파일 전체를 다시 적용하는 경우**다. 재검사 저장은 BASE 전체 행을 복사하고 선택 행만 바꾼다. 바뀌지 않은 원래 행의 `MEASURED` 표시는 그대로 남는다. 새 `_REINSP_` 파일은 경로가 달라 중복 이력에 걸리지 않으며, 보정은 그 파일의 `MEASURED` 행 전체를 읽는다. 따라서 재검사하지 않은 원본 오차가 다시 누적될 수 있다. UI 담당 검토에서도 재검사 전에 BASE 적용 이력을 차단하거나 미변경 행을 별도로 제외하는 경로가 없음을 교차 확인했다. [Revision 저장](https://github.com/kjuws10-rgb/A3Drilling/blob/5aee8e58439c9b455cae7c9593c9be986c3e682e/Drilling.File/ReviewResult/CReviewResultFile.cs#L135-L210) [갱신 열](https://github.com/kjuws10-rgb/A3Drilling/blob/5aee8e58439c9b455cae7c9593c9be986c3e682e/Drilling.File/ReviewResult/CReviewResultFile.cs#L293-L338) [측정행 선택](https://github.com/kjuws10-rgb/A3Drilling/blob/5aee8e58439c9b455cae7c9593c9be986c3e682e/Drilling.UI/Menu/Menus/CMenuCorrection.ReviewData.Offset.cs#L461-L466)

오차 CSV의 잘못된 숫자가 `0.0`으로 바뀌는 기존 경로도 남아 있다. 반면 Review Offset CSV 자체의 비정상 숫자·중복 키 검증은 엄격하다. **Offset 파일의 엄격 검증과 측정 결과 파일의 엄격 검증을 같은 것으로 설명하면 안 된다.** [결과 숫자](https://github.com/kjuws10-rgb/A3Drilling/blob/5aee8e58439c9b455cae7c9593c9be986c3e682e/Drilling.File/ReviewResult/CReviewResultFile.cs#L579-L600) [Offset 검증](https://github.com/kjuws10-rgb/A3Drilling/blob/5aee8e58439c9b455cae7c9593c9be986c3e682e/Drilling.Common/Recipe/CShotCoordinatePlanBuilder.cs#L1140-L1193)

## 3. 좌표 기준·누적 방식

1. 실시간 측정의 오차는 `VisionErrorToStageOffset`에서 XY 교환, X 반전, Y 반전 순서로 변환한다. 이 함수 자체는 Pixel→mm 환산 함수가 아니며, 여기서는 이미 측정 루틴이 만든 오차를 받는다. [Vision 변환](https://github.com/kjuws10-rgb/A3Drilling/blob/5aee8e58439c9b455cae7c9593c9be986c3e682e/Drilling.Common/Review/CReviewManager.cs#L3486-L3512)
2. AUTO는 변환된 증가분을 같은 Cell·설계 X 열에서 Y 방향으로 보간한다. 측정점이 없는 열은 기존 값을 보존한다. 단일 기준점은 그 열에 같은 증가분을 주며, 여러 기준점은 다항식 보간이다. “항상 선형 보간”이라고 쓰면 소스와 다르다. [FINE 계산](https://github.com/kjuws10-rgb/A3Drilling/blob/5aee8e58439c9b455cae7c9593c9be986c3e682e/Drilling.Common/Review/CReviewManager.cs#L3416-L3481)
3. 저장된 기존 행이 `SCANNER`이면 현재 Head의 축 반전·XY 교환·Stage Y 방향을 역변환하여 DESIGN 값으로 만든다. 기존 DESIGN 값은 그대로 사용한다. `최종 = 기존 DESIGN + 이번 증가분`으로 누적하고 저장 행의 `COORDINATE_SPACE`를 DESIGN으로 둔다. [AUTO 누적](https://github.com/kjuws10-rgb/A3Drilling/blob/5aee8e58439c9b455cae7c9593c9be986c3e682e/Drilling.Common/Review/CAutoFineReviewCoordinator.cs#L94-L166) [역변환](https://github.com/kjuws10-rgb/A3Drilling/blob/5aee8e58439c9b455cae7c9593c9be986c3e682e/Drilling.Common/Recipe/CShotCoordinatePlanBuilder.cs#L1260-L1281)
4. ReviewData는 CSV의 `VISION_FLIP_CONVERT_X/Y` 등 변환 완료 열을 우선 읽고, 보간 함수에는 `Normal`을 전달한다. 정상 자체 저장 파일에서는 Vision Flip을 두 번 적용하지 않는 구성이다. 다만 별도 수입 파일이 변환 완료 열 없이 수신 원본 열만 가진 경우까지 좌표 기준을 보증하는 강한 스키마는 없다. [오차 열 우선순위](https://github.com/kjuws10-rgb/A3Drilling/blob/5aee8e58439c9b455cae7c9593c9be986c3e682e/Drilling.File/ReviewResult/CReviewResultFile.cs#L390-L431) [수동 계산](https://github.com/kjuws10-rgb/A3Drilling/blob/5aee8e58439c9b455cae7c9593c9be986c3e682e/Drilling.UI/Menu/Menus/CMenuCorrection.ReviewData.Offset.cs#L375-L458)
5. Offset은 `(CellId, 정규화 ShotId)`가 키다. 저장 CSV는 Head/Beam/Glass/Run별 독립 보정 테이블이 아니다. 같은 Recipe 안에서 Head·형상·좌표 설정을 바꿨을 때 과거 파일의 호환성을 별도 버전으로 보증하지 않는다. 매번 현재 Recipe로 Shot을 찾고 Head 일치를 확인하는 방어는 있다. [행 검증](https://github.com/kjuws10-rgb/A3Drilling/blob/5aee8e58439c9b455cae7c9593c9be986c3e682e/Drilling.Common/Recipe/CShotCoordinatePlanBuilder.cs#L1140-L1193) [Shot·Head 매칭](https://github.com/kjuws10-rgb/A3Drilling/blob/5aee8e58439c9b455cae7c9593c9be986c3e682e/Drilling.UI/Menu/Menus/CMenuCorrection.ReviewData.Offset.cs#L482-L498)
6. 다음 가공 좌표 생성 시 DESIGN 보정을 해당 Head의 스캐너 축 기준으로 바꿔 최종 좌표에 더한다. CSV 저장 즉시 이미 준비된 가공 모델의 좌표가 자동으로 다시 계산된다는 의미는 아니다. ## 4. 저장 형식과 식별 범위

헤더 수는 비교 대상 두 Commit의 저장 함수 안 문자열 헤더를 읽어 계산했다. 측정 샘플의 원문 행은 이 문서와 JSON에 복사하지 않았다.

| 파일 종류 | 이전 → 최신 열 수 | 최신 변화·식별 |
|---|---:|---|
| 일반 Review Result | 30 → 32 | `SHIFT_OFFSET_X/Y` 추가. 결과 경로, Recipe, Glass, Shot/Cell/Head, 원본·변환 오차, Judge 등을 저장 |
| FINE / AUTO 결과 | 42 → 44 | Shift 추가. 일반 Fine Run의 `RunId`는 CSV 열로 저장하지 않음. 0선 후속에서는 `ZERO_LINE_RUN_ID/SAVED_AT`으로 부모 Run을 기록 |
| ROUGH 결과 | 32 → 34 | Shift 추가. 일반 결과와 동일한 단일 스키마로 합쳐졌다는 뜻은 아님 |
| Beam Inspection | 57 → 59 | Shift 2열 추가. 전용 로더가 이전 57열과 새 59열을 모두 허용하고 새 형식은 모든 Shot의 Shift 동일 여부도 검증 |
| Review Offset | 5열 유지 | `CELLID,SHOTID,REVIEWOFFSETX,REVIEWOFFSETY,COORDINATE_SPACE`. 이전의 공간 열 누락은 SCANNER로 호환 |
| 적용 이력 | 신규 3열 | `SOURCE_RESULT_FILE,OFFSET_FILE,APPLIED_AT`. Recipe별 `_apply/yyyy/MM/dd/AppliedSources.csv` |
| 재검사 Revision | BASE 헤더 유지 | 별도 고정 열 수 없음. 같은 폴더의 고유 `_REINSP_시각.csv`. 헤더에 없는 계보·재측정 이력 열은 추가하지 않음 |

### 재검사 파일의 의미

`SaveReinspectionRevision`은 현재 디스크의 BASE를 다시 읽고 전체 행을 복사한다. 모든 행의 `SAVED_AT`은 새 저장 시각으로 바꾼다. 선택한 행은 Cell·Shot, 필요 시 원래 Beam으로 하나를 식별하고, 새 Beam 번호, 원본·변환 오차, Judge, `RESULT_SOURCE=MEASURED`를 갱신한다. 업데이트 값은 유한수와 OK/NG를 엄격하게 검사한다. 원본 파일은 보존한다. 그러나 미변경 행의 기존 측정 시각, 측정 당시 Offset 버전, BASE 콘텐츠 해시, 부모 Revision ID를 별도 열에 남기지 않는다. 또 갱신 열 목록에는 `DESIGN_X/Y`, `REVIEW_X_TARGET`, `STAGE_Y_TARGET`, Flip 메타데이터가 없다. Beam·설정 변경 재검사에서 이 메타데이터가 새 측정 위치를 그대로 설명하는지 UI 담당 검토 및 실제 시험과 함께 확인해야 한다. “새 파일의 모든 행을 새 시점에 다시 측정했다”라고 해석하면 안 된다.

## 5. Rollback과 원자성

### Rollback의 실제 범위

- 가장 최근 활성 Offset 파일 한 개를 Recipe 아래 `Rollback` 폴더로 이동한다. 활성 파일은 상위 폴더의 `*_reviewoffset.csv`를 이름 내림차순으로 고른다. 이전 파일이 없으면 Offset 없는 상태가 된다. [활성 선택](https://github.com/kjuws10-rgb/A3Drilling/blob/5aee8e58439c9b455cae7c9593c9be986c3e682e/Drilling.File/ReviewOffset/CReviewOffsetFile.cs#L389-L403) [Rollback](https://github.com/kjuws10-rgb/A3Drilling/blob/5aee8e58439c9b455cae7c9593c9be986c3e682e/Drilling.File/ReviewOffset/CReviewOffsetFile.cs#L260-L326)
- 롤백할 파일의 저장 날짜에 해당하는 적용 이력에서 그 `OFFSET_FILE` 행을 제거한다. 따라서 취소된 적용의 결과 파일은 다시 적용할 수 있다. 일반 예외가 나면 파일 이동과 이력을 되돌리는 보상 복구를 시도하며, 보상 복구도 실패하면 합친 예외를 보고한다. [Rollback 복구](https://github.com/kjuws10-rgb/A3Drilling/blob/5aee8e58439c9b455cae7c9593c9be986c3e682e/Drilling.File/ReviewOffset/CReviewOffsetFile.cs#L328-L381)
- UI는 선택 Recipe를 재확인하고 준비된 가공 모델을 먼저 무효화한다. 작업 중이면 `InvalidatePreparedReviewOffset`가 거부한다. 성공 후 실제 최신 파일을 다시 읽어 비교하고 DoReady 재실행을 안내한다. [Rollback UI](https://github.com/kjuws10-rgb/A3Drilling/blob/5aee8e58439c9b455cae7c9593c9be986c3e682e/Drilling.UI/Menu/Menus/CMenuCorrection.cs#L4021-L4086) [모델 무효화](https://github.com/kjuws10-rgb/A3Drilling/blob/5aee8e58439c9b455cae7c9593c9be986c3e682e/Drilling.Common/Station/CStationProcess.cs#L1546-L1595)
- 이것은 측정 결과, Recipe, Product 기록, 이미 가공한 기판 전체를 되돌리는 기능이 아니다. 파일 보관과 다음 가공에 사용할 보정 선택을 되돌리는 기능이다.

### 파일 일관성의 범위

| 조치 | 확인한 방어 | 보증하지 않는 범위 |
|---|---|---|
| 새 Offset | 임시 파일 완성 후 고유 이름으로 Move, 덮어쓰기 안 함 | Offset·이력 두 파일을 묶은 crash-safe 트랜잭션은 아님 |
| 이력 추가 | 기존 파일 길이 보관, 디스크 Flush, 일반 예외 시 원래 길이 복원 | 프로세스 강제 종료·전원 차단 시 두 파일 동시 복원은 없음 |
| 새 이력·이력 교체 | 임시 파일 작성 후 Move | 여러 프로세스/여러 `CReviewOffsetFile` 인스턴스 사이의 공통 잠금 없음 |
| 신규 결과·Revision | 임시 파일→고유 CSV, 이름 충돌 시 suffix | generic `Save`의 명시 `TargetFilePath` 경로는 직접 CSV Write이므로 모든 결과 저장을 동일하게 원자적이라고 일반화하면 안 됨 |
| Rollback | 예상 최신 경로 확인, 이동 후 활성 파일 재검증, 예외 시 보상 복구 | 전원 차단을 견디는 복구 저널·복구 마커는 확인되지 않음 |

## 8. 검증 계획과 한계

이번 담당은 소스 읽기·Commit 간 diff·헤더 개수 계산·호출 관계 교차 확인만 수행했다. File/UI/실장비 통과를 주장하지 않는다. 통합 보고서의 별도 검증 Clone 빌드 결과와 혼동하지 않는다.

| 시험 | 준비·행동 | 확인할 결과 |
|---|---|---|
| 같은 날 같은 결과의 중복 적용 | AUTO 보정 저장 후 같은 경로를 수동 Apply; 수동 재적용 취소/허용 각각 | 경고·취소 시 새 파일 없음, 허용 시 의도된 재적용 이력, AUTO는 전용 실패 알람 |
| 날짜·경로 식별 | 주입 가능한 시계를 다음 날로 변경, 파일명 변경 복사본 사용, 같은 경로의 내용 교체 | 현재 동작을 먼저 재현하고 제품 요구의 중복 정의와 비교 |
| BASE 일부 재검사 | 적용한 BASE를 보관하고 일부만 재측정·Revision 저장·Apply | 미변경 MEASURED 행이 재누적되는지, 보간 영향 범위와 기준 Offset 혼합 여부 확인 |
| 숫자 변조 | 오차 열에 문자/NaN/Infinity/빈칸, Judge/Source는 OK/MEASURED 유지 | 결과 로드·미리보기·저장 단계 어디에서 차단되는지. 유효 0과 구분 |
| 기존 Offset 엄격 검증 | NaN/Infinity, 중복 Cell/Shot, 잘못된 공간 문자열, 헤더 누락 | 전체 입력 거부, 기존 파라미터/파일 보존 |
