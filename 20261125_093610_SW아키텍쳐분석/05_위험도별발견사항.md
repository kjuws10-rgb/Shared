# 05 · 위험도별 발견사항

- 원본 저장소: https://github.com/kjuws10-rgb/A3Drilling.git
- 분석 브랜치: master
- 원본 최신 Commit: 0219666f9053b907d96d7e0aa7d0c6c1be3a73d4

아래의 **확인**은 소스·구조를 읽은 결과입니다. **검증 필요**는 조건부 위험이며 실제 설비 결함을 재현했다는 뜻이 아닙니다.

## 높음 · 배포 전에 확인

### ARC-01 · 운영 자료의 대량 변경은 좌표·실행 조건에 영향을 준다

**확인:** 좌표 수식 소스의 diff는 없지만 Recipe Align 값 42,822축 항목, 허용값·Count, 실행 옵션이 변경됐고 Review Offset CSV 109개가 추가됐습니다. 최신 Offset은 공정 준비 시 병합됩니다. [실제 소비 경로](https://github.com/kjuws10-rgb/A3Drilling/blob/0219666f9053b907d96d7e0aa7d0c6c1be3a73d4/Drilling.Common/Station/CStationProcess.cs#L1545-L1564)

**검증 필요:** 현장 모델에 맞는 보정인지, 현재 사용해야 할 최신 파일인지, 새 실행 옵션이 승인된 절차인지 확인해야 합니다. 파일이 Git에 들어 있다는 이유로 기존 설비 Config/Data 전체를 덮어쓰는 배포를 정당화하지 않습니다.

### ARC-02 · PPID 수신과 Recipe 선택은 분리돼 있다

**확인:** Stage PPID로 Product를 만들지만 Recipe 자동 검색·전환을 수행하지 않습니다. 공정 준비는 선택 Recipe를 사용하고 Review는 Product PPID 불일치를 거절합니다. [수신 경로](https://github.com/kjuws10-rgb/A3Drilling/blob/0219666f9053b907d96d7e0aa7d0c6c1be3a73d4/Drilling.UI/Menu/Menus/CMenuMonitor.cs#L4459-L4488), [공정 준비 기준](https://github.com/kjuws10-rgb/A3Drilling/blob/0219666f9053b907d96d7e0aa7d0c6c1be3a73d4/Drilling.UI/CRootView.cs#L1632-L1651), [Review 불일치 거절](https://github.com/kjuws10-rgb/A3Drilling/blob/0219666f9053b907d96d7e0aa7d0c6c1be3a73d4/Drilling.Common/Review/CReviewManager.cs#L1600-L1607)

**검증 필요:** 고객사의 PPID가 Recipe ID와 같은 문자열인지, 빈 값/미등록/버전 다른 PPID에서 누가 어떤 확인을 해야 하는지 합의해야 합니다. 이 기능을 Auto Job Change 완료로 안내하면 안 됩니다.

### ARC-03 · 현재 상태·세션·생성 파일을 소스와 분리해야 한다

**확인:** Data에는 ActiveProduct, Product 이력, Manual 작업 세션, 1,140개의 BufferedRun 생성 Script 등 운영 산출물이 포함됩니다. Product 로드는 ActiveProduct를 현재 상태로 사용합니다. [Active Product 로드와 재시작 처리](https://github.com/kjuws10-rgb/A3Drilling/blob/0219666f9053b907d96d7e0aa7d0c6c1be3a73d4/Drilling.Common/Product/CProductManager.cs#L40-L108)

**검증 필요:** 개발 샘플 상태를 현장 현재 상태로 채택하지 않는 배포·복구 절차가 필요합니다. 운영 CSV 실제 레코드와 세션 JSON 값은 공유 자료에 복제하지 않습니다. AeroScript/scan 원문과 annotated 사본은 유지하되 핵심 구현 코드와 생성 산출물을 구분하고, 생성 자료는 선택적 RAG 입력으로 분리해 검색을 압도하지 않게 합니다.

### ARC-09 · Stage/Dummy Product와 실제 Process의 생명주기 연결이 확인되지 않는다

**확인:** Monitor는 빈 ProcessId로 Product를 생성합니다. Root의 공정 준비는 별도 새 ProcessId를 만들며 Glass/Lot을 재사용하지만 Product를 그 ProcessId로 할당하는 호출은 확인되지 않았습니다. Station은 Product.ProcessId와 공정 모델의 ProcessId가 다르면 Align 결과·완료·정지·오류 Product 갱신을 생략합니다. 전체 소스 직접 호출 검색에서 `PrepareProductForProcess`와 `StartProduct`는 선언만 발견했습니다. [기판 생성](https://github.com/kjuws10-rgb/A3Drilling/blob/0219666f9053b907d96d7e0aa7d0c6c1be3a73d4/Drilling.UI/Menu/Menus/CMenuMonitor.cs#L4480-L4488), [공정 준비](https://github.com/kjuws10-rgb/A3Drilling/blob/0219666f9053b907d96d7e0aa7d0c6c1be3a73d4/Drilling.UI/CRootView.cs#L1642-L1651), [연결 판정](https://github.com/kjuws10-rgb/A3Drilling/blob/0219666f9053b907d96d7e0aa7d0c6c1be3a73d4/Drilling.Common/Station/CStationProcess.cs#L1508-L1516), [상태 기록의 반환 경계](https://github.com/kjuws10-rgb/A3Drilling/blob/0219666f9053b907d96d7e0aa7d0c6c1be3a73d4/Drilling.Common/Station/CStationProcess.cs#L1415-L1459)

**영향·검증 필요:** 생성 성공 안내나 같은 Glass ID만 보고 Product의 공정 상태/결과가 실제 Station과 동기화된다고 판단하지 않습니다. 새 기판 생성 후 할당·시작·완료/Stop/Error의 ProcessId와 두 상태를 한 시나리오로 검증해야 합니다. 현재는 **소스로 확인한 연결 공백**이며 장비 실행으로 재현한 장애가 아닙니다. 직접 호출 검색에 보이지 않는 반사/외부 주입까지 없다고 단정하지 않습니다. 기준 Commit에도 기존 Dummy의 빈 ProcessId 생성 경로가 있어 신규 회귀로 단정하지 않습니다. 이 공백은 자동 Job Change 및 추적성의 완료 조건을 정할 때 우선 확인해야 합니다.

## 중간 · 계약·호환성 확인

### ARC-04 · 기본 map의 한 block과 PLC의 업무 스냅샷은 다른 보장이다

**확인:** 기본 44map은 Device0·1000ms·연속 360WORD로 한 block에 들어갑니다. 캐시는 한 lock에서 기록합니다. ReadAsync 자체는 필드별 Valid를 검사하지만 동일 ReadCycleNo/Stage의 변경 버전·완료 handshake를 검사하지 않습니다. [기본 block 묶기](https://github.com/kjuws10-rgb/A3Drilling/blob/0219666f9053b907d96d7e0aa7d0c6c1be3a73d4/Drilling.Common/Interface/Melsec/CMelsec.cs#L2693-L2717), [읽기 후 검사](https://github.com/kjuws10-rgb/A3Drilling/blob/0219666f9053b907d96d7e0aa7d0c6c1be3a73d4/Drilling.Common/Interface/Melsec/CStageGlassDataMap.cs#L92-L121)

**검증 필요:** 커스텀 map으로 Device/주기/주소가 나뉜 경우와 Stage가 GlassData를 쓰는 중인 경우를 시험해야 합니다. 정상 기본 map의 로컬 캐시 일관성을 “실제 PLC 업무 데이터가 언제나 원자적”이라고 확대하지 않습니다.

### ARC-05 · 기존 현장 map은 자동으로 새 항목을 얻지 않는다

**확인:** map 파일이 이미 있으면 EnsureFile은 바로 반환합니다. 44개 항목이 들어간 새 기본 map 생성은 파일이 없는 경우입니다. [기존 파일 유지](https://github.com/kjuws10-rgb/A3Drilling/blob/0219666f9053b907d96d7e0aa7d0c6c1be3a73d4/Drilling.File/JHMI/CMelsecMapFile.cs#L102-L110)

**검증 필요:** 기존 설정을 보존하면서 새 Stage 항목만 올바르게 병합해야 합니다. 누락 map은 읽기 실패로 이어지며 Dummy로 자동 대체되지 않습니다.

### ARC-06 · 공정 판정 필드의 양방향 호환을 구분해야 한다

**확인:** 새 Result 읽기는 PRODUCT_RESULT가 없을 때 JUDGEMENT를 읽습니다. 상태 전환은 새 필드만 씁니다. [새 쓰기 계약](https://github.com/kjuws10-rgb/A3Drilling/blob/0219666f9053b907d96d7e0aa7d0c6c1be3a73d4/Drilling.Common/Product/CProductManager.cs#L857-L874), [구형 파일 fallback](https://github.com/kjuws10-rgb/A3Drilling/blob/0219666f9053b907d96d7e0aa7d0c6c1be3a73d4/Drilling.Common/Product/CProductManager.cs#L1050-L1057)

**검증 필요:** 외부 CIM/기존 도구가 공정 결과를 여전히 JUDGEMENT에서 읽는지 확인해야 합니다. 새 ActiveProduct를 구형 프로그램에서 열 때의 판정 의미는 별도 호환 시험이 필요합니다.

### ARC-07 · 원시 크기·두께·문자열 단위는 아직 사양 검증 대상이다

**확인:** GLASS_SIZE 두 WORD는 쉼표 문자열, THICKNESS/STATE는 정수 문자열입니다. ASCII 길이 제한은 SIM 쓰기에서 검사합니다. [필드 자료형](https://github.com/kjuws10-rgb/A3Drilling/blob/0219666f9053b907d96d7e0aa7d0c6c1be3a73d4/Drilling.Common/Interface/Melsec/CStageGlassDataMap.cs#L33-L78), [SIM 문자열·정수 검사](https://github.com/kjuws10-rgb/A3Drilling/blob/0219666f9053b907d96d7e0aa7d0c6c1be3a73d4/Drilling.Common/Interface/Melsec/CMelsec.cs#L3075-L3089)

**검증 필요:** endian/WORD 순서·문자 padding·단위·고객 판정 코드표를 확인해야 합니다. 외부 Spec 원문을 읽지 않았으므로 코드 주석과 실제 고객 사양의 일치를 확정하지 않습니다.

### ARC-08 · Product 정보 API의 수정 범위가 넓어졌다

**확인:** HostWritable 목록이 공통 Stage 목록으로 바뀌어 PPID/JUDGEMENT/OPTION 계열도 포함합니다. SetProductInfo는 허용 키를 검사하지만 상태별 금지 조건은 이 메서드에 없습니다. 이번 master에서 외부 호출자는 찾지 못했습니다. [정보 수정 API](https://github.com/kjuws10-rgb/A3Drilling/blob/0219666f9053b907d96d7e0aa7d0c6c1be3a73d4/Drilling.Common/Product/CProductManager.cs#L278-L306), [허용 목록](https://github.com/kjuws10-rgb/A3Drilling/blob/0219666f9053b907d96d7e0aa7d0c6c1be3a73d4/Drilling.Common/Product/CProductManager.cs#L862-L874)

**검증 필요:** 향후 CIM 연결 시 진행 중 PPID 변경을 어떻게 막을지 정해야 합니다. 현재 UI에서 그 문제가 실행됐다고 단정하지 않습니다.
