## 실제 프로젝트 시험으로 반영한 보완

- 2K에서는 작은 합성 코드의 전달검사를 통과했지만 실제 A3 편집은 제안 전 문맥 부족으로 실패했습니다. 이를 합격으로 처리하지 않았습니다.
- 16GB급 PC의 실제 예약 RAM을 고려하고 모델 외1.5GiB 이상 여유가 있을 때4K를 우선 확보하도록 Auto를 보완했습니다. 경계값35/35로 확인하고 실제 A3에서4K 동작을 재확인했습니다. 메모리가 부족하면 무조건 확대하지 않습니다.
- 토큰 한도 응답을 미완성으로 차단하고, 호스트가 계산한 실행 상태를 모델 문장과 분리했습니다.
- 빌드 결과를 채팅 입력으로 준비하는 기능을 추가했습니다. 작은 문맥은 최대1,000자, 큰 문맥은 최대3,000자로 실제 첫 오류 주변을 우선 발췌하며 직접 전송·적용은 사용자 작업입니다.

## 현장 투입 판단

실제 A3의 작은 함수 편집·검증·원복이 가능한 근거를 확보했습니다. 이 결과만으로 모든 신규기능·복잡한 다중파일 변경·Codex 동등 정확도를 보증하지 않습니다. 8B CPU 추론은 이번 과제에 약5분이 걸렸습니다. 일반적인 낮은 지연이나 모든 모델보다 높은 정확도가 입증된 것은 아닙니다.

전체 A3를 빌드하려면 현재 원격에 없는 Log 관련 소스/참조를 정상 작업 환경에서 준비해야 합니다. 누락 모듈을 임의의 대체 구현으로 채워 통과시키지 않았습니다. 코드 읽기와 제한된 함수 검증, 전체 솔루션 빌드, 설비 구동은 구분합니다. 이번 검증에서는 장비 연결·축 이동·레이저·PLC 신호 출력을 실행하지 않았습니다.

검증 중 앱/자식 프로세스의 TCP 관찰12회에서 외부 Established연결0을 확인했으나, 이는 물리 NIC를 끊은 현장시험과 다릅니다. 다른 물리 노트북의 설치·드라이버·장비SDK·실기 성능은 반입 전 별도 확인해야 합니다.
