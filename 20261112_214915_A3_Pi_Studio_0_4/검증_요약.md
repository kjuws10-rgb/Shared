## 발견하여 보완한 항목

- Pi 기본 `streamSimple`의 고정4096 토큰 여유 때문에 작은 문맥에서 출력이1토큰이 되는 문제를 실제 요청으로 확인하고 공식 저수준 stream/문맥별 예산으로 연결했습니다.
- 초기2K 실제 앱 시험에서는 제안까지 생성됐지만 최종 설명 문맥이 부족해 전체 턴이 오류·폐기됐습니다. 검색 코드와 read, 제안 미리보기의 중복 전달 및 시스템 프롬프트를 줄인 최종 실행본으로19/19를 다시 확인했습니다.
- 종료·취소 중 이전 모델 복구가 새 프로세스를 재생성하는 경합은 lifetime 취소·종료 후 재시작 차단·취소 가능한 복구로 보완했습니다.

## 별도 확인 대상

- 실제 다른 물리 노트북, 현장 물리 망분리, GPU/드라이버별 성능은 시험하지 않았습니다.
- 전체 A3 프로젝트 빌드·장비 SDK·실장비 구동·정밀도·인터락 평가는 별도입니다. 실제 A3의 작은 함수와 별도 합성 Git fixture를 사용했습니다. 전체 솔루션은 기준/후보 모두 기존 Common.Log/CLogManager19오류로 실패하고 신규오류0을 확인했습니다.
- 실제 A3 대형 모델 가중치 학습과 Codex 동등 정확도는 검증하지 않았습니다. A3 업데이트는 지식·스타일·학습자료 갱신이며 LoRA 실행은 별도 준비 환경·명시 버튼을 사용합니다.
- 추가 지식갱신/학습 결합 QA 명령은 automatic approval review에서 `blocked by policy`로 거부되어 실행하지 않았습니다. 상세 사유는 제공되지 않았으며 우회 재시도하지 않았습니다. 해당 부분은 소스 정적 확인과 회귀검사 범위로 한정합니다.
- 온라인 모델 준비 도우미의 전체5GB 재다운로드는 반복하지 않았습니다. 다운로드 엔진은22개 fixture로 검증했고 실제 모델 파일은 기존 해시 확인된 GGUF를 사용했습니다.
- 준비된 App에 장비 소스·내부 Context·모델 가중치·사용자 상태가 포함되지 않는지 파일 목록을 검사합니다. 외부 라이브러리/바이너리 전체 보안 감사라는 의미는 아닙니다.

최종 ZIP의 CRC·중복 경로·SHA 및 각 App 파일 해시는 `release-manifest.json`과 `SHA256SUMS.txt`에 기록합니다. 이전0.3 폴더·생산 저장소는 보존했습니다.

실제 프로젝트별 근거와 제한은 [A3 실제 프로젝트 검증](A3_실제프로젝트_검증.md)에 따로 정리했습니다. 자동 승인 검토가 임시 폴더 정리를 거부한 경우 폴더삭제를 재시도하지 않고, 해시가 같은 공개 실행본을 보존한 상태에서 임시 중복 EXE 한 파일만 정리했습니다.
