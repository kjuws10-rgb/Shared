Windows x64 · 인터넷 없이 현장 사용

A3 Pi Studio 0.4
다른 노트북에서도 바로 시작하기

Pi 코딩 에이전트가 현재 A3 코드를 검색하고, 로컬 모델이 설명과 수정안을 만듭니다.
Node·npm을 직접 설치하지 않고, 준비된 실행 폴더를 그대로 옮기는 방식입니다.

Pi 1.5.2Qwen3-8B 기본전체 백업 후 적용기본 오프라인 잠금
① 준비② 다른 노트북③ 채팅·적용현장 개발 순서모델 선택문제 해결반입 체크

설치는 세 단계입니다

1. 온라인 PC에서 준비

도구 ZIP을 풀고 GGUF 모델을 준비합니다. 기존 0.3 모델도 재사용할 수 있습니다.

2. 폴더 전체를 복사

App 전체와 승인된 A3 프로젝트·자료를 현장 노트북으로 옮깁니다.

3. 시작하기 실행

프로젝트 선택 → A3 업데이트 → 채팅. 수정안은 확인한 뒤 적용합니다.

실행 도구 ZIP자료·소스·검증 요약

공개 도구 ZIP에는 모델 가중치·A3 장비 소스·내부 자료가 포함되지 않습니다. 아래에서 모델을 한 번 준비하면 이후 인터넷 없이 사용합니다.

① 인터넷 되는 PC에서 준비

1

실행 도구 ZIP을 압축 해제합니다

예: D:\A3PiStudio. ZIP 안에서 바로 실행하지 말고 짧고 쓰기 가능한 경로에 압축을 풉니다.

2

모델을 준비합니다

기존 0.3의 App\Models\Qwen3-8B-Q4_K_M.gguf를 새 도구의 App\Models에 복사합니다. 기존 0.3 폴더는 그대로 보존하세요.

모델 파일 1개만 두면 첫 실행 시 자동 반입합니다. Models가 비었거나 파일이 여러 개라면 앱에서 모델 넣기로 GGUF 1개를 선택합니다.

App\Prepare-FieldModel.cmd를 더블클릭합니다. 기본 Qwen3-8B Q4_K_M을 Hugging Face에서 받아 크기·SHA256을 확인하고, 반입 가능한 App\Models\A3-a3.gguf로 준비합니다.

약 5.03GB 다운로드이므로 시간이 걸립니다. 완료 후 창에 Ready가 나타나고 Models에 GGUF가 있는지 확인하세요. 실패 시 model-prepare-error.log를 확인합니다. 이 작업은 모델 다운로드이며 코드나 자료를 업로드하지 않습니다.

프로그램 안의 모델 라이브러리에서도 다운로드할 수 있습니다. 다만 그 캐시는 해당 PC의 사용자 폴더에 저장됩니다. 다른 노트북으로 옮길 모델은 이 도우미 또는 Models 직접 복사로 준비하세요.
3

App 전체와 작업 사본을 준비합니다

A3Drilling 전체 Git 작업 폴더에는 .git과 Drilling.sln이 있어야 합니다. .git\config의 원격 저장소는 A3Drilling이어야 합니다. 소스 ZIP만 받은 폴더는 전체 Git 작업 사본과 다릅니다.

인터넷 되는 개발 PC에서 정상 Git 작업 사본을 준비하고, 코드·자료는 현장 반입 승인을 받은 방법으로 별도 옮깁니다. 도구가 Codex의 첨부 자료를 자동으로 가져오지는 않습니다.

A3PiStudio\
 ├─ App\
 │   ├─ 시작하기.cmd                 ← 이것을 실행
 │   ├─ A3.OfflineStudio.exe
 │   ├─ PiRuntime\                  ← Node와 공식 Pi SDK
 │   ├─ Runtime\                    ← 로컬 모델 실행기
 │   ├─ Models\*.gguf               ← 준비한 모델 1개
 │   ├─ toolchain\                  ← 오프라인 .NET SDK와 준비된 feed
 │   ├─ Prerequisites\              ← VC++ 오프라인 설치파일
 │   └─ Prepare-FieldModel.cmd       ← 온라인에서 모델 준비
 └─ A3_Pi_Studio_0_4_설치_사용법.html

별도 작업 경로: D:\Work\A3Drilling\  (.git · Drilling.sln 포함)

② 다른 노트북에서 실행

확인준비 내용
운영체제Windows 10/11 64비트(x64)용입니다. ARM64·macOS·Linux용 묶음이 아닙니다.
메모리8B 모델은 16GB 이상, 여유가 있으면 32GB를 권합니다. 저사양은 작은 모델로 시작합니다. 다른 노트북의 실제 성능은 별도 확인합니다.
디스크모델 원본·검증 캐시·자동 반입 사본 때문에 중복 공간이 필요합니다. 도구·모델용 여유 25GB 이상을 계획하고, 프로젝트 전체 백업 크기는 별도로 확보합니다.
그래픽카드이번 배포는 CPU Auto 기본입니다. NVIDIA 드라이버·CUDA·Python·Node·npm을 별도 설치할 필요가 없습니다.
빌드SDK와 준비된 NuGet feed가 포함됩니다. A3 프로젝트의 별도 장비 SDK·네이티브 DLL·참조 파일까지 모두 해결되는 것은 아닙니다.
1

App 전체를 현장 노트북으로 복사합니다

GGUF까지 들어 있는 App 전체를 복사합니다. EXE만 복사하면 Pi·모델 실행기·모델이 없어 동작하지 않습니다. 구버전 App 위에 덮어쓰기보다 새 폴더를 사용합니다.

2

App\시작하기.cmd를 실행합니다

기존 0.3 앱이 실행 중이면 트레이에서 먼저 종료합니다. 필요한 VC++ 런타임이 없으면 동봉된 Microsoft 설치 창이 나타납니다. 설치에 관리자 권한이 필요할 수 있습니다. 현장 PC 설치 권한은 담당자에게 확인하세요. 재시작을 요청받으면 재부팅 후 다시 실행합니다.

모델 첫 반입은 해시 검사와 사본 준비로 시간이 걸립니다. 완료될 때까지 기다립니다. 앱은 로컬 브라우저 화면을 사용하며 브라우저 창만 닫으면 트레이에 남을 수 있습니다.

3

프로젝트 선택 → 자료 추가 → A3 업데이트

노트북에 복사한 실제 작업 폴더를 선택합니다. 필요한 자료를 추가하고 A3 업데이트를 누르면 현재 코드·자료·스타일·적용 사례를 갱신합니다. 기본 오프라인 잠금을 유지한 상태로 사용할 수 있습니다.

첫 실행은 모델이 없어도 화면을 열 수 있습니다. 채팅을 시작하려면 프로젝트·모델·Pi 준비가 모두 끝나야 합니다. 다른 PC에서 선택한 경로나 채팅 기록이 자동 이전되는 방식은 아닙니다.

③ 채팅하고 수정안을 적용하는 방법

먼저 설명 요청

“이 함수의 입력과 반환값, 호출하는 곳을 설명해줘.”처럼 파일·함수와 목적을 함께 지정하면 검색 범위를 줄일 수 있습니다.

수정 범위 지정

“해당 함수에서 빈 목록일 때 0을 반환하도록 수정안을 만들어줘. 다른 파일은 바꾸지 마.”처럼 한 번에 작은 작업을 요청합니다.

미리보기 후 적용

Pi가 읽기 → 수정안 → 검토 대기까지 진행합니다. 변경 내용을 확인하고 적용 버튼을 누릅니다.

버튼·동작실제로 하는 일확인할 점
A3 업데이트현재 코드·자료 색인, 개발 스타일, 적용 사례와 학습용 데이터를 갱신합니다.모델 가중치 자체를 학습한 것이 아닙니다. 자료가 많으면 시간이 걸립니다.
전송공식 Pi agent loop가 앱의 search/read/propose/review 도구를 호출합니다.응답 속도·정확도는 모델과 노트북 사양에 따라 달라집니다.
수정안 적용.git·미추적·바이너리를 포함한 프로젝트 전체를 외부 백업 폴더에 검증 복사한 후, 선택한 작업 경로를 수정합니다.백업이 실패하면 코드를 수정하지 않습니다. 다른 도구의 동시 수정은 피하세요.
되돌리기승인해 적용한 변경을 이전 바이트로 되돌립니다.적용 후 해당 파일을 다시 편집했다면 덮어쓰기를 차단합니다. 새 편집부터 확인하세요.
빌드 확인 · 이 결과로 수정 요청준비된 로컬 SDK·의존성으로 컴파일을 시도합니다. 실제 결과 아래 버튼으로 로그를 채팅 입력창에 준비하고 직접 전송합니다.빌드 성공과 설비 동작 검증은 다릅니다. 변경된 기능의 시뮬레이션·검증을 함께 수행합니다.
실제 가중치 학습별도로 준비된 Python·HF 원본·학습 환경을 검사하고 LoRA 학습·평가 후보를 만듭니다.일반 채팅에 필요하지 않습니다. 전체 대형 모델 학습 환경은 이번 도구 ZIP에 포함하지 않습니다.

자료 크기·개수에 임의 상한을 두지는 않지만 디스크·메모리·문서 추출 가능 형식에 따른 한계는 있습니다. 한 번에 모든 파일을 LLM 문맥에 넣는 방식은 아니며, 현재 요청에 필요한 코드와 자료를 검색해 전달합니다. 문맥이 부족하면 새 대화에서 파일·함수를 구체적으로 지정하세요.

현장에서 반복 개발하는 순서

현재 구성은 16GB급 Windows 노트북에서 실제 로컬 모델과 A3 소스로 확인한 실용적인 시작 구성입니다. 모든 노트북·모든 과제에서 가장 좋은 모델이라는 비교 결과는 아닙니다. 성능을 판단할 때는 모델 이름보다 같은 A3 과제를 얼마나 정확하게 끝내는지를 확인합니다.

  1. 먼저 기준 빌드: 수정하지 않은 실제 A3 사본을 오프라인에서 빌드하고 결과를 보존합니다. 필요한 장비 SDK·참조 DLL·네이티브 x64 라이브러리·NuGet을 미리 준비합니다. 이미 있던 오류와 새 변경의 오류를 구분합니다.
  2. 현재 코드 확인: A3 업데이트 후 파일 경로·함수명을 지정해 입력, 출력, 호출하는 곳을 설명하도록 요청합니다.
  3. 작게 수정: 바꿀 동작과 보존할 동작, 정상·경계·오류 입력의 기대값을 함께 줍니다. 문맥이 작으면 함수 하나부터 범위를 줄입니다. 실제 A3 편집에는 4K 문맥을 우선 확보합니다.
  4. 미리보기와 백업 적용: 실제 읽은 파일·변경 줄을 확인하고 적용합니다. 앱이 전체 프로젝트 백업을 완료한 뒤 선택한 경로를 수정합니다.
  5. 빌드 → 수정 반복: 빌드 결과 아래 이 결과로 수정 요청을 누릅니다. 실제 로그가 입력창에 준비되며, 확인한 뒤 직접 전송합니다. 모델이 다음 수정을 자동 적용하지 않습니다. 프로젝트·대화가 바뀌면 이전 결과는 재사용하지 않습니다.
  6. 논리 검증과 원복: 정상값뿐 아니라 범위 밖·NaN·누락·빈 입력 등을 검사합니다. 좌표/샘플링 같은 순수함수 검증과 장비 이동·가공 평가는 나눕니다. 필요하면 되돌리기로 적용 전 바이트를 복원합니다.
설명과 실제 실행은 구분합니다. 답변에는 서버가 계산한 ‘호스트 확인’ 박스가 붙습니다. 제안 수와 이 답변에서 실제 코드 변경·빌드·설비 실행을 했는지 표시합니다. 모델이 쓴 ‘완료’ 문장만으로 성공을 판단하지 않습니다. 토큰 한도로 잘린 응답은 미완성으로 차단하고 해당 턴 제안을 철회합니다.
환경·작업현재 선택과 다음 판단
16GB급 CPU 노트북기본8B로 작은 로직부터 검증합니다. 메모리 여유가 충분하면 Auto가 코딩용4K를 우선 확보합니다. 부족하면2K로 줄 수 있고, 한 번의 요청에 수분이 걸릴 수 있습니다. 2K에서는 실제 프로젝트 편집이 문맥 부족으로 실패할 수 있습니다. 작은 모델·다른 앱 종료 등으로 여유를 확보하고, 긴 빌드 로그는 필요한 오류를 지정합니다.
여유 있는 PCRAM32GB 이상을 권장합니다. Auto가 여유 메모리와 모델 묶음의 문맥 한도 안에서 설정합니다. 더 큰 모델·GPU를 쓰면 같은 A3 과제와 오프라인 조건으로 다시 평가해야 합니다.
새 모델로 교체현재 코드 설명, 작은 기존 함수 수정, 경계값 검사, 적용·원복을 같은 기준으로 비교합니다. 작은 모델은 메모리를 아껴도 코드 정확도는 낮아질 수 있습니다.
복잡한 변경여러 파일의 큰 리팩터링·하드웨어 연동·전체 공정 성능은 현재 단일 과제 성공으로 보증하지 않습니다. 작업을 나누고 호출부·시뮬레이션·실기 평가를 함께 검토합니다.

모델 라이브러리는 이렇게 사용합니다

Hugging Face의 모든 모델을 자동 지원하는 대신, 검증용 핀과 SHA256이 등록된 모델 3개를 카드로 제공합니다. 기본은 Qwen3-8B입니다. GGUF는 모델 파일이고 Pi는 이 모델을 사용하는 코딩 에이전트입니다.

카드모델파일 크기선택 기준
A3 기본Qwen3-8B · Q4_K_M5.03GB (4.68GiB)이번 실제 Pi 읽기·수정안 생성 시험에 사용했습니다. CPU에서 느릴 수 있습니다.
코드 중심Qwen2.5-Coder-7B-Instruct · Q4_K_M4.68GB (4.36GiB)다른 코드 중심 모델과 비교할 때 선택합니다. 0.4 Pi에서 같은 정확도가 검증되지는 않았습니다.
가볍게 시작Qwen2.5-Coder-1.5B-Instruct · Q4_K_M1.12GB (1.04GiB)메모리가 부족할 때 시험합니다. 복잡한 코드 이해 능력은 더 제한적일 수 있습니다.

다운로드는 모델 라이브러리 → 온라인 준비 모드 켜기 → 다운로드 → 사용 순서입니다. 기본 오프라인 잠금에서는 다운로드와 최신 코드 준비를 차단합니다. 온라인 준비를 켜도 채팅 추론은 로컬 모델에서 이루어집니다. 준비가 끝나면 오프라인 잠금으로 되돌리세요.

저사양 노트북에 작은 모델을 준비하려면

인터넷 되는 PC의 App 폴더에서 아래 명령을 실행합니다. 기본 모델과 여러 GGUF가 있다면 자동 선택 대신 앱의 모델 넣기로 사용할 파일을 고릅니다.

Prepare-FieldModel.cmd -Model fast
현재 설치된 Pi와 런타임은 무엇인가요?

Pi SDK 1.5.2, Node 24.19.0 Windows x64, llama.cpp b11960 CPU 실행기를 포함합니다. PiRuntime의 package-lock.json·runtime-manifest.json·라이선스로 설치 출처와 버전을 확인할 수 있습니다. 개발자가 공식 Git/npm에서 다시 구성하는 방법은 소스의 Pi/README.md와 Prepare-PiRuntime.ps1에 있습니다.

문제가 생겼을 때

모델이 없다고 나옵니다

새 App\Models에 GGUF 1개가 실제로 있는지 확인합니다. 다운로드한 ZIP 자체가 아니라 압축을 푼 GGUF를 넣어야 합니다. 파일이 여러 개면 모델 넣기를 사용합니다. 오프라인 PC에서는 모델을 새로 다운로드할 수 없으므로 준비 PC에서 먼저 가져옵니다.

PiRuntime이 불완전하다고 나옵니다

전체 ZIP을 다시 압축 해제합니다. PiRuntime\node.exe, bridge.mjs, node_modules 폴더를 함께 보존합니다. EXE만 복사하거나 node_modules를 제외하면 사용할 수 없습니다.

프로젝트 폴더 선택이 거부됩니다

Drilling.sln과 .git이 있는 실제 A3Drilling Git 작업 폴더를 선택합니다. GitHub 소스 ZIP만 받은 폴더나 다른 저장소는 대상이 아닙니다. 온라인 개발 PC에서 정상 Git 작업 사본을 준비하세요.

첫 실행·응답이 느립니다

첫 모델 반입은 파일 검증·복사 때문에 시간이 걸립니다. CPU 8B 추론은 간단한 요청에도 수분이 걸릴 수 있습니다. 요청을 작은 기능으로 나누고 파일·함수명을 지정합니다. 메모리가 부족하면 작은 모델을 시험하세요. 동작 중에는 중지 버튼을 사용할 수 있습니다.

모델 해시 검사에 실패했습니다

파일이 불완전하거나 등록된 모델과 다른 내용일 수 있습니다. 잘못 받은 파일을 별도 보존하고 준비 PC에서 다시 다운로드합니다. 오류를 무시하고 실행하는 기능은 제공하지 않습니다.

백업 또는 원복이 막힙니다

백업 경로의 여유 공간·쓰기 권한과 프로젝트의 잠긴 파일을 확인합니다. 다른 IDE·Git 작업이 파일을 변경했는지도 확인합니다. 백업 완료 전에 직접 덮어쓰지 마세요. 원복 충돌은 적용 후 편집을 보존하기 위해 차단합니다.

빌드가 실패합니다

결과 로그에서 첫 오류를 확인합니다. 코드 오류와 누락된 장비 SDK·참조 DLL·NuGet 패키지를 구분합니다. 공개 도구는 실제 A3 프로젝트에 필요한 모든 별도 라이브러리를 배포하지 않습니다.

PC를 옮기니 이전 설정과 채팅이 없습니다

설정·모델 캐시·제안 기록은 사용자별 로컬 상태에 저장됩니다. App 복사는 실행 환경의 이동입니다. 새 PC에서 프로젝트를 다시 선택하고 자료를 추가하세요. 기존 상태를 지우기 전에 앱을 종료하고 별도 보존합니다.
