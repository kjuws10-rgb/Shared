# 데이터 구조·저장·좌표 흐름

초보자가 먼저 구분할 경계는 **장비 공통값(Setting), 제품 조건(Recipe), 가공 명령 좌표, 측정 결과, 저장 보정값**입니다.

| 데이터 | 새 생산/보관 | 소비 경로 | 주의점 |
| --- | --- | --- | --- |
| ST_ALIGN_KEY_MARGINS / AK_MARGIN_X·Y | Setting Option/ALIGN, 필수 유한·0이상 mm | BuildDesignShots·Default·Review·미리보기·Script·Distortion | 옛 Recipe의 사용자 값이 자동 이관되는 것은 아님. Margin 변경은 같은 Recipe의 좌표 기준도 바꿈 |
| Distortion Snapshot.AlignKeyMargins | Prepare 때 공통 Margin과 StageY를 동결 | Key 배치·보간 모델·Shot Align Offset 계산 | Recipe 변경 검사와 Setting 변경 검사는 별도. 저장 시 Setting 재확인 경계 검토 |
| DISTORTION_PAIR0/1/2_Y | Recipe에서 다시 보이거나 편집 가능한 설계 Y 메타데이터 | Recipe 표시·저장 | 현재 측정 이동·보간 Key의 Y는 Motor DK StageY로 계산. 이 항목을 실제 Stage 위치 I/F로 오인하지 않음 |
| ST_RECIPE_APPLY_HISTORY_CACHE.LatestBySource | Recipe/_apply 하위 날짜별 AppliedSources.csv를 첫 조회에 색인 | FindSourceApplication·SaveNewFromSource·Rollback | 경로 기준 식별. 파일 내용 동일 여부나 다른 프로세스의 외부 변경을 항상 추적하는 것은 아님 |
| RESULT_SOURCE 후보 | MEASURED·RETAINED·EDITED | REVIEW DATA 직접/ROUGH/FINE 적용 | 출처를 보정 허용과 품질 OK로 혼동하지 않음. 보간/적용 조건은 각 경로에서 별도 검사 |
| ONE_LINE → DIRECT_LINE | 한 행의 유효 측정 결과 | 해당 행 직접 Offset 누적 | 전체 기판 보정이나 Fine 보간과 다른 범위 |
| 원측정 mm Number → FormatDouble | Fine 결과 CSV의 값 보존 정밀도 증가 | 결과 재로드 → 새 Fine 계산 | 최종 Offset RoundValue 0.001mm 정책과 실제 측정 분해능은 별도 |
| AUTO INIT ownership/status | ResetStageRequestsAsync·공통 cleanup·강제0 readback | Action WAIT·감시 재시작 | PC 출력/Task 정리이며 Stage 입력, 원점/서보/기판 상태 초기화가 아님 |
| PM 사유/기간/수명 표시 | StartPmSession/CompletePmSession 호출·Setting/선택Recipe 수명값 | PM Lock UI·이력 목록 | Log 구현이 추적 소스에 없음. 표시값을 자동 수명 차단으로 해석하지 않음 |

## 단위와 보정 적용 순서

Margin·좌표·Offset은 mm, 엔코더 명령은 각 Head 배율/방향을 적용한 별도 값입니다. 저장한 Design 보정값은 좌표 생성 때 현재 축 Flip/주행 방향과 배율로 변환됩니다. CSV에 보이는 숫자, UI 표시 반올림, 저장 정밀도, 물리 정밀도는 구분합니다.
