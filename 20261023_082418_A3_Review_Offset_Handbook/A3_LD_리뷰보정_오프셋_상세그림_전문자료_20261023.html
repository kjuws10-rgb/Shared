02 · 목표·실측·명령과 보정값의 첫 개념

먼저 목표 T, 실측 M, 명령 Q를 나눕니다. 목표는 홀이 있어야 할 자리, 실측은 이미 만들어진 홀의 자리, 명령은 다음에 스캐너로 보낼 값입니다. 보정값으로 이미 뚫린 홀을 움직이지는 못합니다.

03 · Default Offset · 스캐너의 기준 자리를 맞춥니다

3-2 · X: 4·5번 Head 사이를 기판 중심 기준으로 배치합니다

회의 방향 기판 중심을 사이에 두고 H4와 H5의 목표 원점을 배분하고, 나머지 Head도 설계 피치만큼 이어 놓습니다. 실제 Head 번호가 X 증가 방향으로 붙어 있는지 먼저 확인합니다.

그림의 계산 가정: H1→H8이 X 증가 방향이고, 8개 Head가 같은 피치 P로 배치된 경우입니다.
목표 X(h) = 기판 중심 X + (h − 4.5) × P
P=110 mm라면 H4는 중심−55 mm, H5는 중심+55 mm입니다. H1~H8의 ±385 등은 이 가정에서 나온 학습 계산값입니다. 실제 간격이 다르면 도면의 Head별 설계 X를 사용합니다.

예를 들어 H4 원점이 기판 중심보다 55 mm 왼쪽이라면, 동일한 X 방향으로 정의한 H4의 +55 mm 명령은 중심을 향합니다. H5의 −55 mm도 중심을 향합니다. 실제 Scanner Local 축이 반대이면 명령 부호가 달라지므로 이 예제를 입력값으로 그대로 사용하지 않습니다.

3-3 · Review로 마크를 찾으면 위치는 어떻게 얻나요?

  1. Head를 구분할 수 있는 테스트 패턴을 가공합니다. 여러 Head·분기빔의 마크가 겹쳐 누가 만든 마크인지 불분명하지 않게 순서를 나눕니다.
  2. Review X를 예상 위치로 이동하고 영상에서 정해진 마크 ID를 찾습니다.
  3. 마크를 FOV 중심에 정확히 맞췄다면 그때의 Review 엔코더 위치로 위치를 비교할 수 있습니다.
  4. 중심에 맞추지 않았다면 영상 중심에서 마크까지의 잔여 이동량을 교정된 같은 좌표계의 mm로 변환해 더합니다. 픽셀 수를 엔코더 mm에 직접 더하지 않습니다.
위치 기록의 개념식: 마크 위치 M = 카메라 광축의 Review 좌표 E + 영상 잔여량 δ(mm).
E의 원점·부호·단위와 δ의 변환이 일치하는 조건입니다. 카메라 광축 위치가 아닌 다른 축 원점·정수 카운트를 그대로 E로 넣으면 안 됩니다. 영상 잔여량을 쓸 수 없다면 중심 맞춤 경로로 측정하고 정렬 정확도를 확인합니다.

기판 중심과 Head의 분기빔 중심은 별개입니다. 기판 중심은 공통 기준이고, 아래 그림의 가운데 O_h는 특정 Head의 가상 원점입니다. 같은 “양쪽 값의 중간” 계산을 쓰더라도 무엇의 중심인지 구분해야 합니다. 기판도 설계상 대칭인 좌우 기준점을 같은 Review 좌표계로 측정했다면 중간값을 사용할 수 있고, 비대칭이면 설계 관계를 반영합니다.

3-4 · 16분기빔: 가운데 홀이 없어도 원점을 찾을 수 있습니다

그림처럼 원점에 대해 설계상 대칭인 두 마크 A·B를 같은 Review 좌표계로 측정했다면 O_h=(M_A+M_B)/2로 가상 원점을 구할 수 있습니다. 계산 위치에 실제 가공홀이 없어도 됩니다. 마크 번호와 대칭 관계가 확인되어야 합니다.

경우계산 / 처리
원점에 대해 대칭인 두 마크중간 위치가 해당 Head의 가상 원점. X/Y 각각 같은 방법으로 계산
대칭이 아닌 두 마크설계상 원점에서 각 마크까지의 변위 dA·dB를 반영: O_h=(M_A+M_B)/2−(dA+dB)/2
마크 하나만 사용하는 방법마크 ID와 설계 변위 dA가 확정되면 O_h=M_A−dA로 계산 가능. 기준 선택은 별도 확정
Zero Order / B11 / 가상 중심같은 점이라고 자동 가정하지 않음. 16개 빔의 인덱스·방향·실제 기준 마크 계약 필요
비대칭 식의 dA·dB는 마크 ID에 대응하는 부호를 포함한 동일 Review 좌표계상의 설계 변위입니다. raw Pixel/Scanner Local 피치를 직접 빼지 않습니다. 회의의 0.09/0.1 피치와 기준 빔 설명은 확정된 장비값·인덱스가 아닙니다.

04 · Head와 Head–Cell · 첫 홀과 적용 구역

2026-10-23 · 사용자 기준 반영
Simple과 Rough 모두 Head / Head–Cell 선택에 따라 측정할 첫 가공홀과 값의 적용 범위가 함께 결정됩니다. Head–Cell과 기존 표기의 Cell–Head는 같은 조합을 뜻합니다. 이 문서는 개발 기준을 정리한 자료이며 생산 SW 수정 완료를 뜻하지 않습니다.

기준점에서 값을 얻고 → 정해진 구역에 같은 값을 넣습니다. Head는 Head마다 한 값, Head–Cell은 Cell 안의 Head 구역마다 한 값입니다. Simple은 선택한 한 대상을 측정·적용하고, Rough는 필요한 대상들의 첫 홀을 자동으로 순회합니다.

4-1 · 같은 Head끼리 공유할까, Cell마다 따로 만들까?

선택 기준어디를 측정하나요?어디에 적용하나요?

Head–Cell각 Cell 안의 해당 Head 구역 첫 가공홀해당 Cell·Head 조합의 모든 유효 가공점에 동일한 Cx/Cy

첫 가공홀은 화면에서 가장 왼쪽인 점을 뜻하지 않습니다. 실제 Recipe의 가공 순서와 유효 가공점 목록을 사용합니다. Head 방식은 그 Head가 담당하는 최상단 Cell을 먼저 찾고, 그 안의 첫 홀을 선택합니다. Head–Cell 방식은 선택한 Cell의 해당 Head 구역에서 첫 홀을 선택합니다. Point ID에는 Cell·Head·X/Y·Branch·Recipe Revision을 함께 연결합니다.

“동일 적용”은 Head들끼리 한 값을 공유한다는 뜻이 아닙니다. Head 방식의 H1·H2·H3는 서로 다른 보정값을 가질 수 있습니다. 같은 Head 안에서만 위·아래 Cell이 같은 값을 사용합니다. Head–Cell 방식에서는 같은 H2여도 C1과 C2의 값이 다를 수 있습니다.

그림 공통 가정: C1이 최상단이고 C2가 그 아래에 있습니다. 각 Cell에서 H1은 X1·X2, H2는 X3·X4, H3는 X5·X6을 담당합니다. 설명용 가공 순서는 Y0에서 각 Head의 첫 담당 X로 시작하며 Branch는 B11입니다. 따라서 H2의 첫 홀은 Y0–X3–B11입니다. 실제 장비의 첫 점은 실제 가공 목록에서 확인합니다. C1–Y50–X3은 Mask이며 이 점은 계속 제외합니다.

4-4 · 한 점이 맞으면 구역 전체도 맞을까요?

한 점에서 얻은 값은 그 위치의 편차를 알려 줍니다. Head 전체가 같은 양만큼 밀렸다면 Head 방식이 맞는 접근입니다. Cell마다 편차가 다르면 Head–Cell 방식이 더 세밀합니다. 한 Cell 안에서도 위치에 따라 달라지는 편차는 한 값으로 모두 맞출 수 없으므로 Fine 보정과 적용 후 측정으로 확인합니다.

Rough 후 Fine을 수행할 때에는 기준 Offset과 적용 Revision을 남기고, 합산·교체 방식 및 적용 기판을 명시하여 같은 오차를 두 번 보정하지 않도록 합니다. 기존의 별도 Cell 전체 모드는 이번에 확정한 두 방식과 구분하며, 대표 Head·값의 선정 규칙이 정해지기 전 임의 적용하지 않습니다.

7-2 · 실제 Y거리 기준이 중요한 이유

별도 예제에서 7개 라인의 Y가 0,10,20,30,40,50,100 mm라면 행 번호 가운데는 4번째 Y30입니다. 그러나 Cell의 거리 가운데는 (0+100)/2=50 mm이므로 Y50이 기준입니다. 행 사이에 빈 구간이 크면 두 기준의 차이가 더욱 커집니다.

녹음에서도 Row 개수 기준으로 값을 나눌 때 실제 Y간격과 맞지 않아 오차가 생긴 사례를 설명합니다. 라인 선정과 보간 모두 같은 실제 Y좌표 기준을 사용해야 합니다.

  3. 3줄 이상은 첫·끝 라인을 고정하고 내부 목표 Y를 계산합니다.

8-7 · Rough 이후 Fine의 값이 잔여량인지 최종량인지 확인합니다

  • 측정 당시 사용한 Recipe Revision·Offset Revision을 저장합니다.
  • 원시 편차 e, 모드 산출값 C, 합성/교체 후 최종 적용값을 각각 보존합니다.
  • Fine이 residual인지 absolute인지 데이터 의미를 인터페이스에서 정의합니다.
  • 기준 Offset이 측정 후 변경되었다면 기존 계산을 그대로 승인하지 않도록 버전 검증 규칙을 정합니다.
  • 적용 완료 뒤에도 Tolerance와 반복성으로 검증합니다. 보간 계산 성공은 검사 합격을 뜻하지 않습니다.

녹음·기존 요구사항의 연결 요약

선택 Y라인의 측정값을 같은 논리 X 위치와 동일 DOE Branch에 대응시켜, X·Y 보정 성분을 각각 독립적으로 보간합니다. Branch 번호만 같다는 이유로 서로 다른 X위치의 데이터를 섞으면 안 됩니다.

λ = (Y − Yₐ) / (Yᵦ − Yₐ)
Cₓ(Y) = (1 − λ) Cₓ,ₐ + λ Cₓ,ᵦ
Cᵧ(Y) = (1 − λ) Cᵧ,ₐ + λ Cᵧ,ᵦ

예: Y=0 mm에서 C=(+0.010, −0.004) mm, Y=100 mm에서 C=(+0.020, +0.002) mm라면, Y=25 mm의 C=(+0.0125, −0.0025) mm입니다. 이 예의 값은 원시 측정편차가 아니라 이미 정의된 보정량입니다.

  • Cell·Head·논리 X인덱스·Branch의 대응을 유지합니다. DOE Branch를 측정하지 않는 모드에는 그에 맞는 일관된 Point ID를 사용합니다.
  • 홀수·짝수 Scanner의 좌표 부호를 Global 좌표계로 정규화한 후 보간합니다.
  • 측정 NG 값은 보간에 사용하지 않습니다. 유효한 양쪽 측정값이 없는 구간은 미확정/보정 불가로 표시하고 임의 외삽하지 않습니다.
  • 1줄 모드는 Y방향 기준점이 하나이므로 보간하지 않습니다. 가운데 라인의 각 X/Branch 보정량을 동일 대응의 모든 Y에 적용합니다.
  • 체스 배치나 마스킹 때문에 동일 논리 X의 물리적 대응이 달라질 경우, 대응 규칙을 확정해야 합니다. 단순 최근접점으로 다른 X/Branch를 임의 연결하지 않습니다.
  • Rough 이후 Fine을 수행하면 큰 편차 제거 후 위치별 잔여오차를 측정할 수 있습니다. 기준 Offset Revision과 합산/교체 정책을 함께 관리합니다.
측정점 기준: 첨부 11의 표준 Review는 DOE 중심이 아니라 사전에 지정한 Branch의 홀입니다. Fine의 X전수 목록에도 가공점 ID와 측정 Branch를 명시합니다. Fine에서 16 Branch 전수까지 확장할지에 대한 Rule 범위는 추가 정의하며, Run의 11번 기본 대표 측정과 수동 16빔 전수 검사를 구분합니다.
