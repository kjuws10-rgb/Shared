# 분석 근거·검증 기록

## 1. 기준점 선택

Shared main을 먼저 fetch하여 `b915a59f3228156c88749190c966ebc392061b5b`로 확인했습니다. 재귀 조회한 원격 tree는 534항목이며 truncated=false였습니다. Git이 추적하는 디렉터리 138개와도 교차 대조했습니다. 새 날짜+접미사 형식과 기존 날짜 형식을 모두 검색한 결과, 조건에 맞는 basename은 6개이고 중첩 후보는 0개였습니다. README의 공식 원본 행이 A3Drilling인 최신 폴더는 `20261108_090646_SW아키텍쳐분석`이며, 기준 SHA는 3a6b021af7dad60578e7fb85e3191b43b3b3c183입니다. 나머지 5개는 IPS 등 다른 원본이므로 제외했습니다. 일반 도구/보고서처럼 다른 접미사를 가진 날짜 폴더 61개도 제외했습니다.

## 2. 읽기 전용 보존

원본은 별도 임시 clone의 detached HEAD 상태에서 분석했습니다. checkout 전에 Push URL을 `DISABLED`로 설정했습니다. 분석 clone에는 파일 수정/추가/삭제·빌드·Commit·Push를 하지 않았습니다. 사용자가 등록한 checkout도 분석 전후의 추적 파일 SHA256·HEAD·branch·status로 대조해 일치를 확인했습니다. 분석 자료/초안/시험 로그는 별도 개인 경로에 보관합니다.

원본 Git diff의 115개 경로를 모두 분류하고, 코드 31개 경로의 변경과 이를 직접 사용하는 호출을 추적했습니다. 404개 파일의 내용을 모두 같은 깊이로 읽었다는 뜻은 아닙니다. CSV 126개(기준 64개)는 양쪽 Commit의 헤더·행 수·열 너비를 스캔하고, Recipe 키/Setting 값·관련 샘플 유형을 추가로 대조했습니다. 실제 리뷰 샘플 32개 파일은 출처·상태·헤더 통계만 사용했습니다.

공통지식의 전체 카테고리 색인을 살펴보고, 장비/비전/데이터/문서/플랫폼 관련 본문과 등록 원본을 선택했습니다. 거래/생활은 범위 밖입니다. 로컬 LLM 도구는 자료의 출처 관계만 검토하고, 생산의 기술 의존성으로 추가하지 않았습니다. 이전 HTML 시뮬레이터를 생산 구현이나 실기 검증의 증거로 사용하지 않았습니다. 개인 지식 MD/대화/원측정 행/전체 소스·빌드 로그는 게시하지 않습니다.

## 4. 빌드 결과

별도 검증 clone에서 원본 최신 Commit을 그대로 checkout하고 Push를 비활성화했습니다. .NET SDK 10.0.400과 로컬에 준비된 공식 패키지 feed로 restore에 성공한 뒤 아래 명령을 수행했습니다. 네트워크 패키지의 변동을 피했으며, 장비 앱은 시작하지 않았습니다.

```text
dotnet restore Drilling.sln --source <local-feed> -p:NuGetAudit=false --disable-parallel
dotnet build Drilling.sln -c Release --no-restore --disable-build-servers -p:NuGetAudit=false
```

| 검사 | 결과 |
| --- | --- |
| Restore | 성공 |
| Release build | 실패·종료 코드 1 |
| 오류·경고 | 오류 19개·경고 0개 |
| 주요 오류 | CS0234 Common.Log / CS0246 CLogManager 누락 |
| 스텁·생산 소스 수정 | 없음 |
| 검증의 한계 | Common 단계에서 차단돼 이후 전체 UI/배포의 합격까지 검증한 것은 아님 |

누락을 재확인했지만 분석 요청 범위에서 생산 파일을 임의로 복구하지 않았습니다. 기준 보고서와 오류 수는 같지만, 이번 결과는 최신 a116220을 별도로 다시 빌드해 얻은 것입니다.

## 5. 보고서 검증과 공개 범위

[고정 소스 링크](source-links.json)는 최신 Commit의 실제 파일과 줄 범위를 검사합니다. [스키마 요약](schema-comparison.json)·[변경코드목록](changed-code.csv)·[구조통계](structure-snapshot.json)를 기계 판독용으로 제공합니다. Mermaid 코드 블록은 로컬 라이브러리로 parse와 SVG 렌더를 수행하고 출력 크기를 검사합니다. Markdown 내부 링크·UTF-8/대체 문자·제어 문자·표의 열 수·코드 펜스와 `git diff --check`를 확인합니다.

[validation.json](validation.json)은 검증 범위를, [manifest.json](manifest.json)은 최종 파일 크기와 SHA256을 기록합니다. Git staging과 원격 main 병합 후 각 blob을 다시 대조합니다. 공개 대상은 이번 폴더뿐이며, 기존 분석/도구 폴더나 사용자의 untracked 파일은 건드리지 않습니다.

## 6. 실행하지 않은 것

실제 WPF 앱·MELSEC·Vision 소켓·Stage/Scanner/레이저·장치 DLL 접속을 실행하지 않았습니다. 광학 정밀도·가공 속도·새 통신 계약의 실기 합격·수치 보간의 실행 회귀 결과를 보고하지 않습니다. CSV 손상·중복 Apply·경합 위험의 예시는 정적 코드 분석이며, 실제 현장 사고의 확정 원인으로 보지 않았습니다.
