# 위험도별 발견사항과 확인 순서

P1은 가공 좌표·보정 누적·빌드에 직접 영향을 줄 수 있어 먼저 확인할 항목, P2는 특정 입력·운용·호환 조건에서 확인할 항목입니다. 우선순위는 코드 분석 제안이며 회의에서 확정한 일정이나 실기 사고의 재현 결과가 아닙니다.

## 1. 먼저 확인할 P1

| ID | 항목 | 발생 조건·영향 | 권고 확인·개선 |
| --- | --- | --- | --- |
| R01 | 같은 측정 결과 재누적 | 새 Review Data에서 동일 CSV를 다시 SAVE하면 최신 보정에 같은 Δ를 다시 더함. 자동 누적이 끝난 AUTO 결과도 이 수동 경로로 재적용 가능 | 측정 결과 ID·기준 OffsetRevision·적용 이력의 영속 계약, 재적용 차단/명시 정책 |
| R02 | 무효 오차가 0으로 바뀜 | 상태 COMPLETED·Judge OK인 편집/손상 CSV에서 오차 누락·NaN·문자열이 0.0이 될 수 있음 | 필수 수치·유한성·출처를 엄격하게 검사하고 invalid와 실측 0을 분리 |
| R03 | 구형 ERROR의 좌표 의미 | 구형 일반 CSV의 ERROR는 Flip 전 mm인데 새 Apply는 변환된 DESIGN으로 가정. Flip이 있으면 부호/축이 다를 조건 | schema/basis 버전 및 명시 변환, 구형 raw와 새 converted 대조 시험 |
| R04 | 카메라 분해능·Y Flip 설정 변경 | 포함 Setting 0.0025→1 mm/pixel, Y Flip ON→OFF. 같은 raw 단위/nResolution이면 길이 400배·Y 방향 변경 | 상대 Vision 단위 계약과 실측 기준값 확인 후 환산·Flip 교차 검증 |
| R05 | 정식 소스 빌드 불가 | 별도 Release 빌드 19오류·0경고, Common.Log/CLogManager 미추적 | 실제 누락 소스와 제외 규칙의 의도 확인·복구 후 정식 빌드. 분석에서는 스텁으로 덮지 않음 |

R01은 모든 기존 화면의 방어가 없다는 뜻이 아닙니다. 기존 Fine에는 `_offsetApplied`, 자동 Coordinator에는 `_saved`가 있지만 새 파일 소비 경로에서 공유되는 적용 기록은 없습니다. 예를 들어 현재 B=0.010mm, 측정 Δ=0.002mm이면 1회 F=0.012, 같은 결과 2회는 0.014가 되는 코드 경로입니다. 수치 예시는 계산 원리이며 장치에서 재현한 시험값이 아닙니다. [파일 기반 Apply와 저장](https://github.com/kjuws10-rgb/A3Drilling/blob/a1162209220fd31caa68cbf82b5a98db9588af39/Drilling.UI/Menu/Menus/CMenuCorrection.ReviewData.Offset.cs#L74-L124) · [자동 누적과 세션 중복 방어](https://github.com/kjuws10-rgb/A3Drilling/blob/a1162209220fd31caa68cbf82b5a98db9588af39/Drilling.Common/Review/CAutoFineReviewCoordinator.cs#L77-L174)

R02는 정상 writer가 손상 파일을 만든다는 주장이 아닙니다. 목록의 상태 UNKNOWN/INVALID는 적용을 막습니다. **COMPLETED·지원 종류·식별자가 맞는 파일**에서 수치가 잘못된 조건을 지적한 것입니다. [구형·신형 오차 열 선택](https://github.com/kjuws10-rgb/A3Drilling/blob/a1162209220fd31caa68cbf82b5a98db9588af39/Drilling.File/ReviewResult/CReviewResultFile.cs#L160-L203) · [누락·비정상 숫자의 기본 0 처리](https://github.com/kjuws10-rgb/A3Drilling/blob/a1162209220fd31caa68cbf82b5a98db9588af39/Drilling.File/ReviewResult/CReviewResultFile.cs#L347-L364) · [보정 대상과 측정 출처 필터](https://github.com/kjuws10-rgb/A3Drilling/blob/a1162209220fd31caa68cbf82b5a98db9588af39/Drilling.UI/Menu/Menus/CMenuCorrection.ReviewData.Offset.cs#L369-L460)

R03은 현재 새 writer가 변환열을 저장한 모든 결과에 해당하지 않습니다. `ERROR_X/Y`가 우선 선택되는 구형/외부 자료가 대상이며, 현재 파일에 두 종류의 열이 함께 있어도 ERROR가 앞섭니다. [구형·신형 오차 열 선택](https://github.com/kjuws10-rgb/A3Drilling/blob/a1162209220fd31caa68cbf82b5a98db9588af39/Drilling.File/ReviewResult/CReviewResultFile.cs#L160-L203)

R04의 400배는 환산 계수 비율 `1/0.0025`입니다. 같은 입력 단위라는 전제 없이 실제 장비 오차가 400배라고 확정하지 않습니다. JHMI 기본값은 0.0025가 남아 있고 실제 Setting 파일만 1이므로 두 자료를 구분해야 합니다. [pixel에서 mm 환산](https://github.com/kjuws10-rgb/A3Drilling/blob/a1162209220fd31caa68cbf82b5a98db9588af39/Drilling.Common/Review/CReviewManager.cs#L2061-L2088)

R05는 빌드를 막는 기존 누락을 재확인한 것입니다. 그 뒤에 가려진 새 UI/C# 오류가 없다는 검증까지 완료된 것은 아닙니다. `.gitignore`의 `[Ll]og/`가 해당 경로를 제외하는 사실과 실제 누락을 확인했습니다. [Log 소스 제외 규칙](https://github.com/kjuws10-rgb/A3Drilling/blob/a1162209220fd31caa68cbf82b5a98db9588af39/.gitignore#L29-L35)

## 2. 조건을 정해 확인할 P2

| ID | 항목 | 현재 보호와 남은 한계 | 권고 |
| --- | --- | --- | --- |
| R06 | 읽기→계산→저장의 경합 | Load/Save/Rollback 개별 Semaphore는 있음. 전체 연산의 compare-and-save/expectedRevision은 없음 | 저장 직전 기준 revision 원자적 대조, 모든 writer의 같은 정책 사용 |
| R07 | 과거 결과·Recipe 정합성 | Recipe ID·Shot·Head 검사는 있음. Recipe 좌표/Masking/Flip Revision·원본 hash·결과 점 집합 전수 대조는 없음 | 원본 결과·기준 설계·적용 보정의 식별자와 유효성 저장 |
| R08 | 재시도 RETAINED 앵커 | 파일 Apply는 MEASURED만 사용, 기존 live Fine은 유지 OK도 포함. 최종 Retry 자료의 보간 입력이 달라질 가능성 | 3줄 중간 NG→Retry의 두 경로 Δ/F를 비교하고 정책 확정 |
| R09 | Simulation·폴더 이관 | CSV에 Sim 열은 있으나 Load/Apply guard에 유지하지 않음. 새 Catalog는 옛 ReviewResult/Result 폴더를 자동 발견하지 않음 | 실측 출처 제약과 옛 52열 Beam·구 폴더 이관 시험 |
| R10 | 보정률 상한·설정 효력 | 0 이상의 Int32 % 검사. 허용 %가 최종 Scanner Field 내부를 보장하지 않음. 이미 준비한 모델은 새 Setting으로 재계산 안 됨 | 장비별 % 상한·최종 좌표/경계 검증·DoReady 안내 |
| R11 | 원빔 AUTO 요구 | Default Cross 1점은 구현. Head별 DOE 없음/ZeroOrder 광학 기준의 명시적 생산 모드는 별도, AUTO 대표 Beam 11 유지 | 실제 광학 모드·좌표·Head 유효성·Review/AUTO 계획 함께 정의 |
| R12 | Shift 가공과 Review | AUTO 입력은 Shift 0,0. 수동 UI 값 유지와 비제로 AUTO 확인/양산 초기화 옵션은 다른 문제. Review 목표는 nominal | 사용자 요청 정책과 실제 가공 위치의 촬영 추종을 별도 구현·검수 |
| R13 | AK4·Stage·PTW 인터페이스 | 수동 Load는 AK4 레지스터를 읽음. 새 촬영 시점 보장은 별도. Distortion Stage 입력 USE0/UNASSIGNED, PTW 주소 주석 미확정 유지 | Stage 확정 주소·새 측정 세대·요청/완료 계약과 물리 IO 확인 |
| R14 | Product 이력 연결 | 파일 GlassId 추가·일반 Review Product 경로 유지. AUTO 전용 결과가 Product.REVIEW와 통합됐다는 새 호출 없음 | 같은 Glass의 가공→검사→보정→다음 가공 추적 시험 |

## 3. 이전 발견을 다시 판정한 결과

| 이전 항목 | 현재 판정 | 판단 이유 |
| --- | --- | --- |
| 39열 FINE을 일반 CSV importer가 못 읽음 | 열 호환 개선 확인 | 변환 오차 alias를 읽고 새 DATA LOAD에 연결. 구형 basis·무효 수치까지 완전 해결된 것은 아님 |
| Offset이 Masking 제외 Shot을 바꿈 | 코드 개선 확인 | 설계 위치로 멤버십 고정, UI 표시도 맞춤 |
| 최신 Offset 삭제/복원 후 이전 준비 사용 | 시작 방어 보강 | Rollback 무효화와 Start/Manual MOF의 최신 경로·시각 대조. 내용 hash 검사는 별도 |
| Default 십자도 16 Beam 피팅 | 분리 개선 확인 | Setting Mark 1회/Beam 0/FitCross. Residual 0은 격자가 없다는 표현이며 실측 오차 0의 증거가 아님 |
| Log/CLogManager 누락 | 잔존 | 별도 Release 19오류·0경고 |
| DOE 1·AUTO Beam 11 / 실제 ZeroOrder 원빔 | 잔존 | AUTO 상수와 광학 모드 계약 미변경 |
| test0929 공차 3mm | 잔존 | Align 키 외 Recipe 값 변경 0. 3µm로 해석하지 않음 |
| Distortion Stage 입력·PTW 주소 | 잔존 | 실제 JHMI 맵 미변경 |
| 사용자 편집 오차 Level·기준 Shot의 최종 F 복사 | 미구현 범위 유지 | 새 읽기 전용 표/적용 팝업을 해당 기능의 완성으로 볼 수 없음 |

## 4. 제안하는 확인 순서

1. 누락 Log를 복구한 정식 빌드와 카메라 raw→mm/Flip 계약부터 확정합니다.
2. 동일 AUTO 결과의 2회 Apply·손상 수치·구형 Flip 자료·NG Retry를 장치 없는 분리 시험으로 확인합니다.
3. 결과 ID/RecipeRevision/OffsetRevision과 원자적 저장·중복 방어 정책을 정합니다.
4. 0/100/200%별 최종 Head 좌표와 Masking 불변 여부, Align 초기화 전후 좌표를 대조합니다.
5. Stage 주소·AK4 최신성·Shift 추종·원빔 광학 기준을 확정한 후 장치 단계 검수를 진행합니다.

이 순서는 후속 개발·시험 제안입니다. 이번 분석에서 생산 코드를 수정하거나 장치 검수를 수행하지 않았습니다.
