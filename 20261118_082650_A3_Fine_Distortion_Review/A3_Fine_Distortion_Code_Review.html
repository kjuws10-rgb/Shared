01 · Fine 세 줄 검사무엇을 측정하고 어떤 값이 저장되는지

세 줄은 검사점 세 개를 뜻하지 않습니다. 셀의 처음·중앙·마지막 부근에서 X방향으로 여러 Shot을 측정하고, 같은 설계 X에 있는 위·아래 결과로 미측정 Y 위치의 보정값을 만듭니다.

  1. 01유효 검사점 선정Cell·Head·Beam·Masking/CHESS 조건으로 실제 세 줄을 구성
  2. 02Vision 측정Target/Hole 픽셀 차이 → mm 환산 → Vision Flip
  3. 03열별 보간CellNo + 반올림한 DesignX로 묶어 ΔX·ΔY를 각각 계산
  4. 04기존값에 누적새 Review Offset = 기존값 + 이번 계산값
  5. 05다음 가공에 반영파일 저장 후 다음 가공 준비에서 배율·축 방향 변환

현재 코드는 어떻게 계산하나요?

CalculateFineOffsets는 검사 결과가 모두 OK인지 확인하고, 같은 CellNo와 DesignX(소수 6자리 반올림)끼리 묶습니다. 각 열에서 확보한 측정점 전체를 지나는 하나의 라그랑주 다항식으로 미측정 Shot의 ΔX·ΔY를 각각 구합니다. 인접한 위·아래 두 점만 연결하는 방식이 아닙니다.

측정점 수현재 Fine 계산실제로 확인할 내용
1점한 열에 같은 보정값 복사한 줄 검사 또는 마스킹 후 유효 앵커 1개
2점직선식측정 범위 밖에서도 끝값 고정 없이 직선을 연장
3점최대 2차 라그랑주식세 점이 한 직선 위에 있을 때만 선형 결과와 같음
측정점이 없는 열새 계산 대상에서 제외현재 저장된 그 열의 값 유지. X방향의 다른 열에서 채우지 않음

세 줄을 요청해도 각 열의 유효 앵커가 세 개라고 가정할 수 없습니다. 현재 선정 함수는 기하학적으로 줄을 정한 뒤 Masking/CHESS 대상점을 제외하며, 비어 버린 줄을 대신할 다음 줄을 자동 탐색하지 않습니다. 후속으로 줄 회피를 추가한다면 원래 줄 번호가 아니라 실제 측정한 DesignY로 계산해야 합니다.

픽셀·mm·부호를 연결하는 순서

emm = Review_Camera_Resolution(mm/pixel) × nResolution × (Targetpixel − Holepixel)
δ = VisionFlip(emm)
Fnew = Round(Fold + InterpolateY(δ))

Target−Hole에는 목표 쪽으로 옮길 방향이 이미 들어 있습니다. 이후 임의로 −1을 다시 곱하지 않습니다. Vision의 X/Y 반전·교환과 Head의 Scanner 축 변환은 서로 다른 단계입니다. 파일에서 다시 불러온 결과는 이미 변환된 값이라는 계약에 따라 Normal로 계산하여 Flip을 중복 적용하지 않습니다.

측정 범위 밖은 별도 정책이 필요합니다

현재 Fine 함수는 첫·마지막 측정 Y 바깥도 다항식을 연장하여 계산합니다. 위 예제의 −25% 위치에서는 −12.5µm가 됩니다. 줄 안의 일부 측정점이 마스크로 제외되어 첫·마지막 유효 앵커가 안쪽에만 남아 있으면, 더 바깥 보정 대상에 외삽이 적용될 수 있습니다. 추후 줄 회피를 추가하는 경우에도 보간 범위를 같이 검증해야 합니다.

02 · 선형과 현재 Fine 비교동일한 세 줄 데이터로 차이를 직접 확인

위·중앙·아래 검사에서 한 보정 성분이 0 → 10 → 0µm로 나왔다고 가정합니다. 검사범위의 25% 위치에서 두 계산법의 차이가 드러납니다.

구간 선형 보간 · 요청 기준

t = (Y − Y위) / (Y아래 − Y위)
δ(Y) = (1−t)δ위 + tδ아래

현재 Y를 사이에 둔 두 측정점만 사용합니다. 위–중앙 구간, 중앙–아래 구간을 각각 직선으로 연결하므로 25% 위치는 5µm입니다.

라그랑주 보간 · 현재 실보정

δ(Y) = Σi δiLi(Y)
Li(Y) = ∏j≠i (Y−Yj)/(Yi−Yj)

세 점 전체를 통과하는 하나의 곡선을 만듭니다. 0%, 50%, 100%가 0·10·0µm이면 25% 위치는 7.5µm입니다.

한 열에서 직접 비교교육 예제 · 실제 장비 측정 데이터가 아닙니다.

작은 화면에서는 그래프를 좌우로 밀어 보세요.

요청 기준 · 구간 선형5.000µm
현재 실보정 · 라그랑주7.500µm
두 값의 차이2.500µm

그래프는 반올림 전 계산값입니다. 현재 저장 경로는 최종 mm 소수 3자리, 즉 1µm 단위로 반올림합니다. 예제의 7.5µm는 단독 저장 시 8µm가 됩니다. 실제 Fine는 기존값과 더한 뒤 반올림합니다.

코드에 선형 함수도 있는데 왜 불일치인가요?

ProjectFineResultRows → InterpolateFineMeasurement에는 인접 두 점 선형 보간과 범위 밖 끝값 복사가 남아 있습니다. 이 함수는 HeadNo + DesignX로 묶는 별도 결과 확장용입니다. 반면 실제 Fine 적용은 CalculateFineOffsets로 연결되어 CellNo + DesignX별 라그랑주를 사용합니다.

전체 소스 호출 검색에서 해당 선형 확장의 현재 Fine UI 진입은 확인되지 않았습니다. 따라서 “화면에는 항상 선형, 가공에는 곡선”이라고 단정하지 않습니다. 확정된 사실은 현재 사용되는 세 가지 Fine 적용 경로가 모두 라그랑주라는 점입니다.

03 · Distortion 라그랑주키 측정값에서 기판 전체 보정으로 확장

Distortion은 가공 후 홀 오차를 재는 Fine와 입력 데이터가 다릅니다. 기준으로 저장한 AK/DK의 글로벌 좌표(Base)와 이번 측정 좌표(LastLoad)의 차이를 이용해, 기판 전체 Shot에 줄 Align Offset을 계산합니다.

키 보정 벡터 Ckey = Baseglobal, mm − LastLoadglobal, mm

예를 들어 기준 X가 100.000mm인데 이번 X가 100.010mm이면, 그 키의 ΔX는 −0.010mm입니다. 이 차이 벡터를 설계상 키 위치에 배치해서 보간합니다. 글로벌 실측 좌표를 설계 좌표로 덮어쓰는 계산이 아닙니다.

  1. 01측정 조건 고정Recipe·Base·선택 DK 그룹·Stage Y·Tolerance를 준비
  2. 02Stage 완료 후 수신AK 네 점과 선택 DK 좌우 X/Y를 mm로 취득
  3. 03행 안에서 X 선형각 행 좌우 보정값으로 해당 X의 보정값 계산
  4. 04행 사이 Y 라그랑주모든 선택 행을 이용해 해당 Y의 보정값 계산
  5. 05전 Shot 저장·준비Align Offset 교체 → DoReady에서 스크립트 재생성

어떤 키를 사용하나요?

상단 행 AK1·AK3, 하단 행 AK2·AK4는 항상 포함합니다. DK1~DK6는 좌우 두 점씩 그룹 0~2의 3개 그룹이며 선택한 그룹만 중간 행에 들어갑니다. DK 행의 설계 Y는 기판 높이·AK Margin Y·해당 Stage Y로 계산합니다.

선택 DK 그룹전체 보간 행 수Y방향 최대 차수
0개AK 위·아래 = 2행1차 · 직선
1개AK 2행 + DK 1행 = 3행2차
2개4행3차
3개5행4차

“X 선형 → Y 라그랑주”의 정확한 뜻

Cr(X) = (1−ur)Cr,left + urCr,right
ur = (X − Xr,left) / (Xr,right − Xr,left)
C(X,Y) = Σr Cr(X)Lr(Y)

이 수식은 ΔX와 ΔY 각각에 동일하게 적용됩니다. “X오차만 선형, Y오차만 곡선”이라는 뜻이 아닙니다. 보간 위치를 찾는 공간 축 X·Y와 보정 벡터의 성분 ΔX·ΔY를 구분해야 합니다.

입력과 저장에서 함께 확인할 조건

  • 행 위치: 그림의 위치와 값은 설명용입니다. 실제 DK의 위아래 순서는 그룹 번호가 아니라 Stage Y 설정으로 만든 DesignY로 정렬됩니다.
  • 오류 처리: DK를 선택하지 않으면 두 AK 행으로 계산하지만, 선택한 DK의 값이 없거나 좌우 짝이 잘못되면 예외로 중지합니다. 오류가 나서 자동으로 직선식으로 바뀌는 구조가 아닙니다.
  • 입력 좌표 전제: Base와 LastLoad의 글로벌 X/Y 차이가 저장할 설계 보정 벡터와 같은 축·부호를 뜻한다는 전제가 필요합니다. 현재 보간 함수 안에서 측정한 기판 회전까지 새로 추정하는 단계는 없습니다.
  • Tolerance와 정밀도: 현재 Tolerance는 최종 0.001mm 반올림된 Shot Offset을 기준으로 비교합니다. 공정 정밀도 목표의 합격 여부와는 별도 기준입니다.
