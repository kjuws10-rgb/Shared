새 원격 조회로 원본 main `8872e4ed5176b5d8a39f1711af9501f6fac94deb`와 Shared main `d05d57e52ccac6388a7f872acfcf71a57e902341`를 확인했습니다. Shared 고정 Commit의 전체 재귀 tree288항목은 잘리지 않았으며, 두 폴더명 형식의 적격 A3 분석 폴더3개를 날짜·시간순으로 비교했습니다. 최신 README의 원본은 `99d78ddf0e680b55dbd9662764b71a1ffe93a457`입니다. 독립 담당자도 같은 tree·README blob·원격 refs를 확인했습니다.

새 원본은 기준의 직접 자식1개입니다. 원본 분석 Clone은 분리된 임시 경로에서 해당 Commit에 고정하고 Push URL을DISABLED로 설정했습니다. 원본의769개 tracked 파일을 모두 해시로 기록했으며 게시 전후 같은 값·clean 상태를 확인하는 절차를 사용했습니다. 사용자 기존 원본 checkout은 수정하지 않았습니다.

빌드는 분석 Clone이 아닌 별도 최신 검증 Clone에서만 수행했습니다. 기준 버전 비교도 또 다른 기준 검증 Clone에서 수행해 생성 파일이 분석 원본에 섞이지 않게 했습니다.

## 문서와 링크 검증

이번 분석의 모든 source 링크는 실제 파일의1-based줄 범위를 확인하고 최신 원본 Commit에 고정합니다. 삭제된 `.review` 구현을 보여주는 링크 하나는 이전 기준 Commit임을 명시했습니다. [source-links.json](source-links.json)에 file blob·범위 내용 해시를 기록합니다.

내부 링크·UTF8·잘못된 문자·코드 블록·CSV/JSON·파일 manifest·복사 바이트를 검증합니다. Mermaid는 구조와 문법 검사를 구분해 기록하며, 브라우저 렌더링 여부는 manifest에 명시합니다. 실제 WPF 화면을 열거나 장비 화면을 캡처하지 않았습니다.

원본 diff의 `git diff --check`는exit2, 출력11,260줄로 공백·EOF 문제를 발견했습니다. 이 값은 문제 개수가 아니라 출력 줄 수입니다. 원본을 고치지 않았으며, Shared에 게시하는 이번 보고서의 diff check는 별도로 통과시킵니다.

## 교차 검토와 한계

주 담당자는 전체 구조·Config·MELSEC·보고서 통합을, 독립 담당자는 기준/빌드와UI/장치·Recipe/Review를 나눠 확인했습니다. 같은 파일을 동시에 수정하지 않았습니다. 문서 검토에서 .review 서비스 제거를 실제 운영 기능의 확정 회귀로 과장하지 않도록 좁혔고, 0선 첫X 실기 이동과 본검사 차단을 분리했습니다.

실SDK·PLC·Vision·장치·레이저·축·앱을 기동하지 않았습니다. UI paint·실제 통신 지연·생산 정밀도·정지시간·고객사 승인 상태는 이번 분석으로 검증하지 않았습니다. 저장소 주석의 명세 번호를 실제 외부 PLC 계약의 승인 근거로 대체하지 않았습니다.

## Shared 게시 범위

게시 대상은 이번 `20261102_143906_SW아키텍쳐분석` 폴더의 분석 문서와 요약 증거뿐입니다. 생산 소스·실행파일·전체 Data·개인 지식 작업실·전체 빌드 로그는 추가 게시하지 않습니다. Shared main이 작업 중 변경되면 최신 main을 반영해 이번 폴더만 다시 검증하며, 다른 사용자의 변경을 덮어쓰거나 force push하지 않습니다.

분석 완료와 소스 빌드 성공은 별도입니다. 이번 결과는 **분석 자료는 검증해 공유하되, 분석한 최신 소스는 빌드 실패와 현장 미검증 상태로 보고**하는 것입니다.
