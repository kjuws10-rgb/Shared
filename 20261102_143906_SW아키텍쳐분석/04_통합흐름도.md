# 현재 소스의 통합 흐름도

그림의 실선은 소스에 연결된 호출과 자료 흐름입니다. 연결돼 있다는 사실은 빌드 성공·실장비 검증 완료를 뜻하지 않습니다. 현행 Commit은 로그 구현 누락으로 빌드가 차단됐습니다.

## AUTO Process 요청 순서

~~~mermaid
flowchart TD
  A["AUTO 진입과 Interlock 재확인"] --> B["Stage 요청 감시와 이전 출력 복귀"]
  B --> C["DoReady START 수신"]
  C --> D["Recipe Product 자료 고정과 Script 생성 Load"]
  D --> E["DoReady 완료와 양측 OFF 복귀"]
  E --> F["Process 준비 Stage Ready 확인"]
  F --> Z{"0선 ON인가"}
  Z -- "ON" --> ZP["0선 준비 실기 계약 미정이면 여기서 차단"]
  Z -- "OFF" --> G["MOF 초기화 Task RUN encoder 대기 확인"]
  ZP -- "시뮬레이션 준비 성공" --> G
  G --> H["가공SW Process ABLE"]
  H --> I["Stage START 수신 후 가공SW START 응답"]
  I --> J["Stage 소유 Y 이송과 가공 Task 완료 감시"]
  J --> K["실가공 완료 W8034와 매수 저장"]
  K --> L["필요 0선 결과 저장과 후속 Review 요청 갱신"]
  L --> N["Process COMPLETE와 양측 OFF 복귀"]
  N --> B
~~~

특히 **Task RUN은 Stage Process START를 받은 뒤 처음 실행하는 것이 아니라, Process ABLE를 응답하기 전 준비 단계에서 실행해 encoder 대기를 확인**합니다. 이를 가공 출사 시작과 혼동하면 안 됩니다. [준비와 실행](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/8872e4ed5176b5d8a39f1711af9501f6fac94deb/Drilling.Common/Station/CStationProcess.cs#L5131-L5212)에서 확인할 수 있습니다.

DoReady/Process/Review의 ABLE·START·COMPLETE 신호와 실제 Task 완료·가공 완료·Vision 결과는 서로 다른 완료 조건입니다. 출력 수신 확인은5초 제한인 경로가 있지만, 모든 action의 제한 시간이5초인 것은 아닙니다.
