2점 · 4점 · 8점 운전 비교

상한은 목표값이 아니라 한 Glass의 최대 배정 개수입니다. 모든 조합을 검증한 뒤 선택한 Glass 그룹 정책 안에서 최소 분할을 계산합니다. Head 순차 정책은 인접한 요청 Head끼리 묶으며, 불가능한 그룹은 더 잘게 나눕니다. Glass 안의 촬영은 Y 도착 순서이며 강제 H01→H08 순서는 별도 입력 조건입니다. 같은 글로벌 Y는 동시 도착입니다.

선택 8점 전체의 도착 순서와 간격

모든 요청점을 한 패스에서 촬영한다고 가정한 검증표입니다. 실패 행은 실제 추천 분할 계획에는 함께 배정되지 않습니다.

원하는 고정점을 모두 찍으려면?

한 번에 하나의 조건만 바꾸는 역산입니다. 실제 장비 속도·가감속·광학 사양의 허용 범위를 확인해야 하며, 변경 제안은 버튼을 누르기 전에는 적용되지 않습니다.

이 두 점을 같은 Glass에서 연속 촬영하는 교육 계산입니다. 전체 계획은 별도 검증합니다.

계산과 운영 Flow

  1. Recipe·Head 소유권·Masking으로 유효 가공점만 선택
  2. Stage 프로파일에서 가공·Review·Trigger·노출 시각 계산
  3. X 이동·정착·Camera·블러·Stroke·30/150초 조건 검사
  4. 8점의 최대 255개 조합 → 2/4/8점 상한별 최소 Glass 분할
  5. Glass ID·Point ID·Frame ID 일치 확인 → PASS / NG / INVALID 기록
실기 운영 권고: 물류가 글로벌 좌표·Glass ID·Recipe hash·Point ID를 전달 → IPS가 해당 Glass의 예상 Trigger 목록을 확정 → Stage/Camera Ready 이후 위치 Trigger → 실제 Frame ID 및 개수 대조 → Vision 합/불 회신. “2점 배정인데 3회 Trigger”, 누락·중복 Frame, 좌표 생성 실패는 품질 NG와 구별한 INVALID 알람으로 기록하고 Hold합니다. 이 HTML은 영상 합/불 판정·실제 신호·알람 출력은 수행하지 않습니다.
본 모델은 Camera가 Scanner 이후 downstream에 있다고 가정합니다. 기본 거리 홀수1467 / 짝수1847 mm는 코드의 홀짝380 mm 차이를 적용한 설계 가정입니다. 실제 ATM Box의 거리와 부호를 실측해야 합니다. 현재 원본 gap=0과는 다릅니다.
Review 결과는 이미 촬영한 해당 지점의 가공 후 결과입니다. 촬영 전 이미 끝난 현재 Glass 메인 가공을 예방하는 기능이 아닙니다. NG/INVALID이면 배출 Hold 및 후속 Glass 차단; 0선 결과로 Offset/APC 보정은 하지 않습니다.

한계와 검증 범위

  • Model1~5의 크기·Cell 회전·Hole/Edge/CHESS를 명목 기하에 반영합니다. Default/Recipe Offset, 실제 Align/APC·기판 왜곡은 미적용이며 PPID 미계산 항목은 보존합니다.
  • 가공시간은 기하학적 Stage 구간 시간입니다. Laser·Scanner 서비스시간·Queue·실제 Script 처리량까지 보증하지 않습니다.
  • 가감속은 사다리꼴 모델이며 S-curve jerk, 구동 응답 및 실제 정착오차는 실측해야 합니다.
  • 자동 좌표 배치는 일부 Row/경계/중앙 Column 후보의 탐색입니다. 고정 8점의 조합 분할은 완전 탐색이지만, 전체 가능한 좌표의 전역 최적 배치라는 뜻은 아닙니다.
  • Glass 전환 구간의 물류·Align·Stage 복귀는 입력한 “기타 시간”으로만 반영합니다. 실제 복귀 궤적을 시뮬레이션하지 않습니다.
  • 원본 설정은 H01만 ON / Auto Inspection OFF. 본 프로그램의 8 Head는 설계 검토 대상으로 선택한 것입니다.

X 정착오차는 입력한 실측 예산값으로만 판단합니다. 자동 배치는 기본 B07을 사용하며, 다른 DOE Branch의 촬영·검출 가능 ROI는 실제 Vision 설정을 확인해야 합니다. 촬영 완료 표시는 Frame 취득 계획의 성립이며 영상 품질 PASS를 뜻하지 않습니다.

요청점 중 가장 늦은 Readout이 Stage 구동 이후까지 남으면 대기시간을 Tact에 추가합니다. Glass별 소그룹에도 이 최후 요청점 기준의 동일한 보수적 Tact를 적용합니다. Global Shutter와 위치 Trigger 촬영을 가정하며, Rolling Shutter의 행별 왜곡·스트로브 타이밍은 모델링하지 않습니다.
