02 / 개선 방향무엇을 개선하거나 추가하나요?

02 / 개선 방향무엇을 개선하거나 추가하나요?

  • 고객 합의가 필요한 부분부터 잠그기 — 필드 정의와 상태전이, 완료 조건, Timeout, 오류 코드와 복구 정책을 먼저 정합니다. 아직 미정인 항목은 시험 준비 가능과 합격 판정 가능을 구분합니다. 이후 시험 입력과 기대 결과를 확정된 계약으로 만듭니다.
  • 정상보다 실패와 경계 조건을 충분히 시험 — 정상 A/B 전환 외에도 마지막 항목 불량, 미등록 PPID, 다른 개정 결과, 중복 요청, 통신 단절과 재시작을 넣습니다. 일부 설정만 바뀌거나 완료 전 가공을 허용하는 상황을 잡는 것이 목적입니다. 계약된 원복/재개 정책이 실제로 지켜지는지 함께 확인합니다.
  • PC 시뮬레이션과 실제 장비 판정을 분리 — 가짜 Stage/Vision/CIM 응답으로 데이터 귀속과 순서를 검증할 수 있지만, 실제 이동 방향·정착·Trigger·Vision 검출·가공 정밀도까지 증명하지는 못합니다. 벤더 컨트롤러와 실제 설비 시험은 승인된 환경에서 별도 수행하고 결과를 구분해 표시합니다.

03 / 관리 구분어디에서 관리하나요?

관리 원칙각 시험은 Case ID, 적용 OSS/Recipe/SW 개정, 입력 데이터, 기대 결과, 실제 결과, 로그/파일 근거, 판정, 발견사항과 재시험 연결을 남깁니다. 실패 시 새 기능을 더 붙이기보다 원인과 수정 범위를 고정합니다. 보안과 고객 반출 절차에 따라 시험자료의 공유 범위를 관리합니다.

04 / 동작 흐름어떤 순서로 동작하나요?

  1. STEP 1문서와 적용본 동결

    고객이 승인한 필드·I/F·Recipe 개정을 고정하고 미정 항목을 별도 표시합니다.

  2. STEP 2오프라인 자동 시험

    단위/부호/배율과 목록-N 관계, Recipe 상호검증, 요청/결과 ID 연결과 부분 적용 방지를 검사합니다.

  3. STEP 3연동 실패 주입

    N점 중 NG, 미수신, 다른 기판 결과, 중복 요청, 중간 단절과 재시작을 넣어 진행 보류·오류·복구를 확인합니다.

  4. STEP 4실제 장비에서 방향과 성능 확인

    시뮬레이션 합격 후 승인된 Dry Run과 실기판 평가에서 축·광학·Trigger·보정 성능을 확인합니다.

  5. STEP 5증거와 운영 방법 승인

    정상/실패 로그와 결과 파일, 복구 순서, 합격 기준을 고객과 검토하고 적용 버전을 기록합니다.
