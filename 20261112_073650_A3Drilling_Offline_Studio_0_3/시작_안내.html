도구 수정 소스 · 선택 다운로드

스튜디오 0.3 앱의 소스입니다. 실제 장비 A3Drilling 프로젝트나 현장 자료가 아닙니다. 실행만 할 때는 필요하지 않습니다.

0.3 도구 소스 ZIP 받기 →
  1. Release에서 part01~part03과 A3_0_3_합치기도우미.zip 받기Release에 올라온 같은 버전의 모든 조각을 받습니다. 도우미 ZIP과 소스 ZIP은 서로 다른 파일입니다.
  2. A3_0_3_합치기도우미.zip을 풀고, 그 폴더에 조각을 함께 놓기조각의 파일 이름을 바꾸지 않습니다. 조각 하나만 압축 해제하는 방식이 아닙니다.
  3. 합치기.cmd 실행 → 검증 완료 기다리기Windows PowerShell 5.1로 각 조각과 완성 ZIP의 SHA256을 확인하며 결합합니다. 오류가 나면 안내된 조각을 다시 준비하고, 확인이 끝나기 전에는 다음 단계로 넘어가지 않습니다.
  4. 완성 ZIP 압축 해제 → App/시작하기.cmd 실행App 안의 EXE·Runtime·Models·toolchain 폴더를 함께 유지합니다. 기본 모델은 이미 들어 있어 다시 다운로드하지 않습니다.

여유 공간 약20GB, NTFS 또는 exFAT를 권장합니다. 합친 ZIP과 모델 파일은 각각4GB를 넘으므로 FAT32 위치에서는 합치기·압축 해제를 진행할 수 없습니다. 조각을 PC의 큰 파일 지원 드라이브로 복사해 작업하세요.

누락·손상·저장 공간 오류가 날 때

모든 조각이 같은 Release 버전인지, 도우미를 압축 해제한 폴더에 조각이 함께 있는지 확인합니다. 이름을 임의로 바꾸거나 서로 다른 버전의 조각을 섞지 않습니다. 도우미의 검증 오류를 건너뛰어 실행하지 않습니다.

다운로드 조각·완성 ZIP·압축을 푼 앱이 함께 있으면 저장 공간을 더 사용합니다. 파일을 보존한 상태에서 충분한 여유 공간을 확보하고 다시 실행하세요. 긴 폴더 경로보다 짧은 폴더에 압축을 푸는 편이 좋습니다.

앱에서는 이렇게 사용합니다

  1. 실제 수정할 A3Drilling 프로젝트를 한 번 선택Drilling.sln과 전체 .git이 있는 일반 Git checkout 폴더를 직접 준비합니다. 마지막 선택 경로를 기억합니다.
  2. 자료 추가 → A3 업데이트선택한 코드와 승인된 추가 문서·개발 스타일·적용 사례를 갱신합니다. 평상시에는 인터넷이 필요 없습니다.
  3. 채팅 요청 → 수정 미리보기 → 적용·확인수정 내용을 확인한 뒤 적용합니다. 필요한 빌드·코드 검사는 별도로 수행하고, 문제가 있으면 이번 변경 되돌리기를 사용합니다.

일반 현장 PC에서 사용

별도 학습 환경에서 바꾸는 모델 가중치

호환되는 HF 원본 모델·Python·변환기와 메모리를 별도로 준비하면 LoRA 학습을 실행할 수 있습니다. 독립 평가를 통과한 후보는 사용자가 확인해 적용하거나 이전 후보로 되돌립니다.

준비된 학습 환경 필요

이 실행 묶음에는 학습용 HF 원본과 Python 환경이 없습니다. “지식 갱신 완료”는 “가중치 학습 완료”와 다릅니다. 실제 A3 8B 가중치 학습은 수행하지 않았으며, 작은 합성 모델의 학습·변환 검증과 구분합니다. 준비가 부족하면 기존 모델을 유지합니다.

자료가 학습에 들어가는 방식

현재 코드·문서의 실제 앞부분과 뒷부분을 이어쓰기 예제로 만들고, 실제 적용했던 수정의 전후 내용도 사용합니다. 적용 사례의 검증은 백업·내용 해시 일치이며 코드 동작의 정답 인증은 아닙니다. 원문과 편집 기록의 해시를 확인하며 같은 파일 조각이 학습·평가 양쪽에 섞이지 않도록 합니다. 매번 실제 사용한 학습 행과 제외한 행을 기록합니다.

GGUF 추론 파일만으로 원본 가중치 학습을 수행하지 않습니다. 학습용 HF 원본과 정확히 대응하는 기반 모델·변환기를 별도로 준비해야 합니다. 모델 구조별 라이브러리 지원과 학습용 메모리가 필요합니다.

학습 도구의 상세 준비는 App\Training\README.md를 참고하세요. 기본 학습 조건은 자동이며, 일상 채팅에 이 준비가 필요한 것은 아닙니다.

큰 자료도 추가할 수 있습니다

자료처리
코드·TXT·CSV·HTML·JSON·XML·AScript·선택 로그디스크로 복사·분할·검색. 긴 한 줄의 뒤쪽도 보존합니다.
PDF앱에 포함된 추출기로 페이지별 텍스트를 읽습니다. 이미지뿐이면 OCR이 필요하다고 안내합니다.
Word·Excel·PowerPoint본문·시트·슬라이드/노트를 순차 처리합니다. 부분 추출과 지원하지 않는 내용은 표시합니다.

자료당·전체 자료 용량과 개수에 임의 상한을 두지 않았습니다. 실제 저장 공간과 처리 시간은 필요하며, 자료 전체를 한 번에 RAM이나 모델 문맥에 넣지 않습니다.

문맥·출력 토큰 예산과 한 번의 코드 변경 크기는 별도입니다. 서식·그림·매크로·수식 계산·OCR을 수행한 것으로 표시하지 않습니다. 실제 Codex 대화 전체가 자동으로 수집되는 방식도 아닙니다.

이번에 선택한 실행 모델

Qwen3-8B · Q4_K_M

0.3 개발 당시 A3 Review 오차 레벨을 계산하는 단일 순수함수 과제에서 생성 코드의 컴파일과 22개 경계값·예외 검사를 통과한 모델입니다. 당시 검증 PC의 CPU Auto에서 함수 생성은 273.4초였습니다. 이번 공유 작업에서 이 모델 과제를 새로 반복한 결과는 아닙니다. 엔진 보완을 포함한 제한된 결과이며 모든 과제의 정확도·속도나 Codex 동등 성능을 보장하지 않습니다.

모델 비교는 이 PC의 제한된 A3 개발 과제로 관찰한 결과입니다. 임의의 모든 기능이나 다른 PC에서 같은 정확도·속도를 보장하는 점수는 아닙니다. 모델 출처와 해시는 동봉한 release-manifest.json에서 확인할 수 있습니다.

검증한 내용과 남은 범위

0.3 개발 당시 앱 빌드, Core·통합·전체 백업 고장 주입·대용량 자료·상태 전환·Edge 조작을 각각 검증했습니다. 실제 모델 과제는 소스 근거 확인, 기존 코드 수정, 신규 순수 계산 함수의 컴파일·경계값 검사였습니다. 이 기록을 공유본의 모든 기능을 새로 재검증한 결과로 확대하지 않습니다.

인터넷을 물리적으로 차단한 현장 검수, 전체 A3 설비 동작, 실제 A3 대형 모델의 가중치 학습은 별도입니다. Codex와 동등한 코딩 정확도를 달성했다고 주장하지 않습니다.
