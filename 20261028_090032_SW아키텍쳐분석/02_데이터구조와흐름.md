## 2-1. 계산 재료와 계산 결과를 구분

Recipe CSV는 Cell 배치·Model·Pitch·Head 조건·기본 Offset 같은 계산 재료입니다. 공통 좌표 계획은 이 재료로 Shot/Beam의 설계좌표, Head 배정, Mask/Chess 유무를 정합니다. Review 계획은 가공 가능한 Shot에서 검사점과 카메라/Stage 목표를 뽑습니다. 결과는 ShotKey로 원래 대상을 찾아 연결합니다.

이번 diff는 Model/Cell 기하, Head 배정, Mask의 기본 수학을 바꾸지 않았습니다. Preview의 표시 필터/클릭 영역과 최종 Offset 변환은 바뀌었습니다. 최종 보정 후 Head field·Mask를 다시 검사하는 로직이 새로 추가된 것은 아닙니다.

## 2-3. DESIGN과 SCANNER를 끝까지 구분

| 이름 | 쉬운 뜻 | 이번 저장/계산 규칙 |
| --- | --- | --- |
| DESIGN | 기판 설계 그림의 X/Y 방향 | 새 Simple/Rough/Fine 보정 저장 기준 |
| SCANNER | Head별 실제 Scanner 축 방향 | 구 4열 보정파일의 기본 해석 |
| Review 목표 | 카메라X와 StageY가 가야 할 위치 | 검사계획이 설계 Shot/선택 Beam으로 생성 |
| 측정오차 | 목표 mark와 실제 hole 차이 | 전용 Fine/Rough는 Target−Hole, Vision flip 적용 |

Review Offset 파일은 `CELLID,SHOTID,REVIEWOFFSETX,REVIEWOFFSETY,COORDINATE_SPACE` 5열입니다. 구 4열·빈 space는 SCANNER로 읽고, 모르는 space는 거부합니다. 기존 SCANNER 값을 새 DESIGN 누적값과 더할 때는 먼저 역변환합니다.

가공좌표를 만들 때 DESIGN 보정만 현재 Stage 방향과 Head XY/X/Y flip에 맞춰 SCANNER로 바꿉니다. 최종 합성은 Recipe Offset + Head Default + First Beam + 변환된 Review Offset + 변환된 Align Offset이며 Shift는 별도 단계입니다. 같은 변환을 저장 시와 가공 시 두 번 적용하면 안 됩니다.

근거: [CReviewOffsetData.cs:7–40](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/223b905daf0d7421c187b727a65d180bfa7472d6/Drilling.Common/Recipe/CReviewOffsetData.cs#L7-L40), [CScannerAxisTransform.cs:70–92](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/223b905daf0d7421c187b727a65d180bfa7472d6/Drilling.Common/Recipe/CScannerAxisTransform.cs#L70-L92), [CShotCoordinatePlanBuilder.cs:124–149](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/223b905daf0d7421c187b727a65d180bfa7472d6/Drilling.Common/Recipe/CShotCoordinatePlanBuilder.cs#L124-L149), [CShotCoordinatePlanBuilder.cs:174–208](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/223b905daf0d7421c187b727a65d180bfa7472d6/Drilling.Common/Recipe/CShotCoordinatePlanBuilder.cs#L174-L208), [CReviewOffsetFile.cs:129–169](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/223b905daf0d7421c187b727a65d180bfa7472d6/Drilling.File/ReviewOffset/CReviewOffsetFile.cs#L129-L169). 별도 Probe에서 Stage방향2×flip8=16조합 역변환을 확인했습니다.

## 2-4. Simple·Rough·Fine의 정책은 서로 다름

| 방식 | 입력 | 적용 범위 | 기존값 처리 | NG/미측정 |
| --- | --- | --- | --- | --- |
| Simple | 작업자 DESIGN X/Y | 선택 Head 또는 Head/Cell | 해당 범위를 덮어쓰기, 외부 유지 | 측정 없이 입력값 사용; 유한값만 확인 |
| Rough | 대표 Shot 측정오차 | Head 또는 Head/Cell | OK 미적용 delta만 누적 | NG/미검사/이미 적용된 점은 기존값 유지 |
| Fine 수동 | 선택 검사라인의 모든 결과 | Cell+DesignX 열별 대상 | Y 보간 delta 누적, 없는 열 유지 | 하나라도 NG/미완료면 전체 적용 차단 |
| Fine Auto | 확정된 Auto 계획 결과 | 계획에 해당하는 전체 대상 | 모두 OK일 때 최신값에 누적·새 파일 | NG가 있어도 검사완료 가능, 보정은 전체 미적용 |

Simple 첫 Shot은 화면에 먼저 보이는 Shot이 아니라 공통 가공계획 SequenceNo의 첫 실제 가공 Shot입니다. Rough/Fine은 기존 보정을 지우는 초기화와 누적 적용을 구분합니다. 근거: [CMenuCorrection.SimpleOffset.cs:39–74](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/223b905daf0d7421c187b727a65d180bfa7472d6/Drilling.UI/Menu/Menus/CMenuCorrection.SimpleOffset.cs#L39-L74), [CRoughCorrectionPanel.cs:148–185](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/223b905daf0d7421c187b727a65d180bfa7472d6/Drilling.UI/Menu/Menus/CRoughCorrectionPanel.cs#L148-L185), [CMenuCorrection.Rough.cs:76–108](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/223b905daf0d7421c187b727a65d180bfa7472d6/Drilling.UI/Menu/Menus/CMenuCorrection.Rough.cs#L76-L108), [CFineReviewOffsetCalculator.cs:8–63](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/223b905daf0d7421c187b727a65d180bfa7472d6/Drilling.Common/Review/CFineReviewOffsetCalculator.cs#L8-L63), [CMenuCorrection.FineOffset.cs:33–79](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/223b905daf0d7421c187b727a65d180bfa7472d6/Drilling.UI/Menu/Menus/CMenuCorrection.FineOffset.cs#L33-L79).

## 2-5. 결과 CSV와 적용용 Offset CSV는 다른 자료

| 저장물 | 경로/열 | 용도와 제한 |
| --- | --- | --- |
| FINE 결과 | Data/ReviewResult/FINE/Recipe/날짜, 39열 | Glass·Origin·방식·재시도·라인·ShotKey·flip·raw방향·판정·Stage/Vision simulation 각각 기록 |
| ROUGH 결과 | Data/ReviewResult/ROUGH/Recipe/날짜, 31열 | Scope·Point·초기/NG재시도·측정/유지/미검사·판정 기록; Fine처럼 Glass context 열을 갖지 않음 |
| Review Offset | Config/RECIPE/Recipe_reviewoffset, 5열 | 다음 가공이 소비하는 보정값; 측정 Run/Glass/simulation/승인 revision 없음 |
| ProcessResult | Log/Station/날짜, 9열 | Process/Recipe/Glass/Head/Automation/Task/Simulation/Result/CompletedAt |
| Align Offset | Recipe의 Shot 숨김키 + 별도 log | Recipe 저장과 log 저장은 하나의 transaction이 아님 |

FINE/ROUGH 결과의 좌표·오차는 mm 소수3자리로 저장합니다. Live 계산은 반올림 전 값을 쓸 수 있어 이 CSV만으로 보정 결과를 완전히 재현하지 못할 수 있습니다. 기존 일반 ReviewResult Load와 신규 전용 결과 CSV는 별도 스키마입니다. Product 클래스가 이들 결과를 모두 자동 소유·영속 연결한다고 평가하지 않았습니다.

근거: [CReviewResultFile.FineCorrection.cs:9–77](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/223b905daf0d7421c187b727a65d180bfa7472d6/Drilling.File/ReviewResult/CReviewResultFile.FineCorrection.cs#L9-L77), [CReviewResultFile.RoughCorrection.cs:9–83](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/223b905daf0d7421c187b727a65d180bfa7472d6/Drilling.File/ReviewResult/CReviewResultFile.RoughCorrection.cs#L9-L83), [CStationProcess.StageProcess.cs:70–110](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/223b905daf0d7421c187b727a65d180bfa7472d6/Drilling.Common/Station/CStationProcess.StageProcess.cs#L70-L110).

## 2-6. 다음 기판에 적용되는 시점

Auto Review는 계획을 캡처한 후 현재 기판 Script를 중간 수정하지 않습니다. 모두 OK이면 새 Offset 파일을 저장하고, 다음 Recipe Load에서 최신 파일을 읽어 파라미터에 넣습니다. 이후 새 Script 생성 때 최종 Scanner 좌표로 합성합니다. 현재 기판과 다음 기판의 기준을 혼동하지 않는 것이 핵심입니다. 근거: [CAutoFineReviewCoordinator.cs:27–79](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/223b905daf0d7421c187b727a65d180bfa7472d6/Drilling.Common/Review/CAutoFineReviewCoordinator.cs#L27-L79), [CStationProcess.cs:1358–1364](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/223b905daf0d7421c187b727a65d180bfa7472d6/Drilling.Common/Station/CStationProcess.cs#L1358-L1364).

## 2-7. Align·샘플 데이터·배포값

Align은 Base−LastLoad를 X선형/Y Lagrange로 계산하는 단일 방식으로 바뀌었습니다. Bilinear 선택/추천 UI는 삭제됐습니다. Tolerance 초과 Shot은 X/Y 둘 다 이번 적용에서 제외하지만 **기존 저장값은 유지**합니다. Tolerance를 낮추는 것만으로 과거 보정이 지워지지 않습니다. Simulation LastLoad도 실제 Recipe 저장 차단 gate 없이 로그에 출처를 남길 수 있습니다. 근거: [CAlignInterpolation.cs:13–87](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/223b905daf0d7421c187b727a65d180bfa7472d6/Drilling.Common/Correction/CAlignInterpolation.cs#L13-L87), [CMenuCorrection.AlignOffset.cs:35–105](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/223b905daf0d7421c187b727a65d180bfa7472d6/Drilling.UI/Menu/Menus/CMenuCorrection.AlignOffset.cs#L35-L105).

test0929의 Align 숨김키42,840개는 모두0으로 정리됐습니다(이전 비제로42,828). 그러나 새로운 최신 Review Offset은 전20,740행 비제로, 최대3.013mm, 0.03mm초과20,706행, 3mm초과3행입니다. 이 숫자는 통계이며 공정 NG 판정은 아닙니다. 측정/Simulation 출처를 파일만으로 판별할 수 없습니다. 로더가 이름순 최신 파일을 자동 선택하므로 배포 승인 전 분리가 필요합니다. 근거: [20261026_174834_059_reviewoffset.csv:1342–1344](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/223b905daf0d7421c187b727a65d180bfa7472d6/Config/RECIPE/test0929_reviewoffset/20261026_174834_059_reviewoffset.csv#L1342-L1344).
