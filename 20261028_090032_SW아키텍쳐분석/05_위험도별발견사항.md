# 5. 위험도별 발견사항과 권장 확인

[처음으로](README.md) · [검증](06_분석근거_검증기록.md)

P1은 장비에 배포하기 전 우선 확인해야 하는 항목, P2는 구현/운영 일관성 보완 항목입니다. 위험도는 이번 소스·데이터에 대한 분석 우선순위이며 고객사 공정의 공식 severity 판정은 아닙니다. 코드 수정은 이번 작업 범위가 아닙니다.

## P1-01. MELSEC ON의 wire 값 변경 — 배포 계약

논리 ON=1이 wire raw10000으로 바뀌었습니다. WORD/DWORD read는 READ_SCALE, write는 WRITE_SCALE·반올림·범위검사를 사용합니다. DOUBLE이라는 map type도 IEEE754가 아니라2WORD signedInt32+scale입니다. 기존 map파일은 존재하면 자동갱신하지 않습니다.

새 binary만 또는 CSV만 배포하면 상대와 ON해석이 달라질 수 있습니다. 주소·word순서·signed·raw10000·읽기/쓰기scale을 묶어 승인하고 구맵 복구 시험을 해야 합니다. 외부 CIM/PLC 사양서와의 일치는 이번에 검증하지 않았습니다. 근거: [CMelsec.cs:476–512](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/223b905daf0d7421c187b727a65d180bfa7472d6/Drilling.Common/Interface/Melsec/CMelsec.cs#L476-L512), [CMelsec.cs:724–760](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/223b905daf0d7421c187b727a65d180bfa7472d6/Drilling.Common/Interface/Melsec/CMelsec.cs#L724-L760), [JHMI_MELSEC_MAP.csv:2–42](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/223b905daf0d7421c187b727a65d180bfa7472d6/Config/JHMI_MELSEC_MAP.csv#L2-L42), [CMelsecMapFile.cs:45–77](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/223b905daf0d7421c187b727a65d180bfa7472d6/Drilling.File/JHMI/CMelsecMapFile.cs#L45-L77).

## P1-02. Simulation 보정이 실가공 Offset 경로로 저장될 수 있음 — 구조상 경로 확인

새 Fine/Rough 결과 CSV에는 simulation표시가 있지만 보정 Apply/AutoSave는 그 출처를 차단하지 않습니다. OffsetCSV에는 simulation/Glass/Run승인 정보가 없고 다음 load는 파일명 최신값을 자동 사용합니다. Align도 Simulation LastLoad를 실제 Recipe로 저장할 수 있습니다.

가상·실측 저장영역 분리 또는 명시 승인 gate가 필요합니다. 실제 양산 데이터가 오염됐다고 단정한 것은 아닙니다. 근거: [CAutoFineReviewCoordinator.cs:41–79](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/223b905daf0d7421c187b727a65d180bfa7472d6/Drilling.Common/Review/CAutoFineReviewCoordinator.cs#L41-L79), [CReviewOffsetFile.cs:9–24](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/223b905daf0d7421c187b727a65d180bfa7472d6/Drilling.File/ReviewOffset/CReviewOffsetFile.cs#L9-L24), [CReviewOffsetFile.cs:48–57](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/223b905daf0d7421c187b727a65d180bfa7472d6/Drilling.File/ReviewOffset/CReviewOffsetFile.cs#L48-L57), [CMenuCorrection.AlignOffset.cs:86–105](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/223b905daf0d7421c187b727a65d180bfa7472d6/Drilling.UI/Menu/Menus/CMenuCorrection.AlignOffset.cs#L86-L105).

## P1-03. 자동 선택되는 대규모 Offset과 완화된 공차 — 현재 샘플 설정

동봉 최신 Offset은20,740행 모두 비제로·최대3.013mm입니다. Review공차는3mm, Align공차는12mm로 완화됐고 StageStartY3960·flip변경·BufferedON도 포함됩니다. 이 값은 JHMI 신규 설치 기본값과 다르며 단위/제품/장비 유효범위를 승인해야 합니다.

CSV에 출처가 없어 실측/Simulation을 단정할 수 없습니다. 운영 load폴더에서 시험자료를 분리하고 적용할 파일 revision을 명시하는 것이 우선입니다. 이전 Align샘플의 비제로값은0으로 정리돼 해당 과거지적은 그 샘플 범위에서 해결됐습니다. 근거와 통계: [schema-diff.json](schema-diff.json), [데이터 설명](02_데이터구조와흐름.md).

## P1-04. Fine 보간/누적 변위의 상한 없음 — 수치 재현 R01

같은 Cell/X에서 Y=0,2,4,6,8의 오차를+.03,−.03,+.03,−.03,+.03mm로 모두OK 처리했습니다. 현재 calculator의 Y=1 결과는 **−.04875mm**였습니다. 앵커는±.03 안이어도 보간 중간값은 밖으로 나갈 수 있습니다.

이는 Lagrange 수학식 오류가 아니라 별도 max-delta/max-accumulated 정책 부재입니다. 유한값 검사만으로 안전하다고 볼 수 없습니다. 보간 결과·기존값+누적값 상한, 실제 가공영역/Mask 재검증을 승인 정책으로 추가 검토해야 합니다. Simple도 현재 유한 입력값 이외에 변위 상한이 없습니다. 근거: [CFineReviewOffsetCalculator.cs:29–63](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/223b905daf0d7421c187b727a65d180bfa7472d6/Drilling.Common/Review/CFineReviewOffsetCalculator.cs#L29-L63), [CAutoFineReviewCoordinator.cs:66–75](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/223b905daf0d7421c187b727a65d180bfa7472d6/Drilling.Common/Review/CAutoFineReviewCoordinator.cs#L66-L75), [CSimpleCorrectionPanel.cs:518–524](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/223b905daf0d7421c187b727a65d180bfa7472d6/Drilling.UI/Menu/Menus/CSimpleCorrectionPanel.cs#L518-L524). 실행 증거: [validation.json](validation.json).

## P1-05. 실제 Review/0선/Power 완성으로 오인할 위험 — 의도적 거부와 미연결

Fine/Rough 실제 PLC이동은 시작 전 차단됩니다. 0선은 계획검증만 있고 Stage 실행 coordinator가 없습니다. Main의0선/그룹/후속 옵션3개는 실행소비 미확인, PowerMeasure는 SimulationSession입니다. 표시·설정 저장을 개발완료로 집계하면 일정/현장 검증을 잘못 판단하게 됩니다.

계획/UI완료와 실제 PLC binding·장비검증을 분리하십시오. 상세 근거: [영향 분석](03_가공_Review영향분석.md).

## P1-06. Safety 표시와 실제 HW안전 검사 차이 — 기존 부채

새 DOE/Optic 검사는 실제 Auto 준비조건에 추가됐지만 기존 Station의 io=[]는 유지됩니다. IO규칙이 비어 있으면 Door/EMS 등의 평가가 생략되는 기존 경계가 있으므로 대표 Safety OK를 전체 HW인터락 통과로 해석하면 안 됩니다. 새 변경에서 도입된 결함이 아니라 배포 전 유지 확인할 기존 부채입니다. 근거: [CStationProcess.cs:1172–1202](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/223b905daf0d7421c187b727a65d180bfa7472d6/Drilling.Common/Station/CStationProcess.cs#L1172-L1202), [CInterLockManager.cs:36–44](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/223b905daf0d7421c187b727a65d180bfa7472d6/Drilling.Common/InterLock/CInterLockManager.cs#L36-L44).

## P2-01. 공유 가상 Stage가 예약 중에도 공용 Stop으로 멈춤 — 수치 재현 R02

MOF가 독점 lease를 가진 상태에서 PowerMeasure START는 반대방향 MOF busy검사를 하지 않습니다. 측정 busy전환이 같은 공유 Stage의 공용 Stop을 호출합니다. 공용Stop은 소유권을 검사하지 않습니다.

Probe에서100mm목표·속도10으로 이동 후1초 위치10mm에서 공용Stop을 호출했습니다.20초 후도10mm·정지이며 IsReserved=true였습니다. **실제 PLC충돌이 아니라 가상 이동/시험 신뢰성 문제**입니다. 양방향 실행잠금과 소유권 기반Stop을 검토해야 합니다. 근거: [CMenuManual.PowerMeasure.cs:15–25](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/223b905daf0d7421c187b727a65d180bfa7472d6/Drilling.UI/Menu/Menus/CMenuManual.PowerMeasure.cs#L15-L25), [CManualPowerMeasurePanel.cs:137–185](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/223b905daf0d7421c187b727a65d180bfa7472d6/Drilling.UI/Menu/Menus/CManualPowerMeasurePanel.cs#L137-L185), [CManualPowerStagePanel.cs:72–77](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/223b905daf0d7421c187b727a65d180bfa7472d6/Drilling.UI/Menu/Menus/CManualPowerStagePanel.cs#L72-L77), [CManualStageMotionSimulation.cs:81–88](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/223b905daf0d7421c187b727a65d180bfa7472d6/Drilling.Common/Motion/CManualStageMotionSimulation.cs#L81-L88).

## P2-02. 보정 revision·중복적용·동시 저장 계약

Fine source signature는 OFFSET키를 제외합니다. 다른 Simple/Rough 저장 이후 기존 Fine 측정치를 최신 Offset에 누적할 수 있으며, LoadLatest→SaveNew 전체의 CAS/영속 적용RunId가 없습니다. Auto `_saved`는 인스턴스 메모리 플래그입니다.

실제 동시실행 가능성은 mode/Station interlock까지 검증해야 하므로 확정 race로 단정하지 않습니다. 어떤 Offset으로 가공한 기판의 측정값인지 revision을 보존하고 재적용/재시작/동시저장 정책을 시험해야 합니다. 근거: [CFineCorrectionPanel.cs:101–108](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/223b905daf0d7421c187b727a65d180bfa7472d6/Drilling.UI/Menu/Menus/CFineCorrectionPanel.cs#L101-L108), [CMenuCorrection.FineOffset.cs:56–79](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/223b905daf0d7421c187b727a65d180bfa7472d6/Drilling.UI/Menu/Menus/CMenuCorrection.FineOffset.cs#L56-L79), [CAutoFineReviewCoordinator.cs:16–79](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/223b905daf0d7421c187b727a65d180bfa7472d6/Drilling.Common/Review/CAutoFineReviewCoordinator.cs#L16-L79).

## P2-05. 레거시 API·ReviewRule migration

기존 public Fine projection에는 Head+X로 다른Cell을 섞는 코드가 남았습니다. 선별시험 N02도0.015혼합을 확인했습니다. 그러나 현재 새 FineUI/Auto는 Cell+X calculator를 호출하므로 **활성 경로에서는 개선**됐습니다. 구API 재사용 시 회귀위험으로 관리해야 합니다. 구 SIMPLE rule의 ROUGH정규화도 명시 migration대상입니다. 근거: [CReviewManager.cs:1710–1741](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/223b905daf0d7421c187b727a65d180bfa7472d6/Drilling.Common/Review/CReviewManager.cs#L1710-L1741), [CReviewManager.cs:1787–1821](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/223b905daf0d7421c187b727a65d180bfa7472d6/Drilling.Common/Review/CReviewManager.cs#L1787-L1821), [CMenuCorrection.cs:754–789](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/223b905daf0d7421c187b727a65d180bfa7472d6/Drilling.UI/Menu/Menus/CMenuCorrection.cs#L754-L789).

## 배포 전 검수의 권장 순서

1. 시험 Config/Offset 분리 및 승인값 고정.
2. MELSEC binary/map/PLC wire 동시 검증.
3. Simulation 출처·보정상한·revision 정책 확정.
4. 실제 축/Trigger와0선/파워 coordinator연결.
5. Timeout/NG/STOP/재시작/양방향중복조작 시험.
6. 실기 측정 단위/부호/공차/결과·다음기판 적용 확인.
