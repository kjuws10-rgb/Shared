# 4. 갱신된 통합 흐름도

[처음으로](README.md) · [데이터 설명](02_데이터구조와흐름.md)

그림의 실선은 현재 코드의 데이터/호출 연결입니다. `미연결` 상자는 실제 장비 실행까지 이어지지 않는 경계입니다. 저장·표시 기능과 실행 완료를 구분해서 읽습니다.

## 4-1. 프로그램 전체 책임

```mermaid
flowchart TB
    CFG["JHMI 정의 · Setting · Recipe CSV"] --> FILE["Drilling.File<br/>읽기 · 검증 · 결과/보정 저장"]
    FILE --> COMMON["Drilling.Common<br/>좌표계획 · Review · Station · 장치관리"]
    UI["Drilling.UI<br/>Main · Recipe · Manual · Correction"] --> COMMON
    COMMON --> UI
    COMMON --> CACHE["공유 snapshot/cache<br/>유효성 · freshness · version"]
    CACHE --> A1["Automation1<br/>실제 SDK 또는 Simulation"]
    CACHE --> PLC["MELSEC<br/>raw/논리 scale · 입력 · 출력"]
    COMMON --> VIS["Vision<br/>PtoP · 1001/1002/1003"]
    COMMON --> RESULT["Process/Fine/Rough 결과 CSV"]
    COMMON --> OFFSET["Review Offset 새 버전 CSV"]
    OFFSET --> FILE
    PLC -.-> UNWIRED["실제 Review 축/Trigger<br/>0선방어 실행은 미연결"]
```

## 4-2. Stage 요청과 가공측 응답

```mermaid
sequenceDiagram
    participant S as Stage/PLC
    participant Q as Stage 요청 Sequence
    participant A as Automation1
    participant F as 파일/Product
    S->>Q: DoReady ABLE / START handshake
    Q->>F: Recipe·Glass 캡처, Script 생성·업로드
    Q-->>S: DoReady COMPLETE 후 상호 해제
    S->>Q: Process ABLE
    Q->>Q: Stage 시작위치·Busy 확인
    Q->>A: AUX=0 새 값 확인, prepared Task RUN
    A-->>Q: 같은 RunId 준비표시
    Q-->>S: Process ABLE
    S->>Q: Process START
    Q-->>S: Process START 응답
    A-->>Q: 모든 Head program/queue 완료
    Q->>F: ProcessResult 저장·Product 완료 보고
    Q-->>S: Process COMPLETE
    S->>Q: 상대 COMPLETE 후 신호 해제
    Q->>Q: 정상완료 Task 소유권 해제, 추가 STOP 없음
```

Task RUN은 초기화 선준비이고 Process START는 가공 진행 handshake입니다. 두 시점을 같게 그리지 않았습니다. 오류/취소는 별도로 소유한 Task 정지·출력해제·정리확인을 거칩니다.

## 4-3. Review 결과가 다음 기판 보정으로 가는 과정

```mermaid
flowchart TB
    A["Stage Review ABLE"] --> B["Recipe · Glass · 옵션 고정<br/>AUTO Fine 계획 캡처"]
    B --> C["가공측 ABLE / Stage START 확인"]
    C --> D["가상 Stage 이동 + Vision 측정<br/>실제 PLC 이동은 차단"]
    D --> E["Fine 종료 결과 CSV 저장 확인"]
    E --> F{"완료·파일저장 정상?"}
    F -- "아니오" --> X["오류 · 정상 COMPLETE 금지"]
    F -- "예" --> G{"모든 점 OK?"}
    G -- "아니오" --> H["검사완료 · 보정 미적용<br/>기존 Offset 유지"]
    G -- "예" --> I["Cell+X열별 Y보간<br/>기존값 DESIGN 변환 후 누적"]
    I --> J["Review Offset 새 버전 저장"]
    J --> K["Review COMPLETE / 상호해제"]
    H --> K
    K --> L["다음 DoReady / Recipe Load"]
    L --> M["최신 Offset 소비 · 새 Script 생성"]
```

NG 검사완료와 보정 적용완료는 서로 다른 상태입니다. 현재 Offset 파일에는 Simulation/Run/승인 출처가 없어 별도 보완이 필요합니다.
