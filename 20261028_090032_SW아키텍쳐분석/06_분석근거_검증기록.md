## 6-1. 기준 탐색과 범위

- Shared main을 먼저 fetch하고 전체 트리에서 `YYYYMMDD_HHMMSS`와 `YYYYMMDD_HHMMSS_SW아키텍쳐분석` 이름을 모두 검색했습니다. 재귀 검색에서 일치한 최신 폴더는20261022_090959_SW아키텍쳐분석입니다.
- README의 원본SHA `e6ff3c6fd8fb706adbff3ded070cca2502000b4d`를 기준으로 사용했습니다. 최초 fallback SHA는 이번에 사용하지 않았습니다.
- 원본 main `223b905daf0d7421c187b727a65d180bfa7472d6`와의 ancestry를 확인했고 새 Commit1개를 분석했습니다.
- 전체 2,027개 목록을 분류하고 소스 171/Config 25의 diff와 영향받은 호출을 추적했습니다. 변경되지 않은 전체 소스파일을 줄 단위 전수검증했다고 주장하지 않습니다.
- Review·Recipe/좌표·Device/UI를 3보조에이전트가 읽기 전용으로 분담하고 주에이전트가 Stage/Script/결과/수치 재현과 통합 판정을 담당했습니다. 같은 파일 동시 수정은 없었습니다.
- 최종 보고서도 세 담당자가 다시 교차검토했습니다. 0선 선택이 없는 Recipe의 저장 허용, Simulation Ready의 검증 우회, Shift의 후단 적용을 명료화하고 Safety 생략의 직접 근거를 추가했습니다.
- 기존 지식기록·회의/자료의 주장은 맥락으로만 사용하고 이번 구현 판정은 고정 SHA의 실제 코드와 실행한 Probe를 우선했습니다. 외부 PLC/CIM/Vision 사양서·실장비는 별도 미검증입니다.

## 6-2. Clone 및 원본 보호

| 구역 | 수행 | 금지/미수행 |
| --- | --- | --- |
| 등록된 사용자 원본 | 시작/종료 tracked 소스·Config hash와 Git 상태 확인 | 파일 수정·추가·삭제·Commit·Push·빌드 없음 |
| 신규 분석 Clone | NEW에 detach, diff/코드 읽기, push URL DISABLED | 파일 수정/빌드/장비 기동 없음 |
| 별도 검증 Clone | NEW 기준 Release 빌드·ArchitectureProbe만 수행 | 원본 Push·UI/레이저/PLC/Stage 동작 없음 |
| Shared | 이번 보고 폴더만 추가·검증·게시 | 기존 사용자 폴더 덮어쓰기/강제 Push 없음 |

원본 보존 검사는 사용자 원본과 읽기 전용 Clone을 구분합니다. 원본의 기존 변경은 그대로 보존하며 시작/종료 사이 소스/Config/상태의 동일성을 비교합니다. 빌드 산출물을 원본에 만들지 않았습니다.

## 6-3. Release 빌드

명령: `dotnet build Drilling.sln --configuration Release --nologo --verbosity minimal`

- 별도 validation Clone에서 실행, exit 0.
- 결과 **0 Warning / 0 Error**.
- 영어 출력 재빌드의 외부 측정 2.56초, MSBuild 출력 2.16초(증분 빌드).
- 최초 fresh 빌드도 성공했으나 출력 문자 해석 문제를 피하기 위해 영어 출력으로 재확인했습니다.
- WPF 창·장비 연결·Sequence 실가동은 하지 않았습니다. 빌드 성공은 문법/참조/컴파일 확인 범위입니다.

## 6-6. 문서·링크·전송 검증

- 소스 링크는 모두 NEW 전체 SHA에 고정했습니다. 각 파일 실재·총행수·시작/끝 범위·파일/발췌 SHA256은 [source-links.json](source-links.json)에 기록합니다.
- 문서 내부 링크 존재·Markdown 코드 펜스 짝·UTF-8/잘못된 제어문자/대체문자·JSON 파싱·CSV 2027목록·git diff --check를 검사합니다.
- Mermaid는 flowchart/sequenceDiagram 텍스트 정적 검증입니다. 이번 작업에서 Mermaid 렌더러 브라우저 시각 시험은 하지 않았습니다.
- Shared 게시 전 원격을 재확인하고 원격 진행이 있으면 안전하게 동기화합니다. 이번 폴더 밖의 변경은 stage/commit하지 않습니다.
- 최종 원본 보존/원격파일 hash/manifest 검증은 [share-manifest.json](share-manifest.json)과 최종 대화 보고의 Commit으로 확인합니다.
