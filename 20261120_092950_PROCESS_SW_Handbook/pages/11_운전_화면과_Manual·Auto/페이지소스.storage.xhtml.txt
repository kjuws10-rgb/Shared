<p>운전 화면에서는 사용자가 입력한 값뿐 아니라 현재 기판에 적용된 실행 기준과 장치 피드백, 검사·저장 결과를 함께 읽어야 한다.</p>
<h2>화면에 보이는 값의 출처와 시점</h2><p>편집값은 사용자가 바꾸는 조건이고 준비값은 실행 준비 시점에 설정·Recipe·보정을 합성한 사본이다. 실제값은 장치 피드백, 결과값은 측정·판정에서 얻은 자료다. 같은 숫자를 표시하더라도 생산자와 갱신 시점이 다르다.</p><p>Recipe 저장 뒤에도 이미 준비한 Snapshot과 Script가 자동으로 같은 값이 됐다고 판단하지 않는다. 저장본·재로드·새 준비를 거쳤는지 보고, 어떤 Recipe와 보정본으로 현재 계획을 만들었는지 확인한다.</p><p><ac:image ac:width="1200" ac:alt="표시값 네 종류를 한눈에 구분한다."><ri:attachment ri:filename="p19_11_B.png"/></ac:image></p><p><em>네 칸은 시간 순서가 아니라 값의 출처다. 편집값·준비 사본·장치 피드백·측정 결과를 비교하여 값이 달라진 경계를 찾는다.</em></p>
<h2>현재 작업과 실행 상태를 연결한다</h2><p>Main에서는 Glass·Recipe·현재 Step·대기 원인을 먼저 확인한다. 선택 Head·Controller·Task와 준비 Script가 실제 실행 대상인지, 검사 계획의 점 수와 수집 결과가 맞는지를 연결한다. 같은 작업의 식별자와 시각으로 화면·로그·결과를 비교한다.</p><p>Task 실행 종료, 가공 완료 신호, 검사 OK/NG, 파일 저장은 각각 확인한다. 장치 상태 표시에는 현재 위치·Busy·오류와 마지막 수신 상태가 필요하다. 화면 정지·지연을 실제 장치 정지로 해석하지 않는다.</p><p>동작 허가도 Auto·Manual·Laser별로 읽는다. 차단 이유를 화면에 표시하는 경로와 실제 명령 전에 허가를 검사하는 경로가 연결되는지 확인한다. 중복 Start, 늦은 상태 갱신과 저장 실패도 다른 상태로 드러나야 한다.</p>
<h2>Manual과 AUTO는 시작 범위와 끝 상태를 확인한다</h2><p>Manual은 선택 대상과 단일 기능의 범위를 먼저 정한다. AUTO는 현재 기판의 준비 계획과 Step·Handshake를 따라 진행한다. 공통 기능을 사용하더라도 진입 조건과 실행 범위를 동일하다고 가정하지 않는다.</p><p>Manual 작업 뒤에는 남은 Task·이동·요청 신호와 기판 상태를 확인한다. Manual 종료가 AUTO 자동 재개를 의미하지 않는다. 재준비·재개 기준은 정지·복구 상태와 함께 판단한다.</p><table class="wrapped"><tbody><tr><th>작업</th><th>시작 전에 볼 것</th><th>종료 뒤 확인</th></tr><tr><td>Manual 축·Head 기능</td><td>대상 장치·축·Head·현재 위치·Busy·허가</td><td>명령 결과와 실제 도착/중지·오류</td></tr><tr><td>Manual 검사·재검사</td><td>선택 Point와 원 결과·측정 범위</td><td>이번에 바뀐 결과·Revision·저장</td></tr><tr><td>보정 적용·원복</td><td>현재 Recipe·적용본·출처·이력</td><td>새 적용본 또는 복원본과 다음 준비</td></tr><tr><td>AUTO</td><td>기판·Recipe·계획·상대 준비·이전 요청 정리</td><td>Step/Task·검사·저장·보고별 결과</td></tr></tbody></table><h2>함께 읽기</h2><p><ac:link><ri:page ri:content-title="03. 프로그램 구조와 실행 데이터"/><ac:plain-text-link-body><![CDATA[03. 프로그램 구조와 실행 데이터]]></ac:plain-text-link-body></ac:link> · <ac:link><ri:page ri:content-title="05.
