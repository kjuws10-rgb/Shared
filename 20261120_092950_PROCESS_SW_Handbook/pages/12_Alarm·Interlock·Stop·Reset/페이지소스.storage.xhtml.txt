<p>Alarm은 문제를 기록하고 Interlock은 동작 허가를 판단한다. Stop·실제 장치 종료·신호 정리·Reset·재준비는 범위가 다르므로 단계별 상태를 확인한다.</p>
<h2>동작 허가와 Alarm을 구분한다</h2><p>Interlock은 AutoRun·ManualMove·LaserOn 대상으로 나눠 평가한다. 원신호의 사용 여부·극성·최신값과 차단 사유를 함께 본다. 장치 연결 성공만으로 해당 동작의 허가가 성립했다고 판단하지 않는다.</p><p>Alarm의 현재 목록과 발생 이력은 다른 자료다. 화면에 보인 알람이 이력에도 저장됐는지 확인하고 최초 발생 시각·코드·수준·현재 Step과 작업 식별자를 보존한다. 같은 코드의 반복과 처음 원인이 된 사건을 구분한다.</p>
<h2>Stop 반환 뒤 실제 상태를 확인한다</h2><p>Stop이나 취소가 어느 Station·Task·Queue·상대 장치에 전달됐는지 확인한다. 응답 또는 Timeout 결과와 실제 Task/축/출력 상태를 나란히 본다. 소프트웨어 요청 반환만으로 물리 정지 완료를 판정하지 않는다.</p><p>자신이 소유한 Request·Start·Complete의 OFF와 readback, 남은 세션도 확인한다. 늦은 완료가 다음 작업에 붙지 않도록 정리 실패를 남겨야 한다. 한 부분의 실패가 다른 장치까지 정상 정리됐다는 보장은 아니다.</p>
<h2>Reset과 원복은 정해진 대상에만 적용된다</h2><p>Alarm Reset은 현재 알람 목록을 정리한다. 센서 원인 해소, 축 정지·원점, 출력 차단과 기판 재개 승인까지 해결하는 동작으로 해석하지 않는다.</p><p>검사 세션 정리, 진행 상태 복구, Offset 원복도 서로 다른 범위다. Offset의 직전 적용본을 복원해도 원측정·재검사 Revision·Recipe 전체가 같이 돌아가는 것은 아니다. 초기화하거나 유지한 자료와 다음 준비에서 사용할 기준을 명시한다.</p><p><ac:image ac:width="1200" ac:alt="목록 초기화와 실제 원인 해소의 경계를 설명한다."><ri:attachment ri:filename="p19_12_B.png"/></ac:image></p><p><em>알람 목록 Reset과 원인 해소 사이의 ≠ 표시는 별도 확인이 필요하다는 뜻이다. 목록이 비어도 실제 장치와 남은 작업을 확인해야 한다.</em></p>
<h2>보호윈도우 매수와 추가 요청</h2><p>보호윈도우는 Current/Maximum과 Stage가 인계한 TrayCount를 함께 다룬다. 교체 완료를 받았다고 사용매수를 무조건 0으로 만들지 않는다. 인계 매수 저장→Count 보고→Request OFF 확인 순서를 보존한다.</p><p>추가 요청 횟수는 최초 요청과 구분한다. 인계값이 한계 이상인 경우 Request와 Complete가 모두 OFF인지 확인한 다음 추가 요청을 판단한다. 이전 Complete ON을 새 교체 완료로 다시 사용하지 않는다.</p><p>현재 횟수 소진 경로에는 LIGHT 알람을 요청하고 AUTO를 계속하는 분기가 있다. 이를 교체 품질 합격이나 HEAVY 자동 정지로 바꾸어 설명하지 않는다. 실제 배포 알람 정의·후속 처리와 재시작 때 유지되는 횟수 범위를 함께 확인한다.</p><p><ac:image ac:width="1200" ac:alt="인계 매수·신호 OFF·추가 요청의 순서를 설명한다."><ri:attachment ri:filename="p17_12_윈도우_교체요청.png"/></ac:image></p><p><em>처음 Request와 추가 요청을 분리해 따라간다. Stage 인계값을 저장·보고한 뒤 OFF를 확인하고, 남은 추가 횟수와 소진 경로를 판단한다.</em></p>
<h2>재개할 작업의 기준을 다시 만든다</h2><p>현재 기판의 완료/미완료 가공, 검사 결과, 적용 Offset과 준비 Script를 확인한다. 재가공·재검사·배출 중 무엇을 할지와 중복 가공·중복 보정 가능성을 먼저 정리한다.</p><p>원인·장치 상태·신호 정리·자료 정합이 확인되면 최신 기준으로 재준비하고 동작별 허가를 다시 확인한다. 실제 안전 회로와 현장 재개 절차는 프로그램 상태표만으로 대체하지 않는다.</p><p><ac:image ac:width="1200" ac:alt="중단 뒤 재개 전에 확인할 상태를 한 흐름으로 묶는다."><ri:attachment ri:filename="new_recovery-gates.png"/></ac:image></p><p><em>Task·Queue의 처리, 축·출력의 실제 상태, 기판의 완료/미완료 구간을 확인한 뒤 재준비로 진행한다. 화살표는 판단 순서이며 모든 항목을 한 번에 자동 복구하는 기능을 뜻하지 않는다.</em></p><h2>함께 읽기</h2><p><ac:link><ri:page ri:content-title="09. 통신과 장비 인터페이스"/><ac:plain-text-link-body><![CDATA[09. 통신과 장비 인터페이스]]></ac:plain-text-link-body></ac:link> · <ac:link><ri:page ri:content-title="10. 광학 장치와 Power 측정"/><ac:plain-text-link-body><![CDATA[10. 광학 장치와 Power 측정]]></ac:plain-text-link-body></ac:link> · <ac:link><ri:page ri:content-title="11. 운전 화면과 Manual·Auto"/><ac:plain-text-link-body><![CDATA[11. 운전 화면과 Manual·Auto]]></ac:plain-text-link-body></ac:link> · <ac:link><ri:page ri:content-title="15. 증상별 개발 확인"/><ac:plain-text-link-body><![CDATA[15. 증상별 개발 확인]]></ac:plain-text-link-body></ac:link> · <ac:link><ri:page ri:content-title="16. 데이터 관리와 변경 반영"/><ac:plain-text-link-body><![CDATA[16. 데이터 관리와 변경 반영]]></ac:plain-text-link-body></ac:link></p>
