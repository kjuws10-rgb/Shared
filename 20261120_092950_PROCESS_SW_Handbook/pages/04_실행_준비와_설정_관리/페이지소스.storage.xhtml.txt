<p>프로그램 시작을 확인할 때는 어떤 Config를 읽었는지와 장치 초기화가 어디까지 끝났는지를 나누어 본다. 창이 열리는 것은 화면이 만들어졌다는 뜻이며 통신·축·운전 허가까지 모두 준비됐다는 뜻은 아니다.</p>
<h2>실제로 읽는 Config 위치</h2><p>설정 위치 탐색은 실행 파일의 위치에서 시작한다. 상위 폴더를 차례로 올라가 Drilling.sln을 찾으면 그 파일과 같은 폴더의 Config를 사용한다. 끝까지 찾지 못하면 현재 작업 폴더 아래의 Config를 사용한다.</p><p>따라서 실행 파일 옆에 둔 Config가 항상 선택되는 것은 아니다. 바로가기의 작업 폴더나 실행본의 위치가 바뀐 경우에는 표시된 ConfigRoot와 실제 읽은 파일을 먼저 확인한다. 다른 폴더의 설정을 수정해 놓고 프로그램 값이 바뀌지 않는다고 판단하지 않도록 한다.</p><p><ac:image ac:width="1200" ac:alt="상위 탐색과 작업 폴더 대체 경로를 분기 그림으로 설명한다."><ri:attachment ri:filename="p19_04_A.png"/></ac:image></p><p><em>실행 위치에서 상위 탐색 화살표를 따라가고, Drilling.sln 발견 여부에 따라 옆 Config 또는 작업 폴더 Config로 갈라 읽는다.</em></p>
<h2>화면 표시와 장치 Ready가 갈라지는 이유</h2><p>프로그램은 공유 Manager를 만든 뒤 초기화를 별도 작업으로 시작하고 화면과 상태 감시를 구성한다. 화면이 먼저 보이는 동안 파일 로드나 장치 연결이 계속 진행될 수 있다. 초기화 중 오류는 그 단계의 상태와 기록을 확인해 구분한다.</p><p>연결됨은 상대와 통신할 수 있다는 상태이고, 축 Ready는 필요한 축 상태가 갖춰졌다는 뜻이다. 운전 허가는 선택한 동작의 인터락과 실행 조건까지 포함한다. 이 상태들을 하나의 녹색 표시로 대신 판단하지 않는다.</p><table class="wrapped"><tbody><tr><th>보이는 현상</th><th>먼저 확인할 경계</th></tr><tr><td>값이 예상과 다름</td><td>ConfigRoot, 읽은 조건 파일, 선택한 Recipe</td></tr><tr><td>창은 열렸지만 연결되지 않음</td><td>초기화 단계와 해당 장치의 연결 오류</td></tr><tr><td>연결됐지만 움직이지 않음</td><td>축 상태·실행 모드·대상 동작의 인터락</td></tr><tr><td>초기화 후 준비가 거부됨</td><td>실행에 필요한 조건과 장치 상태, 보정본 일치 여부</td></tr></tbody></table>
<h2>실행본을 바꾸거나 설정을 되돌린 뒤</h2><p>실행 파일과 필요한 DLL, Config·Recipe·보정 자료가 같은 운전 조건을 가리키는지 확인한다. 설정 파일만 교체한 경우에도 Manager가 어떤 값을 읽었는지와 다음 준비에서 어떤 값이 합성되는지를 확인해야 한다.</p><p>초기화 실패를 화면 재시작만으로 해결됐다고 판단하지 않는다. 실패한 단계가 정상으로 바뀌고 실제 장치 상태가 확인된 뒤 필요한 준비를 다시 수행한다.</p><h2>함께 읽기</h2><p><ac:link><ri:page ri:content-title="03. 프로그램 구조와 실행 데이터"/><ac:plain-text-link-body><![CDATA[03. 프로그램 구조와 실행 데이터]]></ac:plain-text-link-body></ac:link> · <ac:link><ri:page ri:content-title="09. 통신과 장비 인터페이스"/><ac:plain-text-link-body><![CDATA[09. 통신과 장비 인터페이스]]></ac:plain-text-link-body></ac:link> · <ac:link><ri:page ri:content-title="12.
