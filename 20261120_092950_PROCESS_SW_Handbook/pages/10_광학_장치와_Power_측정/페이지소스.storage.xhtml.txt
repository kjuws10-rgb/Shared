<p>광학 제어는 장치 상태를 준비하고 실제 출력을 측정한 뒤 ATT 각도를 조정하는 흐름이다. 측정 실적·보고와 Recipe 각도 저장, 종료 정리를 각각 확인한다.</p>
<h2>장치별로 제어하는 값이 다르다</h2><p>Laser는 출사 조건과 상태, ATT는 감쇠 위치, BEX는 광학 배율·발산과 관련된 위치를 다룬다. PowerMeter는 실제 출력 W를 측정한다. 명령을 수락했다는 응답과 목표 위치 도착, 출력의 안정화는 각각의 상태로 확인한다.</p><p>목표 출력 W, 측정 출력 W, ATT 각도는 서로 다른 데이터다. ATT를 어느 방향으로 움직이면 출력이 변하는지는 실제 광학 관계와 유효범위에 따라 판단한다. 각도 값을 출력 W로 표시하거나 각도를 늘리면 항상 출력도 커진다고 가정하지 않는다.</p><p><ac:image ac:width="1200" ac:alt="약어로만 보이던 광학 장치의 기능과 관측 단위를 물체 그림으로 구분한다."><ri:attachment ri:filename="new_optic-roles.png"/></ac:image></p><p><em>각 칸은 장치의 역할을 병렬로 비교한 것이다. 설치 순서를 뜻하지 않는다. Laser의 출사 조건, ATT 각도, BEX의 빔 조건과 PowerMeter의 실제 W를 서로 다른 값으로 읽는다.</em></p><table class="wrapped"><tbody><tr><th>대상</th><th>역할</th><th>함께 확인할 값</th></tr><tr><td>Laser</td><td>출사·주파수 등 조건과 출력 상태</td><td>응답·현재 상태·출력 OFF</td></tr><tr><td>ATT</td><td>감쇠 위치를 이동하고 현재 위치를 확인</td><td>목표/현재 각도·한계·도착</td></tr><tr><td>BEX</td><td>광학 배율·발산 관련 위치 제어</td><td>Motor 위치와 장비 교정 관계</td></tr><tr><td>PowerMeter</td><td>센서 조건으로 실제 출력 측정</td><td>센서 대응·파장 조건·W 단위·오류</td></tr><tr><td>Stage·Scanner</td><td>측정 위치와 실행 경로 준비</td><td>현재 위치·Busy·Task·새 상태</td></tr></tbody></table>
<h2>유효 측정값으로 평균과 오차를 계산한다</h2><p>측정 전에는 대상 Head와 센서·ATT·Controller·Task의 대응을 확인한다. Stage 위치·Busy와 최신 피드백, Scanner 및 출력 경로의 준비 상태도 검사한다. 측정 Run 자체가 Stage Y를 이동시키는 것으로 설명하지 않는다.</p><p>출사 직후 안정화 구간과 실제 수집 구간을 나누고 설정된 횟수·간격으로 얻은 유효 측정값을 사용한다. 미수신·파싱 실패·포화·오류를 정상 0으로 평균에 넣지 않는다. 목표 W와 허용오차를 비교해 필요하면 출력을 정리하고 ATT를 이동한 뒤 위치를 확인하여 다시 측정한다.</p><p><ac:image ac:width="1200" ac:alt="안정화·수집·종료 구간의 의미를 설명한다."><ri:attachment ri:filename="p17_10_Power_수집구간.png"/></ac:image></p><p><em>가로 방향은 시간이다. 출사 직후 구간은 평균에서 제외하고 유효 수집 구간의 새 샘플을 사용한다. 그림의 파형은 구간 설명이며 실제 출력 실측값이나 고정 시간 기준이 아니다.</em></p>
<h2>보고가 만들어져도 Recipe 저장 여부는 따로 판단한다</h2><p>Manual과 AUTO가 공유하는 측정 실행은 준비→측정→정상 결과의 Recipe 저장→정리로 이어진다. 실제 장치 세션과 모의 세션을 구분하고 실행 대상과 측정 조건을 결과에 연결한다.</p><p>측정이 시작된 실행의 Snapshot과 보고는 전체 대상의 OK 검사보다 먼저 남을 수 있다. NG나 중단 과정에서도 보고·측정 실적이 존재할 수 있으므로 보고 파일 존재를 보정 성공으로 표시하지 않는다.</p><p>Recipe ATT 각도는 측정 대상으로 선택한 Head가 모두 OK인 정상 결과에만 저장한다. 설치된 모든 Head를 의미하는 것이 아니다. NG·미완료이면 정상 저장 단계로 넘어가지 않으며, 저장을 호출한 뒤에도 실제 저장 결과를 따로 확인한다.</p><p><ac:image ac:width="1200" ac:alt="측정 보고와 Recipe 저장 조건을 분리한다."><ri:attachment ri:filename="p19_10_B.png"/></ac:image></p><p><em>왼쪽은 결과 보고, 가운데는 측정 대상 전체의 OK 판정이다. 정상 경로에서만 각도 저장으로 진행하고 NG 경로는 기존 각도를 유지한다. 보고 존재와 저장 완료를 같은 표시로 묶지 않는다.</em></p>
<h2>실패·취소 뒤의 끝 상태를 남긴다</h2><p>준비 실패, 측정 중 취소, 센서 오류, 목표 미달, 시도 소진, 저장 실패를 구분한다. 당시 목표/실제 W, ATT 각도, Head별 상태·시각·시도와 실패 원인을 보존한다.</p><p>종료 때는 출력 OFF, 측정 관련 신호, 남은 이동과 세션 해제 결과를 확인한다. 창이 닫히거나 취소가 반환된 사실만으로 정리가 끝났다고 표시하지 않는다. 정리 실패가 있으면 원래 실패와 함께 남기고 재실행 전에 준비 조건을 다시 확인한다.</p><h2>함께 읽기</h2><p><ac:link><ri:page ri:content-title="05.
