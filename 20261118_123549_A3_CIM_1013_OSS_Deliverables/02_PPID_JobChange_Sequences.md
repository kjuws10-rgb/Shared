# PPID 관리와 자동 Job Change 시퀀스

기준: 2026-11-18. 참고 PPT는 10/13 CIM Validation·Handshake 4장 보완본 하나이며, 현재 첨부 OSS·CIM V235와 대조했다. 사양 확인·설계 제안·협의를 구분한다. 구현·실통신·실장비 검증 완료 자료가 아니다.

데이터 생성/수정과 로드 허가·현재 PPID 변경, 전체 Job의 최종 준비 판정을 구분한다. 요청ID/Revision 같은 내부 식별은 제안이며 기존 필드를 재사용할 수 있는지 확인한다. 상위·CIM·PLC·가공 간 실제 연결과 각 전문의 응답 기한은 협의한다.

## SEQ-P01 PPID 생성/삭제 정상 및 거절

상태: 첨부 사양 + 내부 원자처리 설계

| 순서 | 담당/방향 | 처리 | 성공 조건 | 응답·근거 |
| --- | --- | --- | --- | --- |
| 1 | Host→CIM | S7F21 MODE/Module/PPID/TYPE/본문 수신 | 대상 endpoint/TYPE를 확인 | 별도 접수응답을 만들더라도 F22로 조기 성공회신하지 않음 |
| 2 | 가공 SW/Recipe 소유자 | 전체 필수항목·형식·범위·존재/중복·운전중 변경허용상태 검증 | 요청 전체 수용 가능; 생성은 기존 PPID 없음, 삭제는 존재 |  |
| 3 | Recipe 소유자 | 동일 요청 snapshot을 일괄 생성/삭제 및 영속화 | 부분 본문이 활성/조회 결과에 노출되지 않음 |  |
| 4 | CIM→Host | 완전 처리 또는 거절 후 S7F22 응답 | 사양 ACKC7 의미와 실제 처리결과 일치 |  |
| 5 | CIM→Host | 변경된 전체 본문/상태를 S7F107 보고 | F108은 보고 이해응답 | F22와 F107 사이 상세 송신순서는 별도 합의; F108을 RMS승인으로 사용하지 않음 |

| 실패 조건 | 필요한 결과 |
| --- | --- |
| 필드 하나 이상 오류/미등록 Module/중복생성/없는대상삭제 | 전체 요청 거절·부분변경 금지·사양 오류코드 응답 |
| 영속화/중계 적용 실패 | 성공 F22 금지; 실제상태 보존·복구/정확한 오류코드는 합의 |

근거: CIM Message V235 p137-138,145

## SEQ-P02 PPID 수정·조회·로컬변경 상위동기

상태: 첨부 사양 + 개정동결 설계

| 순서 | 담당/방향 | 처리 | 성공 조건 | 응답·근거 |
| --- | --- | --- | --- | --- |
| 1 | Host→CIM→가공 SW | S7F23 수정 요청 또는 로컬 편집 후보 생성 | 기존 편집본·검증본·현재적용본 구별 |  |
| 2 | 가공 SW | 전체 요청을 검증하고 사용중/경쟁수정 상태를 검사 | 한 항목이라도 불가하면 전체 거절 |  |
| 3 | 가공 SW | 허용된 동일 개정 전체본문을 일괄 commit | 부분저장·동일본문 이중적용 방지 |  |
| 4 | CIM | 원격 요청은 S7F24 처리결과, 변경은 S7F107 전체본문 보고 | 모든 파라미터가 같은 snapshot | S7F108 수신실패/재시도 정책은 별도 |
| 5 | Host↔CIM | S7F25/26 본문, S7F101/102 목록, S7F103/104 존재, S7F109/110 Running 조회 | 각 질의가 요청한 역할에 맞는 snapshot 반환 | 목록/존재/Running은 본문승인/전체 JobChange완료의 대용 아님 |

| 실패 조건 | 필요한 결과 |
| --- | --- |
| 사용 중 PPID/길이·범위·대상 오류 | F24 사양오류·부분적용 금지 |
| 보고 실패/통신재연결 | 동일 개정·결과를 보존하여 협의된 재동기화; 오래된 snapshot을 최신으로 덮지 않음 |

근거: CIM Message V235 p138-139,144-146

## SEQ-J01 사전 Validation 후 자동 JobChange 정상

상태: 주 PPT 10/13 기준 설계안·구체주소 미확정

| 순서 | 담당/방향 | 처리 | 성공 조건 | 응답·근거 |
| --- | --- | --- | --- | --- |
| 1 | CIM/물류→가공 SW | 요청/기판·모델·PPID 대상 식별과 후보본문 고정 | 관련 Section/핀조건 참조 존재 | 접수 ACK는 처리예정만 의미 |
| 2 | 가공 SW | 로컬 본문·좌표·단위·범위·모델/핀매핑 검사 | 오류 없음; 승인요청 대상이 명확 |  |
| 3 | 가공 SW→CIM→상위 | 업무 Validation 요청과 PASS 대기 | 요청ID·모델·본문식별이 같은 PASS | 실제전문/주소/Timeout 미정; F108/존재ACK를 PASS로 사용하지 않음 |
| 4 | 가공 SW | 기존 기판·운전종료/안전조건 확인 후 승인된 조건의 실제 전환 | tV 성립; 승인 후 본문이 바뀌지 않음 |  |
| 5 | 가공 SW/광학계 | Recipe 적용, DOE Z 실제도착·파워/윈도우 필요동작·유효성 확인 | 합의된 광학계 준비조건 정상 | 모델변경만으로 윈도우교체를 강제하지 않음 |
| 6 | 가공 SW→각 Section | 동일 요청·개정으로 조건 게시; 물류/PLC/비전별 수신과 실제적용 확인 | 각 Section Applied조건이 후보와 동일 | 10/13 기준안은 PinReady 확인 후 기판 수신. 실제 허가신호·안전조건은 협의 필요. |
| 7 | 물류/PLC/비전 | 핀 실제값/센서와 비전조건, 기판/대상 일치 확인 | 주PPT안에서 수신/검사 허가조건 충족 |  |
| 8 | 가공 SW/비전 | 합의된 전셀검사 대상의 결과와 누락/NG 검증 후 보정 계산·저장·재조회·좌표갱신 | 같은 모델/개정·모든필수결과·보정범위/비누적 확인 |  |
| 9 | 가공 SW→CIM→상위 | 최종조건 일치 시 결과보고·합의된 양산허가 | 승인=실제적용·직전파워/핀/비전/검사/보정/좌표 버전 일치 | 로드허가/Recipe저장ACK/가공SW준비완료/전체완료를 각각 구별 |

| 실패 조건 | 필요한 결과 |
| --- | --- |
| 동작전 FAIL·Timeout·통신단절·대상불일치 | tV 미성립; 새 조건 실제 적용 금지·원인응답 |
| 동작중 Section NG/핀미도착/광학NG/측정누락·NG/보정실패 | 최종완료·양산허가 보류, 단계/실제적용/기판상태 기록. 재이동·재측정·롤백은 별도 복구정책 |
| 승인후 Recipe 수정·개정변경 | 이전 PASS로 새본문 실행 금지; 후보 재검사·재승인 |

근거: 주 PPT 10/13 p1-4

## SEQ-J02 지연·중복·취소·재시작 실패 시퀀스

상태: 설계안·복구정책 협의 필요

| 순서 | 담당/방향 | 처리 | 성공 조건 | 응답·근거 |
| --- | --- | --- | --- | --- |
| 1 | 가공 SW | 요청ID/대상/개정과 마지막실행 단계로 수신응답을 분류 | 이번요청에 속하는 응답만 인정 |  |
| 2 | 가공 SW | 이전요청/다른개정 PASS·ACK·Done을 기록하고 이번 합류에서 제외 | 해당요청 완료를 잘못 생성하지 않음 |  |
| 3 | 가공 SW/각 Section | 통신단절·Cancel·재시작 시 실제 적용본·기판·진행단계 수집 | 상태 불명확하면 최종완료/양산허가 보류 |  |
| 4 | 정의된 복구주체 | 실제상태와 안전허용 범위로 재검증·이어하기·중단·원복 중 정책선택 | 정책 승인과 요청/개정 추적이 가능 | 전원재투입으로 자동재가공/자동축이동을 발명하지 않음 |

| 실패 조건 | 필요한 결과 |
| --- | --- |
| 중복 요청 재수신 | 동일논리요청을 이중변경·이중보정·이중최종완료로 실행하지 않도록 결과재사용 범위 협의 |
| 물리상태/영속상태/상위기록 불일치 | 자동 PASS 금지·불일치명시·복구권한/절차 적용 |

근거: 주 PPT 10/13 p1-4
