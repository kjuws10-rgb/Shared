# 04. 갱신된 통합 흐름도

이 문서는 세부 코드를 읽지 않아도 데이터가 어디서 생기고, 어디서 걸러지고, 어디에 저장되는지 한눈에 볼 수 있도록 만든 그림 모음입니다.

## 1. 전체 프로그램 데이터 흐름

```mermaid
flowchart TB
    subgraph Definition[1. 정의와 설정]
        JR[JHMI_RCP.csv<br/>Recipe 입력 형식]
        JS[Setting.csv<br/>Head/축/Flip]
        JI[JHMI_INTERFACE.csv<br/>통신/Simulation]
        JM[JHMI_MELSEC_MAP.csv<br/>PLC 신호 주소]
    end

    subgraph Recipe[2. 제품 Recipe]
        RC[Recipe CSV]
        CELL[Cell 위치·회전·Model]
        MODEL[Model별 Pixel/Pitch/Chess]
        MASK[Hole/Corner Mask]
        HEAD[Laser/Ramp/Offset]
    end

    subgraph Plan[3. 좌표 계획]
        SG[Cell Shot Group]
        BEAM[DOE Beam 좌표]
        FILTER[Chess + Masking]
        ASSIGN[Head 배정]
        TRANS[Scanner 좌표 변환]
    end

    subgraph Process[4. 가공]
        SCRIPT[Automation1 Script]
        COORD[Coordinate CSV/Text]
        LASER[Scanner 이동 + Laser]
    end

    subgraph Review[5. Review]
        RULE[Review Rule / Sampling]
        RPLAN[Review Plan]
        MOVE[Stage Y / Vision X 이동]
        VISION[Vision 측정]
        RESULT[ReviewResult CSV]
        CORR[Correction Plan]
    end

    subgraph Product[6. 제품 이력]
        PROD[Product / Glass 상태]
    end

    JR --> RC
    RC --> CELL
    RC --> MODEL
    RC --> MASK
    RC --> HEAD
    CELL --> SG
    MODEL --> SG
    SG --> BEAM
    MODEL --> FILTER
    MASK --> FILTER
    BEAM --> FILTER
    JS --> ASSIGN
    FILTER --> ASSIGN
    ASSIGN --> TRANS
    JS --> TRANS
    TRANS --> SCRIPT
    TRANS --> COORD
    SCRIPT --> LASER
    FILTER --> RPLAN
    RULE --> RPLAN
    RPLAN --> MOVE
    JI --> VISION
    JM --> MOVE
    MOVE --> VISION
    VISION --> RESULT
    RESULT --> CORR
    CORR -->|Shot별 REVIEW_OFFSET 저장| RC
    PROD --> SCRIPT
    SCRIPT --> PROD
    RESULT --> PROD
```

현재 `MOVE`는 명령 문자열만 만들고 MELSEC로 보내지 않으며, Station의 자동 Review 단계도 예약 로그만 남깁니다. 그림은 의도된 연결까지 포함하지만 이 두 화살표는 아직 완성된 실장비 동작이 아닙니다.

## 2. JHMI 기본값과 Recipe 실제값 합치기

```mermaid
flowchart LR
    A[JHMI Form Item<br/>이름·기본값·범위] --> C{Recipe CSV에<br/>같은 TAB+NAME?}
    B[Recipe CSV 행] --> C
    C -->|있음| D[Recipe 값 선택]
    C -->|없음| E[JHMI 기본값 선택]
    D --> F[ST_RECIPE_PARAMETER]
    E --> F
    G[Cell/Shot 반복 항목] --> H[Scoped Parameter 추가]
    H --> F
    F --> I[Parameter Map]
```

중요한 예외는 외부 도구가 JHMI 병합 없이 Parameter Map을 직접 만드는 경우입니다. 이때 새 Model별 키가 없으면 Reader 자체 기본값을 사용합니다.

## 4. Shot과 Beam이 걸러지는 순서

```mermaid
flowchart TD
    A[Cell Shot Group 생성] --> B{Chess 조건 통과?}
    B -->|아니오| X[완전 제외<br/>Script/CSV 행 없음]
    B -->|예| C[DOE Beam 좌표 확장]
    C --> D{Hole과 겹침?}
    D -->|예| OFF1[미가공<br/>이동은 함, Laser OFF]
    D -->|아니오| E{Corner 직사각형과 겹침?}
    E -->|예| OFF2[미가공<br/>이동은 함, Laser OFF]
    E -->|아니오| ON[가공<br/>Laser ON]
    OFF1 --> H[Head 배정]
    OFF2 --> H
    ON --> H
```

`가공여부` 열은 이 마지막 ON/OFF를 나타냅니다. Chess에서 빠진 그룹은 `미가공` 행으로도 남지 않습니다.

## 5. Glass 좌표에서 Scanner 좌표로 바꾸기

```mermaid
flowchart LR
    A[Cell Design 좌표] --> B[AK Margin / Cell 배치]
    B --> C[Shot별 Review Offset]
    C --> D[Glass 좌표]
    D --> E[Head 작업 범위와 Head Gap]
    E --> F[Head Local 좌표]
    F --> G{XY Swap}
    G -->|ON| H[X와 Y 교환]
    G -->|OFF| I[교환 없음]
    H --> J[X Flip / Y Flip]
    I --> J
    J --> K[Scanner 명령 X/Y]
    K --> L[Encoder 축 선택]
    L --> M[Scale·Feedback Flip]
    M --> N[AuxiliaryFeedback wait 값]
```

이번 Commit에서 H01의 `XY Swap`, X/Y Flip, Encoder 축이 모두 바뀌어 목표 좌표가 서로 바뀐 형태로 출력됐습니다.

## 6. 활성 Head가 H01에 미치는 전역 영향

```mermaid
flowchart TB
    H1[H01 활성] --> A[활성 Head 전체 범위 계산]
    H2[H02~H08 활성 여부] --> A
    GAP[HeadGapY=380] --> A
    DELAY[SCAN_START_DELAY_LENGTH_Y] --> B[전역 Scan 시작 기준]
    A --> B
    B --> C[H01 Local Scan 좌표]
    C --> D[H01 Scanner 변환]
```

따라서 H02~H08을 켜는 것은 H01과 독립적인 설정이 아닙니다. 회귀 시험도 Head 단독/전체 두 조건으로 나눠야 합니다.

## 8. Review Plan과 측정 결과

```mermaid
sequenceDiagram
    participant R as Recipe/좌표 Builder
    participant P as Review Plan
    participant M as Stage/Vision Move
    participant V as Vision
    participant F as ReviewResult File
    participant C as Correction

    R->>P: 가공 후보 좌표·Masking·Head 전달
    P->>P: Review Rule + Sampling 적용
    P->>M: Target X/Y 요청
    Note over M: 현재 MELSEC 전송 TODO
    M->>V: Mark Find 요청
    alt Simulation=1
        V-->>P: 임시 측정값
    else 실제 모드
        V-->>P: Vision 응답 파싱값
    end
    P->>F: 목표/측정/오차/판정 저장
    F->>C: Result 불러오기
    C->>C: CorrectionPlan으로 Offset 계산
```

## 9. Correction Offset의 되먹임

```mermaid
flowchart LR
    A[ReviewResult] --> B[ShotKey 기준 매칭]
    B --> C[Correction 후보]
    C --> D[Apply Preview]
    D --> E{사용자 Save?}
    E -->|아니오| F[Recipe 변경 없음]
    E -->|예| G[CELLnnn_SHOTnnnn_REVIEW_OFFSET_X/Y]
    G --> H[Recipe CSV 저장]
    H --> I[다음 Process/Review 좌표]
```

이번 변경으로 메모리에서 즉시 Review Offset을 적용하는 API는 제거되고, 저장 가능한 Correction 경로가 더 분명해졌습니다.

## 10. Product/Glass 상태 연결

```mermaid
stateDiagram-v2
    [*] --> Prepared: Recipe + Glass 준비
    Prepared --> Processing: Process 시작
    Processing --> Completed: Script/공정 완료
    Processing --> ReviewTracked: Review 진행 기록
    ReviewTracked --> Completed: Review 완료 처리
    Processing --> Error: 예외/중단
```

Product 저장 로직 자체는 이번 Commit에서 바뀌지 않았습니다. 좌표 출력의 식별 열만 `ProductId`에서 `GlassId`로 정리됐습니다.

## 11. MELSEC Monitor의 현재 수준

```mermaid
flowchart LR
    A[JHMI_MELSEC_MAP<br/>29개 Placeholder] --> B[Polling<br/>최대 32개]
    B --> C[DoReady/Process/Review/<br/>Move/IOF/Power 화면]
    C --> D[현재 값 표시]
    C -.-> E[실제 시퀀스 상태 머신]
    E -.-> F[Timeout/순서/Interlock]
```

점선 부분은 아직 구현된 것으로 확인되지 않았습니다. Monitor의 상태 문자열도 현재 `WAIT` 고정값입니다.
