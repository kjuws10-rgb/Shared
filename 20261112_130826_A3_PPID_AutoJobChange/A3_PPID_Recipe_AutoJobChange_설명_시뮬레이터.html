01 · 시작하기

처음에는 연결하고, 양산에서는 자동으로 전환합니다

기존 Recipe 편집 기능은 유지하고, 그 안에 PPID 연결·전환 조건·진행 상태를 추가하는 구성입니다. 사용자는 매번 가공 조건을 다시 입력하는 대신, 어떤 상위 식별값에 어떤 가공·리뷰 레시피를 사용할지 미리 연결합니다.

  1. PPID와 레시피 연결왼쪽 연결 목록을 고르고 가공·리뷰 레시피를 지정한 뒤 연결표 저장을 누릅니다.
  2. 전환 전에 확인저장된 연결 시험으로 매칭을 확인하고, 레시피 내용에서 조건과 개정을 살펴봅니다.
  3. Job Change 시험Auto Job Change 탭에서 상황을 선택하고 가상 요청 보내기를 눌러 진행·대기·실패를 확인합니다.
이 파일의 저장은 가상 저장입니다. 연결표와 레시피 개정은 이 페이지를 열어둔 동안만 유지됩니다. 새로고침하거나 다시 열면 초기 예시로 돌아갑니다. 실제 프로젝트·Recipe CSV·PLC·Vision·설비 상태는 변경하지 않습니다.

Host PPID + Sub PPID 조합은 화면을 설명하기 위한 가정입니다. SDC 해당 설비의 공식 필드·주소·단독/조합키·응답 순서는 사양 확정 후 맞춰야 합니다. 예시 PPID·속도·개정·모델 프로파일은 실제 생산 조건이 아닙니다.

현재 적용값과 편집값을 구분하는 레시피 작업 화면

    04 · 화면별 역할

    자주 쓰는 작업은 한곳에서, 상세 조건은 필요할 때 엽니다

    화면보여줄 정보사용자의 작업동작 원칙
    레시피 · PPID 연결Host/Sub PPID, 가공·리뷰 레시피와 개정, 사용 여부연결 추가·수정·저장·연결 시험동일한 활성 키의 중복을 막고, 목록 선택만으로 실제 가공 레시피를 바꾸지 않음
    레시피 내용가공 조건·Masking·리뷰 샘플링 예시조건 편집 후 새 개정으로 저장기존 개정을 보존하고, 연결표 저장과 실제 적용을 따로 진행
    Auto Job Change요청·대상·8단계 진행·대기 이유·실패 단계가상 요청·대기 해제·취소·보고 재확인·복구 시험가공 중 대기, 유효성 NG 차단, 부분 적용 시 운전 금지
    현재와 비교현재 구현과 제안, 검사 항목, 고정 소스 링크현재 지원 범위와 추가 개발 범위 검토설명·제안·실제 구현 사실을 섞지 않음
    변경이력연결표·레시피 개정·요청·실패·복구 기록어떤 값으로 무엇이 바뀌었는지 확인편집/저장/실적용/보고를 구분해 기록

    기존 UI의 좌측 Recipe 목록과 VIEW·SELECT·SAVE는 유지할 수 있습니다. 다만 미래 연결을 편집하려고 현재 가공 Recipe를 SELECT해야 하는 구조는 바꾸는 것이 좋습니다. 편집 대상 선택과 운전 대상 전환을 분리하면 자동화 요청을 준비하면서도 현재 작업을 유지할 수 있습니다.

    05 · Auto Job Change 동작

    파일을 읽는 것부터 전체 전환 완료까지 단계별로 확인합니다

    1. 1요청 수신요청 ID와 받은 원문 보관
    2. 2연결 확인사용 가능한 연결 1건 확인
    3. 3Recipe 유효성가공·리뷰와 승인 응답 확인
    4. 4안전조건 확인가공 종료·기판·축·통신·Shift
    5. 5후보 데이터 준비좌표·Masking·Review·MOF 준비
    6. 6적용 일치 확인LD·PLC·Vision 대상값 대조
    7. 7부대 동작 확인와이퍼·핀·파워보정 등 완료
    8. 8결과 보고실제 선택값과 성공·실패 보고

    이 순서는 기능과 완료 경계를 설명하는 설계안입니다. 실제 장비별 적용 순서는 별도 합의가 필요하며, 특히 기판을 받기 전에 끝나야 하는 핀·와이퍼 준비는 실제 운전 시퀀스의 선행 조건으로 연결해야 합니다. 가공 SW의 준비 완료만 보고 PLC·Stage·Vision의 준비까지 끝났다고 처리하면 안 됩니다.

    상황화면 상태동작·복구 방향
    가공 중 새 요청가공 종료 대기현재 가공 조건을 유지하고 종료·안전조건 확인 후 진행
    미등록/미사용/중복 연결·유효성 NG전환 실패임의의 다른 레시피로 대체하지 않고 명확한 실패 사유 보고
    후보 데이터 준비 실패적용 전 실패준비한 후보를 폐기하고 기존 적용값 유지
    LD만 바뀌고 PLC·Vision 실패적용 불일치 · 운전 금지각 제어부 실제 상태를 확인하고 복구·일치 검증 후 재개
    적용 후 파워보정 실패적용 후 실패 · 운전 금지레시피 적용 성공과 공정 준비 실패를 구분해 복구
    전환은 끝났으나 보고 응답 없음적용 완료 · 보고 확인 대기이미 적용한 레시피를 다시 적용하지 않고 보고만 재확인
    같은 요청 ID 재수신과거 결과 재조회 또는 요청 충돌내용이 같으면 이전 결과를 돌려주고, 다르면 전환 차단
    기존 회의 기준 반영: Job Change 단독은 파워보정으로 구분합니다. 보호윈도우 교체는 사용매수·ATT 조건으로 별도 판단하며, Job Change를 단독 교체 사유로 다시 추가하지 않습니다.
    06 · 저장과 적용 범위

    연결표·레시피·장비 설정을 구분해 관리합니다

    대상관리 방법 제안Job Change에서 확인할 내용
    PPID ↔ 레시피 연결전체 연결표와 개정으로 관리받은 키에 맞는 유효한 연결이 정확히 1건인지
    가공·리뷰 조건함께 사용할 레시피·개정을 묶음으로 지정가공과 리뷰가 서로 다른 모델/개정으로 섞이지 않는지
    Default 등 장비 교정값현재 Recipe 저장 항목과 장비 공통 항목을 분류한 뒤 Setting 분리 여부 검토기존 파일 이관·값 일치·제품별 예외를 확인하고 임의 초기화하지 않음
    모델별 와이퍼·핀·Vision모델 프로파일을 연결하고 제어 책임을 구분목표값을 전달했다는 사실과 실제 도착·적용 완료를 구분
    평가용 Shift원수신/현재값·유효성·전환 정책을 구분확인된0/비0/미확인을 구분하고 승인된 정책만 적용

    요청을 처리할 때는 요청 ID·원문 PPID·연결표 개정·가공/리뷰 개정·관련 Setting·Shift 정책을 한 묶음으로 고정합니다. 전환을 기다리는 사이 연결표를 편집하더라도 이미 받은 요청이 다른 조건으로 바뀌지 않아야 합니다.

    Shift가 확인된 0이면 통과합니다. 비0이면 유지 확인을 받고, 양산 정책을 선택한 경우에는 초기화 결과를 확인한 뒤 진행하도록 합니다. 미수신 상태의 초기 표시값 0은 확인된 0으로 취급하지 않습니다. 원수신값과 적용 후 값도 따로 남깁니다.

    07 · 검증 방안

    화면 시험과 실제 설비 검증을 나누어 진행합니다

    검증 항목시험 방법확인 기준
    정상 매칭같은 Host에 서로 다른 Sub 2개 입력각각 의도한 가공·리뷰 레시피와 개정이 선택됨
    중복·미등록·미사용동일 활성 키 추가, 없는 값/미사용 값으로 요청중복 저장·임의 대체 없이 원인 표시
    미저장 내용 보호조건을 수정하고 닫기·다른 연결·다른 Recipe 선택저장/버림/계속편집을 구분하고 다른 대상에 잘못 저장하지 않음
    개정·현재값 분리새 개정과 연결표 저장 후 상단 확인현재 적용값은 유지되고 다음 요청에서 저장 개정 사용
    대기 중 편집가공 중 요청 대기 상태에서 연결표 변경기존 요청은 수신 시 고정된 연결·개정으로 처리
    적용 전/후 실패유효성·준비·부분 적용·파워보정 NG 주입이전 유지와 운전 금지·복구 대기를 정확히 구분
    보고 실패·재요청전환 후 응답 누락, 동일/상이 내용의 같은 요청 ID재적용 없이 보고 재확인·과거 결과 조회·충돌 차단
    Shift확인0·비0·미수신0·양산 초기화 옵션 조합미확인 값은 통과하지 않고 수신값/적용값을 별도 기록
    실제 I/F최종 SDC 맵·문자열 규칙·실제 송수신값 대조주소·길이·의미·유효성·완료 보고 계약 일치
    실제 연동과 재기동LD·PLC·Stage·Vision 및 통신 단절/중간 재기동 평가실제 적용 상태·기판 수신 조건·복원·Ready 허용이 일치

    이 HTML의 성공은 가상 UI 동작 성공입니다. 실제 장치의 이동·파워·간섭·가공 정밀도·인터락 또는 SDC 정식 I/F 검증을 대신하지 않습니다.

    08 · 개발 진행 순서

    사양을 맞춘 뒤, 같은 전환 경로로 수동과 자동을 연결합니다

    5. 예외·복구·재기동 평가부분 적용, 보고 누락, 중복·충돌, 취소, 대기 중 새 요청, 통신 재연결 및 중간 재기동을 평가합니다.
