1. Pitch 개념 — 무엇이 바뀌었는가

Pitch는 현재 DOE 중심 명령좌표에서 다음 DOE 중심 명령좌표까지 건너뛰는 원본 Pixel 개수입니다. DOE가 한 번의 출사로 만드는 16개 Hole 사이의 내부 간격이 아닙니다.

이전의 잘못된 해석

0.09 mm/px × 10 px × 4 = 3.6 mm

DOE 축당 4분기를 명령좌표 간격에 다시 곱하는 방식입니다. 중심 간격과 내부 Branch 배열을 혼합합니다.

정정된 해석

Δcommand = PixelSize × Pitch = 0.09 × 10 = 0.9 mm

DOE 4×4는 각 중심좌표에서 동시에 생성되는 내부 Pattern이며, 별도 Branch Offset으로 관리합니다.

Hole(k, b) = CommandCenter(k) + DOE_BranchOffset(b),   b = B01 … B16
첨부 DOE 그림도 “가공좌표는 DOE의 중심 위치”라고 명시합니다. Review는 중심이 아니라 B06 또는 B11 같은 지정 Branch를 볼 수 있으므로, 측정값을 가공 중심 오차로 환산할 때는 해당 Branch Offset을 제거해야 합니다.

3.1 중심 격자

Δ = '레시피 조건'!C3 × C7 = 0.09 × 10 = 0.9 mm

현재 파일은 ix=0…13, iy=0…24를 사용합니다. 설계 X index가 GY(Review)에, 설계 Y index가 부호 반전되어 GX(Stage)에 반영됩니다.

3.2 Head 선택과 Local 좌표

Wfield = 110 mm · HalfField = 55 mm · Field(h) = [Wfield(h−1), Wfield·h)
h = floor(Xglobal / Wfield) + 1
FieldCenter(h) = HalfField + Wfield·(h−1)
GYh = Xglobal − FieldCenter(h),   −55 ≤ GYh < +55 mm
GXh = −{Yglobal + 120 + [h가 홀수이면 380, 짝수이면 0]}

Excel 셀 참조형으로 직접 쓰면 다음과 같습니다.

GYh = C28 + CELL_X + ix·Δ − Wfield·(h−1)
GXh = −{C21 + C26 + CELL_Y + iy·Δ + IF(ODD(h), C20, 0)}

Head 전수 대조는 Excel의 Head 또는 GY에서 Xglobal을 되만들어 확인한 것이 아닙니다. CellCol과 CommandGridIndexX만으로 Xglobal=100×(CellCol−1)+25.8375+0.9×CommandGridIndexX를 독립 재계산한 뒤 Head를 선택했으며, 16,742개 모두 Excel Head와 일치하고 GY 역산 Xglobal과의 차이도 0입니다.

5.1 Ground Truth 992개 연속 반복 좌표 레코드

좌표 생성 SW는 정답 탭의 992개 반복을 제거하지 않고 16,742개 Raw 레코드를 그대로 출력해야 합니다. 다만 모든 행을 Laser-On 가공점으로 처리하면 992개 중심이 이중 가공됩니다. DOE 16개 기준으로는 15,872회의 추가 Hole 노광, 총 267,872 Hole 노광 위험입니다 (공간 고유 중심 기준 명목 252,000 Hole 대비). 이 반복이 실행 시 Jump/Lead-in 역할이라면 CommandType과 LaserGate를 반드시 명시해야 합니다. “Lane 시작”은 위치·순서를 설명하는 분석상 분류이며, 실제 장비 명령 의미는 파일만으로 확정할 수 없습니다.

5.2 P0 보정 후 110 mm Field Guard

현재 좌표 중심만 보면 Field 이탈은 0개지만, H4 첫 중심의 여유가 0.3375 mm뿐이므로 보정과 DOE footprint를 합친 최종 좌표를 기준으로 검사해야 합니다.

명목 소유권: −55 ≤ GYcenter < +55 mm
사전 예산: |GYnominal| + CorrectionBudget + DOEmaxOffsetGY(rotated) + BeamRadius + MappingError < 55 mm
실행 판정: |GYcorrected| + DOEmaxOffsetGY(rotated) + BeamRadius + MappingError < 55 mm
Head를 먼저 고정하고 보정값을 나중에 더하면 H3/H4 경계에서 Field를 벗어날 수 있습니다. 처리 순서는 Global 중심 생성 → Cell Align·Global Process 보정 → 보정된 Global X와 보정된 Head Field map으로 Head 재선택 → Head별 설치/Default 변환과 왜곡 보정 → Local GY 변환 → Field Guard 검사여야 합니다. 경계 초과 좌표를 Clamp하면 실제 가공 위치가 바뀌므로 금지해야 합니다.

NX=floor(144/10)=14 → 0…130 px

Cell당 350, 전체 15,750개 공간 고유 중심입니다. 정답 Raw 출력은 반복 패턴을 포함한 16,742개입니다.

5.4 P0 무라벨 C26과 DOE 숨은 결합 가능성

C26=0.3375 mm는 GY와 GX 원점에 모두 사용되지만 라벨과 수식이 없습니다.

0.3375 = (0.09 × 10 / 4) × (4−1) / 2

수치상으로는 “0.9 mm 구간을 4개 Branch로 균등 분할했을 때 중심에서 최외곽 Branch까지의 반폭”과 정확히 같습니다. 이 경우 Branch pitch는 0.225 mm, 축 Offset은 −0.3375, −0.1125, +0.1125, +0.3375 mm가 됩니다.

그러나 Excel에는 C26 라벨, DOE Branch pitch, 회전, B06/B11 Offset이 없으므로 숫자가 일치한다는 가설일 뿐 확정할 수 없습니다. 사용자가 정정한 사양대로라면 DOE 내부 Offset은 Pitch와 분리된 독립 광학/Calibration 데이터여야 합니다. 따라서 C26의 생성 근거를 확인하고, DOE 관련값이라면 DOE_CENTER_TO_BRANCH_X/Y 또는 Branch별 Offset Table로 명시해야 합니다. 특히 C26이 실제 DOE 최외곽 반폭 0.3375 mm라면 H4의 최외곽 Branch 중심은 명목 −55 mm 경계에 정확히 닿고, Beam radius나 추가 보정까지 포함하면 Field 밖으로 나갈 수 있습니다.

// 2) Cell 내 DOE 중심 명령좌표와 Global 보정

                     abs(Rotate(doePattern.Angle, branch.OffsetXY).Y));

        < scanFieldHalfMm);

// 5) DOE 실제 Hole — 별도 Calibration 데이터
for each branch in doePattern.Branches:
    physicalHole = localCenter + Rotate(doePattern.Angle, branch.OffsetXY);

// 6) Review 기준점
reviewTarget = localCenter + doePattern[reviewBranchId].OffsetXY;
