1. Pitch 개념 — 무엇이 바뀌었는가

Pitch는 현재 DOE 중심 명령좌표에서 다음 DOE 중심 명령좌표까지 건너뛰는 원본 Pixel 개수입니다. DOE가 한 번의 출사로 만드는 16개 Hole 사이의 내부 간격이 아닙니다.

이전의 잘못된 해석

0.09 mm/px × 10 px × 4 = 3.6 mm

DOE 축당 4분기를 명령좌표 간격에 다시 곱하는 방식입니다. 중심 간격과 내부 Branch 배열을 혼합합니다.

정정된 해석

Δcommand = PixelSize × Pitch = 0.09 × 10 = 0.9 mm

DOE 4×4는 각 중심좌표에서 동시에 생성되는 내부 Pattern이며, 별도 Branch Offset으로 관리합니다.

Hole(k, b) = CommandCenter(k) + DOE_BranchOffset(b),   b = B01 … B16
첨부 DOE 그림도 “가공좌표는 DOE의 중심 위치”라고 명시합니다. Review는 중심이 아니라 B06 또는 B11 같은 지정 Branch를 볼 수 있으므로, 측정값을 가공 중심 오차로 환산할 때는 해당 Branch Offset을 제거해야 합니다.

3.1 중심 격자

Δ = '레시피 조건'!C3 × C7 = 0.09 × 10 = 0.9 mm
Xglobal = CELL_X + C25 + C26 + ix·Δ = CELL_X + 25.8375 + 0.9·ix
Yglobal = CELL_Y + C26 + iy·Δ = CELL_Y + 0.3375 + 0.9·iy

현재 파일은 ix=0…13, iy=0…24를 사용합니다. 설계 X index가 GY(Review)에, 설계 Y index가 부호 반전되어 GX(Stage)에 반영됩니다.

3.2 Head 선택과 Local 좌표

h = floor(Xglobal / 110) + 1
HeadCenter(h) = 55 + 110·(h−1)
GYh = Xglobal − HeadCenter(h)
GXh = −{Yglobal + 120 + [h가 홀수이면 380, 짝수이면 0]}

Excel 셀 참조형으로 직접 쓰면 다음과 같습니다.

GYh = C28 + CELL_X + ix·Δ − 110·(h−1)
GXh = −{C21 + C26 + CELL_Y + iy·Δ + IF(ODD(h), C20, 0)}

3.3 Cell 1 첫 좌표 대조

① Global X

0 + 25.5 + 0.3375 = 25.8375

Head 1 Center 55 mm를 빼면 GY1 = −29.1625 mm

② Global Y

0 + 0.3375 = 0.3375

홀수 Head이므로 120+380을 더한 후 반전: GX1 = −500.3375 mm

③ Excel 일치

(−29.1625, −500.3375)로 정확히 일치합니다.

첨부 스캐너 좌표계 그림에는 “부호, 축이름 확인 필요”라고 적혀 있습니다. 따라서 위 식은 현재 Excel을 재현하는 식이지, 장비 실축 부호 검증까지 완료된 확정 사양은 아닙니다.

5. 파일에서 확인된 결함 후보와 미정 사양

5.1 P0 992개 연속 중복 좌표

각 Head는 125개 Stage Lane(5 Cell rows × 25 Y index)을 갖습니다. 첫 Lane을 제외한 124개 Lane에서 첫 좌표가 정확히 두 번 연속 기록됩니다.

예시GY1GX1판정
A19:B19−29.1625−501.2375완전 동일
A20:B20−29.1625−501.2375
모든 행을 Laser-On 가공점으로 처리하면 992개 중심이 이중 가공됩니다. DOE 16개 기준으로는 15,872회의 추가 Hole 노광, 총 267,872 Hole 노광 위험입니다 (고유 결과 252,000 Hole 대비). Lane 시작 Jump/Lead-in 좌표라면 CommandType과 LaserGate를 반드시 명시해야 합니다.

5.2 P0 끝점 생성 정책

현재 파일: 정수 나눗셈 횟수

NX=floor(144/10)=14 → 0…130 px
NY=floor(256/10)=25 → 0…240 px

Cell당 350, 전체 15,750 중심입니다.

유효 Index < PixelNum 정책

NX=floor((144−1)/10)+1=15 → 0…140 px
NY=floor((256−1)/10)+1=26 → 0…250 px

Cell당 390, 전체 17,550 중심입니다.

두 정책의 차이는 1,800개 중심, DOE 기준 28,800개 Hole입니다. 잔여 Pixel 구간을 의도적으로 폐기하는지, 범위 안 마지막 좌표까지 포함하는지 사양으로 확정해야 합니다.

5.3 P0 무라벨 C26과 DOE 숨은 결합 가능성

C26=0.3375 mm는 GY와 GX 원점에 모두 사용되지만 라벨과 수식이 없습니다.

0.3375 = (0.09 × 10 / 4) × (4−1) / 2

수치상으로는 “0.9 mm 구간을 4개 Branch로 균등 분할했을 때 중심에서 최외곽 Branch까지의 반폭”과 정확히 같습니다. 이 경우 Branch pitch는 0.225 mm, 축 Offset은 −0.3375, −0.1125, +0.1125, +0.3375 mm가 됩니다.

그러나 Excel에는 C26 라벨, DOE Branch pitch, 회전, B06/B11 Offset이 없으므로 숫자가 일치한다는 가설일 뿐 확정할 수 없습니다. 사용자가 정정한 사양대로라면 DOE 내부 Offset은 Pitch와 분리된 독립 광학/Calibration 데이터여야 합니다. 따라서 C26의 생성 근거를 확인하고, DOE 관련값이라면 DOE_CENTER_TO_BRANCH_X/Y 또는 Branch별 Offset Table로 명시해야 합니다.

7.1 계산 계층을 분리해야 합니다

// 2) Cell 내 DOE 중심 명령좌표

// 3) Head 선택 및 Scanner Local 변환

// 4) DOE 실제 Hole — 별도 Calibration 데이터
for each branch in doePattern.Branches:
    physicalHole = localCenter + Rotate(doePattern.Angle, branch.OffsetXY);

// 5) Review 기준점
reviewTarget = localCenter + doePattern[reviewBranchId].OffsetXY;
