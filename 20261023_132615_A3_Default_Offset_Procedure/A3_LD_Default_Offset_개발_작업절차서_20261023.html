01

무엇을 맞추고, 언제 완료하나요?

Default Offset은 스캐너가 명령한 기준점과 실제로 가공되는 위치 사이의 기본 어긋남을 맞추는 셋업입니다.

목적

Head마다 기준 자리를 정합니다

기판 중심을 기준으로 각 Head가 있어야 할 설계 위치를 정하고, 시험 마크의 실제 위치와 맞춥니다.

진행 순서

최초 가공평가 전에 먼저 합니다

4·5번 Head의 X/Y 기준을 먼저 검증한 뒤 나머지 Head를 연결합니다. 그다음 제품 가공 결과로 Simple·Rough·Fine 보정을 진행합니다.

완료 결과

새 가공 결과로 검증한 값

Head별 Default 값, 공통 기준, 적용 Revision, 새 시험 마크의 검증 결과를 하나의 셋업 이력으로 남깁니다.

작업 완료의 의미

추천값을 화면에 표시한 상태나 장치에 쓴 상태만으로 완료하지 않습니다. 적용 후 새로 만든 마크가 정해진 X/Y 허용 범위와 반복성 기준을 만족해야 완료입니다.

구분이 절차에서 다루는 범위
Default OffsetHead의 기준 위치를 맞추는 설치·셋업 보정. 회전·배율·렌즈 왜곡까지 한 번에 해결한다고 판단하지 않습니다.
제품 Review 보정Default 검증 후 Simple 또는 Rough로 1차 보정 → 새 가공·Review → Fine → 업데이트 후 검증으로 연결합니다.
재실행 시점매 기판마다 자동으로 다시 맞추는 기능으로 정의하지 않습니다. 최초 셋업, 관련 광학계·기준 변경 후 재검증, 주기와 허용 기준은 장비 운영 기준으로 정합니다.
이 문서의 성격사용자가 정한 작업 방향과 기존 회의 내용을 토대로 작성한 개발·작업 절차안입니다. 제안 화면·내부 데이터 이름은 실제 구현 완료를 뜻하지 않습니다.
02

기판 중심과 Head 원점은 서로 다른 점입니다

4·5번 스캐너를 중앙에 맞춘다는 뜻은, 두 Head의 설계 배치를 기판 중심에 맞춘다는 의미입니다.

이름쉽게 이해하기프로그램에서 반드시 구분할 것
기판 중심 C_ref모든 Head 목표를 놓을 공통 기준점Align·Teaching 등 어떤 근거로 얻었는지, 좌표계·기판 자세·기준 Revision.
Head 목표 원점 T_h설계상 그 Head의 원점이 있어야 할 자리기판 중심 + 같은 좌표계로 변환한 Head별 설계 배치 d_h.
실측 가상 원점 O_h마크를 측정해 역으로 구한 실제 Head 원점실제 마크 위치에서 알려진 테스트 명령·분기빔 변위를 뺀 위치.
실제 가공 마크 M_hkReview에서 실제로 찾은 십자·홀 등Head·마크·Branch ID와 촬영 당시 적용값. 가운데 홀이 없을 수도 있습니다.
중심은 계산으로 정할 수 있습니다

별도의 중심 표시가 반드시 필요한 것은 아닙니다. 다만 어떤 기준점·설계 관계로 중심을 구했는지 추적할 수 있어야 합니다. 좌우 기준 마크가 비대칭이면 단순 중간값을 쓰지 않습니다.

개발자 계산식 · Head 목표 위치
T_h = C_ref + d_h

d_h는 이미 공통 좌표계 방향으로 변환한 설계 벡터입니다. 기판 로컬 설계값이면 기판의 회전·방향을 반영한 뒤 더합니다.

동일 간격 P, H번호가 X 증가 방향으로 배치된 학습 모형에서만 T_x(h)=C_x+(h−4.5)P로 표현할 수 있습니다. 실제 개발은 Head별 설계 배치표를 기준으로 합니다.

03

시작 전에 고정할 입력과 조건

무엇을 기준으로 어떤 마크를 측정할지 먼저 정하면, 잘못된 값을 보정으로 덮어쓰는 일을 줄일 수 있습니다.

준비 항목작업자가 확인할 내용프로그램 처리
기준 기판·장비 상태평가용 기판과 Align 상태, 기판 중심/ESC/Teaching 관계. 기판 안착·Chuck/ESC, 축 원점·실제 위치·허용 범위, 수동/단동 권한, 레이저 허용·기존 인터록.Machine·Model/Recipe·기준 기판 ID와 위치·자세를 세션에 고정. 해당 장비의 기존 점검 기준을 확인.
Head 배치H1~H8 번호 방향, H4/H5의 목표 X, Head별 설계 Y단차.Head별 목표표와 설계 Revision을 읽고 누락·중복 확인.
시험 패턴어떤 명령 좌표로 어떤 Head·Branch의 마크를 만들지. 겹치지 않고 식별 가능한 배치.Pattern ID, Head, 테스트 명령, 전체 마크 설계 변위, 가공 이력을 연결.
Review 측정 경로Review 원점·축 방향·단위와 카메라 교정. 영상이 어느 축 위치에서 촬영됐는지.Raw pixel과 촬영 당시 위치를 저장. 공통 mm 변환 종류와 교정 Revision 확인.
현재 적용 보정기본 좌표 교정과 현재 Default, 기존 Review 보정이 시험 마크에 들어가는지.시험용 셋업 모드의 적용층을 명시. 필수 광학/좌표 교정을 유지하고, 제품 보정은 제외 또는 명시적으로 계산에 반영.
값을 쓰는 규칙입력 필드가 X/Y 무엇을 움직이는지, 부호·배율·단위, 증분인지 새 총량인지.실제 필드와 응답 모델의 대응표. 미확인 필드의 자동 적용 제한.
평가 기준X/Y 잔여 허용값, 반복 횟수·반복성, 적용 범위, 검증 마크·Field 위치.미입력 기준으로 자동 합격 처리하지 않음. 장비 담당자가 확정한 값을 설정으로 관리.
이번 셋업의 기준을 묶어 보관합니다

설계·카메라 교정·기판 자세·현재 보정값을 묶어 기준 Snapshot으로 저장합니다. 측정 도중 하나라도 바뀌면 기존 후보의 적용 가능 여부를 다시 판단합니다.

측정은 유효하지만 위치가 크게 틀린 경우

검출·대상 식별·좌표 변환이 정상이라면 실제 편차 데이터입니다. 후보 계산은 가능하되 적용 한계와 기구·광학 점검 조건을 별도로 확인합니다.

마크를 못 찾았거나 다른 빔인 경우

유효한 해당 마크 좌표로 취급할 수 없습니다. 원시 영상과 실패 사유를 보존하고 다시 찾습니다. 0이나 옆 Head 값으로 채우지 않습니다.

04

전체 작업 순서 · 중심 Head부터 확장합니다

4·5번 Head에서 좌표 기준과 적용 방향이 맞는지 먼저 확인하고, 같은 기준을 나머지 Head로 확장합니다.

  1. 기준 고정중심·설계·교정·현재값
  2. H4/H5 셋업X/Y 계산·적용·검증
  3. 다른 Head 확장같은 기준·설계표 사용
  4. 전체 검증·저장새 마크·이력·Revision
작업 방법을 먼저 정합니다

시험 패턴을 정지형 단동으로 만들지, 검증된 MOF 경로를 쓸지는 실제 장비 기능과 평가 조건으로 정합니다. MOF를 사용하면 해당 실행 준비 절차를 따릅니다. Default 셋업이라는 이유만으로 IOF·MOF 시퀀스를 모두 새로 강제하지 않습니다.

05

실제 작업 절차 · 단계별로 확인합니다

아래 10단계는 작업자 행동, 프로그램 처리, 다음 단계 조건을 함께 읽을 수 있도록 구성했습니다.

01

기준을 선택하고 기존값을 보관합니다

작업자
평가 기판·모델과 시험 패턴을 선택합니다. 기판 중심·Head 목표표·Review 교정·현재 Default를 확인합니다.
가공SW
기준 Snapshot과 세션 ID 생성. 필요한 필드가 없으면 이유를 보여 줍니다. 현재 장치값과 저장값이 맞는지 확인합니다.
다음 단계 조건
기준표·현재 적용값·Revision이 일치. 원복에 필요한 이전 검증값이 조회됩니다.
02

기판을 Align하고 중심을 확인합니다

작업자
기준 기판을 정상 Align합니다. 화면에서 C_ref와 H4/H5 목표 위치가 어디인지 확인합니다.
가공SW
Align·Teaching·Review 좌표 관계로 C_ref와 Head별 T_h를 표시합니다. 화면의 그림과 실제 축 방향을 대응시킵니다.
다음 단계 조건
중심의 출처, 좌표계, X/Y 방향이 확정됩니다. H4/H5가 C의 양쪽 설계 위치에 놓입니다.
03

H4/H5 시험 마크를 가공합니다

작업자
계획된 Head·Branch·테스트 명령으로 식별 가능한 패턴을 만듭니다. 기존 마크와 이번 마크를 구분합니다.
가공SW
새 MachiningRun과 실제 실행 Snapshot을 기록합니다. 가공 중인 Script의 좌표를 후보값으로 덮어쓰지 않습니다.
다음 단계 조건
어떤 보정값으로 어떤 마크를 만들었는지 이력이 남습니다. 가공 실패는 측정 단계로 넘기지 않습니다.
04

Review로 찾아 마크를 식별합니다

작업자
예상 위치에서 탐색합니다. 예상 범위를 벗어나면 지정된 탐색/수동 확인 절차로 찾습니다. Head·Branch·Pattern을 확인합니다.
가공SW
Vision 요청/결과와 Stage 위치를 같은 측정 시도에 연결합니다. 발견 위치·영상·검출 상태와 식별을 저장합니다.
다음 단계 조건
화면에 보이는 마크가 계획한 대상입니다. 찾지 못한 경우 재탐색하며 비슷한 다른 마크로 대체하지 않습니다.
05

실제 원점을 계산합니다

작업자
가능하면 승인된 중심 맞춤 또는 교정된 영상 잔차로 마크 위치를 얻습니다. 가상 원점 계산에 사용할 마크들을 확인합니다.
가공SW
촬영 당시 위치/자세로 공통 mm 좌표 M을 구합니다. 알려진 설계 변위를 빼서 O를 추정하고 마크 간 불일치를 표시합니다.
다음 단계 조건
같은 프레임·단위에서 O가 계산됩니다. 빔 식별·마크 간 거리·방향이 설계와 맞습니다.
06

X/Y 후보와 입력 방향을 확인합니다

작업자
목표 대비 실측이 어느 쪽으로 틀렸는지 봅니다. X와 Y의 물리 이동량과 실제 입력 필드값을 비교합니다.
가공SW
e·C·필드 증분·새 총량을 나눠 표시합니다. 확인된 필드 응답 모델로 계산합니다. 부호/배율 확인은 승인 범위의 시험 변경과 새 측정으로 검증합니다.
다음 단계 조건
필드·부호·단위·증분/총량 규칙이 확인됩니다. 범위 밖이면 자동 적용하지 않고 원인을 확인합니다.
07

H4/H5에 적용하고 새로 가공합니다

작업자
후보의 현재값/새값/대상 Head를 확인해 셋업값을 적용합니다. 별도 위치에 검증 마크를 새로 가공·측정합니다.
가공SW
적용 요청과 실제 반영 상태를 기록합니다. 상태를 적용·미검증으로 표시하고, 새 검증 Run을 연결합니다.
다음 단계 조건
H4/H5 모두 X/Y 잔여와 반복성 기준을 만족합니다. 미달이면 새 잔여로 후보를 다시 계산합니다.
08

같은 기준으로 나머지 Head를 맞춥니다

작업자
H1~H3, H6~H8도 동일한 설계 배치표를 기준으로 시험 가공·측정·적용·검증합니다.
가공SW
기준 중심과 설계 Revision을 유지합니다. Head별 진행 상태와 X/Y 잔여를 따로 표시합니다.
다음 단계 조건
모든 대상 Head를 같은 기준으로 검증했습니다. 바로 전 Head의 남은 오차를 다음 Head의 새 기준으로 누적하지 않습니다.
09

전체를 독립 반복 검증합니다

작업자
새 마크 가공 → 측정을 정한 횟수 반복합니다. 같은 마크의 반복 촬영은 측정 반복성으로 구분합니다. 승인된 검증 위치에서 Head 간 관계와 Field 내 잔여를 확인합니다.
가공SW
가공/측정 반복성·최대 잔여·마크 간 거리/방향을 비교합니다. 회전/배율/왜곡 의심을 병진값으로 숨기지 않습니다.
다음 단계 조건
설정한 검증 위치·반복 기준을 모두 통과합니다. 한 점만 맞춘 결과를 전체 Field 합격으로 표시하지 않습니다.
10

검증값을 확정하고 다음 평가로 넘깁니다

작업자
최종 보고에서 Head별 이전/새값, 실제 검증 결과, 기준과 예외를 확인합니다. 제품 가공평가를 시작합니다.

06

Review 측정값을 실제 위치로 바꾸는 방법

엔코더는 카메라가 어디에 있는지 알려 주고, pixel은 영상 안에서 마크가 어디에 있는지 알려 줍니다. 두 정보는 단위와 기준을 맞춘 뒤 연결합니다.

측정 결과 형태실제 위치 M을 얻는 방법필요한 확인
카메라 중심에 마크를 맞추는 방식촬영 시 카메라 광축의 공통 좌표 E를 기준으로 사용. 남은 중심 오차는 측정 허용 범위로 확인.엔코더 count를 그대로 쓰지 않습니다. 축 원점·방향·단위·기판 자세를 반영한 E여야 합니다. 중심 잔차를 임의로 0으로 만들지 않습니다.
교정값이 로컬 잔차를 주는 방식영상 중심 대비 잔차를 공통 프레임 mm로 변환한 δ를 얻어 M=E+δ.ROI 원점, 영상축 반전·회전·왜곡 및 이동축 변환을 포함합니다. 영상과 같은 시점의 E를 사용합니다.
교정값이 절대 위치를 주는 방식출력 좌표가 이미 현재 공통 프레임이라면 그 값을 M으로 사용.E를 또 더하면 이중 이동입니다. 기준 자세의 절대좌표 출력이라면 현재 자세와의 차이만 별도 변환합니다.
화면에서는 값의 의미를 함께 보여 줍니다

원시 pixel → 변환 방식·교정 Revision → 공통 mm → 가상 원점 순으로 표시합니다. Align 카메라에서 구한 교정값을 Review 카메라에 자동으로 재사용하지 않습니다. 해당 Review 광학계와 이동축의 좌표 계약이 필요합니다.

개발자 확인 · 촬영 위치와 변환 식

일반적으로 M = F(촬영축위치, pixel, 기판자세, Calibration)로 다룹니다. 원시 축 count나 나중에 읽은 현재 위치를 촬영 위치로 대체하지 않습니다. 정지 촬영은 위치 유지 확인으로 시각 대응을 확보할 수 있습니다.

Homography로 위치를 구할 때는 출력이 로컬인지 절대인지 먼저 명시합니다. 아래 H(p)는 동차좌표 정규화 후 얻은 mm 위치입니다. projective 변환의 중심 잔차는 H(p)−H(p₀)처럼 변환된 두 위치 차이로 구합니다. H(p−p₀)로 임의 대체하지 않습니다.

가상 원점을 구하려면 마크가 만들어질 때의 Head 변위도 공통 프레임으로 옮겨야 합니다. 카메라 회전과 Head 회전은 서로 다른 교정 항목입니다.

07

실제 홀이 없어도 Head 원점을 찾을 수 있습니다

Review에서 측정한 점은 실제 마크입니다. Head의 가상 원점은 그 마크의 설계상 위치 관계를 이용해 계산합니다.

실측 Head 원점 = 실제 마크 위치 − 원점에서 그 마크까지의 알려진 전체 변위

여기서 전체 변위는 테스트 명령 위치 + 해당 분기빔의 설계 변위를 포함하고, Head 축 방향·회전·배율을 반영해 공통 좌표계로 바꾼 값입니다.

상황원점 계산주의점
마크 한 개O=M₁−D₁ID와 D가 확실하고 순수 병진 모델이 유효할 때 가능. 한 점으로 회전·배율·Field 전체 정합을 검증할 수는 없습니다.
여러 마크O=평균(M_k−D_k)각 마크에서 구한 원점이 서로 맞는지 먼저 봅니다. 평균이 마크 오식별·회전 차이를 가리지 않게 합니다.
설계 대칭 두 마크D₁+D₂=0이면 O=(M₁+M₂)/2같은 좌표계에서 대칭이고 같은 셋업 상태여야 합니다. 비영점 테스트 명령이라면 그 기여량까지 고려합니다.
비대칭 두 마크O=(M₁+M₂)/2−(D₁+D₂)/2측정점의 중간을 그대로 원점이라고 쓰면 설계 비대칭만큼 편향됩니다.
분기빔 기준은 구현 전에 정해야 합니다

16개 분기 마크처럼 가운데 실제 홀이 없는 배열에서도 가상 원점은 계산할 수 있습니다. 다만 Zero Order, 특정 Branch 번호, 배열의 가상 중심이 같은 점이라고 가정하면 안 됩니다. 기준 마크/쌍과 식별 규칙을 광학·Vision·Process가 함께 확정합니다.

숫자 예제 · 단순 중간값이 틀리는 경우

1차원 학습 예입니다. 설계 변위가 D₁=−2, D₂=+4이고 실제 마크가 M₁=8, M₂=14이면 중간값은 11입니다. 하지만 원점은 (8−(−2)+14−4)/2=10입니다. 원점에서 비대칭으로 떨어진 두 점의 중간이 원점은 아닙니다. 단위는 모두 같은 mm이며 장비 설정값이 아닙니다.

08

X·Y 편차와 실제 입력값을 구분합니다

어느 방향으로 옮겨야 하는지와, 프로그램 필드에 어떤 값을 써야 하는지는 별도로 확인해야 합니다.

① 실제 오차

e = O − T

실측 원점이 목표보다 어디로 벗어났는지.

② 필요한 물리 이동

C = T − O

목표에 맞추려면 실제 마크가 얼마나 움직여야 하는지.

③ 필드 입력 증분

ΔB = C / g

한 축 응답 g가 확인된 경우의 입력 변화량. 실제 장치 필드 계약을 사용.

물리 보정량과 필드값의 부호가 같다고 단정하지 않습니다

어떤 장치에서는 필드가 +로 바뀌어도 실제 위치가 −로 움직일 수 있습니다. X/Y 단위·부호·배율 및 축 결합을 검증한 뒤 입력값으로 변환합니다. Vision 결과가 이미 필요한 보정량 C라면 다시 반전하지 않습니다.

Y 기준 선택계산의 의미작업 완료 판단
외부 절대 Y 기준Y_ref는 C_ref의 Y 또는 같은 기준으로 연결한 Teaching Y입니다. 이 공통 기준 하나를 사용하며 중복 적용하지 않습니다. T_y=d_y+Y_ref, C_y=T_y−O_y.Head별 설계 단차와 공통 Y 위치가 모두 맞는지 검증합니다.
Head 간 상대 Y 기준먼저 b_h=O_y−d_y. 같은 기준의 유효 Head 그룹 b 평균을 상대 Y_ref로 선택합니다. 이 모드의 T_y는 선택한 상대 기준의 목표입니다.Head 간 어긋남만 줄일 수 있습니다. 전체가 똑같이 이동한 오차는 알 수 없으므로 절대 위치 합격으로 표시하지 않습니다.
개발자 계산과 합성 · 적용 필드가 가산형일 때

한 축에서 ΔO=g·ΔB이면 ΔB=C/g입니다. 실제 X/Y가 결합되면 확인된 2×2 응답 ΔO=J·ΔB를 사용합니다. 응답이 미확인·특이·불안정하면 자동 역산을 진행하지 않습니다. g=±1은 아래 교육 예제의 단순 가정입니다.

이번 측정이 현재값 B에서 나온 잔여이고 필드가 가산형이면 B_new=B+ΔB입니다. API가 새 총량 F를 받으면 B_new=F로 교체합니다. 새 총량을 다시 B에 더하지 않습니다. 절대 원점/교체형 필드는 실제 좌표식으로 역산합니다.

제품 보정층이 측정에 포함돼 있었다면 그 기여와 상태를 추적해야 합니다. Default·Simple/Rough·Fine를 이름만 보고 모두 더하지 않습니다.
