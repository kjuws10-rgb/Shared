# ECID 조회·Set·전체 실패 시퀀스

기준: 2026-11-18. 참고 PPT는 이번에 첨부한 상세플로우 검토자료 3장이며, 현재 첨부 OSS·CIM V235와 대조했다. 사양 확인·설계 제안·협의를 구분한다. 구현·실통신·실장비 검증 완료 자료가 아니다.

첨부 V235의 조회는 S2F29/F30, Set은 S2F15/F16이다. Set은 ECID·이름·설정값·정지/경고 상하한을 포함하며, 한 항목이라도 부적합하면 전체 요청을 거절한다. 검증 전에 유효한 항목부터 저장하거나 장치에 쓰지 않는다. 변경 가능 필드·허용 상태·실제 반영 시점과 실패복구 범위는 협의한다.

## SEQ-E01 ECID 조회 정상/오류

상태: 첨부 사양

| 순서 | 담당/방향 | 처리 | 성공 조건 | 응답·근거 |
| --- | --- | --- | --- | --- |
| 1 | Host→CIM | S2F29 MODULEID 및 ECID목록 요청 | n=0은 전체정보 요청 |  |
| 2 | CIM→EC 소유자 | ECDEF/한계의 같은 시점 데이터 수집 | 실제 ECID를 No 열과 혼동하지 않음 |  |
| 3 | CIM→Host | S2F30 전체 구조로 응답 | 존재하지 않는 ECID/Module의 n=0 예외 의미 준수 |  |

| 실패 조건 | 필요한 결과 |
| --- | --- |
| 미존재 ECID/Module | 사양상 빈목록 예외 반환; ECID 번호를 No로 대체하지 않음 |
| 소유자 통신 실패/불완전 snapshot | 정상 실제값으로 조작하여 보고하지 않음; 세부 오류전달/재시도 협의 |

근거: CIM Message V235 p52; OSS ECID!B6:U6

## SEQ-E02 ECID Set 정상

상태: 첨부 사양 + 실제소유자 원자적용 설계

| 순서 | 담당/방향 | 처리 | 성공 조건 | 응답·근거 |
| --- | --- | --- | --- | --- |
| 1 | Host→CIM | S2F15 MODULEID 및 ECID별 7개 항목 수신 | 요청 전체 후보로만 보관 |  |
| 2 | CIM/소유자 | ID/명칭/자료형/쓰기허용상태/값·한계관계/범위 및 장치배율 변환 검증 | 모든요청항목 수용 가능 |  |
| 3 | EC 소유자 PLC/가공 SW | 검증된 전체 후보를 승인된 일괄commit 방식으로 적용·영속화 | 전체 성공 또는 무변경을 보장; readback 기준 합의 |  |
| 4 | CIM→Host | 소유자의 확정결과를 S2F16 MIACK/TEAC/필드 EAC로 회신 | 접수만으로 성공을 만들지 않고 합의된 완료기준 충족 |  |
| 5 | CIM→Host | 변경보고/재조회로 동기화 확인 | 적용값·한계와 읽기값이 동일 | EC 변경 CEID102 적용범위/송신시점 상세 합의 |

| 실패 조건 | 필요한 결과 |
| --- | --- |
| Busy/하나이상 없는상수/범위초과/허용불가 필드 | 전체 NAK·어떤요청항목도 변경하지 않음 |
| 중계 또는 일부소유자 반영 실패 | 성공ACK 금지; 사전준비/commit 또는 검증된복구로 All or Nothing 보장. 현재 OSS H/S만으로 그 보장을 주장하지 않음 |

근거: CIM Message V235 p49-50,105-106
