4. Recipe 기반 재생성과 전행 대조 방법

4.1 Pitch와 Cell당 중심

commandStep = PixelSize × Pitch = 0.09 mm/px × 10 px = 0.9 mm
X index = 0…13 (14개), Y index = 0…24 (25개)
45 Cell × 14 × 25 = 15,750 고유 중심

Pitch는 현재 명령 중심에서 다음 명령 중심까지의 Pixel 개수이며 DOE 4×4 내부 Branch 간격과 무관합니다. 현재 Excel은 floor(144/10)=14, floor(256/10)=25 정책을 사용합니다.

4.2 좌표식

Xglobal = CellAlignX + 25.8375 + 0.9×ix
Yglobal = CellAlignY + 0.3375 + 0.9×iy
Head = floor(Xglobal / 110) + 1
GY = Xglobal − {55 + 110×(Head−1)}
GX = −{Yglobal + 120 + (홀수 Head이면 380, 아니면 0)}

4.3 Excel의 실제 Queue 순서

  1. Cell Y row: 0 → 200 → 400 → 600 → 800
  2. 각 Cell row의 iy: 0 → 24
  3. 각 Head가 소유한 Cell X와 ix를 작은 값부터 기록
  4. 전체 첫 Lane을 제외한 각 Lane 시작 좌표를 한 번 더 삽입
위 순서로 만든 16,742개 예상 레코드와 Excel Raw를 Head별 같은 순번으로 비교한 결과, 길이·GY·GX·순서의 불일치는 모두 0개였습니다.
원시 XML에는 −29.162500000000001 같은 이진 부동소수 문자열이 있으므로 문자열 비교는 부적절합니다. 본 검증은 표시 정밀도 4자리로 정규화하고 수치 차이 ≤1×10⁻⁹ mm를 일치로 판정했습니다.

7. 실제 가공 횟수는 파일만으로 확정할 수 없음

992개가 이동·Lead-in이고 Laser-Off라면

실제 가공 중심 후보: 15,750개

DOE 16분기 명목 발생수: 252,000

Excel Raw의 모든 행이 Laser-On이라면

가공 명령: 16,742개

DOE 16분기 명목 발생수: 267,872

Excel에는 LaserGate, CommandType, Jump/Mark가 없고 좌표 셀의 스타일도 동일합니다. 따라서 992개를 자동 삭제해서도, 실제 이중 가공이라고 단정해서도 안 됩니다. 좌표 생성 SW에는 최소한 LaneId, PointRole, LaserGate를 추가해야 합니다.

추가 사양 확인: 마지막 Pixel 포함 정책

현재 Excel은 14×25 중심을 사용하지만, 유효 인덱스가 PixelNum보다 작으면 포함하는 정책은 15×26이 됩니다. 후자의 경우 45×15×26=17,550으로 현재 고유 중심보다 1,800개 많습니다. 이 차이는 이번 992개 반복 문제와 별개의 끝점 정책입니다.
