간소화 설정과 사이클 누적 표시

기본 입력은 Stage Y속도, Review X속도, 노출시간, 품질 기준입니다. Recipe 기하·Head 소유권·Mask/DOE 및 현재 동작 규칙은 고정 표시합니다. 가감속·정착·Trigger·거리/축 원점 등 실측이 필요한 항목만 전문가 설정에서 바꿉니다. 새로운 Recipe/장비 사양은 검증한 조건 JSON으로 가져옵니다.

조건 안내는 좌표, Stage Stroke, Review X 범위, 30/150초, Camera/Blur와 실제 Glass 계획을 각각 검사합니다. 불가 원인에 따라 필요한 노출·속도·Y간격을 보여주며, 숫자 적용 버튼은 선택한 Glass 상한의 최소 이론 장수까지 전 조건을 다시 검증한 경우에만 표시합니다. Camera 사양을 넘는 FPS 또는 최소노출 미만 값, 품질허용 완화는 자동 적용하지 않습니다.

Stage 설계 Stroke 3960 mm / Review 1025 mm를 사용합니다. 첨부 도면의 Limit3980/1033 mm와 Stopper Gap을 가용 Stroke에 더하지 않습니다. Stage 이동거리 검증과 절대 시작/종점의 현장 원점 등록은 별도입니다. Review 기본 구간0~1025 mm는 등록 가정이며 실제 원점을 확인해야 합니다.

H01~H08 한 사이클에서 취득한 점은 Glass가 바뀌어도 지도·이동 기판·Cell 색과 Head 추적에 녹색으로 누적합니다. 이전 Glass 기록을 새 기판에 표시하는 것은 사이클 오버레이입니다. 새 기판에서 해당 점을 이미 다시 촬영했다는 뜻이 아닙니다. 「이번 Glass 완료」와 「사이클 누적」 개수를 분리하여 보여줍니다.

슬라이더를 과거 시각으로 되돌려도 이미 표시한 누적은 유지합니다. 마지막 Glass의 사이클 끝까지 녹색을 유지하고, 반복 재생으로 새 사이클에 진입하거나 「처음」을 누르면 초기화합니다. 조건/좌표/상한/정책 변경은 다른 계획이므로 누적을 초기화합니다. 실제 Frame/PASS 신호는 연결되어 있지 않습니다.

사용 순서와 화면 해석

  3. 8점 좌표 설정에서 Head마다 Cell·Shot 열/행·Branch를 지정합니다. 자동 배치, 동일 Y, 2점 또는 4점 프리셋으로 비교할 수 있습니다. 기본 자동안은 일부 Row17을 사용합니다. 첫 행만 검사하려면 별도 첫 행 제한을 켜고 재계산합니다.

01. 먼저 단위를 맞춥니다

나누기 전에 “거리 ÷ 속도 = 시간”인지 확인하면 대부분의 혼동을 줄일 수 있습니다.

예를 들어 100 mm/s는 기판이 1초에 100 mm 이동한다는 뜻입니다. 1 ms에는 0.1 mm, 10 µs에는 0.001 mm=1 µm 이동합니다. 가속도 1,000 mm/s²는 매초 속도를 1,000 mm/s만큼 바꾸는 능력이며, 정지에서 200 mm/s까지는 0.2초가 필요합니다.

Laser Shot, DOE Branch, Camera Frame은 서로 다릅니다. DOE 4×4는 한 Laser Shot의 16개 분기 가공점입니다. 여기서는 그중 지정한 한 가공점을 Head당 Camera Frame 하나로 리뷰합니다. Camera FPS23은 Laser 주파수200 또는 Laser Shot Count1과 같은 뜻이 아닙니다.

코드의 p.dx는 X 감속도입니다. 간격표의 edge.dx는 ΔX 거리입니다. 이름이 비슷해도 단위가 mm/s²와 mm로 다릅니다.

02. Cell → Shot 중심 → DOE 가공점

측정 대상은 Cell 중심이 아니라, 선택한 Laser Shot 안의 실제 Branch 가공점입니다.

Shot pitch P = Design pixel 크기 × PITCH
DOE 간격 Pᴅ = P ÷ 축당 분기 수 n
Shot 중심 오프셋 H = (n−1) ÷ 2 × Pᴅ
P = 0.0900 × 30 = 2.7000 mm
Pᴅ = 2.7000 ÷ 4 = 0.6750 mm
H = (4−1) ÷ 2 × 0.6750 = 1.0125 mm

Cell 번호는 1부터, Shot 열·행도 1부터 시작합니다. 따라서 첫 Cell이나 첫 Shot의 간격 횟수는 0번입니다. “열 번호”에 곧바로 pitch를 곱하지 않고 열−1에 곱합니다. 이 시뮬레이터의 원본 Planner 기준에서 첫 Shot 중심은 첫 Branch 기준점보다 H만큼 안쪽에 있습니다.

X중심 = AKMarginX + CellOffsetX + (Shot열−1)×P + H
Y중심 = AKMarginY + CellOffsetY + (Shot행−1)×P + H
X가공점 = X중심 + BranchOffsetX
Y가공점 = Y중심 + BranchOffsetY
H01 / C1 / 열28·행1 / B07
X중심 = 15.5000 + 0.0000 + (28−1)×2.7000 + 1.0125 = 89.4125 mm
Y중심 = 15.5000 + 0.0000 + (1−1)×2.7000 + 1.0125 = 16.5125 mm
X가공점 = 89.4125 + (0.3375) = 89.7500 mm
Y가공점 = 16.5125 + (-0.3375) = 16.1750 mm
Branch B07의 0부터 센 열·행 = 2, 1
BranchOffsetX = (2 − (4−1)/2) × 0.6750 = 0.3375 mm
BranchOffsetY = (1 − (4−1)/2) × 0.6750 = -0.3375 mm

Cell은 9열×5행이며 Cell 시작점 pitch는 X 100.00, Y 200.00 mm입니다. Cell 실물 가공 모델 크기 77.76×46.08 mm와 시작점 pitch를 혼동하면 안 됩니다. 예를 들어 기본 C22는 4번째 열, 3번째 행이므로 CellOffset=(300,400) mm입니다.

03. Head 소유권과 Mask를 먼저 검사합니다

빠르게 이동할 수 있어도 다른 Head 영역이나 금지 Hole 위의 점은 유효 검사점이 아닙니다.

Head 기준 중심 X = AKMarginX + H01 AK X + (Head번호−1)×HeadPitch
소유권 비교 X = Laser Shot 중심 X + 소유권 기준차
|비교 X − Head 기준 중심 X| ≤ Field 폭/2
H01 기준 중심 = 15.500 + 39.500 + (1−1)×110.000 = 55.0000 mm
비교 X = 89.4125 + 10.000 = 99.4125 mm
허용 반폭 = 110.000 / 2 = 55.000 mm

비교 범위 안에 있는 가장 가까운 Head를 선택합니다. 기본 소유권 기준차 10 mm는 제공 조건의 ESC/Scanner 기준차 5+5 mm를 따른 값입니다. 실제 Branch X가 아니라 Laser Shot 중심 X으로 Head를 배정합니다. 동률에서는 이 명목 모델은 낮은 Head 번호를 사용하며 원본 Planner의 누적 개수 동률 처리는 별도 확인이 필요합니다.

Mask 사각형의 접촉도 Skip입니다

원본 코드의 Mask 기준점은 Shot 중심과 별도입니다. Cell 로컬에서 xm=(열−1)×P, ym=(행−1)×P를 사용하며 판정 외곽은 xm±P/2, ym±P/2입니다. 이 기준점을 위의 Shot 중심으로 바꿔 계산하지 않습니다.

Mask 외곽 [xm−P/2, xm+P/2] × [ym−P/2, ym+P/2]
Hole 외곽 [HoleX, HoleX+Width] × [HoleY, HoleY+Height]
X 구간이 겹치고 Y 구간도 겹치면 → 해당 Shot 전체 Laser Skip
X겹침: Mask왼쪽 ≤ Hole오른쪽 AND Mask오른쪽 ≥ Hole왼쪽
Y겹침: Mask위쪽 ≤ Hole아래쪽 AND Mask아래쪽 ≥ Hole위쪽
Mask와 경계 접촉은 허용하지 않습니다. Shot에 속한 Branch 하나만 피해도 Shot 전체 Skip 여부는 별도로 검사해야 합니다. Field 미배정 점도 검사 대상에서 임의로 PASS 처리하지 않습니다.
H01의 현재 좌표는 기하 검증을 통과했습니다. 시간·Camera·품질 조건은 뒤에서 별도로 검사합니다.

04. 기판 Global과 축 좌표를 분리합니다

Global Y가 양수인데 Stage Y가 음수여도 오류가 아닙니다. 좌표 원점과 진행 방향이 다릅니다.

Review X = Review AK 축 X + Global X − AKMarginX
Target Stage Q = Review AK 축 Y + σ×(Global Y − AKMarginY)
σ = Stage 진행 방향: −Y이면 −1, +Y이면 +1
H01: Review X = 0.0000 + 89.7500 − 15.5000 = 74.2500 mm
Stage Q = 0.0000 + (-1)×(16.1750−15.5000) = -0.6750 mm

Review X는 Camera 축에 명령할 위치입니다. Stage Q는 그 가공점이 고정 Camera Y 면을 지나는 순간의 Stage 절대 위치입니다. Camera가 Y로 따라가는 것이 아니라, 기판 이동으로 이 Q에 도달했을 때 위치 Trigger를 발생시키는 것입니다.

Scanner Gx/Gy Flip은 Scanner 로컬 축 변환입니다. 이 자료에서는 이미 기판 Global로 통일한 점을 사용하므로 Global 점에 홀짝 Flip을 다시 곱하지 않습니다. 실제 좌표 교정·Default Offset·Align/왜곡 보정은 현재 명목 0이며 별도 실측이 필요합니다.

05. Y 가감속으로 도착 시각을 구합니다

처음부터 100 mm/s로 달리는 것이 아니므로 전체 시간을 “거리÷속도” 하나로 계산하지 않습니다.

1) 설정 속도에 도달할 만큼 거리가 충분한지 확인

가속시간 tₐ = V/A, 가속거리 Lₐ = V²/(2A)
감속시간 tᵦ = V/B, 감속거리 Lᵦ = V²/(2B)
L ≥ Lₐ+Lᵦ이면 등속 구간이 있는 사다리꼴 운동
L < Lₐ+Lᵦ이면 설정 속도 미도달, 삼각형 운동
실제 최고속도 Vpeak = min(V설정, √(2L/(1/A+1/B)))
tₐ=Vpeak/A, tᵦ=Vpeak/B
L등속=L−Vpeak²/(2A)−Vpeak²/(2B)
T이동=tₐ+L등속/Vpeak+tᵦ
Stage 거리 L = (-1,584.5000−2,345.9875)×(-1) = 3,930.4875 mm
Vpeak = 100.000000 mm/s
가속 = 0.200000 s / 10.000000 mm
등속 = 39.104875 s / 3,910.487500 mm
감속 = 0.200000 s / 10.000000 mm
TStage = 0.200000+39.104875+0.200000 = 39.504875 s

2) 선택점까지의 진행거리 s를 시간으로 바꾸기

s = (Target Q−시작 Q)×σ
가속 중: t = √(2s/A)
등속 중: t = tₐ+(s−Lₐ)/Vpeak
감속 중: t = T이동−√(2(L−s)/B)
H01까지 s = (-0.6750−2,345.9875)×(-1) = 2,346.6625 mm
현재 도착 구간: 등속 / Review 중심 시각 23.566625 s
t = 0.200000 + (2,346.6625−10.0000)/100.000 = 23.566625 s

속도 그래프 아래 면적이 이동거리인 이유는 “속도×시간=거리”이기 때문입니다. 가속 삼각형 면적은 밑변 tₐ×높이 Vpeak÷2이며, 이 값이 Vpeak²/(2A)입니다.

06. Scanner→Camera 거리와 점→점 간격은 다릅니다

1467 mm는 가공 후 리뷰까지의 이동 거리이고, 두 리뷰점 사이의 시간 여유는 두 점의 ΔY로 정해집니다.

Head 거리 D = 홀수 거리 + (짝수 Head이면 추가거리)
Laser Q = ReviewAKY − σD + σ×(Shot중심Y−AKMarginY)
가공→Review 지연 = tReview − tLaser
두 순간 모두 등속이면 지연 ≈ (D+BranchOffsetY)/Vᵧ
H01 거리 D = 1,467.000 mm
가공 시각 8.900000 s → Review 중심 23.566625 s
정확한 시간 차 = 14.666625 s
등속일 때의 대입 = (1,467.000+(-0.3375))/100.000 = 14.666625 s

위의 등속 대입은 가공 시점과 Review 시점 사이가 모두 등속일 때만 정확합니다. 가감속을 지나면 거리/한 속도로 계산하지 않고 두 Q의 Stage 도착 시각을 각각 역산한 뒤 뺍니다. Branch가 Shot 중심보다 Y로 치우친 만큼 시간 차도 조금 바뀝니다.

H01→H02의 실제 ΔY = |216.1750−16.1750| = 200.0000 mm
정확한 도착 간격 = 25.566625−23.566625 = 2.000000 s
둘 다 등속·앞으로 진행하면 Δt = ΔY/Vᵧ = 200.0000/100.000 = 2.000000 s
같은 Global Y의 다른 X는 Camera Y 면을 같은 시각에 통과합니다. 단일 Camera를 두 X에 동시에 둘 수 없으므로 FPS만 높여 해결하지 못합니다. Y가 다른 유효점을 선택하거나 Glass를 나누어야 합니다. ΔX와 ΔY의 2D 직선거리 √(ΔX²+ΔY²)를 Stage 속도로 나눈 값도 올바른 Y 도착 간격이 아닙니다.

07. X 이동시간: 왜 ΔX/Vₓ보다 오래 걸릴까요?

Camera X축은 각 촬영 위치에서 정지·정착하고, 다음 점까지 다시 가속·감속합니다.

사다리꼴: 멀리 이동하여 Vₓ에 도달

L필요 = Vₓ²/(2Aₓ)+Vₓ²/(2Bₓ)
ΔX ≥ L필요이면
TX = Vₓ/Aₓ + [ΔX−Vₓ²/(2Aₓ)−Vₓ²/(2Bₓ)]/Vₓ + Vₓ/Bₓ
정리하면 TX = ΔX/Vₓ + Vₓ/2×(1/Aₓ+1/Bₓ)

삼각형: 가까워서 Vₓ에 도달하지 못함

ΔX < L필요이면
Vpeakₓ = √(2ΔX/(1/Aₓ+1/Bₓ))
TX = Vpeakₓ/Aₓ + Vpeakₓ/Bₓ = √(2ΔX×(1/Aₓ+1/Bₓ))
현재 L필요 = 200.000²/(2×1,000.0) + 200.000²/(2×1,000.0) = 40.000000 mm
현재 H01→H02: ΔX=100.0000 mm → 사다리꼴
실제 X 최고속도 200.000000 mm/s
가속 0.200000 + 등속 0.300000 + 감속 0.200000 = 0.700000 s

반드시 익혀둘 고정 교육 예시

예시 조건: Vₓ200, Aₓ=Bₓ1000거리÷속도만 계산가감속 포함한 실제 계산이유
110 mm 이동110/200 = 0.550000 s0.750000 s가속20 mm + 등속70 mm + 감속20 mm / 0.2+0.35+0.2 s
2.7 mm 이동2.7/200 = 0.013500 s0.103923 s최고속도51.961524 mm/s의 삼각형 / 0.051962+0.051962 s
고정 교육 예시는 현재 입력과 별개입니다. 110 mm는 Scanner 기준 Pitch 예시이고 실제 Camera ΔX는 두 글로벌 검사점으로 구해야 합니다. 기본 H03→H04는 Scanner Head가 다르지만 Camera ΔX가 2.7 mm입니다.

08. 노출 중심에 맞춰 Trigger를 미리 보냅니다

명령을 보내자마자 촬영되는 것이 아니므로 지연과 노출의 절반을 앞당깁니다.

보상 ON: t명령 = tReview − Trigger지연 Dₜ − 노출 E/2
t노출시작 = t명령 + Dₜ
t노출종료 = t노출시작 + E
t노출중심 = (t노출시작+t노출종료)/2
현재 보상 ON: H01
t명령 = 23.566625−0.00005000−0.00000500 = 23.56657000 s
노출 시작 = 23.56657000+0.00005000 = 23.56662000 s
노출 종료 = 23.56662000+0.00001000 = 23.56663000 s
노출 중심 = 23.56662500 s / 목표 중심 = 23.56662500 s

Jitter는 고정 지연과 다릅니다. 고정 지연은 매번 같아서 보상할 수 있지만 Jitter ±J는 Shot마다 빨라지거나 늦어질 수 있습니다. 그래서 이전 노출 종료는 +J, 다음 Trigger 마감은 −J로 잡습니다. 서로 다른 두 Shot의 최악 시간 오차를 각각 확보합니다.

가장 빠른 노출 시작 = 23.56662000−0.00000500 = 23.56661500 s
가장 늦은 노출 종료 = 23.56663000+0.00000500 = 23.56663500 s
X 준비 마감 = 23.56657000−0.00000500−0.020000 = 23.54656500 s
가장 빠른 노출도 Laser 가공 후 최소 대기시간 이후여야 하고, 가장 늦은 노출까지 Stage 등속/구동 구간 안이어야 합니다. 보상 OFF는 t명령=tReview로 두므로 노출 중심이 지연+E/2만큼 늦습니다.

09. 연속 촬영은 X와 Camera 두 검사를 모두 통과해야 합니다

시간 여유가 0 이상이면 타이밍 조건을 만족합니다. X가 가능해도 Camera가 재준비되지 않으면 실패합니다.

X 이동 시작 = 이전 노출 종료 + 이전 Jitter J
X 준비 마감 = 다음 명령 − 다음 Jitter J − Guard G
X 가용시간 = 준비 마감 − 이동 시작 − 정착 S
X 시간 여유 = X 가용시간 − TX
H01→H02
X 가용 = 25.56657000−0.00000500−0.020000−23.56663000−0.00000500−0.050000 = 1.92993000 s
X 여유 = 1.92993000−0.70000000 = 1.22993000 s = 1,229.930 ms

Camera의 FPS는 노출시간과 다릅니다

23 FPS라면 Frame 시작 간격은 적어도 1/23초입니다. 노출이 10 µs라고 해서 10 µs마다 새 Frame을 촬영할 수 있는 것은 아닙니다. Readout은 센서 영상 데이터를 읽어 내는 시간이므로 Camera의 중첩 지원 여부도 필요합니다.

Readout 중첩 ON: T꜀=max(1/FPS, E, Readout)
중첩 OFF: T꜀=max(1/FPS, E+Readout)
최악 Frame 간격 = 다음 명령−이전 명령−2J
Frame 시간 여유 = 최악 Frame 간격−T꜀
1/FPS = 1/23.000 = 0.04347826 s = 43.478 ms
노출 0.00001000 s / Readout 0.00000000 s / 중첩 ON
T꜀ = 0.04347826 s = 43.478 ms
Frame 여유 = 25.56657000−23.56657000−2×0.00000500−0.04347826 = 1.95651174 s
이 두 점의 X 이동·Frame 간격·촬영 순서 조건은 성립합니다. 개별 점의 기하·노출·블러 및 전체 Tact·초기/복귀 조건도 모두 통과해야 최종 실행 가능한 계획입니다.

등속이면 필요한 Y 간격을 바로 볼 수 있습니다

필요 시간 = max(TX+정착+Guard+지연+노출+2J, T꜀+2J)
필요 ΔY = Vᵧ × 필요 시간
현재 X 경로 필요 = 0.77007000 s
Camera 경로 필요 = 0.04348826 s
필요 ΔY = 100.000×max(0.77007000, 0.04348826) = 77.007000 mm
두 촬영 사이에는 X 조건과 Camera 조건이 동시에 적용됩니다. 그러나 같은 시간에 진행되는 부분이 있으므로 두 전체 시간을 무조건 더하지 않고 더 큰 필요 시간을 사용합니다. 가감속 구간의 Y 간격 역산은 이 등속식 대신 실제 Stage 프로파일로 다시 계산합니다.

10. Blur와 위치오차는 별도 품질 조건입니다

점에 제때 도착해도 노출 중 기판이 많이 움직이면 홀의 영상이 퍼져 정확한 판정이 어려워집니다.

등속 Blur(µm) = Vᵧ(mm/s)×E(s)×1000
Object pixel(µm/px) = Sensor pixel(µm/px) ÷ 광학배율
Blur(px) = Blur(µm) ÷ Object pixel(µm/px)
현재 노출 중심 Y속도 = 100.000000 mm/s
등속 근사 Blur = 100.000000×0.00001000×1000 = 1.000000 µm
실제 프로파일·Jitter 극값 검사 Blur = 1.000000 µm
Object pixel = 3.4500/20.000 = 0.172500 µm/px
Blur = 1.000000/0.172500 = 5.797101 px

정속이 아니면 “속도×노출” 근사만 사용하지 않습니다. 각 노출 구간의 Stage 위치 차이 |Q끝−Q시작|를 구하고, Jitter ±J 범위의 가장 큰 값을 선택합니다. 가속/감속 경계와 내부 극값도 검사합니다.

입력 Blur 허용 1.000000 µm 기준은 만족합니다. 이 허용값 자체가 영상 검출 품질을 보증하지는 않습니다.
1 px 이내를 원하면 E ≤ Object pixel/Vᵧ
현재 Stage 최고속도 기준 E ≤ 0.172500/100.000×1000 = 1.725000 µs
Camera 최소 노출 = 10.000 µs
현재 노출 유지 시 1 px의 Y속도 상한 = 17.250000 mm/s
기본 100 mm/s×10 µs는 1 µm이지만 3.45 µm/20×에서는 5.80 px입니다. “1 µm 허용”과 “1 px 이하”를 같은 기준으로 보지 마세요. 기본 최소노출10 µs Camera에 1.725 µs를 입력하는 것은 Camera 사양을 위반합니다. 스트로브로 유효 조명 시간을 줄이는 설계는 별도 검증 대상이며 현재 모델에 자동 반영되지 않습니다.

Y 위치오차 예산

오차 = 최악 노출 중심의 |Q실제−Q목표| + Encoder 반 count + 추종오차
Encoder 반 count(µm) = 0.5/EncoderScale(count/mm)×1000 = 500/EncoderScale
Jitter 등속 성분 = 100.000×0.00000500×1000 = 0.500000 µm
Encoder 반 count = 500/16,000 = 0.031250 µm
추종오차 예산 = 0.000000 µm
정확한 Y 오차 예산 = 0.531250 µm / Y 허용 30.000000 µm
X 정착오차 입력 0.000000 µm / X 허용 30.000000 µm

위치오차는 노출 중심이 목표점에서 얼마나 벗어나는지, Blur는 노출 동안 얼마나 퍼지는지입니다. 위치허용 30 µm라고 해서 Blur 30 µm를 허용한다는 뜻은 아닙니다. X 정착오차 0은 계산상 입력 가정이지 실측으로 0이 확인된 값이 아닙니다.

11. 처음 준비와 다음 Glass 복귀도 필요합니다

중간 점들만 가능한지 확인하면 첫 촬영과 다음 기판에서 실패할 수 있습니다.

최초 X 준비 시작 = −사전준비시간
첫 준비 완료 = −사전준비시간 + Park→첫점 이동 + 정착
첫 X 여유 = 첫 명령−J−Guard−첫 준비 완료
복귀 여유 = Tact−다음 사전준비시간−마지막 노출종료−J−복귀이동−정착
전체 요청점을 한 Glass에 배정한다고 가정
Park 0.0000 → 첫점 H01의 Review X 74.2500 mm
첫 준비 완료 = −2.000000+0.571250+0.050000 = -1.378750 s
첫 X 여유 = 24.925315 s
마지막 촬영 후 복귀+정착 = 3.986250 s
다음 Glass 준비 전 복귀 여유 = 62.519990 s

시간 0은 Stage 통과 시작입니다. −2초는 Camera가 Stage 시작 2초 전부터 준비한다는 뜻입니다. 일반 반복 Tact에서는 이전 물류 구간에 준비가 겹친다고 가정합니다. 아무 준비도 없는 Cold Start에서는 이 사전준비시간을 별도로 확보해야 합니다. 화면의 물류 대기 생략은 실제 장비 준비를 생략한다는 뜻이 아닙니다.

12. 가공 30초와 전체 Tact 150초를 나눠 봅니다

30초는 메인 가공 구간 예산이고, 150초는 기판 1매의 물류·통과·검사 처리를 포함한 전체 예산입니다.

기하 가공 시간 = 마지막 가공 Q 도착시간−첫 가공 Q 도착시간
전체 가공 구간이 등속이면 T가공 = L가공/Vᵧ
30초 예산의 등속 속도 하한 = L가공/30
가공 구간 길이 = |622.7875−1,845.9875| = 1,223.2000 mm
기하 가공 시간 = 12.232000 s / 예산 30.000 s
등속 가공 속도 하한 = 1,223.2000/30.000 = 40.773333 mm/s
Tact = Stage 전체 이동 + 미완료 Readout 대기 + 영상처리 Tail + 기타 물류/Align/복귀
Stage 가용시간 = 기획 Tact−Readout 대기−Tail−기타
Stage 전체 시간은 가감속을 포함하여 다시 검증
현재 Tact = 39.504875+0.000000+1.000+60.000 = 100.504875 s
기획 예산 150.000 s / 남은 여유 49.495125 s
Stage 가용시간 = 150.000−0.000000−1.000−60.000 = 89.000000 s
이 길이·가감속의 Stage 시간만 맞추는 속도 하한 = 44.206696 mm/s

기본 1500 mm를 무조건 30초로 나누어 50 mm/s로 결정하면 실제 가공 구간과 전체 통과 길이를 섞게 됩니다. 본 엔진은 8 Head의 유효 Shot 중심·가공면 거리를 반영한 첫/마지막 가공 Q를 구합니다. 시작에는 가공 전 선행길이, 종료에는 기판 후단 여유까지 포함하므로 전체 이동 길이는 Glass Y보다 깁니다.

Stage 시간 하한은 현재 Readout 대기를 고정한 설명용 계산입니다. Laser/Scanner 서비스시간·Script Queue·진공 물류 응답까지 보증하지 않습니다. 실제 역산 탭은 속도를 바꿔 기하·가공 구간·블러·노출·X·전체 Tact를 함께 다시 검사합니다.

13. 원하는 점을 유지하려면 어떤 조건을 바꿀까요?

빠른 Stage는 간격 시간을 줄이고, 빠른 X는 이동시간을 줄입니다. 느린 Stage는 촬영에는 유리하지만 Tact에는 불리합니다.

변경도움이 되는 부분동시에 확인할 문제
Stage Y 감소같은 ΔY에서 도착 간격 증가 / Blur 감소가공30초·전체150초 초과 가능
Review X 속도 증가사다리꼴 이동시간 감소짧은 삼각형 구간은 최고속도만 높여도 개선 없음
X 가속/감속 증가출발·정지 시간 감소Servo 진동·정착·실제 하중·정격 확인
FPS 증가Frame 재준비 간격 감소X 이동 충돌·Blur·Readout 한계는 해결 못함
노출 감소Motion Blur 감소Camera 최소노출·조명·신호대잡음·검출 성능 확인
검사점 Y 간격 증가Camera X 이동에 시간을 확보유효 Cell/Shot/Branch로 스냅하고 다시 검증
Glass를 분할현재 점·광학/동작 조건을 유지한 사이클 시간이 증가 / 품질 NG를 분할로 해결할 수는 없음

X 속도만 높여 해결할 수 있는지

고정 가감속에서, 속도를 아무리 높여도 최소 TX = √(2ΔX×(1/Aₓ+1/Bₓ))
X 가용시간이 이것보다 짧으면 속도만으로 해가 없음
사다리꼴에서 C=1/Aₓ+1/Bₓ라 두면
TX=ΔX/Vₓ+C×Vₓ/2 → C×Vₓ²−2TX×Vₓ+2ΔX=0
가능한 최소속도 = [TX−√(TX²−2CΔX)]/C
현재 가감속 하한 = 0.632456 s
X 가용 = 1.929930 s
현재 두 점의 최소 X 설정속도 = 53.286629 mm/s
현재 두 점의 FPS 하한 = 0.500003 Hz
등속 Blur 기준의 Y속도 상한 = 100.000000 mm/s

14. 한 Glass의 점 수와 전체 Glass 수

8개 Head 고정점 각각을 사이클에서 한 번씩 촬영하며, 모든 Cell을 전수 리뷰하는 모델은 아닙니다.

N = 활성 요청 Head 수 / K = 한 Glass 상한
Glass 수의 단순 하한 = ceil(N/K)
ceil은 나눈 결과를 다음 정수로 올리는 것: ceil(8/3)=3
실제 Glass 수 = 모든 개별 점·구간·복귀 조건을 통과하는 분할의 최소 장수
현재 N=8, 물리적으로 가능한 한 Glass 최대=8
