## 현재 확인된 보호도 함께 유지해야 한다

- Masking/Chess 제외 Shot은 Review `Use=false`로 전달된다. IOF의 실제 Count/좌표 읽기 확인과 Vision의 고정 슬롯 계약은 다른 역할이다.
- Vision은 헤더/본문을 각각 끝까지 읽고 UID·Command·ErrorCode를 확인한다. 상대 Vision 구현은 이번에 제공되지 않아 양측 패킹 일치를 실증하지 않았다.
- AUTO FINE은 결과 정체성·완료·전체 OK·CSV 저장 확인 후 누적한다. 0선 후속검사는 Offset를 바꾸지 않는다.
- Distortion 보간은 선택 키 영역 밖을 거부하고 측정값 유한성·키 행 구성·허용오차를 확인한다. 이 부분을 무제한 외삽이라고 설명하지 않는다. [보간 영역/유한성 검사](https://github.com/kjuws10-rgb/A3Drilling/blob/3a6b021af7dad60578e7fb85e3191b43b3b3c183/Drilling.Common/Correction/CAlignInterpolation.cs#L18-L111).
- Review Offset 저장은 temp→충돌 없는 move이고, 일반 Recipe Save와 구분한다. 화면 세션의 중복 적용 방지를 영속 결과ID 검증과 같다고 확대하지 않는다.

## 다음 검토 순서

1. 실제 개발 저장소의 로그 구현과 Git 추적을 복구한 뒤 수정 없는 정식 빌드를 다시 확인한다.
2. 전용 결과 파일 재로드, 원빔 AUTO 대상, 실제 공차/누적 보정의 승인값을 확인한다.
3. Shift 추종과 Stage/PTW 주소 계약을 확정하고 장비 없는 검증부터 수행한다.
4. 결과ID·보정 기준버전·Product 갱신을 연결하고, 별도 승인된 실기 평가에서 시간·물리 좌표를 검증한다.

이번 자동 분석에서는 위 개선을 생산 코드에 적용하지 않았다. 원본과 Config를 그대로 보존했다.
