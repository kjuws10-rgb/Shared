### 새 검토 후보와 한계

1. **DOE 정의 배포**: Level 7키는 built-in 보충되지만 DOE_EXIST 8키는 같은 보충 목록에 없습니다. 구형 JHMI_SETTING+새 값만 배포하면 Default가 키를 읽지 못할 수 있습니다. 화면은 비활성 Head까지 8개를 읽습니다.
2. **색상 swatch 통지**: Value setter가 ColorBrush 알림을 요청하지만 CBindingBase의 ColorBrushChanged 이벤트/case가 없습니다. 즉시갱신 누락의 정적 후보이며 WPF 재바인딩/뷰 재생성 우회는 실행 확인하지 않았습니다.
3. **Level 오류 처리 차이**: Live는 잘못된 Level 설정에 기본값 fallback, Review Data 모델은 로드 실패 경로입니다. 이미 잘못된 기존 색은 picker 생성 전 NormalizeColor에서 예외가 날 수 있습니다.
4. **판정·출처와 Level 차이**: Live는 VisionFind NG를 Level에서 제외하지만 결과 로드는 각 행 ErrorX/Y로 등급을 매깁니다. 낮은 Level 색을 실측 OK로 해석하지 않도록 Find NG·미측정·EDITED를 비교해야 합니다.
5. **표시·성능**: DOE ON 조건창의 4×4 문구와 실제 허용되는 전역격자1을 구분하고, 단일 Control의 전체 순회·blink·행 구독 수명·빠른 탭 변경은 실기 검증합니다.

모두 정적 위험·검증 우선순위입니다. 장비 불합격·재현 완료로 보고하지 않습니다.
