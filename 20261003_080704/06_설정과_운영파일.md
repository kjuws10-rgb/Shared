## Data/Script 441개: 왜 이렇게 많나?

[`CAutomation1ScriptFile.Build`](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/a25ba3cdfd70cff5d78172d13ec957318704b1e1/Drilling.File/Script/CAutomation1ScriptFile.cs#L43)은 실행마다 격리된 폴더를 만들고 보통 `Standard` 또는 `BufferedRun` 아래에 `PROCESS_COORDINATES.csv`(표), `PROCESS.txt`(사람이 읽는 목록), `PROCESS_Hxx.ascript`(Head별 장비 명령)를 쓴다. 저장소에는 `Standard` 353개, `BufferedRun` 74개, `Data/Script` 바로 아래 14개의 과거 파일이 추적돼 있다. 각각이 서로 다른 **프로그램 기능 파일**은 아니고, 여러 날짜·시각에 생성된 실행 기록이다. 정확한 전체 경로는 [99번 색인](99_전체_추적파일_목록.txt)에서 검색할 수 있다. 실제 실행에 사용된 파일은 `ST_SCRIPT_BUILD_RESULT.HeadScripts`의 경로를 봐야 한다. 이름이 같아 보여도 다른 실행의 스크립트를 섞으면 안 된다.

## Data/Product 21개와 Log 31개

[`CProductFile`](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/a25ba3cdfd70cff5d78172d13ec957318704b1e1/Drilling.File/Product/CProductFile.cs#L11)이 `Data/Product/ActiveProduct.csv`와 `Data/Product/History/<날짜>/ProductHistory_<날짜>.csv`를 관리한다. 현재 Git 추적본은 활성 제품 1개와 날짜별 이력 20개다. 현재 활성 파일이 곧 현재 장비의 실제 투입 제품인지 여부는 실행 환경에서 확인해야 한다. `Log/` 31개는 장비 Interface 통신, Station, Product, Recipe, Setting, UI, ProgramOpen, QueueCount, ScannerStatus 등의 과거 텍스트 기록이다. 작성 주체는 [`CLogManager`](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/a25ba3cdfd70cff5d78172d13ec957318704b1e1/Drilling.Common/Log/CLogManager.cs#L11), [`CProgramOpenLog`](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/a25ba3cdfd70cff5d78172d13ec957318704b1e1/Drilling.Common/Log/CProgramOpenLog.cs#L4), 공정의 상태 로거들이다. 분석 시 **증거/진단**이지만 레시피 입력으로 읽지 않는다.

## SDK 바이너리 13개와 패키지 7개

`Drilling.Common/Interface/Automation1/Sdk`의 Aerotech/Automation1 DLL·XML 5개, `Interface/PicoMotor/Sdk`의 DLL 6개, `Motion/ACS`의 DLL 1개, `Motion/XPS`의 DLL 1개는 제조사가 제공한 라이브러리다. 코드가 호출할 함수의 실행체 또는 API 설명이지 사람이 편집할 C# 원본이 아니다. `Drilling.Common/Packages`의 7개 `.nupkg`는 System.IO.Ports 로컬 패키지 묶음이고, [`NuGet.config`](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/a25ba3cdfd70cff5d78172d13ec957318704b1e1/NuGet.config#L1)이 복원 원천을 지정한다. SDK DLL을 다른 버전으로 바꾸는 것은 동작과 호환성에 영향을 줄 수 있다.

## 빌드·IDE 산출물 5,901개와 기타 4개

`.vs`, `bin`, `obj`, `BuildCheck`, `.buildcheck`는 편집기 캐시·컴파일 중간/최종 산출물이다. *현재 소스 구조를 이해할 때는 먼저 읽지 않는다.* 다만 과거 빌드 흔적이 Git에 추적되어 있으므로 [99번 색인](99_전체_추적파일_목록.txt)에는 모두 나온다. 나머지 파일은 [`README.md`](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/a25ba3cdfd70cff5d78172d13ec957318704b1e1/README.md#L1) (저장소 안내; 현재 동작과 다를 수 있음), [`pull_build_run.bat`](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/a25ba3cdfd70cff5d78172d13ec957318704b1e1/pull_build_run.bat#L1) (갱신/빌드/실행 보조), [`push_file.bat`](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/a25ba3cdfd70cff5d78172d13ec957318704b1e1/push_file.bat#L1) (Git 푸시 보조), `NuGet.config`이다. 배치 파일은 자동으로 실행하지 않았으며, 초보자는 내용과 대상 저장소를 확인하기 전 실행하면 안 된다.
