01. 처음 가공평가의 기준을 만드는 기능

Default Offset은 각 Head가 명령한 기준 위치와 실제 가공 위치 사이의 기본 어긋남을 맞춥니다. 가공·측정·추천·적용·새 가공검증을 하나의 기능으로 개발합니다.

숫자와 상태를 읽는 기준

이 자료의 110 mm·±55 mm 및 소수 편차는 원리를 설명하는 교육 예시입니다. 실기 입력값이 아닙니다. 아래 ‘완료’는 제공된 프로그램 리뷰표의 진행상태이며, 이번 문서 작성으로 실제 코드나 장비 검증이 완료된 것은 아닙니다.

02. 기판 중심 → H4·H5 → 8개 Head

H4와 H5를 ‘중앙에 맞춘다’는 말은 두 원점을 하나로 겹친다는 뜻이 아닙니다. 기판 중심을 사이에 둔 두 설계 위치부터 확인합니다.

HeadTarget[h] = CommonGlassCenter + HeadDesignPosition[h]
# 동일 피치·번호 방향이 확인된 교육 모형에 한해서:
TargetX(h) = CenterX + (h - 4.5) * Pitch
개발 입력저장할 의미잘못된 처리 방지
C_refAlign/Teaching으로 얻은 공통 중심, Frame·Pose·기준 Revision서로 다른 카메라의 raw Pixel 평균 금지
d_hHead별 설계 X·Y 배치, 번호 방향, 설계 Revision110·Y 단차를 상수로 박지 않음

AK로 중심을 구할 때

대칭쌍 또는 4점 평균은 설계상 대칭·같은 프레임 조건에서 사용합니다. 비대칭 배치라면 설계 AK와 실측 Pose를 대응시켜 설계 중심을 옮깁니다. 기판/ESC/Teaching 가운데 어느 중심을 기준으로 하는지 먼저 확정합니다.

03. Review 측정값을 공통 mm로 만드는 계약

엔코더·카메라 Pixel·기판의 이동을 같은 좌표로 연결해야 추천값의 의미가 생깁니다. Align 카메라 교정과 Review 카메라 교정을 별도로 확인합니다.

결과 타입계산필수 기록
Local 잔여M=E+δ. E와 δ가 같은 Frame·mm인 경우촬영 시 AxisPose, ROI, 카메라, 교정 Revision
현재 공통 AbsoluteM=교정 출력. E를 다시 합산하지 않음출력 Frame, 기준 Pose와 현재 Pose의 대응
FOV 중심 맞춤중심에 맞춘 뒤 광축의 공통 위치 사용남은 중심 오차와 승인 허용범위
개발자가 정할 변환 인터페이스
MeasurementPoint = NormalizeReviewMeasurement(
    markId, cameraId, pixel, roiOrigin,
    capturedAxisPose, glassPose, calibrationRevision)
# 결과: commonMm, frameId, validity, failureReason
# Projective H의 중심 잔여:
delta = normalize(H * pixel) - normalize(H * imageCenter)
# H * (pixel - imageCenter)로 대체하지 않는다.
측정 실패와 실제 큰 편차는 다릅니다

검출·ID·변환이 정상인 큰 편차는 실제 데이터로 보존합니다. 다만 적용 한계는 별도로 판단합니다. 미검출·오식별·프레임 불명은 0이나 옆 Head 값으로 채우지 않고 실패 사유를 표시합니다.

04. 분기빔의 어느 마크를 측정했는지 먼저 정합니다

Default는 마크 위치 자체를 목표에 붙이는 작업이 아닙니다. 그 마크가 Head 원점에서 얼마나 떨어진 설계점인지 알아야 합니다.

데이터개발 규칙리뷰표 연결
DOE Geometryn_x, n_y, Pitch X/Y, Row/Column→Branch ID, 회전·방향·Revision125·126: 한 샷의 분기빔 전체와 배열 변경
Test Command패턴 ID·Head·명령 좌표·크기·레이저 조건96·121~124: 기준위치와 실제 가공 적용
Reference MarkZero Order/특정 Branch/대칭쌍/가상 중심 중 승인된 정의10/22 회의의 기준 빔 확인 필요
Mark Match영상의 Head·Branch·Pattern을 실행계획과 매칭비슷한 다른 마크를 발견해 성공 처리 금지
bx(i) = (i - (nx - 1) / 2) * pitchX
by(j) = (j - (ny - 1) / 2) * pitchY
# 위 값은 정의된 Head Local mm 설계 좌표이다.
# 실제 Branch의 단위·방향을 확인한 뒤 공통 Frame으로 변환한다.
가상 중심 ≠ 광학 Zero Order

4×4 배열의 가운데는 홀 사이에 있습니다. 3×3·5×5 중앙 인덱스도 광학 Zero Order인지 별도 확인해야 합니다. 기존 고정 16개·6×6 배열에 종속된 분석/저장 구조를 파라미터화하는 방향을 권고합니다.

05. 마크 → 실제 Head 원점을 계산합니다

테스트 명령과 Branch 설계 변위를 공통 좌표로 변환한 전체 D를 빼야 Head의 원점이 나옵니다.

D[h,k] = TransformHeadDisplacement(testCommand, branchOffset, headTransform)
O[h,k] = M[h,k] - D[h,k]
O[h]   = mean(O[h,k])  # 병진 모델 일치성을 먼저 확인
# 대칭이면: D[a] + D[b] = 0 → O = (M[a] + M[b]) / 2
# 비대칭이면: O = (M[a] + M[b] - D[a] - D[b]) / 2
관찰개발 동작
여러 마크의 O_hk가 일치한 Head의 병진 원점 추정으로 사용하고 개별 잔여도 저장
마크 간 O_hk가 다름ID·설계 D·회전·배율·교정을 점검. 평균만으로 불일치 숨기지 않음
한 마크만 정상승인된 병진 기준은 구할 수 있으나 회전·배율·전체 Field 검증과 구분
설계 대칭이 미확인임의 두 마크 중간을 원점으로 쓰지 않음

06. 오차 → 물리 이동 → 필드 증분 → 새 총량

화면에 ‘추천 Offset’ 하나만 표시하면 부호·증분·총량을 혼동하기 쉽습니다. 네 단계를 나누어 계산하고 보여 줍니다.

값뜻계산
e현재 원점이 목표에서 벗어난 실제 편차O−T
C실제 가공점을 목표로 옮길 물리 이동T−O
ΔB실제 입력 필드를 바꿀 양확인된 J에서 J·ΔB=C
B_new최종 입력할 새 총량잔여 증분 모델이면 B_base+ΔB
# 예시 입력 계약
residual = targetMm - measuredOriginMm
deltaField = SolveVerifiedResponse(responseModel, residual)
candidateTotal = baseFieldValue + deltaField
ApplyCandidate(candidateId, expectedBaseRevision, candidateTotal)
# API가 새 총량을 받으면 교체한다. base + candidateTotal로 다시 더하지 않는다.
실제 필드 계약은 반드시 확인

No.246은 GetHeadXpos/Y + DefaultOffsetX/Y 적용이 보고되었습니다. 실제 필드가 가산형인지·절대 원점형인지, X/Y 단위·부호·배율·결합을 확인해야 합니다. Vision 결과가 이미 보정량 C라면 다시 반전하지 않습니다. J가 특이·불안정하거나 미확인일 때 자동 역산을 중단합니다.

07. Y는 설계 단차를 보존하고 기준을 선택합니다

Head별 설계 Y가 다르면 실측 Y를 그대로 평균하지 않습니다. 설계단차를 뺀 잔여를 비교하고 같은 설계단차를 다시 더합니다.

모드개발 계산표시할 검증 범위
절대 기준Y_ref=확정된 공통 기판/Teaching Y. T_y=Y_ref+d_yHead 간 단차와 외부 절대 Y 위치
상대 평균b_h=O_y−d_y. Y_ref=승인된 유효 Head 그룹의 평균Head 간 상대 정렬만. 공통 Y 이동은 식별 불가
계약으로 저장할 항목

Y 모드, 절대 기준의 출처·Revision 또는 평균 그룹, 설계 Y 단차, 유효 Head·제외 사유, 검증 허용값을 저장합니다. 상대 평균을 사용해 놓고 ‘기판 절대 Y 기준 완료’라고 보고하지 않습니다.
