01. 목적과 전체 컨셉

Head마다 원하는 파워가 실제로 나오는지 확인하고, 필요한 만큼 ATT를 조정한 뒤 다시 확인한다.

읽는 기준

현재 사용자 리뷰 요구, 10/22 회의 방향, 최신 Stage 인터페이스를 함께 사용했다. 아래의 내부 상태명·자료구조·기울기 유효성·문맥 관리 방식은 개발 권고이며, 실제 장비에 구현되었다는 뜻이 아니다.

구분이 자료에서의 의미
확정 요구매 가공 후 보정, 최초 수동 성공 Precheck, Manual 가공/ATT Init 후 재측정, Head별 Min/Max, 과대각 교체 분기, Stage 회피·출사 인터락.
개발 권고신규 샘플 식별, Head별 결과 문맥, 상태 전이, 안전한 국소 기울기 사용, 데이터 무효화·저장 방식.
계약 확인사용률 계산식, 99.9% 경계, 3회의 범위, 예열·에이징 시간, 초기각 원점, 실패 복구/요청 해제·Count 인계.

04. 측정 한 번은 어떻게 만드는가

안정된 시간 구간에서 새 계측값을 모아 Head별 평균을 계산한다. 화면 갱신 횟수는 샘플 수가 아니다.

// 개발 예시: 센서가 제공한 새 샘플을 Head별로 수집
// Run/Head 메타데이터는 어댑터의 현재 측정 문맥으로 연결한다.
if (!sample.IsValid || sample.ContextId != current.ContextId
    || sample.RunId != runId || sample.HeadId != head) {
  Reject("invalid sample or context"); return;
}
if (sample.Timestamp < collectStart || sample.Timestamp > collectEnd) {
  Ignore("outside measurement window"); return;
}
power_mW = ToMilliwatt(sample.Value, sample.Unit);
if (!IsFinite(power_mW) || power_mW < 0) {
  Reject("invalid power"); return;
}
// Run/Head별 집합. 앞서 받은 ID가 늦게 다시 와도 중복 계산하지 않는다.
if (!seenSampleIds[runId, head].Add(sample.SampleId)) {
  Ignore("duplicate sample"); return;
}
sum_mW[head] += power_mW;
freshCount[head] += 1;
mean_mW[head] = sum_mW[head] / freshCount[head];
구분필요 데이터·처리
계측기 예열메이커 기준 Ready 확인. 출사 후 안정화와 별개.
안정화 / Aging안정화 제외 시간은 출사 뒤부터 적용. Aging의 장비 내 의미·시점은 별도 정의.
유효 측정Head별 sum / freshCount / 시각 / 센서 상태 / 시도 ID 유지. 각 Head에 같은 count를 공통 사용하지 않음.
샘플 부족·무수신유효하지 않은 측정 결과. 0이나 이전 평균으로 대체 금지.
종료·냉각출사 차단 확인 후 필요한 냉각. 시간은 레이저/파워·계측기 권장 조건으로 확정.
3회 정도초기 측정 포함 총 Cycle인지 추가 보정 횟수인지 명시. 최대 횟수·미수렴·강제종료 처리도 설정.

05. 이전 각도와 파워로 다음 각도를 예측하기

“얼마 돌리면 파워가 얼마나 바뀌는가”를 최근 유효 데이터에서 추정한다.

s = (P2 - P1) / (theta2 - theta1);     // mW / degree
deltaThetaRaw = (Ptarget - Pmeasured) / s;
thetaCandidate = thetaActual + deltaThetaRaw;
// 필요 시 승인된 감쇠계수 g를 사용: delta = g * deltaThetaRaw
// 후보각도는 제한 검사 후 이동하고 반드시 실제 재측정한다.
상황개발 방향
유효한 기울기 있음같은 Head·윈도우/구간·광학/레이저 조건인지 확인 후 초기 예측에 활용. 현재 판 실측을 반영해 갱신.
같은 각도 두 점 / 너무 작은 Δθ분모 문제로 기울기 계산 금지. 최소 이동 폭·유효 기준을 설정.
기울기 부호 이상 / 값 너무 작음출력 반응·방향·포화/오류 확인. 대량 각도 이동 금지.
첫 기울기 없음승인된 초기 응답표 또는 작업자 확인/허용 소량 탐색의 운영안을 정함. 임의 기울기 1이나 타 Head 이력으로 대체하지 않음.
이전 판 두 점 활용판 간 오염/광학 변화가 ΔP에 섞일 수 있음. 사전 추정으로만 사용하고 현재 판 실측/재측정으로 검증.
1.7 / 1.2 / 0.7회의의 경험값. 곱/나눗셈 위치·갱신식·허용 범위가 미정이므로 승인된 상수로 하드코딩하지 않음.
다음 판 예측의 한계

다음 기판의 ATT가 교체 기준에 도달할지 사전 계산하는 기능은 필요하다. 다만 θ/P 두 점만으로 마모 속도까지 확정할 수는 없다. 저장 이력과 승인된 예측 규칙으로 예상값·근거·유효성을 함께 표시한다. 예측 실패를 “교체 불필요”로 처리하지 않는다.

11. 바로 구현할 수 있는 개발 단위

장치 통신, 계산, 상태 전이와 화면을 분리하면 실패 케이스를 먼저 시험하기 쉽다.

// 컨셉 의사코드. 장치 API가 아니며 실제 응답 계약을 연결해야 한다.
RunPowerCorrection(context):
  InvalidateCurrentPower(context, reason="measurement started")
  ValidateTargetAndConfig(context)
  RequireStageSafeAndStationary(context)
  for cycle in 1 .. Config.MaxMeasurementCycles:
    RequireEmissionPermit()         // 출사 중에도 계속 감시
    EmitAndWaitSettling()
    samples = CollectFreshSamplesByHead()
    LaserOffAndConfirm()
    result = ValidateAndAverage(samples)
    if !result.valid: return Fault(result.reason)
    if AllRequiredHeadsInTolerance(result):
      return CommitPassAtomically(context, result)
    slope = EstimateValidLocalSlope(context.history, result)
    if !slope.valid: return NeedApprovedInitialMethod()
    candidate = CalcCandidate(result, slope)
    decision = CheckLimitsAndExchangeCriteria(candidate)
    if decision.requiresExchange: return RequestPTW(decision.reasons)
    if !decision.moveAllowed: return Fault(decision.reason)
    MoveATTWithLaserOffAndConfirmArrival(candidate)
  return Fault("not converged within configured cycles")
// 실패/취소/예외 공통: LaserOff, 결과무효, NeedPower 유지, 이유 저장.
