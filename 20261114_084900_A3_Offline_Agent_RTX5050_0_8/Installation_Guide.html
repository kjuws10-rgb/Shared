RTX 5050에 맞춘
오프라인 코딩 실행 구성

VS Code · Cline · Qwen3-Coder 30B MoE를 연결하는 구성입니다. 대상 노트북은 RTX 5050 / VRAM 8GB / RAM 32GB로 반영했습니다. 세부 모델 주소와 GPU 파라미터는 준비 도구가 설정합니다.

실제 RTX 5050 개발 성능은 아직 검증하지 않았습니다.
현재 원격 준비 PC는 16GB RAM·920MX 환경입니다. 이 PC에서는 파일 준비와 호스트·모의 검사를 진행했습니다. 앞선 7B·9B 모델의 개발 과제는 미합격이었으며, 새 30B 모델도 실제 파일 수정·빌드·원복 시험에 합격했다고 표시하지 않습니다.

실제 파일 탐색·편집프로젝트 전체 검증 백업GPU 자동 탐지·점검일상 사용은 로컬 추론Pi 서버 불필요
두 단계 시작개발 흐름GPU와 모델다른 노트북검증 결과문제 해결
01

처음 준비, 이후 시작

준비가 끝나면 모델·포트·API key·GPU 레이어 수를 직접 입력하지 않습니다.

인터넷이 되는 곳 · 처음 한 번

처음 준비 실행

1_Initial_Setup_5050.cmd

실행 ZIP을 D:\A3Agent 같은 짧은 로컬 폴더에 풉니다. 모델·Editor·승인한 A3 코드와 실행 파일을 준비하고 GPU 상태를 확인합니다.

최초 모델 다운로드 약 18.6GB. 모델과 소프트웨어 준비에 여유 공간 40GB를 권장합니다. 프로젝트·자료·전체 백업 공간은 별도로 필요합니다.

필요할 때 Microsoft VC++ 설치 창과 Windows 권한 안내가 나옵니다. 폴더 신뢰 안내도 처음 한 번 출처를 확인합니다. 기존 프로젝트를 자동 reset/merge/push하지 않습니다.

현장 · 준비한 파일로

시작 후 자연어 요청

Start_5050.cmd

GPU·메모리·실행 파일을 확인한 뒤 전용 VS Code를 엽니다. A3 개발 시작 또는 Ctrl+Alt+A에서 기능을 입력합니다.

수정 전 전체 백업을 검증합니다. 모델이 현재 코드를 읽고 여러 파일을 수정하며 빌드 결과를 확인하는 흐름을 사용합니다. 작업 파일은 먼저 모두 저장합니다.

엔진 시작 성공과 기능 개발 성공은 다릅니다. 최종 변경 내용과 실제 검사 결과를 확인합니다.

02

목표는 기능 개발을 끝내는 흐름입니다

소스 설명뿐 아니라 실제 파일과 명령 결과를 기준으로 판단합니다.

처음에는 작은 실제 변경으로 확인하세요

Review 오차 레벨 상한을 사용자가 설정하도록 구현해줘. 현재 설정·저장·UI 구조를 먼저 읽고 같은 스타일로 수정해줘. 경계값과 설정 재로드를 검사하고, 빌드 실패는 고친 다음 실제 변경 파일과 검사 결과를 알려줘.

현재 코드·A3 개발 지침·빌드 결과를 작업 문맥으로 사용합니다. 이번 준비에서 모델 가중치 학습은 수행하지 않았습니다. 이전 Pi의 PDF/Office 가져오기 UI가 자동 이식된 구성도 아닙니다.

백업과 원복
시작·새 작업 전에 전체 프로젝트를 복사·SHA 검증합니다. 각 편집마다 전체 복사를 새로 만들지는 않습니다. Cline 체크포인트는 별도 코드 변경 이력이고, 전체 폴더 자동 복원 UI/CLI는 제공하지 않습니다. 실제 체크포인트 원복도 대상 노트북에서 추가 확인해야 합니다.
03

8GB GPU와 32GB RAM을 함께 사용합니다

모델 파일이 GPU 8GB 안에 전부 들어간다고 가정하지 않습니다.

항목이번 실행 프로필
모델Qwen3-Coder-30B-A3B-Instruct · Unsloth Q4_K_M · 18,556,689,568 bytes. 공식 Qwen 원본 모델과 Unsloth 양자화 배포를 구분합니다.
배치 전략MoE expert를 CPU/RAM에 두고 나머지 가능한 가중치·연산을 GPU에 배치하는 후보입니다. 실제 적재와 여유 메모리를 기동 시점에 확인합니다.
문맥과 메모리16K 문맥·단일 슬롯·Q8 KV cache·제한된 batch를 사용합니다. 실제 슬롯 문맥이 다르거나 여유가 정책에 못 미치면 기동을 통과시키지 않습니다.

자동 보호RAM·전용 VRAM·드라이버·모든 실행 파일 SHA·GPU 적재·문맥·로드 후 여유를 검사합니다. CPU로만 실행되면서 GPU 성공으로 표시하는 경로를 허용하지 않습니다.
시스템 변경NVIDIA 드라이버는 자동 설치하지 않습니다. Microsoft 실행 라이브러리는 처음 준비에서 필요할 때만 공식 설치 창으로 진행합니다.

이 표는 구현한 후보 설정입니다. 실제 RTX 5050에서 측정한 속도·GPU 메모리 사용량·코드 정확도는 아직 없습니다. 모델 생성 속도와 정답률을 같은 지표로 보지 않습니다.

04

다른 PC에서 준비해서 가져갈 때

개인 상태 파일에 이전 PC의 경로·프로세스 정보가 남지 않도록 새로 준비합니다.

  1. 준비 PC에서 ZIP을 풀고 Prepare_Only_5050.cmd 실행인터넷으로 파일만 준비합니다. GPU가 없는 준비 PC에서도 사용할 수 있으며, 모델 서버·GPU probe·Microsoft 설치 프로그램·Editor GUI를 시작하지 않습니다.
  2. 대상 노트북에 ZIP을 새로 해제준비 PC의 Editor, Models, 승인된 Project, 개인 준비용 Prerequisites 폴더를 복사합니다. 소스·자료 반입은 현장 절차에 맞춰 진행합니다.
  3. 개인 실행 상태는 복사하지 않기UserState, EditorData-*, Extensions-*, Backups, Cache는 새 PC에 자동 이식하지 않습니다. 이전 백업은 원래 위치에서 보존합니다.
  4. 대상 노트북에서 처음 준비를 한 번 확인모든 파일을 반입했다면 로컬 파일 검증과 GPU 확인을 진행합니다. 필수 파일이 빠지면 안내하고 중단합니다. 첫 설치 권한·폴더 신뢰 안내는 사용자가 확인합니다.

실행 ZIP에는 모델·Microsoft Editor·A3 장비 원본·개인 상태가 없습니다. 처음 준비에서 내려받거나 승인된 준비 파일을 복사합니다. 준비용 PC의 RAM/GPU를 현장 노트북 사양으로 기록하지 않습니다.

06

진행이 멈추면 표시된 원인부터 확인합니다

표시확인할 내용
가용 RAM·VRAM 부족큰 프로그램과 이전 모델 실행을 정리한 뒤 다시 확인합니다. 임계값을 무조건 낮추지 않습니다.
GPU/드라이버 확인 실패실제 RTX5050이 열거되는지 확인합니다. 임의 DLL 다운로드나 드라이버 자동 교체는 진행하지 않습니다.
모델·실행 파일 SHA 불일치부분 복사·손상·다른 버전 여부를 확인합니다. 검증되지 않은 파일로 이어서 실행하지 않습니다.
기존 서버 설정이 다름실행 중인 작업을 저장하고 종료 상태를 확인합니다. 다른 설정의 생존 서버를 임의 종료하지 않습니다.
설명만 하고 파일이 안 바뀜변경 비교와 실제 명령 기록을 확인합니다. 기능 개발 합격으로 집계하지 않고 과제·모델을 재평가합니다.

대형 모델 다운로드가 중단되면
같은 폴더에서 처음 준비를 다시 실행하면 정상적인 부분 파일을 이어받습니다. 임시 partial 파일과 sidecar 정보를 유지하세요. 잠금 회수 도중 강제 종료되어 guard가 남은 경우에는 임의 삭제하지 말고 표시된 원인을 확인합니다.
