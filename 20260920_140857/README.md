## 핵심 결론

1. 프로그램은 `.NET 8 / WPF` 기반이며 `UI → Common → File`의 3개 프로젝트가 중심입니다.
2. 가공 레시피는 두 층입니다. `JHMI_RCP.csv`가 항목의 형식·기본값·범위를 정의하고, `Config/RECIPE/*.csv`가 레시피별 실제 값을 저장합니다.
3. 레시피 값은 메모리에서 `ST_RECIPE_DEFINITION → Dictionary<string,string> → ST_SHOT_COORDINATE_PLAN → ST_PROCESS_MODEL` 순서로 변환되고, 마지막에는 Head별 Automation1 스크립트와 좌표 CSV가 됩니다.
4. 코드에서 실제로 동작하는 “리뷰 레시피”는 별도의 리뷰 CSV가 아니라, **선택된 가공 레시피에서 만든 전체 리뷰 계획 + 화면에서 고른 SIMPLE/ROUGH/FINE/EDGE 규칙**입니다.
5. `JHMI_REVIEW_RULE.csv`, `Config/ReviewRule/*.csv`, 가공 레시피의 `REVIEW_RULE_FILE` 값은 존재하지만, 현재 C# 실행 코드에서 읽는 로더가 없습니다. 즉, 파일은 있으나 실행 흐름에 연결되지 않았습니다.
6. 메인 자동 공정의 `INSPECTION` 단계는 아직 실제 리뷰를 실행하지 않습니다. REVIEW 화면에서 별도 시작해야 합니다.
7. REVIEW 화면의 Stage Y 이동과 Vision X 이동 명령은 연결되어 있지만, **Vision 측정 시작·결과 조회는 TODO이고 현재 항상 임시 난수 측정값을 반환**합니다. 실기 모드에서도 같은 코드 경로입니다.
8. 리뷰 결과를 읽어 `Vision 오차 → Scanner 보정량`으로 바꾸고 `CELLn_A1_REVIEW_OFFSET_X/Y` 형태로 가공 레시피에 다시 저장하는 보정 왕복 경로는 구현되어 있습니다. 다음 가공 준비 시 이 값이 좌표에 더해집니다.

## 기능 연결 상태

| 기능 | 상태 | 간단한 뜻 |
|---|---|---|
| 레시피 정의·읽기·저장 | 구현 | CSV와 메모리 모델 사이 변환이 있음 |
| 셀/모델별 Shot Group 좌표 생성 | 구현 | 회전, Pitch, DOE 중심, Head 배정 포함 |
| Masking/CHESS 판단 | 구현 | 실제 스크립트 생성 시 레이저 발진 생략에 반영 |
| Automation1 스크립트 생성·업로드·실행 | 구현 | Standard/Buffered Run 경로가 있음 |
| 메인 공정 `INSPECTION` → Review 자동 연결 | 미연결 | 현재 예약 로그만 기록 |
| Review Stage Y / Vision X 이동 | 명령 연결 | WonikCtrl 함수 명령을 전송 |
| Vision 실측 | 미연결 | 임시 난수값 사용 |
| Review 결과 CSV 저장 | 구현 | 날짜 폴더 아래 저장 |
| Review 결과 → 레시피 보정값 저장 | 구현 | CORRECTION 화면에서 Load/Calculate/Apply/Save |
| 리뷰 규칙 CSV 로딩 | 미연결 | 화면의 메모리 설정이 실제 규칙 소스 |

## 빌드 확인 결과

- 원본과 별개의 검증용 복제본에서 `Drilling.UI/Drilling.UI.csproj` Release 빌드: **성공**, 오류 0개, 경고 2개.
- 경고는 `CRootView.CanAccessMenu()`가 첫 줄에서 항상 `true`를 반환하여 뒤 코드가 도달 불가라는 내용입니다.
- `Drilling.sln` 전체 빌드: **실패**. 솔루션이 참조하는 `Drilling.Regression`과 `Drilling.UI.Regression` 프로젝트 파일이 저장소에 없습니다.
- 실제 장비 연결, 레이저 발진, Stage/Vision 실동작 시험은 수행하지 않았습니다.
