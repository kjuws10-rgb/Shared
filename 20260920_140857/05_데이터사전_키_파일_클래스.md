# 데이터 사전 — Key·파일·클래스

## 1. 가장 중요한 데이터 객체

| 객체 | 한 줄 설명 | 만들어지는 곳 | 다음 사용처 |
|---|---|---|---|
| `ST_RECIPE_FORM_ITEM` | 레시피 항목의 형식·단위·범위 | `JHMI_RCP.csv` 로드 | Recipe Parameter 생성·UI 검증 |
| `ST_RECIPE_VALUE` | CSV 한 줄의 단순한 Tab/Name/Value | Recipe CSV 파싱 | Form Item과 합치기 |
| `ST_RECIPE_PARAMETER` | 값과 표시·검증 정보를 합친 한 항목 | `CJhmiRecipeFile` | UI, 좌표 계산, 저장 |
| `ST_RECIPE_DEFINITION` | 한 레시피 전체 | `CRecipeManager` | Process/Review 시작점 |
| `ST_CELL_PATTERN_DEFINITION` | Cell 하나의 위치·회전·모델 격자 입력 | 좌표 Builder | Cell Pattern 계산 |
| `ST_SHOT_GROUP_CENTER` | Cell 안 Shot Group 중심 한 점 | `CCellPatternCalculator` | Head 배정 |
| `ST_HEAD_SHOT_POINT` | Head·Stage·Scanner·Offset이 모두 붙은 가공점 | `CShotCoordinatePlanBuilder` | Process Model, Script |
| `ST_HEAD_PROCESS_PLAN` | Head 하나의 조건과 Shot 목록 | `CStationProcess` | Script 생성·실행 |
| `ST_PROCESS_MODEL` | 한 번의 가공 실행 스냅샷 | `CStationProcess` | 자동 공정 전체 |
| `ST_REVIEW_PLAN_POINT` | Review 한 점의 목표·결과·상태 | `CReviewManager` | 이동·측정·결과 저장 |
| `ST_REVIEW_PLAN` | 한 번의 Review 실행 계획 | `CReviewManager` | Review 시퀀스 |
| `ST_REVIEW_RESULT_FILE_ROW` | 결과 CSV를 읽은 한 행 | `CReviewResultFile` | Correction |
| `ST_PRODUCT_DATA` | 현재 Glass의 공정·정렬·Review 전체 상태 | `CProductManager` | 화면·복구·이력 |

## 3. `ST_HEAD_SHOT_POINT` 필드 해설

| 필드 | 쉬운 뜻 |
|---|---|
| `SequenceNo` | 최종 가공 순서 번호 |
| `ShotKey` | 내부 가공 Key, 예: `CELL001_SHOT0001` |
| `HeadNo` | 담당 Head 번호 |
| `CellNo` | Cell 번호 |
| `ShotGroupNo` | Cell 안 Shot Group의 일련번호 |
| `GroupColumn`, `GroupRow` | 0부터 시작하는 열·행 |
| `GroupCountX`, `GroupCountY` | 해당 Cell의 전체 Shot 열·행 수 |
| `DesignX`, `DesignY` | 글라스 설계 좌표 |
| `ScannerGx`, `ScannerGy` | 최종 Scanner 이동 좌표 |
| `StageX`, `StageY` | Stage 기준 좌표 |
| `RecipeOffsetX/Y` | Shot별 수동 Recipe 보정 |
| `HeadDefaultOffsetX/Y` | Head 기본 보정의 원래 값 |
| `ReviewOffsetX/Y` | Review 결과로 저장된 누적 보정 |
| `FinalScannerOffsetX/Y` | 실제 Scanner에 더한 세 Offset의 합 |
| `EncoderWaitPosition` | 이동 Stage와 동기화할 Encoder 대기값 |

## 6. 실행 시 Recipe를 덮어쓰는 Setting Key

`CStationProcess`와 `CReviewManager` 모두 Recipe Dictionary를 만든 후 OPTION/MOTOR 값을 넣습니다. 같은 Key는 Setting 값이 최종값입니다.

특히 확인할 Setting:

| Key | 영향 |
|---|---|
| `Hxx_USE` | Head 활성 여부 |
| `H01_AK_POSITION_X`, `HeadGapX` | 모든 Head 중심 X |
| `REVIEW_TO_HEAD1_GAP_Y`, `HeadGapY` | Head 중심 Y 기본값 |
| `Hxx_SCAN_FIELD_WIDTH_X` | Head 배정 범위 |
| `Hxx_STAGE_X_TO_GX_SIGN` | Review Offset X 방향 |
| `Hxx_STAGE_Y_TO_GY_SIGN` | Review Offset Y 방향 |
| `VisionXFlip`, `VisionYFlip`, `VisionXyFlip` | Vision Error 변환 |
| `AUTO_PROCESS_USE`, `AUTO_INSPECTION_USE` 계열 | 공정 단계 Skip 여부 |
| `SCRIPT_BUFFERED_RUN_USE` | Standard/Buffered 실행 선택 |

## 7. Key·이름 대응표

물리적으로 같은 첫 번째 Shot Group을 여러 계층에서 다르게 부릅니다.

| 계층 | 형식 | 예 |
|---|---|---|
| Process 내부 | `CELL{000}_SHOT{0000}` | `CELL001_SHOT0001` |
| Review 내부 | `CELL{000}_HOLE{0000}` | `CELL001_HOLE0001` |
| Review/Recipe 행렬 | `CELL{n}_{ColumnLetters}{Row}` | `CELL1_A1` |
| Recipe Offset | 위 Prefix + `_RECIPE_OFFSET_X/Y` | `CELL1_A1_RECIPE_OFFSET_X` |
| Review Offset | 위 Prefix + `_REVIEW_OFFSET_X/Y` | `CELL1_A1_REVIEW_OFFSET_Y` |
| Automation 표시 | `{RowLetters}{Column:00}` | `A01` |

행렬 변환 예:

| GroupColumn(0 시작) | GroupRow(0 시작) | Review/Recipe 이름 | Automation 표시 |
|---:|---:|---|---|
| 0 | 0 | `A1` | `A01` |
| 1 | 0 | `B1` | `A02` |
| 0 | 1 | `A2` | `B01` |
| 26 | 0 | `AA1` | `A27` |

## 8. 주요 상태 Enum

### 가공

```text
EN_PROCESS_STEP
Idle → PreCheck → OpticReady → PowerCheck → Align
     → Process → Inspection → Completed
     또는 Stopped / Error
```

### Script

```text
NotCreated → Created → Running → Completed
                      또는 Stopped / Error
```

### Review Point

```text
Ready → Current → Ok / Ng
Skip는 이번 Plan에서 실행하지 않는 점
```

### Review Sequence

```text
Idle → Running → Completed
             ↘ Stopping → Stopped
             ↘ Failed
```

### Product Review

```text
NotStarted → Running → Completed / Stopped / Error
```

## 9. Review 결과 CSV 사전

| 열 | 뜻 | Correction 사용 여부 |
|---|---|---|
| `SAVED_AT` | 저장 시각 | 파일 정보 |
| `RECIPE_ID` | 결과가 속한 Recipe | 선택 Recipe 일치 검증 |
| `RULE` | DIRECT/SIMPLE/ROUGH/FINE/EDGE | 표시·추적 |
| `RESULT_SOURCE` | MEASURED/COPIED/INTERPOLATED | 표시·추적, Apply 필터에는 사용 안 함 |
| `SHOT_NAME` | A1 등 행렬명 | 표시 |
| `ROW`, `COLUMN` | 1부터 시작하는 행·열 | 표시 |
| `DESIGN_X/Y` | 글라스 설계 좌표 | 파일 추적용 |
| `HOLE_KEY` | `CELL1_A1` | Recipe Offset Key 생성에 핵심 |
| `HEAD_NO` | Head 번호 | Vision→Scanner 부호 변환 |
| `CELL_NO` | Cell 번호 | Key 보완 |
| `ERROR_X/Y` | Vision 오차 | 보정량 계산 |
| `JUDGE` | OK/NG | 표시 상태, 현재 Apply 제외 조건은 아님 |

필수 헤더는 `SAVED_AT, RECIPE_ID, HOLE_KEY, HEAD_NO, CELL_NO, ERROR_X, ERROR_Y, JUDGE`이고, 나머지는 없어도 로드할 수 있습니다.

## 12. 헷갈리기 쉬운 이름

| 코드 이름 | 실제 의미 |
|---|---|
| `Hole` | Review에서 개별 Pixel이 아니라 Shot Group |
| `PixelCountX/Y` in Review Point | 원 Pixel 수가 아니라 GroupCountX/Y |
| `SPLITED_BEAM_COUNT` | 총 Beam 수가 아니라 한 축 Beam 수 |
| `ALL HOLE` | 모든 Shot Group에서 선택 Beam 하나씩 |
