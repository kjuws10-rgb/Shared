정리된 개발 컨셉

“각 카메라의 기존 교정값으로 픽셀을 mm로 변환하고, 실제 촬영 Pose를 제거해 같은 기준에 모은다. Align OK Benchmark와의 위치 차이를 좌우 구간 선형 모델로 연결해, 기준 가공 좌표에 더한다.”

촬영 구조: AK는 4대 카메라로 측정합니다. DK는 주행 Y축으로 기판을 이동하면서, 이 4대 중 주행 방향 쪽의 좌우 2대로 중앙 부근 세 쌍을 차례로 측정합니다. 새 DK 전용 카메라 교정을 만드는 방식이 아니라, 해당 2대의 기존 교정과 각 Grab 시점의 실제 이동량을 함께 활용하는 구조입니다. 실제 Camera ID와 Key 대응은 레시피로 명시합니다.

“Local 글로벌 좌표”라는 한 표현은 나누어 쓰는 것이 좋습니다. FOV 중심을 원점으로 한 좌표는 ‘FOV 기준 평면 mm’, 설비 원점 기준은 ‘기계 글로벌 mm’로 명시합니다. FOV 중심이 원점이라는 사실만으로 X/Y축 방향까지 같아지는 것은 아닙니다.

π([a,b,w])=(a/w,b/w)는 동차좌표의 마지막 값으로 나누는 연산입니다. H는 평면 간 3×3 변환이며 물리 mm는 교정 대응점의 목적 좌표에서 정해집니다. OpenCV Homography

기존 교정의 목적 좌표가 ‘움직인 마크의 실제 평면 위치’인지 ‘Stage 명령값’인지 확인합니다. 두 값은 부호·회전 중심에 따라 다릅니다. H 하나를 얻었다는 사실만으로 FOV 글로벌 위치까지 검증됐다고 보지는 않습니다.

4. Benchmark를 0으로 두는 방법

기준 기판 등록

  1. Model / Recipe와 교정 버전을 확인합니다.
  2. 검증·승인한 기준 기판을 Align OK 상태로 만듭니다.
  3. AK와 DK의 픽셀·실제 촬영 Pose·상태를 저장합니다.
  4. 공통 Ready mm로 변환한 위치 qB,i를 Benchmark 버전으로 고정합니다.
  5. 기준 가공 경로가 해당 Benchmark에 맞는지도 별도로 확인합니다.

후속 기판 보정

  1. 같은 Model의 유효한 Benchmark를 선택합니다.
  2. 현재 AK/DK를 같은 공통 Ready 좌표로 변환합니다.
  3. di = qCurrent,i − qBenchmark,i를 구합니다.
  4. 활성 Key의 실제 편차를 그대로 연결합니다.
  5. 기준 가공 경로에 상대 변위 지도를 더합니다.
Benchmark=0의 정확한 의미

“기준 기판과의 차이가 0”입니다. 최초 기판이 CAD와 완전히 같거나 미측정 내부에 변형이 없다는 뜻은 아닙니다. 기준판 자체의 절대 형상 오차를 없애려면 별도 기준 측정이 필요합니다.

AK는 Align에 쓰였어도 변형 정보가 남습니다

X·Y·θ의 강체 정렬로는 팽창·수축·전단까지 사라지지 않습니다. Align 이후 AK 잔차도 실제 값으로 보존합니다. 네 AK를 무조건 0으로 만들거나, 매 기판에 전체 Homography를 다시 맞춰 모두 설계점에 일치시키면 보정하려던 변형까지 지울 수 있습니다.

AK가 Align 이전의 값이면 실제 실행된 Align 변환을 한 번 적용해 Align 이후 DK와 맞춥니다. 실제 Align 후 AK 재측정값이 있으면 그 값을 우선 사용할 수 있습니다. 이미 완료된 Align을 다시 더하거나, 전후 관측을 그대로 섞지 않습니다. 변환으로 예측한 Align 후 AK와 실제 재측정값은 출처를 구분합니다.

동일 Pose일 때의 단순식과 일반식
일반식: di = TCurrent,i⁻¹ Fc(pCurrent,i) − TBenchmark,i⁻¹ Fc(pBenchmark,i) 같은 H·같은 Camera·같은 Pose이면: di = Rᵀ [ Fc(pCurrent,i) − Fc(pBenchmark,i) ] 회전도 없고 FOV 축이 기계축이면: di = H로 각각 환산한 local mm의 차이 설계 위치에 붙인 표현: qEquivalent,i = qDesign,i + di → 이는 상대 보정용 대응 위치입니다. Benchmark 실제 위치가 설계와 다르면 현재 실제 좌표 qCurrent,i와는 다릅니다.

현재 실제 위치는 qCurrent,i = qBenchmark,i + di입니다. 설계값은 실제 Benchmark 좌표를 대체하지 않습니다. 동일 Pose가 보장되지 않는 일반 경로를 먼저 구현하고, 조건을 만족할 때만 빠른 경로로 단순화하는 것을 권합니다.

5. 좌우를 먼저 잇고, 가운데를 연결합니다

권장 기본안: Y 구간 선형 + X 선형 연결. 각 측면에서 가까운 두 Key 사이를 직선으로 이은 뒤, 가공점이 왼쪽과 오른쪽 사이의 어디에 있는지에 따라 두 값을 섞습니다. X변위와 Y변위를 각각 같은 방법으로 계산합니다.

① 왼쪽의 변화

AK1 → DK1 → DK2 → DK3 → AK2를 Y순서로 잇습니다.

② 오른쪽의 변화

AK3 → DK4 → DK5 → DK6 → AK4를 Y순서로 잇습니다.

③ 내부 가공점

같은 Y의 좌우 보정값을 구하고 X위치 비율로 연결합니다.

이 식은 구간별 1차 라그랑주 보간으로도 설명할 수 있습니다. 양측의 Y배열이 같으면 각 구간의 네 꼭짓점 변위를 사용하는 bilinear 연결입니다. 좌우 Y가 다르면 각각 자기 배열에서 인접점을 선택합니다. 좌우 Y목록의 합집합으로 구간을 나누어 검증할 수 있습니다.

범위 안에서는 비음수 가중치의 합이 1이므로, 각 변위 성분이 해당 구간 측정값의 최솟값~최댓값을 넘지 않습니다. 이는 수식에서 직접 얻는 성질입니다. 실제 내부가 그 범위 안이라는 측정 증거를 새로 만드는 것은 아닙니다. SciPy 선형 격자 보간 참고

보간 영역: X는 두 Key 열 사이, Y는 양쪽 활성 노드 범위가 겹치는 구간입니다. Key 열과 물리 Glass 엣지는 다를 수 있습니다. 바깥은 기판 안에 있더라도 외삽이며, 임의 0이나 자동 연장으로 정상 좌표를 만들지 않는 정책을 권합니다.

6. 측정이 완벽해도 안쪽 모양은 하나로 정해지지 않습니다

좌우 Key가 모두 같은 위치에 있어도, 가운데만 더 휘어진 기판이 있을 수 있습니다. 보간은 미측정 위치를 잇는 명시적인 모델입니다. 이 한계를 측정 노이즈 탓으로 설명하지 않습니다.

선택하면 주황 점선이 추가됩니다. 이 기판은 모든 측면 AK/DK에서 파란 기판과 정확히 같지만 가운데 Y변위는 최대 0.18 mm 다릅니다. 주황선은 반례를 위해 만든 가상 정답이며, 이번 10점으로 발견한 실제 내부 형상이 아닙니다.

왜 같은 측정값에서 다른 내부가 가능한가
t = (x − xL)/(xR − xL), r = (y − y0)/(y1 − y0) v(x,y) = (0, 4A·t(1−t)·sin(πr)), A=0.18 mm 왼쪽 t=0, 오른쪽 t=1에서는 항상 v=0 → 모든 양측 AK/DK의 관측은 동일 가운데 t=0.5, r=0.5에서는 vY=A → 안쪽은 다를 수 있음

이 반례와 보간의 수학 성질은 이번 컨셉을 위한 직접 유도입니다. 실제 내부 검증에는 별도 중앙 측정점이나 가공 자국 등 보간에 사용하지 않은 위치의 데이터가 필요합니다. 같은 Key를 다시 정확히 맞추는 것만으로 라그랑주·선형·TPS의 내부 우열을 정할 수는 없습니다.

7. SVD와 보간은 담당하는 문제가 다릅니다

SVD: 카메라의 자를 만듭니다

교정 때의 물리 위치와 픽셀 대응으로 A·h=0을 만듭니다. 그 조건을 가장 잘 만족하는 H의 계수 9개를 구할 때 최소 오른쪽 특이벡터를 사용합니다.

보간: Key 사이를 연결합니다

공통 mm로 환산한 현재–Benchmark 차이에서 내부 변위를 만듭니다. 기본 선형 연결은 작은 특잇값 공간을 따로 고르지 않아도 계산됩니다.

따라서 이번 컨셉에서는 “SVD로 구한 H는 공통 좌표변환에 재사용하고, 기판 변형은 우선 구간 선형으로 잇는다”가 명확합니다. ‘라그랑주 vs 라그랑주+SVD’라는 옵션명만으로는 어느 부분이 달라지는지 알기 어렵습니다.

사용자 설명의 SVD·호모그래피 방식은 정당한가
A = UΣVᵀ h = argmin ||A·h||², 단 ||h||=1 → 최소 특잇값 방향의 오른쪽 특이벡터 → 특잇값이 내림차순이면 Vᵀ의 마지막 행을 3×3으로 reshape → 정규화한 대응점으로 계산했다면 목적·입력 정규화를 역반영해 H 복원

이 특정 목적식에서는 정당합니다. Vᵀ의 마지막 벡터 하나의 9성분을 H로 배열합니다. H 자체가 직교 회전행렬이라는 뜻은 아닙니다. 최소 특잇값이 ‘영향력이 적으므로 어떤 최적화에도 좋은 공간’이라는 일반 결론으로 확대하지 않습니다. MIT Homographies의 DLT 설명

  • 일반 3×3 H는 스케일을 제외하고 8자유도입니다. 카메라마다 적절히 분포한 2D 대응점이 필요합니다. 한 직선의 Y 이동만으로는 전체 H가 퇴화할 수 있습니다.
  • 4대 카메라가 있다는 것이 각 카메라의 H에 필요한 4개 대응점을 대신하지 않습니다. UVW의 다양한 실제 위치에서 각 카메라 안에 생긴 대응을 사용합니다.
  • 최소4점의 A는 8×9입니다. economy SVD가 필요한 영공간의 9번째 벡터를 빼는 구현인지 확인합니다. FULL_UV 또는 검증된 solveZ 경로를 사용할 수 있습니다. OpenCV SVD, NumPy full/reduced 차이
  • 노이즈0 전제에서도 단위 차이·수치 반올림·랭크 부족은 확인합니다. 좌표 정규화와 독립 위치에서의 환산 검증은 관측값을 평탄화하는 작업이 아닙니다.
기판 보간 후보무결한 Key 보존이번 개발에서의 역할
구간 선형 + 좌우 선형활성점 정확 통과첫 구현 권고. 국소적이고 설명·디버깅이 쉽습니다. 구간 경계에서 기울기는 바뀔 수 있습니다.
측면 전체 라그랑주활성점 정확 통과비교 후보. 관측 사이 진동이 생길 수 있고 한 점 변화가 측면 전체에 영향을 줍니다. 노이즈0이어도 생기는 모델 특성입니다.
측면 PCHIP + 좌우 연결활성점 정확 통과기울기 연속이 가공 요구일 때 비교할 2차안. 성분별 형상 보존이 실제 2D 형상이나 접힘 방지를 자동 보장하지는 않습니다. 공식 특성
TPS 등 전체 면 + SVD 풀이정확 제약 설정 시 통과최소 굽힘 같은 다른 내부 가정입니다. 실제 내부 검증 자료가 있을 때 비교합니다. SVD 계산 자체가 우수성을 뜻하지 않습니다.

α<1의 ‘약한 보정’이나 자동 평활화를 기본으로 넣으면 측정한 편차를 그대로 재현하는 계약이 깨집니다. 이번 전제에서는 측정값을 보존하고 연결 방법과 검증 범위를 명시하는 편이 적합합니다.

8. 개발은 좌표 변환부터 작게 검증합니다

가공점에는 어느 방향으로 적용하는가

설계 재료 위치 s에서 검증된 기준 가공경로를 B(s)라 할 때: 현재 가공 목표 QCurrent(s) = B(s) + u(s) B(s)=s라는 계약일 때만 Q=s+u(s)로 단순화합니다. 변위 u는 같은 설계 재료 위치 s에서 평가합니다. 기준 경로의 글로벌 숫자를 곧바로 보간 입력으로 쓰려면 설계축 대응이 필요합니다.

가공은 기준 재료점이 현재 이동한 방향으로 +u만큼 따라갑니다. 영상을 기준 모양으로 되돌리는 역변환과 목적이 다릅니다. 일반적으로 역변환이 단순히 p−u(p)가 되는 것은 아닙니다.

기존 v6의 좌표 어댑터 계약이 그대로 유효하다면 GY'=GY+uX, GX_STAGE'=GX_STAGE−uY로 전달합니다. 이는 이번에 장비 부호를 새로 확정한 것이 아닙니다. 기존 Head·순서·Gate·120 mm 등 오프셋은 중복 적용하지 않으며, 이 문서는 Masking/DOE/축 동기화를 새로 구현하지 않습니다.

선형 지도의 접힘 검사를 구현하려면

기준 지도가 항등인 F(s)=s+u(s)에서는 det(I+Du)>0를 확인합니다. 각 bilinear 구간 안에서 이 행렬식은 x,y의 affine 함수이므로 각 구간 네 모서리의 단측 기울기를 검사해 구간 내부의 국소 접힘을 판정할 수 있습니다. 구간 경계 양쪽을 각각 확인합니다. 이 성질은 직접 유도한 것이며, 멀리 떨어진 구간끼리 겹치지 않는다는 보장은 아닙니다.

기준 실제 지도 B(s)가 항등이 아니면 det(DB+Du)를 검토해야 합니다. 기준 경로를 갖고 있다는 이유만으로 전체 면의 DB를 이미 알고 있다고 가정하지 않습니다. 장비의 속도·가속도·스캐너 범위·DOE footprint는 별도의 가공 검증입니다.

누적 데이터로 좋아질 수 있는 부분

같은 Model에서 독립 내부 검증 결과가 쌓이면 선형/PCHIP/TPS 중 어떤 연결이 맞는지 비교할 근거가 생깁니다. 10개 Key만 계속 정확히 맞춘 기록으로 내부 모델의 최적성을 자동 학습했다고 할 수는 없습니다. 검증용 기판과 향후 적용 기판을 나누고, 승인된 Benchmark 버전은 유지합니다.

10. 개발자에게 전달할 컨셉 요약

목적: Align OK 기준 기판을 Benchmark로 두고 후속 기판의 상대 변형을 가공 좌표에 반영한다.

입력: AK4+DK6/4/2의 pixel, 기존 카메라 H, Camera/FOV 배치, 촬영 순간 실제 Y·UVW Pose, Key 설계치와 Benchmark.

처리: pixel→기계 mm→Align 완료 Ready mm→Benchmark 차이→좌우 Y 구간 선형→X 선형 연결.

출력: 같은 설계 재료 위치에서 평가한 변위를 검증된 기준 가공 경로에 더한 좌표와 적용 범위·버전 기록.

첫 개발: 한 Key의 좌표 정합성을 검증한 뒤 상대 변위와 선형 지도를 구현한다. 기존 SVD-H는 활용하고, 전체 내부를 복원했다는 주장은 독립 내부 검증 전까지 하지 않는다.

구현 전에 확인할 네 가지

  1. 현재 H의 입력 방향과 출력이 FOV local mm인지 기계 global mm인지, 교정 목적 좌표의 정확한 정의.
  2. DK Grab 시점의 실제 메인 Y Encoder와 UVW Pose를 Frame/Trigger ID에 연결해 받을 수 있는지.
  3. AK 값이 Align 전/후 중 어느 시점인지, 실제 실행된 Align 변환 또는 후 재측정값이 있는지.
  4. Benchmark에 맞춰 검증된 기준 toolpath와 설계 재료 위치의 대응이 있는지.

이 네 가지는 컨셉을 보류하기 위한 추가 옵션이 아니라, 개발 모듈의 입력 계약입니다. 현재 설명만으로 합리적인 설계안을 제시했으며 실제 교정 원자료나 생산 좌표계의 정확도를 검증한 것은 아닙니다.
