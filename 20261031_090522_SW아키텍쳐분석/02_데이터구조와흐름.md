# 데이터 구조와 저장 형식

## 새로 생긴 데이터는 파일이 아니라 메모리 진단입니다

새 ST_MELSEC_POLLING_DIAGNOSTIC은 한 번의 SDK 읽기를 공유하는 블록의 상태를 복사한 record입니다. [정의](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/99d78ddf0e680b55dbd9662764b71a1ffe93a457/Drilling.Common/Interface/Melsec/CMelsec.Polling.cs#L16-L29), [조회](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/99d78ddf0e680b55dbd9662764b71a1ffe93a457/Drilling.Common/Interface/Melsec/CMelsec.Polling.cs#L54-L76), [갱신](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/99d78ddf0e680b55dbd9662764b71a1ffe93a457/Drilling.Common/Interface/Melsec/CMelsec.Polling.cs#L279-L354).

| 필드 묶음 | 의미 |
| --- | --- |
| DeviceNo·Address·WordCount·PollMs·Ids | 어느 장치의 어떤 블록이며 어떤 화면 행들이 공유하는지 |
| State·AttemptNo·IsReading | 캐시 상태, 시도 번호, 현재 읽는 중 여부 |
| LastAttemptStartedAt·CompletedAt | 최근 블록 처리 시작·종료 시각, 읽는 중에는 종료 미확정 |
| LastSuccessfulUpdateAt | 마지막 정상 블록 수신 반환 직후 기록한 기준 시각 |
| LastAttemptDurationMs | 블록 처리 전체 소요, 변환·캐시 게시 등도 포함 |
| LastUpdateIntervalMs | 최근 두 성공 수집 사이의 간격 |

시작·종료 시각은 UTC, 기간·간격은 Stopwatch의 단조 시계를 사용합니다. 수신 기준 시각은 ReadWords 반환 직후, 변환·캐시 게시 전에 잡으며 UpdatedAt과 LastSuccessfulUpdateAt에 같은 값을 기록합니다. 엄밀한 캐시 게시 완료 시각은 아닙니다. GetPollingDiagnostics는 로컬 진단을 복사할 뿐 통신을 만들지 않으며 외부에서 Ids/목록을 바꿀 수 없도록 제공합니다. 기존 ST_MELSEC_CACHED_VALUE의 Id·Value·State·UpdatedAt·ReadCycleNo·ErrorMessage 계약은 그대로입니다.

맵을 다시 로드하면 새 블록이 만들어져 진단도 초기화됩니다. 반면 재연결은 이전 성공 시각을 보존하므로 성공 갱신 간격에 오프라인 기간이 포함될 수 있습니다. 또 2초 backoff는 배경 Poll의 재시도 제한이지 모든 직접 Read/Write/Readback의 전역 제한은 아닙니다.

화면 행에는 ReceivedAt·PresentedAt·ReceiveAgeMilliseconds·FeedbackTimingDescription이 추가됐습니다. 이는 WPF 표시 모델의 메모리 값으로 Recipe CSV·ReviewResult·Product에 새 열로 저장되지 않습니다. [행 모델](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/99d78ddf0e680b55dbd9662764b71a1ffe93a457/Drilling.UI/Menu/Menus/CMenuMonitor.cs#L6092-L6146).

## 값 나이와 통신 지연의 차이

| 지표 | 실제 의미 | 잘못된 해석 |
| --- | --- | --- |
| 캐시 UpdatedAt | 정상 블록 ReadWords 반환 직후 잡은 수집 기준 시각 | PLC 내부 값 생성 시각 또는 캐시 게시 완료 시각 |
| PresentedAt | 화면 모델에 값을 적용한 시각 | 실제 화면 그리기 완료 시각 |
| ReceiveAge | UI 적용 시각 − 캐시 수집 완료 시각 | 순수 네트워크 왕복 시간 |
| 블록 처리 소요 | 현재 블록 시도 전체 시간 | SDK 호출 부분만의 시간 |
| 성공 갱신 간격 | 같은 블록의 최근 성공 간격 | 주소의 값이 실제로 변한 간격 |

수집이 오래 걸린 직후에는 Age가 작을 수 있습니다. 값 projection과 블록 진단도 따로 가져오므로 동일 시도의 원자적 추적 한 세트가 아닙니다. Age·성공 간격·처리 소요를 함께 보아야 합니다.

## 보정 파일과 새 진단을 혼동하지 않기

Review Offset의 기존 열은 CELLID, SHOTID, REVIEWOFFSETX, REVIEWOFFSETY, COORDINATE_SPACE입니다. 새 형식에서 DESIGN으로 저장한 값은 가공 준비 시 Scanner 방향으로 바꾸고, 구4열 파일은 기존 SCANNER 해석을 사용합니다. 이번 진단 정보는 이 파일에 붙지 않습니다. [좌표계 소비](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/99d78ddf0e680b55dbd9662764b71a1ffe93a457/Drilling.Common/Recipe/CReviewOffsetData.cs#L7-L40).

Product의 Review 결과는 ShotKey·HeadNo·CellNo·BeamNo·ErrorX/Y·Judge 등을 연결합니다. 빠른 Monitor 갱신은 이 결과를 새로 만들거나 보정 파일을 자동 저장하지 않습니다. Product Active는 TYPE·NAME·VALUE, History는 시각·기판/공정/Recipe·동작·상태·판정 등 기존 CSV 형식을 유지합니다. [Product 파일](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/99d78ddf0e680b55dbd9662764b71a1ffe93a457/Drilling.File/Product/CProductFile.cs#L5-L14), [Review 결과 연결](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/99d78ddf0e680b55dbd9662764b71a1ffe93a457/Drilling.Common/Review/CReviewManager.cs#L929-L966).

파일을 바꾸지 않으므로 이번 버전만을 위한 데이터 변환 작업도 없습니다. 단, 기존 파일·Simulation 출처·Revision의 승인 문제는 그대로 남습니다.
