# 위험도별 발견사항

이번 diff와 장비 없는 회귀 시험에서는 새 장비 제어 결함을 재현하지 않았습니다. 아래는 배포 전 확인할 위험과 이번 변경으로 해결되지 않은 경계입니다. “높음”은 검수 우선순위이며 실제 현장 장애 발생을 단정한 등급이 아닙니다.

| 번호 | 우선순위 | 구분 | 발견 내용과 영향 | 필요한 확인 |
| --- | --- | --- | --- | --- |
| F01 | 높음 | 신규 동작의 trade-off | Readback 대기 중 일반 Read가 새로 가능해짐. 그 동기 Read가 길면 다음 Write 확인이 늦어질 수 있음 | 지연 Read와 Write 응답 대기·Timeout·Stop을 함께 현장 계측 |
| F02 | 높음 | 배포 계약 | 새 UI가 Common.GetPollingDiagnostics API를 호출 | UI/Common/File을 동일 버전 세트로 배포, 구 DLL 혼합 금지 |
| F03 | 높음 | 기존 한계 유지 | native 한 호출이 멈추면 8ms 묶음 제한이나 Stop 검사로 중단할 수 없음 | 실제 SDK/보드의 호출·Timeout·복구 동작 검수 |
| F04 | 중간 | 성능 검수 | 활성 UI에서 10Hz 캐시/맵 복사와 진단 문자열 구성, 기존250ms projection도 남음 | CPU/GC·스크롤·입력·UI 부하 시 수집/표시 간격 측정 |
| F05 | 중간 | 진단 해석 | Age가 낮아도 성공 수집 간격은 길 수 있음. 값과 진단은 별도 snapshot | Age·블록 소요·갱신 간격을 함께 판단 |
| F06 | 중간 | 시간·화면 경계 | Background 타이머는100ms 보장이 아님, ViewModel 적용은 paint 완료가 아님 | Dispatcher와 실제 화면 그리기 별도 계측 |
| F07 | 중간 | 기존 공정 계약 | 새 값을 더 빨리 읽어도 짧은 신호 Pulse·같은 Glass/Frame·PLC 생성시각은 보장하지 않음 | 신호 유지/ACK·측정세대·시각 계약 검수 |
| F08 | 기존 중요 잔건 | 이번 해결 아님 | 실제 Review 이동·0선 Coordinator·LastLoad 주소·보정 승인/Revision 경계 | 이전 기준 분석의 잔건을 유지하고 별도 구현·실기 검수 |

## F01과 F03의 정확한 범위

최대4블록/8ms는 추가 Poll을 계속할지 판단하는 정책입니다. 첫 Poll은 대기 제어가 있더라도 기회를 가지며, 이미 시작한 native 호출을 끊지 않습니다. “8ms 안에 제어에 복귀” 또는 “Write가 언제나 우선”이라는 보장은 없습니다. [묶음 정책](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/99d78ddf0e680b55dbd9662764b71a1ffe93a457/Drilling.Common/Interface/Melsec/CMelsec.Polling.cs#L261-L277), [일반 Read 처리](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/99d78ddf0e680b55dbd9662764b71a1ffe93a457/Drilling.Common/Interface/Melsec/CMelsec.cs#L890-L900), [Readback·양보 조건](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/99d78ddf0e680b55dbd9662764b71a1ffe93a457/Drilling.Common/Interface/Melsec/CMelsec.cs#L1402-L1425).

무한히 들어오는 일반 요청에 대한 queued Write의 공정성 보장도 새로 추가하지 않았습니다. 이는 기존 요청 우선순위를 유지한 한계이며 이번에 발생했다고 재현한 장애가 아닙니다.

## F02와 F04의 배포·화면 검수

새 UI와 오래된 Common을 섞으면 메서드 부재 등 실행 문제가 생길 수 있습니다. 솔루션 빌드 통과는 같은 버전 세트를 검증한 것이지 임의의 DLL 조합까지 검증한 것이 아닙니다. [새 UI 호출](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/99d78ddf0e680b55dbd9662764b71a1ffe93a457/Drilling.UI/Menu/Menus/CMenuMonitor.cs#L1834-L1881), [새 Common API](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/99d78ddf0e680b55dbd9662764b71a1ffe93a457/Drilling.Common/Interface/Melsec/CMelsec.Polling.cs#L54-L76).

이번 UI 시험은 Row 모델·메모리 적용·Changed 이벤트·XAML/타이머 정적 연결입니다. 실제 CRootView·장치 Manager·Dispatcher·화면을 기동하지 않았으므로 활성 화면의 비용을 그 시험 수치로 대신하지 않았습니다.

## 기존 중요 잔건을 해결로 바꾸지 않기

- Review는 실제 MELSEC Stage/Review 이동 주소·도착 확인이 아직 미연결입니다.
- 0선 사용 시 실제 실행 Coordinator가 연결되지 않아 Stage Ready 경로에서 차단합니다.
- LastLoad20맵은 USE=0/UNASSIGNED이고, 빨라진 Read가 새 Vision 측정이나 동일 기판 데이터를 만들어 주지는 않습니다.
- 기존 보정의 Simulation 출처 승인, 누적 상한·측정 Revision, Lagrange 내부 오버슈트 확인사항은 그대로입니다.

이전 분석에서 관찰한 현상을 이번 시험에서 다시 재현했다고 쓰지 않았습니다. 해당 코드가 동일하다는 범위에서 잔건을 이어갑니다. [실기 Review 경계](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/99d78ddf0e680b55dbd9662764b71a1ffe93a457/Drilling.Common/Review/CReviewManager.DeviceModes.cs#L21-L26), [0선 경계](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/99d78ddf0e680b55dbd9662764b71a1ffe93a457/Drilling.Common/Station/CStationProcess.StageRequests.cs#L28-L48), [맵](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/99d78ddf0e680b55dbd9662764b71a1ffe93a457/Config/JHMI_MELSEC_MAP.csv#L84-L103).
