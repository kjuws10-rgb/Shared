3. Zero Order는 “16빔의 가공 기준 중심”

리뷰카메라는 실제 마크를 보고, 프로그램은 마크 사이의 가상 중심을 구합니다.

6. P 중심으로 16개 예상 슬롯을 만들고 DOE 방향을 반영

명목 슬롯은 탐색·식별의 출발점입니다. 실제 위치는 카메라 측정으로 확인합니다.

회전과 격자 맞춤의 두 가지 표현
DOE 기준 슬롯 u(row,col) = ((col−1.5)d, (row−1.5)d)
명목 실제 빔 위치 = P + R(DOE_Globalθ)·u

Cell Local에서 표현할 경우:
uLocal = R(DOE_Globalθ − Cellθ)·u
R(Cellθ)·uLocal = R(DOE_Globalθ)·u    // 두 식은 동일

피팅 표현 ①: mᵢ = Z + F·uᵢ
  F는 DOE 회전·간격·전단 등을 포함. 예상 축 반응과 비교.
피팅 표현 ②: uGlobal을 미리 회전하고 잔여 변환만 맞춤.
  이미 회전한 좌표에 DOE/Cell 회전을 다시 적용하지 않음.

검증된 비대칭 DOE 프로필이면 uᵢ를 해당 원점 기준 교정 좌표로 교체.
명목 p/q/N에서 만든 대칭 u와 실측 교정 프로필의 원점 정의·버전을 구분.
잔차만 작다고 Pitch가 맞는 것은 아닙니다.

자유롭게 크기를 바꾸는 affine 맞춤은 잘못 입력한 Pitch를 Scale에 흡수할 수 있습니다. 최대 잔차와 함께 실제 빔 간격, 회전, 축별 Scale·전단, 반복성, 중심 불확도를 검사합니다.

7. “비율을 고려한다” = DOE 원점 기준 격자 맞춤

빔에 임의의 가중치를 주는 방식이 아니라, 각 빔과 원점 사이의 알려진 위치 관계를 계산에 넣습니다.

개발 계산식
설계 슬롯 uᵢ = (DOE 원점 기준 X, Y)
대칭 4×4: uᵢⱼ = ((j−1.5) dX, (i−1.5) dY)
실측 mᵢ = 중심 Z + F × uᵢ + 측정오차

구할 값: Z(현재 샷의 중심 X/Y), F(회전·간격·전단의 2×2 행렬)
min Σ || mᵢ − Z − F uᵢ ||²
→ Z가 현재 샷 P에 해당하는 DOE 원점(0,0)의 실측 위치

설계 좌표는 알려진 입력값. 16점 잔차를 숨기려고 슬롯 좌표를 임의로 변경하지 않음.
실제 구현은 수치 안정성을 위해 QR/SVD 사용, 좌표/행렬 퇴화와 조건수 검사.
여기서 dX/dY는 DOE 빔 간격이며 명령 Pitch q와 다름. 예제는 dX=dY=s/N=0.225 mm.
명목 슬롯은 가공좌표 생성에서 재사용

현재 A3 예제의 d는 s/4=0.225 mm입니다. 중심 맞춤의 입력 슬롯은 각 축 −0.3375/−0.1125/+0.1125/+0.3375 mm를 사용합니다. 실제 위치 m은 카메라로 구한 공통 mm 좌표입니다.

8. 평균이 맞는 조건과 더 정밀하게 가는 조건

16개 평균은 대칭·동일 비중 모델의 정확한 특수해입니다. 새 계산은 식별·모델·품질을 함께 검사합니다.

경우계산개발 판단
대칭 완전 4×4 + 선형 변환 + 동일 비중Z = 16점 평균 = affine 맞춤 원점평균 대비 숫자 정밀도가 자동 향상되는 것은 아님
비대칭 DOE 기준 좌표각 슬롯의 알려진 좌표를 넣어 Z 계산단순 평균과 다른 원점이 맞을 수 있음
점마다 반복측정 분산이 다름WLS/GLS: 분산이 작은 좌표에 더 높은 신뢰도밝기·마크 면적·중심까지 거리로 임의 가중 금지
검증된 비선형 Beam Map 존재원점에 대한 교정된 상대 좌표/모델로 맞춤Camera 왜곡은 먼저 교정. Beam Map은 원점 기준과 버전 필수
잔차 큼 / 오인식 / 15개만 검출해당 슬롯 재촬영·재접근후보 추정은 탐색용. 최종 16/16 gate 유지
가중치와 불확도 구현
Σᵢ = 반복 촬영·재접근으로 확인한 마크 좌표 공분산
GLS: min Σ (mᵢ − Z − F uᵢ)ᵀ Σᵢ⁻¹ (mᵢ − Z − F uᵢ)
축별 독립·등방성인 단순 경우만 wᵢ = 1 / σᵢ²인 WLS로 축별 계산

잘못된 식: Σ wᵢ mᵢ / Σ wᵢ     // DOE 설계좌표 관계를 빠뜨림
올바른 식: 설계좌표 uᵢ와 실측 mᵢ를 함께 가중 맞춤

엔코더·카메라 교정·프로필 원점 오차는 공통 성분으로 별도 관리.
16점이라고 전체 정확도가 항상 4배 좋아지는 것은 아님.
중앙 4점과 외곽 점의 원점 차이는 이상 진단값이며, 더 작은 RMS만 보고 모델을 바꾸지 않음.
순환 교정 방지

실측 DOE 간격을 예상 Pitch와 강제로 같게 만들어 카메라 배율을 맞추지 않습니다. 카메라는 독립 기준으로 교정하고, 실제 DOE 간격 편차와 원시 16점 좌표는 그대로 보존합니다.

명목 Pitch만 바꾸었을 때의 해석

완전 대칭 16점의 affine 맞춤에서는 명목 d의 배율을 바꾸어도 중심 절편은 같을 수 있습니다. 따라서 기존 중심값이 모두 틀렸다고 판단하지 않고, 누락된 가공 엔진 연결과 탐색 크기·슬롯 식별·Scale 검사를 바로잡습니다.

9. 어디에서 찾든 FOV 중앙까지 자동 이동

분해능과 예상 Pitch로 탐색 범위를 만들고, 실측한 위치로 중심을 다시 계산합니다.

작업쉬운 설명개발 처리
영상 좌표를 mm로 변환마크가 화면 중앙에서 얼마나 떨어졌는지 실제 길이로 환산카메라 Flip·회전·왜곡 보정 → 실제 축 기준 이동
촬영 위치와 연결사진 찍은 순간 카메라가 본 위치를 엔코더로 기록같은 시점의 X/Y + 영상 차이. 이미 절대좌표면 엔코더를 재가산하지 않음
가상 중심 이동16개 마크에서 구한 중심 위치로 Review X / Main Y 이동이동 제어권·축 범위·Laser OFF 확인 후 이동
빈 중심 검증중앙에 홀이 없어도 주변 마크를 다시 보면 위치가 맞는지 확인 가능선택 슬롯 재방문 → 재계산 중심 복귀 → 편차 확인
좌표 변환과 중앙 맞춤
p₀ = ((영상폭−1)/2, (영상높이−1)/2)   // 실제 지정 FOV 중심
J = [축 X/Y를 실제로 움직였을 때 영상이 몇 px 움직이는지] 2×2 교정 행렬
각 마크를 중앙에 맞추는 축 이동 = J⁻¹ × (p₀ − 마크 영상위치)
마크 위치 = 촬영 당시 축 엔코더 + 위 이동량     // 공통 축 좌표 표현

1) Laser OFF → 제어권 확인 → 이동 → 정지·안정화 → 촬영
2) 왜곡 보정 후, 각 점을 개별 변환. 비선형 변환은 픽셀 차이만 넣지 않음.
3) 카메라 축 좌표에서 기판/Head 공통 mm 좌표로 변환 후 격자 맞춤.
4) 계산된 중심의 축 목표로 이동 → 실제 도착 엔코더 확인.
5) FOV가 작아 중심이 비어 있으면 기준 슬롯 재방문으로 검증.

J는 카메라 구동 환산. Scanner Default 응답 K와 별도 저장.
카메라에서 예상되는 간격

예: 센서 Pixel 3.45 μm / 유효 배율 2이면 초기 환산값은 1.725 μm/px입니다. 명목 DOE 간격 225 μm는 약 130.43 영상 px입니다. 이 값은 탐색 초기값이며 실제 축 이동·왜곡 교정으로 확인합니다.

12. 가공좌표 생성 → DOE 중심 측정 연결 계산

같은 p·q·N과 원점 규칙으로 명목 위치를 만들고, 실측 중심과 비교합니다.

첨부 좌표 생성 예제를 직접 바꿔 보세요. 기본값 p=0.09, q=10, N=4입니다.

실제 간격 불일치 예제

명목 간격 0.225 mm에 실제 간격이 0.270 mm여도 자유 affine는 최대 잔차를 거의 0으로 만들 수 있습니다. 따라서 모델 잔차와 독립적으로 실측 Pitch·Scale 범위를 검사합니다. 이 예제의 ±2%는 계산 설명용 값입니다.

이 화면이 계산하는 범위

B/A/P·명목16슬롯·합성실측 중심·P대비잔차를 보여 줍니다. 실제 장비에서는 T와Camera/축 교정, 유효성·반복성·전체Field·Revision 검사를 연결합니다.

분기 수 변경

현재 중심 피팅 예제는 4×4, 최종 16/16 확인입니다. 다른 N을 지원할 때는 좌표 템플릿뿐 아니라 식별·피팅 입력·완료 조건도 N²개로 함께 확장합니다.

13. Y 측정은 Q−R, 중심 계산만 새 방식으로 개선

카메라 중심 계산이 정밀해지면 R도 더 안정적으로 얻을 수 있습니다. 기존 기구거리와 측정쌍은 유지합니다.

Y 목표와 Offset을 구분

1277/1657 mm는 기구 기준거리입니다. 이 전체 거리를 Default에 입력하지 않습니다. 실측 거리와 목표의 차이만 보정합니다. 가공 명령 Y=0, 추가 Shift=0 조건을 저장합니다.

기구거리 Q−R 평가는 전용 중심 명령 0 시험입니다.

이 절의 1277/1657 mm 직접 비교는 SETUP_CENTER의 명령 Y=0·추가 Shift=0 조건입니다. RECIPE_SHOT의 Y가 0이 아니면 원시 Q−R을 이 거리와 바로 비교하지 않습니다. 해당 P를 검증된 장비 변환 T로 옮긴 목표와 실측 Z의 잔차를 사용합니다. dirY는 축 방향의 ±1이며 샷 간격 s와 다른 값입니다.

14. 유효한 Default 추천: 중심 + 현재 값 + Field

중심을 잘 찾는 것과 스캔 가능한 추천값을 만드는 것은 별도의 계산입니다.

추천값 계산과 실제 반영
현재 Default가 반영된 실측 거리 D
Head 열별 목표 Dnom = 1277 또는 1657 mm
거리 편차 r = D − Dnom
Head의 Default 입력 응답 k = Default 1 변화 시 물리 거리 변화

공통 출사 조정 없음: Bnew = Bcur − r / k
실제 공통 Y 조정 지원: Bnew = Bcur + (c − r) / k
→ 실제 광학 기준 Dnew = Dnom + c
→ 실제 MOF 출사 엔코더 Qnew = Qcurrent + dirY × (cnew − ccurrent)

예: 1277 − 5000 = −3723
    1284 − 5007 = −3723   // 같은 기판 위치 유지

c는 단순 평균으로 고정하지 않고, 전체 Head의 최종 Field 제약 안에서 선택.
기존 Default도 포함. 값 이름만 나눠 적고 실제 출사 구간이 같으면 Field 개선 없음.
공통 이동 미지원: c=0 고정. 현재 c≠0인데 지원 상실: 계산·적용 차단.
축추천 계산적용 경계
X기판 중앙 + 설계 Head Pitch − 실측 중심 → Head별 입력 응답 역변환Review X 이동은 측정 이동. 실제 가공 X 보상과 구분
Y기구 목표거리와 실측 Q−R 잔차 + 지원되는 공통 출사 c실제 출사 엔코더·구간까지 함께 반영
X 공통 / θ실제 기판 X/UVW 회전 지원이 확인된 경우에만 함께 계산기판 기준·회전 중심·X/Y 재측정·전체 Field 확인
2축 결합Default 입력 반응 K가 2×2라면 ΔB = K⁻¹ × 필요한 물리 이동X/Y 교차반응이 크면 독립 1축 계산으로 적용하지 않음
8 Head 격자 원점과 Field는 별개

각 Head의 설치 오차를 전 Head 직선 회귀로 지워서 처리하지 않습니다. Head별 실측 중심은 보존하고, 그 결과를 이용해 공통 기준·개별 Default를 제한 범위 안에서 함께 추천합니다.

Default 이후의 리뷰 보정

Default로 기판 기준과 Head 기본 가공 위치를 맞춘 뒤, 실제 가공 결과에 Simple / Rough 보정 → Fine 정밀 보정을 적용합니다. 슬롯 식별 실패나 무효한 중심 계산을 리뷰 보정으로 덮어 완료 처리하지 않습니다.

이 절의 c는 Y 공통 출사 조정량

B→A의 cBA와 다른 값입니다. 전용 시험에서는 알려진 Head 목표를, 레시피 시험에서는 검증된 T(P)를 기준으로 잔차만 보정합니다. T가 준비되지 않은 레시피 측정은 위치 확인용으로 두고 Default 자동 적용을 허용하지 않습니다.

15. X/Y 보정 전후: 무엇이 달라지는가?

X는 좌우 간격, Y는 앞뒤 가공 기준을 맞춥니다. 마지막에는 두 방향을 함께 다시 확인합니다.

16. Field 균형 계산 예제

전체 Head를 같은 조건으로 모아야 끝단 Head까지 함께 절충할 수 있습니다.

기울기와 Field 여유를 바꿔 보는 계산 예제

편차는 각 Head의 열 기준거리(1277/1657)를 뺀 값입니다. 모든 Head의 현재 Default=0, 반응=+1, 공통 출사 기준 허용 ±20 mm로 단순화했습니다. 아래 입력값은 장비 규격값이 아닙니다.

최종 Field 검사는 중심점 하나로 끝내지 않습니다.

전체 가공점·16개 Branch·현재 Default·Align/Distortion/Review/Fine/APC·추가 보정 여유를 포함한 최종 Galvo 좌표를 검사합니다. 원형/다각형 유효 Field와 이동 경로가 있으면 해당 형상도 검사합니다. 공통 c로도 한계를 만족하지 못하면 추천 불가로 표시합니다.
