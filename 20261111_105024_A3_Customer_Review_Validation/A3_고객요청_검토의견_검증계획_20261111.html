분류·이관 필요

1. Review Align Key X/Y를 Recipe에서 Setting으로 분류

전달용 답변안
장비 기준 좌표라면 Setting에서 관리하는 방향에 동의합니다. PPID별 제품 조건, 장비 교정값, 기판별 측정 보정을 먼저 구분한 후 이관하겠습니다. 기존 레시피의 좌표가 바뀌지 않도록 이전/이후 계산 결과를 대조해야 합니다.

현행 코드 판단 CameraAlignKey X/Y는 Recipe 양식에 있으며 일반 Review와 배치 계산기가 Recipe에서 직접 읽습니다. Setting에 같은 이름의 행만 추가하거나 메뉴만 옮겨서는 모든 경로가 일치하지 않습니다. 일부 경로는 Recipe/Setting 병합 우선순위도 다릅니다.

진행할 작업
  • PPID 조건=Recipe, 장비 고정 기준=Setting, 매 기판의 Align/Review 결과=별도 보정 이력으로 분류한다. 모든 Offset을 일괄 Setting으로 옮기지 않는다.
  • 공통 기준값 해석기와 준비 시점의 동일 Setting 스냅샷을 사용한다. 수동 Review·AUTO·Rough/Fine·Default·미리보기·결과 재로드의 소비부를 함께 연결한다.
  • 구형 Recipe 값이 여러 파일에서 다르면 자동으로 한 값을 선택하지 않고 이관 충돌 목록을 만든다. 이전 원본과 Setting revision을 보관한다.
검증 순서
  1. 현재 Recipe별 CameraAlignKey 값과 동일 입력의 ReviewX/StageY 기준 결과를 추출한다.
  2. 같은 값/서로 다른 값/누락값을 가진 구형 Recipe로 이관을 시험한다.
  3. 같은 좌표를 넣은 상태에서 이관 전후 모든 측정 경로의 목표를 비교하고, 재시작·Recipe 전환 뒤에도 같은 Setting이 사용되는지 확인한다.

합격/완료 기준 같은 유효 입력의 계산 결과가 정해진 수치 정밀도 내에서 동일해야 한다. 서로 다른 기존 값은 조용히 덮어쓰지 않고 명시적으로 해결하며, 준비된 작업에 중간 Setting 변경이 섞이지 않아야 한다.

확정할 조건 장비 고정 좌표인지, 기판 규격·치구별로 달라지는 기준인지 항목별 확정. PPID 파일과 장비 Setting의 소유자·변경 권한·적용 시점.

추가 보완 필요

2. 가공 Shift를 전셀 Review 이동·측정에 반영

전달용 답변안
Shift 가공 기능과 Shift된 흔적을 따라가는 Review 기능은 별개입니다. 현재 원격 코드에서는 리뷰 목표까지 일관되게 따라가는 연결이 확인되지 않아 반영 완료로 답변하기 어렵습니다. 회차별 실제 Shift 이력을 기준으로 검사 좌표와 검색 영역을 함께 만들겠습니다.

현행 코드 판단 가공 플래너에는 Shift가 들어가지만 Review 목표는 Design/AK/Beam 기준입니다. Stage AUTO 요청도 Shift를 0,0으로 생성합니다. 화면의 Shift 값이 남아 있는 것만으로 AUTO Shift 가공이나 검사 추종이 지원되는 것은 아닙니다. ShiftY는 Scanner 명령뿐 아니라 Encoder 대기 위치에도 관여합니다.

진행할 작업
  • 공통 좌표 변환을 통해 각 가공 회차의 의도한 기판상 목표와 검사 목표를 연결한다. ReviewX에 ShiftX, StageY에 ShiftY를 단순 가산하는 식으로 처리하지 않는다.
  • Pass별 Shift·Align/보정 revision·Head/Shot/광학 모드·검사 ROI를 동결한다. Shift가 바뀌면 이미 만들어진 검사 계획의 유효성을 다시 확인한다.
  • 비제로 Shift의 AUTO 유지/취소 확인과 양산용 자동 초기화 옵션을 분리한다. 초기화 옵션은 평가 중 사용하지 않도록 정책을 명시한다.
검증 순서
  1. 기준 위치를 실측한 뒤 +X/−X/+Y/−Y Shift를 각각 한 조건씩 적용한다.
  2. 8개 Head의 실제 가공흔, 계산된 Review 목표, 지령·현재 위치, Vision 검색 ROI를 대조한다.
  3. 전셀 Review·OneShot·수동 Fine·AUTO Fine과 1~10회 흔적을 시험하고, Shift=0·비제로 유지·취소·양산 초기화 분기를 확인한다.

합격/완료 기준 각 회차의 의도한 Shift 후 목표에서 올바른 흔적을 측정해야 한다. 다른 회차 흔적을 잡거나 Shift를 중복 적용/누락하면 실패다. 적용한 Shift와 검사에 사용한 Shift가 이력으로 일치해야 한다.

확정할 조건 Shift의 좌표 기준·누적/절대값·회차별 크기와 방향, AUTO 전환 정책. 실기 배포 버전과 소스 버전 일치.

공통 검증 필요

3. Default·Review·First Offset 방향 검증

전달용 답변안
정지 가공과 MOF를 같은 숫자 부호만으로 비교하면 안 됩니다. 기판·Scanner·Stage·Vision 좌표계를 구분하고 Offset을 하나씩 변화시켜 계산 방향과 실제 흔적 이동 방향을 검증하는 공통 표를 만들겠습니다.

현행 코드 판단 Default/First와 DESIGN Review는 서로 다른 변환 함수를 통과하며, SCANNER로 저장된 구형 Review 보정은 별도 취급됩니다. 현재 정지 CENTER 시험은 Default 중심 확인용으로 Cell/Align/Review/Shift를 모두 합성하는 시험이 아닙니다. 따라서 그 시험 하나로 전체 Offset 방향을 검증했다고 할 수 없습니다.

진행할 작업
  • 기판상 X/Y, Stage 양방향, Head X/Y/XY Flip, Vision Flip, Offset의 저장 좌표계를 표로 고정한다.
  • 기존 교정 기준을 보관하고 다른 기여를 고정한 상태에서 하나의 Offset만 ±δ 변화시킨다. 독립 기준 계산·최종 Script·엔코더와 실측 흔적을 비교한다.
  • Default/Review/First 각각의 단독·합성·0/100/200% 조건을 구분한다. 현재 정지 CENTER가 포함하지 않는 Offset은 동등한 정지 시험 경로를 마련한 뒤 검수한다.
검증 순서
  1. 원시 pixel 오차→mm→μm 환산과 Vision Flip을 알려진 입력으로 먼저 확인한다.
  2. 장치 없이 Stage 방향·Flip 조합과 DESIGN/SCANNER 자료의 부호·축 교환·이중 변환 여부를 검증한다.
  3. 허용된 시험 영역에서 Head별 정지/MOF·±X/±Y·중심/경계 조건을 실제 가공·측정한다. 마지막에는 보정 후 잔차가 줄어드는지 확인한다.

합격/완료 기준 예상한 기판상 변위와 실측 변위의 부호·축·크기가 일치해야 한다. MOF는 엔코더 추종/발진 시점을 포함해 비교하고, 잘못된 방향·두 번 적용·누락은 허용하지 않는다. 정밀도 합격 수치는 고객과 합의한 측정 지표를 따른다.

확정할 조건 ±δ 크기·시험 영역·외부 기준 측정 수단. 현재 카메라 분해능/Flip와 S/G 정의. 공정 tolerance의 OK를 5μm 평가 합격으로 사용하지 않음.

I/F 확정 후 개발

4. 디척 전 Setup용 2nd Align

전달용 답변안
전달 예정인 I/F 맵을 기준으로 신규 거래를 구성하는 것이 맞습니다. 기존 AK 레지스터 읽기나 일반 Align 요청을 그대로 2차 Align 완료로 취급하지 않고, 동일 기판의 새 측정 완료와 결과 취득을 확인하겠습니다.

현행 코드 판단 일반 수동 Align 요청·가능·완료 표시와 취소는 있으나 가공 SW의 2차 Align 전용 거래와 Dechuck 허가 연결은 확인되지 않았습니다. 실제 Stage 내부 동작 여부와 신규 주소는 제공된 자료만으로 확정할 수 없습니다.

진행할 작업
  • 요청→수락/Busy→측정 완료→결과 유효성→ACK/신호 복귀를 별도 사이클로 정의한다.
  • 같은 Glass/회차의 AK 결과와 측정 시각·단위를 저장하고 재측정/NG/취소/Timeout을 구분한다.
  • Stage가 Chuck/Dechuck의 물리 제어와 허가를 소유하도록 하고, 가공 SW의 결과 자격과 분리한다. 기존 카메라 번호/배치는 유지한다.
검증 순서
  1. 새 요청 전에 이전 완료 ON 상태를 남겨 오래된 완료를 잘못 받지 않는지 시험한다.
  2. 정상·NG·일부 키 무효·늦은 응답·취소·통신 끊김·프로그램 재시작을 주입한다.
  3. 완료/유효 결과 확인 전 Dechuck 진행을 막는 합의된 동작과 원자료 이력 보존을 확인한다.

합격/완료 기준 정상 거래의 새 결과만 같은 기판에 귀속해야 한다. NG/Timeout/오래된 완료를 정상으로 승격하지 않으며 Dechuck 해제는 Stage와 합의한 조건에서만 이루어져야 한다.

확정할 조건 I/F 주소·자료형·극성·완료 의미·거래 세대 식별·NG시 디척/재측정 정책. 이 자료에서는 주소를 임의 지정하지 않음.

복구 계약·고장 시험 필요

5-1. A1 실행 중 알람과 0선 복구

전달용 답변안
현재 Task/Queue 정지·Laser OFF·0선 부분 결과 보존·출력 정리 흐름은 있습니다. 다만 모든 A1 알람에서 Stage 실제 정지까지 보장되는지 공동 검수가 필요합니다. 복구는 단순 RESET 후 같은 기판의 가공 재시작이 아니라, 정지 확인과 부분 가공 상태를 판단하는 절차로 정리하겠습니다.

현행 코드 판단 0선 Stage-buffer 세션의 Stop은 Stage Y를 소유하지 않아 Stage Y Stop을 직접 호출하지 않는 경로가 있습니다. 실제 Task 완료, 0선 판정, Process 거래 완료는 서로 다른 사건입니다. 가공이 완료된 뒤 검사/ACK 오류가 나더라도 이미 확정한 가공 사용매수를 취소하는 처리는 맞지 않습니다.

진행할 작업
  • 오류 단계별로 가공 미시작/부분 진행/실가공 완료/검사 미완료를 기록한다. 새 RUN·보정 저장·재시작을 차단하고 각 소유자의 종료를 확인한다.
  • 가공 SW는 소유 Task/Queue·Vision/0선과 우리 출력을 정리하고, Stage/PLC의 실제 축 정지 요청·ACK·Busy 확인 책임을 합의한다.
  • 부분 결과와 최초 원인/정리 실패를 함께 남긴다. 부분 가공 기판의 재출사·재가공은 자동 재개하지 않고 검사만 재수행/반출/새 기판 정책을 정한다.
검증 순서
  1. 시작 전, 출사 중간, Task 정상 완료 직후, 1002/1003 대기 중, Stage ACK 대기 중 오류를 각각 주입한다.
  2. Task STOP 실패·Queue 잔류·Vision 지연·Stage Busy 지속·출력 OFF readback 실패를 확인한다.
  3. RESET·재접속·재기동 후 오래된 응답/신호로 완료나 재가공이 발생하지 않는지 검증한다.

합격/완료 기준 합의된 정지 조건이 확인되기 전 재시작할 수 없어야 한다. 미완료는 미완료로 보존하고 성공 COMPLETE를 만들어 복구하지 않는다. 가공 완료 매수는 중복 증가/임의 취소하지 않으며 실제 Stage 정지는 별도 확인한다.

확정할 조건 Stage Abort/ACK·정지 제한시간·부분 가공 기판 처분·0선 검사만 재시도 조건. 광학 Bit 별도 평가는 이번 6번 제외 범위를 유지하되 기존 보호를 우회하지 않음.

I/F 분기 보완 필요

5-2. 보호윈도우 교체 NG·평탄 NG의 종료/매수/알람

전달용 답변안
교체 실패와 교체 후 평탄도 불량을 구분해야 합니다. 물리적으로 교체된 사실·가공매수 인계와 해당 윈도우를 사용할 수 있는 자격을 나눠 관리하고, 실패 종류별 알람 및 Stage와의 비정상 종료 절차를 확정하겠습니다.

현행 코드 판단 현재는 section 완료 후 Stage Count를 받아 저장·보고하고 교체 요청을 내리는 흐름이 있습니다. 교체 결과/평탄도 결과 맵은 USE=0이며 해당 NG 소비 분기는 확인되지 않았습니다. 구간 완료·TPM 완료·정상 사용 자격이 모두 같은 것은 아닙니다. 기존 2 OR 계약의 ATT 예측과 현재 Count 조건 구현의 차이도 확인 대상입니다.

진행할 작업
  • 정상/교체 NG/Flat NG/Count 오류/Timeout/TPM 실패의 종료표를 Stage·Process 공동으로 정한다. DONE/거래 종료와 OK/정상 자격을 구분한다.
  • 교체 NG에서는 기존 사용매수를 임의 초기화하지 않는다. 실제 교체 완료 후 Flat NG라도 물리 Window/Count 사실은 기록할 수 있으나 사용 자격은 NG로 유지한다. 신규 Count의 수락·ACK 시점은 합의한다.
  • Count 갱신·요청 해제·알람 발생의 순서와 재시작/중복 완료 처리 이력을 보관한다. JobChange 단독을 새 교체조건으로 추가하지 않는다.
검증 순서
  1. 교체 전/중/후 NG, 교체 완료 후 Flat NG, Count 지연·무효·중복, TPM NG를 각각 주입한다.
  2. 이미 정상 가공한 후 NG가 나도 Count가 취소되지 않는지, 같은 완료를 두 번 받아도 중복 갱신하지 않는지 확인한다.
  3. 실패 시 다음 출사 허가가 차단되고 양쪽 신호가 합의한 Fault 종료/복구 대기로 귀결되는지 확인한다.

합격/완료 기준 정상·실패 원인이 구별되고 Count와 실제 Window 상태가 모순되지 않아야 한다. 수신 실패를 Count=0으로 대체하거나 Busy OFF만으로 정상 완료 처리하면 실패다.

확정할 조건 확정 I/F 맵·Count 단위·인계 시점·NG 알람 책임·전체 거래 종료 규칙. 같은 기판 10회 가공에서 1장/10회 중 어떤 사용량을 기록할지도 별도 합의.

7. HIAA·Round Masking을 피하는 Flying 위치/경로

전달용 답변안
현재는 Masking Shot을 촬영 대상에서 제외하더라도 Flying 이동이 첫 유효점과 마지막 유효점 사이를 통과합니다. 따라서 고객이 요구한 주행 회피까지 반영됐다고 보기 어렵습니다. 먼저 Masking을 가로지르지 않는 검사 줄을 선정하고, 필요한 경우 유효 구간과 재이동 경로를 별도로 계획하겠습니다.

현행 코드 판단 촬영 제외·Count/좌표 전송 반영은 있으나 연속 경로의 물리 우회 기능은 확인되지 않았습니다. 설계 기준 Masking 고정은 제외 Shot 멤버십의 개선이며, Shift 후 실제 흔적·카메라 이동의 금지영역 검사와는 다릅니다.

진행할 작업
  • HIAA·Round 도형과 Shift 후 검사 목표를 같은 기판 좌표계로 놓고 유효한 샘플링 줄을 자동 선정한다. 가공 제외 정책과 리뷰 경로 정책을 구분한다.
  • 측정 이동·가감속/overscan·재이동 중 어디까지 회피할지 확정하고, 선택 구간이 없으면 대체 줄 또는 검토 필요로 안내한다.
  • 구간 분할 후 사이 이동이 같은 Mask를 관통하면 전체 주행 회피를 달성한 것이 아니다. 모든 대상 구간의 선분-영역 교차를 검사한다.
검증 순서
  1. HIAA 내부 홀·Round 모서리·전 구간 제외·Shift로 경계에 들어간 점·정/역방향을 계획 단계에서 확인한다.
  2. 도형/금지 여유를 반영한 모든 대상 선분과 실제 지령·엔코더 경로를 겹쳐 본다.
  3. 선정한 줄의 유효점/Count/순서를 Vision 결과와 대조하고 반복 10회 흔적도 빠지지 않는지 확인한다.

합격/완료 기준 합의한 회피 범위의 이동 경로가 금지영역과 교차하지 않아야 한다. Trigger만 OFF인 경우를 물리 회피 합격으로 판정하지 않는다. 임의 다른 검사점으로 바꿔 원래 요구를 숨기지 않는다.

확정할 조건 촬영선만 회피인지 재이동까지 금지인지, ROI/기구 여유와 허용 대체 줄, 가감속 구간. 필요 좌표/Stage 운용 계약.

일부 반영·후속 필요

8. 많은 리뷰 측정점의 Offset UI 편의 개선

전달용 답변안
결과 목록·Cell/Shot 맵과 표의 연동·보정 미리보기는 반영돼 있습니다. 사용자가 정하는 오차 Level, 기준 Shot의 동일 최종 보정 복사, 선택점 이동/재측정과 중복 적용 방지는 추가 보완이 필요합니다. 기본 조작은 결과 열기→위치/오차 확인→필요점 재검사→보정 확인→적용/복원 순서로 단순화하는 방향이 좋습니다.

현행 코드 판단 새 Review Data는 파일 조회·선택·현재/추가/최종 Offset 팝업·저장/초기화/복원 화면입니다. 맵 선택만으로 실제 Move/재촬영이 실행되지는 않습니다. 같은 결과가 자동/수동 경로로 다시 누적될 수 있고, 손상 CSV 수치가 0으로 바뀌는 경로도 남아 있습니다.

진행할 작업
  • 기존 tolerance와 원측정 Judge를 유지하면서 별도 사용자 Level 이름/범위/단위를 제공한다.
  • 기준 Shot의 최종 F를 대상 F로 복사하고 대상별 Δ=기준 F−대상 기존 B를 미리 보여준다. 다른 기여를 그대로 두고 기준 Δ만 복제하는 동작과 구분한다.
  • 실측/보간/수동 대체·측정없음·적용됨을 구분한다. 결과 ID·기준 Offset revision·사유/작업자 이력과 1회 적용 정책을 제공한다.
검증 순서
  1. Level 경계 바로 전/동일/후·단위 전환·저장/재시작을 검증한다.
  2. 대상별 기존 B가 서로 다른 예에서 모두 기준 F와 같아지는지, 제외/미측정/NG 점의 처리와 취소를 확인한다.
  3. 같은 결과 반복 Apply·자동 적용된 결과 재Apply·무효 수치·팝업 중 외부 변경·과거 Recipe 결과를 시험한다.

합격/완료 기준 표·맵·계산·저장 대상이 같아야 하고 원측정·원래 판정을 덮어쓰지 않아야 한다. 동일 결과 재누적과 손상 입력을 식별/차단해야 하며 화면에 없는 측정을 0/OK로 만들지 않는다.

확정할 조건 Level 지표(X/Y별·최댓값·거리)와 경계 포함 방향, 기준값 복사 의미·수동 후보 승인 범위. 생산 구현과 교육용 HTML의 기능을 구분.

9. 리뷰 Offset 적용 전 백업·원복

전달용 답변안
최신 보정파일을 보관 폴더로 옮겨 직전 보정을 활성화하는 Rollback은 구현돼 있습니다. 다만 평가 전 특정 기준 상태를 다시 선택해 복원하는 기능과 전체 조건 백업은 별도입니다. 적용 전 기준을 식별해 보관하고 복원 후 DoReady 반영까지 검증하는 방향으로 보완하면 좋겠습니다.

현행 코드 판단 SaveNew는 기존 파일을 덮지 않고 새 CSV를 저장합니다. Rollback은 최신 파일을 보관하고 직전 파일을 활성화하며, 직전 파일이 없으면 Offset 없는 0상태가 됩니다. 준비된 가공 데이터 무효화와 최신 파일 비교 가드가 있습니다. Init=0 저장과 Rollback은 다른 동작입니다.

진행할 작업
  • 적용 전 Offset 원본·Recipe/Setting·Align·Shift·스크립트·결과 ID를 평가 기준 패키지와 hash/revision으로 연결한다.
  • 필요하면 원하는 시점 선택·비교·복원을 제공한다. 최신 1단계 롤백과 최초 평가 기준 복원을 화면에서 분리한다.
  • 복원 후 활성 revision·DoReady 재생성 여부를 표시하고 과거 결과를 다시 Apply하는 경우 중복 이력도 검사한다.
검증 순서
  1. 기준 B→F1→F2를 저장한 뒤 1회 Rollback이 F1인지 확인한다. B까지 복원을 원하면 대상 시점을 명시한다.
  2. 파일 0/1/여러 개, 직전 파일 손상, 취소, 확인 중 파일 변경, 재시작·저장 실패를 시험한다.
  3. 복원한 전체 Offset 값과 원본 hash를 대조하고 DoReady 전 시작 차단·재생성한 Head 최종 좌표가 기준과 같은지 확인한다.

합격/완료 기준 원측정 결과와 기준 백업은 그대로 보존해야 한다. 실패 시 활성 보정이 조용히 0/부분 상태로 바뀌면 안 되며, 복원 후 실제 다음 가공 준비에 올바른 값이 반영돼야 한다.

확정할 조건 백업 범위·보관 정책·원복 기준 시점·부분 복원 허용 범위. 직전 파일이 없는 경우의 0상태를 사용자에게 명확히 안내.

10. 실제 Flying Trigger 누락 평가

전달용 답변안
단동 평가 기간에 포함하는 것이 맞습니다. 현재 Count/응답 검사는 통신·목록 검증이며 실제 전기 펄스와 카메라 수신·Grab을 모두 증명하지는 못합니다. 계획→Stage 수용→펄스→Vision/Grab→결과를 같은 회차로 대조하는 검수표가 필요합니다.

현행 코드 판단 좌표 배열 readback·1002의 Count 일치 여부·1003 유효 결과 개수 검사는 있습니다. 1002 응답은 실제 펄스 수가 아니라 일치 여부이고, 같은 수라도 순서 바뀜 또는 누락1+중복1은 Count만으로 검출하지 못할 수 있습니다.

진행할 작업
  • 계획 좌표/순서 hash, Stage 수용 세대, 실제 pulse/시각, Vision Trigger·Grab/프레임 ID, 결과 index를 연결한다. 제공되지 않은 카운터/주소는 Stage/Vision과 합의한다.
  • 기존 카메라 미연결·가상 Trigger·랜덤1003 평가는 통신/매핑 시험으로 구분한다. 실제 Trigger 합격은 실카메라·계측 근거로 확인한다.
  • 정/역방향·첫/끝점·Masking 전후·가감속·패킷/버퍼 경계·중지/재시도를 포함한다.
검증 순서
  1. 정상 기준을 기록하고 펄스1개 누락·중복·순서 변경·지연·잘못된 UID/이전 거래 응답을 각각 주입한다.
  2. 계획 수와 수용/펄스/Grab/유효 결과 수를 대조하고, 각 영상이 해당 목표·회차에 연결되는지 확인한다.
  3. 최소/최대 운용 조건과 버퍼 경계에서 반복 시험하며 장치 정격에 맞는 펄스 폭/간격/레벨도 계측한다.

합격/완료 기준 검수 대상 모든 점에서 누락·추가·순서 오귀속이 없어야 한다. Count가 같아도 영상/점 대응이 다르면 실패이며, 전기·카메라·통신 중 실패 위치를 구분할 수 있어야 한다.

확정할 조건 카운터·프레임/시간축 제공 방식, 실제 정격·속도/펄스 수치·반복 표본 수. 이 자료에서 최대 속도나 누락률 합격치를 임의 지정하지 않음.

목표 좌표각 회차가 의도한 Shift 후 목표를 평가 기준으로 고정하고 실제 가공 명령은 별도 기록.실제 흔적/명령에 맞춰 목표를 사후 이동해 오차를 없애거나 현재 보정값을 검사 목표에 더해 평가 오차를 숨기면 안 됩니다.
실제 촬영 분할3개의 논리 샘플링 줄과 실제 Stage Y·ROI·capacity별 촬영 구간을 구분.Y Shift라면 회차마다 실제 줄이 달라집니다. X Shift도 ROI 겹침·흔적 식별·10배 Count와 버퍼 한도를 검증해야 합니다.
보정 동결평가 전 기준 보정을 보관하고 평가 중에는 측정·결과 저장만 수행.일반 AUTO Review는 전체 OK 때 Offset을 자동 누적합니다. 평가 전용 정책이 필요하며 0선 FollowUp 모드를 우회 사용하지 않습니다.
목표 정밀도5μm=0.005mm. S/G 정의·산식·X/Y 또는 거리·통계·표본·이상치/미검사 처리 방식을 고객과 합의.test0929의 현재 X/Y tolerance는3mm입니다. 공정 Judge OK를 5μm 평가 합격으로 사용하지 않습니다. S/G의 뜻과 산식은 원문만으로 확정할 수 없습니다.
완전성예상 Trace 집합과 실측 Trace 집합을 Head/Cell/Pass별 대조.누락·중복·가상/실측 혼재를 숨기지 않고, 미검사 값을0으로 넣어 통계를 개선하지 않습니다.

평가 진행 순서

  1. S/G 규격과 8개 Head의 광학 조건을 확정한다.
  2. 평가 전 Recipe/Setting/기준 보정을 보관하고 변경을 동결한다.
  3. 1회 가공으로 DOE Head와 Zero Order Head의 실제 흔적·좌표·검사 ROI 대응을 검증한다.
  4. Pass1~10 각각의 Align·Shift·실가공 완료·TraceId를 저장하며 반복한다.
  5. 전셀 논리 3줄의 전체 Trace를 실제 Y/ROI/capacity에 맞게 나눠 검사한다.
  6. 예상/실측 집합·누락/중복을 대조하고 실측만으로 합의한 지표를 산출한다.
  7. 평가 결과를 보관한 뒤에만 보정 적용 여부를 결정하고 필요 시 기준 상태로 복원한다.

가공 회차·물리 광학 모드·검사 위치·원측정값이 같은 TraceId로 추적되고, 누락/중복이 없어야 합니다. 측정·보정·통계 표기가 섞이지 않아야 합니다.
