핵심 요약

자동 Recipe 전환

위치가 보이는 센서 화면

Leak·EMS는 목록에 더해 위치와 상태를 표시하고 실제 터치 가독성을 확인한다.

모드와 복귀의 범위

단동·연속 시퀀스·Auto 전환·원점/준비 복귀를 구분하고 PC/PLC 책임을 정리한다.

01자동 레시피 전환과 Host / Sub PPID 구분

사양 합의 필요

같은 모델이라도 공정 경로에 따라 적용할 설비 레시피가 달라질 수 있으므로, 설비가 구분할 수 있는 전달 항목과 매핑을 확정한다.

구분회의 내용
회의 설명상위 시스템에 모델·레시피 관련 등록과 설정을 해두었다는 설명이 있었고, 설비에서 자동 전환이 되지 않는다는 문제 제기가 있었다. 현재 적용 상태는 공동 확인이 필요하다.
쟁점레시피명을 키로 활용할 수 있다는 제안과, 상위 PPID만으로는 설비 레시피를 구분하기 어렵기 때문에 별도 구분자가 필요하다는 의견이 함께 나왔다.
방향관련 IT·자동화/CIM·설비 담당이 같은 자리에서 Host PPID, Sub PPID, 모델/공정 구분, 로컬 레시피명의 관계를 설명하고 하나의 사양으로 정리한다.
미결Sub PPID를 실제로 어떤 필드·주소로 전달할지, 기존 등록 체계가 설비까지 연결되는지, 별도 구분자가 추가로 필요한지는 확정되지 않았다.

다음 협의 질문

  • 같은 모델에서 증착 공정만 거치는 경우와 LD 공정까지 진행하는 경우를 어떤 값으로 구분하는가?
  • 상위에서 내려오는 값 한 세트가 설비 레시피 하나를 유일하게 가리키는가?
  • 레시피명 자체를 사용할지 별도 Sub PPID/구분자를 사용할지, 각 값의 관리 주체는 누구인가?

확인·검증 방안
대표 모델과 공정 경로별로 상위 전달값 → 설비 수신값 → 선택된 로컬 레시피를 한 표로 대조한다. 전환 불가 사례에서는 어느 단계부터 값이 달라지는지 확인한다.

02CIM I/F 최신 사양과 주소·공유 체계

최신본 통일

기존 주소 체계를 가능한 한 유지하되, 문서별 항목 차이와 비어 있는 항목·가용 통신 영역을 최신 I/F 맵에서 정리한다.

구분회의 내용
회의 설명기존에 편의상 정한 주소를 유지하는 방향이 언급됐다. 반면 전달된 문서마다 항목이 다르거나 빠진 부분이 있어 같은 사양을 보고 있는지 확인이 필요하다.
확인 과제필요 항목을 대조하고 사용 가능한 통신 영역을 확보할 수 있는지 검토한다. 정확한 메모리 영역명·주소·할당 범위는 최신 맵으로 확인한다.
공유 방향기존 수신에서 빠진 관련자를 포함해 갱신본을 다시 공유하고, 자동화 측 추가 요청도 취합해 한 번에 반영 검토한다.
미결최종 필드명·주소·자료형·길이·버전·전달 담당과 상세 인터페이스 조건은 최신본에서 확정해야 한다.

다음 협의 질문

  • 어떤 문서가 현재 기준본이며, 기존본과 달라진 항목은 무엇인가?
  • 기존 주소 유지가 가능한 항목과 새 할당이 필요한 항목은 무엇인가?

확인·검증 방안
버전·수신자·변경 이력을 포함한 I/F 맵 하나로 대조한다. 레시피 구분값과 실제 송수신 항목이 빠짐없이 연결되는지 확인한다.

03양산 자동화와 모델 변경 시 부대 동작

요구 구체화

사람의 개입을 줄이는 방향으로 수동 작업과 모델 변경 동작을 정리하고, SW와 기구가 함께 대응해야 할 항목을 분리한다.

구분회의 내용
회의 방향양산을 고려해 현재 수동으로 수행하는 작업을 가능한 범위에서 자동화하는 방안을 지금부터 검토하자는 요청이 있었다.
구체 요청모델 변경에 따라 와이퍼가 자동으로 이동해야 한다는 요구가 언급됐다. 자동화 시나리오에 필요한 기구 조건도 함께 검토한다.
미결와이퍼의 정확한 대상·위치·동작 조건과 수동 작업의 자동화 범위는 별도 목록 및 시나리오로 확정해야 한다.

다음 협의 질문

  • 모델 변경 때 운영자가 지금 직접 수행하는 작업은 무엇인가?
  • 와이퍼 이동과 레시피 전환 사이의 순서·완료 확인·간섭 조건은 어떻게 정의할 것인가?

확인·검증 방안
현 수동 작업 목록과 목표 자동 시나리오를 나란히 정리한다. 모델별 위치와 기구 조건을 확인하고, 정상 전환·실패·취소 시 운영 상태를 점검한다.

04카메라 평가 계획과 일정 제출

일정 확인 요청

설명이나 시연 완료와 카메라 평가 완료를 구분하고, 구체적인 평가 계획과 일정을 받아 검토한다.

구분회의 내용
요청카메라 평가의 구체적인 계획과 일정을 수립해 전달해 달라는 요청이 반복됐다.
평가 범위정지 상태에서의 카메라 평가가 언급됐다. 실제 설비에 장착한 상태의 평가 범위와 완료 판단은 추가 확인이 필요하다.
일정 표현회의에서 “이번 주 끝까지 일정 수령”, “다음 주 일정 확인” 취지의 표현이 나왔다. 평가 완료일이 확정된 것으로 볼 수는 없다.

다음 협의 질문

  • 평가 대상·조건·측정 항목·결과물·완료 판단 기준은 무엇인가?
  • 계획 제출일과 실제 시험일·결과 공유일은 각각 언제인가?

확인·검증 방안
평가 계획서에 준비 조건·시험 범위·담당·실행일·결과 공유일을 기재한다. 회의의 상대 날짜는 일정표에서 실제 날짜로 다시 확인한다.

05Leak 센서 위치와 상태를 평면도로 표시

화면 적용 후 확인

센서 목록만 보지 않고 실제 장착 위치를 빠르게 찾을 수 있도록 도면과 상태 램프를 물류 PC 터치 화면에 연결한다.

구분회의 내용
운영 요구챔버 내부 센서는 외부에서 보기 어려우므로, 어디에 있는 센서인지 바로 확인할 수 있는 평면도 표시가 필요하다는 요청이 있었다.
표현 방향설비 도면 또는 이미지를 화면에 넣고 센서 위치에 램프로 상태를 표시하는 방향이 설명됐다. 운영자가 벤트·점검·교체 준비를 빠르게 판단하는 것이 목적이다.
수량Leak 센서는 30개라는 설명이 있었다. 최종 개수와 ID·실제 위치는 I/O 목록 및 도면으로 대조한다.
사용성 확인PC에서 보기 좋은 화면도 실제 터치에서는 해상도·글씨·표식이 잘 보이는지 확인해야 한다. 우선 적용한 화면을 보고 판단하기로 했다.

다음 협의 질문

  • 각 램프의 센서 ID·도면 위치·현재 상태가 실제 현장과 일치하는가?
  • 터치 화면에서 챔버 내부/외부 위치와 이상 센서를 구분할 수 있는가?

확인·검증 방안
센서별 I/O·설치 위치·화면 램프 매핑표를 만든다. 개별 신호를 대조하고 실제 터치 패널에서 글씨·색상·확대/표식 가독성을 확인한다.

06Leak 센서 Skip / Use·Unuse의 승인 조건

환경안전 협의 선행

기술적으로 변경 기능을 만들 수 있다는 설명과 실제 사용 허가는 별개다. 승인 없이 숨김 화면이나 비밀번호로 우회하는 방식은 채택하지 않는다는 의견이 제시됐다.

구분회의 내용
사용 배경센서 고장·부품 교체 대기 중 미사용 전환 필요성이 운영 측에서 언급됐다.
회의 답변환경안전 관련 기능이므로 공식 허가·공문을 먼저 받아야 구현을 검토할 수 있다는 설명이 있었다.
운영 제약비밀번호·숨겨진 등급/화면을 통해 임의로 우회하는 방식은 허용하지 않는다는 발언이 있었다. 이번 회의록은 별도 우회 기능을 승인한 것이 아니다.
미결승인 주체와 실제 허용 범위·변경 가능 조건·표시 방식은 환경안전 협의 결과에 따라 정해야 한다.

다음 협의 질문

  • Skip 또는 Unuse가 가능한 센서와 조건을 공식적으로 허용받을 수 있는가?
  • 허용되는 경우 어떤 상태에서 변경할 수 있고 누가 승인·복귀를 확인하는가?

확인·검증 방안
승인 문서와 대상 센서·허용 조건을 먼저 확인한다. 승인 전에는 기능 구현/운영 허용을 완료 처리하지 않는다. 승인 후 시험 범위는 별도로 정한다.

07EMS / Safety 상태 시각화

기존 화면 활용 설명

기존에 사용 중인 EMS 화면을 활용하는 방향으로 상태를 표시하고, 관련 I/O 수량과 실제 동작 연결을 확인한다.

구분회의 내용
회의 설명기존 운영 EMS 화면을 그대로 활용하는 방향이 설명됐다.
수량EMS에 Safety를 포함하면 총 31개라는 설명이 있었다. 이는 Leak 센서 30개와 별도 발언이며 두 수량을 단순 합산하지 않는다.
확인 과제상태 표시 항목과 실제 I/O, 설비 구역·상태의 대응 관계를 최신 도면/맵으로 확인한다.

다음 협의 질문

  • 31개에 포함되는 EMS/Safety 항목은 정확히 무엇인가?
  • 이상 위치와 조치 대상이 화면에서 즉시 구분되는가?

확인·검증 방안
EMS/Safety 목록을 최종 I/O 맵과 대조하고 항목별 상태 표시 및 해당 조건의 설비 반응을 확인한다.

08Manual / Semi Auto / Auto와 조건 모니터링

기능 설명·범위 확인

단일 수동 동작과 여러 장치가 이어지는 동작을 구분하고, Auto 전환을 막는 조건을 운영자가 볼 수 있도록 한다.

구분회의 내용
Manual핀 상승·하강, 축 이동 등 단일 동작을 수행하는 방식으로 설명됐다.
Semi Auto / Auto기판 수취/반출 위치 준비처럼 핀과 Stage가 연속으로 연동되는 동작은 Semi Auto 또는 Auto의 영역으로 설명됐다.
Auto 전환Auto 버튼에서 조건 확인 화면을 열어 어떤 조건 때문에 전환이 안 되는지 실시간으로 모니터링하는 기능이 설명됐다.
버튼별 조건Auto 모드뿐 아니라 구동 버튼의 Enable 조건도 표시할 수 있도록 구성했다는 설명이 있었다. 실제 표시 범위와 운영 가독성은 사용하면서 확인해야 한다.

다음 협의 질문

  • 요청한 연속 동작이 어느 Semi Auto 시퀀스에 들어가는가?
  • Auto 전환 조건과 원점/준비 위치 이동은 각각 어떤 기능이 담당하는가?

확인·검증 방안
대표 연속 동작을 하나 선정해 Manual 단동과 Semi Auto 순서를 비교한다. Auto 전환을 막는 조건을 하나씩 확인하고 화면 표시가 실제 원인과 일치하는지 점검한다.

09Auto Ready·원점 복귀와 PC / PLC 제어 경계

통합 초기화 검토 필요

Auto 전환 조건 표시가 전 설비 자동 원점 복귀를 의미하지는 않는다. 기판 유무와 PC·PLC가 맡는 축을 나눠 복귀 범위를 정한다.

구분회의 내용
운영 요구수동 조작 이후 여러 축을 순서대로 원점·준비 위치로 복귀시키는 통합 초기화 편의 기능이 요청됐다. 축 간 간섭 때문에 순서가 중요하다는 우려가 있었다.
회의 설명일부 Auto Ready 기능은 설명됐으나, 메인 주행·리뷰·LDS 등의 PC/ACS 제어 영역과 PLC 영역이 나뉘어 있어 현재 PLC만으로 전 설비 일괄 원점 복귀는 어렵다는 설명이 있었다.
기판 없음빈 챔버/기판 없는 상태에서의 자동 초기화부터 검토할 수 있다는 제안이 있었다. 구현 완료나 전체 동작 승인으로 확정된 것은 아니다.
기판 있음기판 파손·간섭 우려로 수동 조치 의견이 나왔다. 기판이 있는 모든 상태에서 자동 복귀할 수 있다는 합의는 없었다.

다음 협의 질문

  • 원점 복귀와 준비 위치 이동을 구분했을 때 PC·PLC별 담당 축/완료 조건은 무엇인가?
  • 기판 없음 자동 초기화의 시작 상태·축 순서·중단 조건·복구 범위를 어디까지로 할 것인가?

확인·검증 방안
PC/PLC 제어 책임표와 축별 간섭 조건·복귀 순서를 만든다. 빈 챔버 조건의 시나리오부터 검토하고, 기판 있는 복구는 별도 상태/위험 검토 후 범위를 확정한다.

10크라이오펌프 온도·Regen·Use/Unuse와 설치 상태

설명된 기능 확인

실시간 온도·자동 Regen·Use/Unuse 화면이 준비됐다는 설명과, Regen 관련 설치 조건에 대한 확인 질문이 있었다.

구분회의 내용
기능 설명실시간 온도 표시, Auto Regen, Use/Unuse 기능이 구성돼 있다는 설명이 있었다. 실제 운전 시험 완료가 확인된 것은 아니다.
설치 확인Heating jacket이 보이지 않는다는 질문과, Regen에 필요한 구성인지·현재 미설치인지에 대한 확인 요청이 있었다.
미결해당 펌프의 실제 사양과 Regen에 필요한 장착 조건은 확정되지 않았다. Heating jacket을 모든 경우의 필수 조건으로 단정하지 않는다.

다음 협의 질문

  • 펌프 모델·Regen 방식에 필요한 부품은 무엇이고 현재 장착 상태는 어떤가?
  • 화면 표시·명령·실제 온도/운전 상태는 일치하는가?

확인·검증 방안
펌프 사양과 설치 구성, 현재 온도 및 Regen 상태/명령을 대조한다. 실제 시운전·인수 상태는 결과 기록으로 확인한다.

11성능 저하 시 자동 격리와 펌핑 중 Unuse 전환

조건 미확정

성능이 저하된 펌프의 밸브를 닫고 미사용으로 전환하는 요구와, 운전 중 전환 가능 조건이 미결로 남았다.

구분회의 내용
요청·질문특정 펌프의 성능이 저하되면 연결/격리 밸브를 닫고 Unuse 상태로 바꿀 수 있는지 논의됐다. 정확한 밸브 명칭·태그는 별도 확인이 필요하다.
수동 운용현재는 수동으로 처리한다는 설명이 있었고, 설정 메뉴에서 Unuse로 바꿨을 때 해당 펌프를 격리한 상태로 운전 가능한지가 문의되었다. 자동 성능 저하 판단·자동 격리가 구현됐다고 확정할 수는 없다.
마지막 쟁점“펌핑 중에 Unuse를 누르면 어떻게 되는가?”라는 질문 뒤에 전환 조건을 논의하다 제공된 발언이 끝났다.
미결즉시 전환·전환 금지·대기 후 전환 중 어느 방식인지, 밸브 닫힘과 상태 전환의 완료 확인·실패 처리는 확정되지 않았다.

다음 협의 질문

  • 성능 저하를 자동으로 판단하는 기능이 필요한가, 수동 Unuse 기능만 필요한가?
  • 운전/밸브 상태별로 Unuse 요청을 허용·거부·대기시키는 조건은 무엇인가?
  • 미사용 설정과 실제 밸브 닫힘이 불일치할 때 어떻게 표시하고 처리할 것인가?

확인·검증 방안
자동 기능 여부와 수동 전환 조건표를 먼저 확정한다. 정지/펌핑·밸브 열림/닫힘·전환 실패 등 상태별 요청과 실제 피드백을 대조하는 평가 계획을 만든다. 임의 전환 순서를 이 회의록에서 새로 정하지 않는다.
