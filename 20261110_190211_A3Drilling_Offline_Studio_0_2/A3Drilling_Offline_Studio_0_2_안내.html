3

전체 .git이 포함된 A3Drilling 작업 사본을 선택합니다. 온라인에서는 Git을 설치하고 업데이트 → 새 코드 준비 → 새 사본 열기로 준비할 수도 있습니다.

4

채팅하고 변경 검토

“Review 결과 문구를 이렇게 바꿔줘”처럼 요청합니다. 근거·미리보기를 확인한 뒤 이 변경 적용을 누릅니다.

HTML은 안내와 사용자 화면을 맡고 실제 모델 추론·파일 처리는 로컬 앱과 llama.cpp가 담당합니다. 이 안내 파일에서 직접 채팅하는 것은 아닙니다. 도구 화면을 HTML 단독으로 열면 실행 앱이 필요하다는 안내를 보여줍니다.

작업 폴더는 A3Drilling 원격 주소와 솔루션이 확인되는 정상 Git 사본이어야 합니다. GitHub Download ZIP이나 .git을 제외한 소스 복사본은 사용할 수 없습니다. 외부 .git 경로를 가리키는 worktree만 옮기지 말고 완전한 일반 Clone을 준비하세요.

첫 기준은 기존 7B CPU 모델

개발 검증에 사용한 기준 모델은 Qwen2.5-Coder-7B-Instruct Q4_K_M이며 모델 파일은 약 4.68GB입니다. 개발 검증 PC의 물리 RAM은 약 15.91GiB, 논리 CPU는 8개로 확인했습니다. 모델 외에 OS·IDE·문맥 메모리가 추가로 필요합니다.

개발 검증에서 실제 7B 모델이 작은 C# 계산 함수를 제안하는 데 138.4초가 걸렸습니다. 당시 CPU 4스레드·문맥 2,048·사용 가능 RAM 약 6GiB였습니다. 한 예제의 관측값이며 질문·출력 길이와 동시 실행 프로그램에 따라 달라집니다.

처음에는 설명·검색·간단한 UI·작은 로직 수정에 사용하고, 여러 통신·시퀀스·좌표계가 함께 바뀌는 요청은 나누어 진행하는 편이 적합합니다. 큰 모델로 교체한다고 A3 전용 정확도가 자동 보장되지는 않습니다.

모델 형식과 라이선스는 Qwen 공식 GGUF 모델 카드, 로컬 API·문맥·CPU 옵션은 반입 실행기 b11960의 공식 문서를 기준으로 확인합니다. --fit 같은 자동 옵션만으로 CPU RAM 부족이 방지되는 것은 아닙니다.

사용하면서 확인할 위험은 네 가지입니다.

앱은 로컬 추론을 사용합니다. 코드 준비를 위한 온라인 작업과 채팅 추론을 구분하며, 사용자 코드·대화를 외부 모델로 자동 업로드하는 방식은 사용하지 않습니다.

현장 반입 전, 내 코드·모델·자료까지 함께 준비하세요.

도구 ZIP의 압축을 풀어 폴더 구성을 유지하고, GGUF 모델과 완전한 A3Drilling Git 작업 사본을 별도로 준비합니다. 시작하기.cmd로 모델·폴더 선택과 질문 한 번을 미리 확인한 후 현장으로 옮기는 편이 좋습니다. 도구는 자체 .NET 실행 환경을 포함하므로 채팅용 별도 .NET 설치는 필요하지 않습니다.

Windows x64가 대상입니다. 모델 파일 외에 앱의 모델 반입 복사본·작업 사본·추가 자료·빌드 캐시를 고려해 충분한 디스크 여유를 확보하세요. 오프라인 채팅에는 인터넷이나 git.exe 실행이 필요하지 않지만, 완전한 .git 메타데이터는 있어야 합니다. 온라인 새 코드 준비와 공식 링크 다운로드는 인터넷 연결이 필요합니다.

첫 실행에 필요한 선행 설치를 확인합니다. 시작 도우미가 Visual C++ v14 x64 DLL을 확인하고 필요할 때만 동봉한 Microsoft 공식 설치 창을 엽니다. 최초 설치에는 현장 PC 관리자 승인이 필요할 수 있습니다. 설치 파일의 Microsoft 서명과 SHA256은 준비 과정에서 확인했으며 개발 중 시스템 설치는 실행하지 않았습니다. 도구 EXE는 서명되지 않은 초안이므로 현장 실행 정책을 확인하세요. Microsoft 런타임 안내

사용 중 추가·교체한 모델과 설정은 현재 PC의 로컬 앱 데이터에도 저장됩니다. 이후 다른 PC로 옮길 때는 활성 작업 사본·추가 자료·사용할 GGUF를 함께 준비해야 합니다. 사용자의 모든 변경을 새 반입 폴더로 자동 내보내는 기능은 제공하지 않습니다.

도구 검증과 장비 프로젝트 빌드는 구분합니다. 개발 검증 환경에서 원본 A3Drilling을 별도 SDK·패키지로 빌드했을 때 기존 Common.Log / CLogManager 누락 19개 오류가 확인되었습니다. 이번 도구 작업으로 원본 장비 코드를 수정해 해결하지 않았습니다. 실제 장비 앱·모션은 실행하지 않았습니다.
