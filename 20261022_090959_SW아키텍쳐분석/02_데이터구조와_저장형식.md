# 데이터 구조와 저장 형식

## 용어부터 구분합니다

Model은 셀의 픽셀/Mask/라운드 규칙, Cell은 Glass 위의 배치, Shot은 여러 Branch가 함께 가공되는 단위, Beam/Branch는 Shot 안의 실제 홀입니다. 설계 좌표, Scanner 명령, Stage/Review 이동 좌표, 측정 오차와 보정량을 서로 같은 값으로 취급하면 안 됩니다.

## 1. Recipe CSV

기본 저장은 계속 헤더 없는 TAB,NAME,VALUE 3열입니다. JHMI_RCP는 표시/형식/범위 메타데이터의 별도 헤더 표입니다. 서로 다른 파일입니다.

- 기준 키: `ALIGNBASE_AK1_X`부터 AK1~4/DK1~6의 X/Y, 총20개.
- 파생 보정 키: `CELL1_A1_ALIGN_OFFSET_X`, `CELL1_A1_ALIGN_OFFSET_Y`처럼 Cell+Shot 이름+축으로 식별합니다.
- 저장 보정의 단위는 설계계 mm이며 최종 값은 소수3자리, 즉0.001mm 간격으로 반올림합니다. 중간 보간 계산은 먼저 반올림하지 않습니다.
- 일반 편집 화면에는 생성 키를 숨기고, 일반 Save 때 누락돼도 기존 키를 보존합니다. 따라서 보이지 않는 값이 실제 가공에는 적용될 수 있습니다. 초기화는 전용 Offset Init을 써야 합니다.
- Recipe 변경 이력과 선택 이력을 File 계층에서 읽고 Manager 캐시를 새로 갱신합니다.

## 2. AlignOffset 이력 CSV

Data/AlignOffset/Recipe 아래 날짜·알고리즘 이름의 파일을 만듭니다. KEY 행과 SHOT 행을 같은 파일에 저장하며, Base/LastLoad 원시값, 설계 좌표, 계산 값, 저장 값, 제외 사유/상태를 구분합니다. 임시 파일 작성 후 이름 변경으로 저장하고 같은 초 중복은 접미사로 구분합니다.

Recipe 저장과 로그 저장이 하나의 원자적 트랜잭션은 아닙니다. 코드가 Recipe 저장 성공·로그 실패를 별도 오류로 알려 주므로 그 메시지를 보고 재적용하지 말고 실제 저장 상태를 먼저 확인해야 합니다. 근거: [CAlignOffsetLogFile.cs:10–40](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/e6ff3c6fd8fb706adbff3ded070cca2502000b4d/Drilling.File/Correction/CAlignOffsetLogFile.cs#L10-L40) · [CMenuCorrection.AlignOffset.cs:91–121](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/e6ff3c6fd8fb706adbff3ded070cca2502000b4d/Drilling.UI/Menu/Menus/CMenuCorrection.AlignOffset.cs#L91-L121).

## 3. BeamInspection 결과 CSV

고정52열입니다. 식별4열 GLASS_NAME/HEAD_NAME/CELL_NAME/SHOT_NAME와 Beam1~16 각각 X_MM/Y_MM/JUDGE 3열이 이어집니다. 한 행이 Shot 하나이며 X/Y는 목표 좌표가 아니라 측정 편차입니다. 미검사 Beam은 세 칸 모두 `미검사`입니다.

저장 경로는 Data/BeamInspection/YYYYMMDD, 시뮬레이션은 그 아래 SIM/YYYYMMDD로 분리합니다. 최근 파일 로더는 전체 하위 폴더에서 파일 수정시간이 가장 최신인 것을 고르며 SIM도 포함합니다. 헤더52개/중복 ID/Glass 혼합/유한 수/미검사 조합을 검사합니다. 최신 파일이 손상되면 오래된 파일로 조용히 대체하지 않고 실패를 표시합니다. 이는 일반 ReviewResult CSV와 별도의 형식입니다.

## 4. MELSEC와 장치 설정

READ_SCALE/WRITE_SCALE는 읽기와 쓰기 의미가 다릅니다. 새 기본 맵은 3접점/IOF/TPM 인터페이스 정의를 추가하지만 맵 행의 존재가 동작 시퀀스 완성을 뜻하지 않습니다. AK/DK LastLoad20개 행은 현재 USE=0, ADDRESS=UNASSIGNED입니다. 실제 주소·수치형·스케일·단위를 확정해야 온라인 Load가 가능합니다.

연결 설정 변경은 바뀐 장치만 Reload합니다. MelsecNet 인자 검증 일부는 저장 단계에서 제거돼 오류가 연결 시 OFFLINE으로 드러나는 쪽으로 바뀌었습니다. 설정 저장 성공과 장치 연결 성공을 구분해야 합니다. 근거: [JHMI_MELSEC_MAP.csv:79–99](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/e6ff3c6fd8fb706adbff3ded070cca2502000b4d/Config/JHMI_MELSEC_MAP.csv#L79-L99) · [CMelsecMapFile.cs:47–72](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/e6ff3c6fd8fb706adbff3ded070cca2502000b4d/Drilling.File/JHMI/CMelsecMapFile.cs#L47-L72) · [CMelsecMapFile.Handshakes.cs:5–39](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/e6ff3c6fd8fb706adbff3ded070cca2502000b4d/Drilling.File/JHMI/CMelsecMapFile.Handshakes.cs#L5-L39) · [CInterfaceManager.Reload.cs:8–67](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/e6ff3c6fd8fb706adbff3ded070cca2502000b4d/Drilling.Common/Interface/CInterfaceManager.Reload.cs#L8-L67).
