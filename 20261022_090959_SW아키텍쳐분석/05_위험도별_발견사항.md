# 위험도별 발견사항

위험도는 분석 우선순위이며 장비 안전 인증 등급이 아닙니다. 신규 변경, 기존 미완료, 운영 계약 확인을 구분합니다. 원본 코드 수정은 하지 않았습니다.

## R01 높음 새 Align 경로의 Simulation 값 저장

새 Simulation Load는 Base±1mm의 샘플을 만들고 화면/로그에는 Simulation 출처를 보관합니다. 그러나 Offset Apply에서 LastLoadIsSimulation을 저장 금지 조건으로 검사하지 않고 실제 Recipe에 저장하는 경로입니다. 표시만 SIM이라고 안전하게 분리된 저장소라는 뜻은 아닙니다. 시험 값이 양산 Recipe로 남지 않게 별도 Recipe/출처 gate/배포 전 초기화 정책을 확인해야 합니다. 정적 호출 경로로 확인했으며 실제 양산 파일에 시험 저장하지 않았습니다.

## R02 높음 Fine 계획 개선 뒤에도 Cell 혼입

**기존 계산 부채 + 이번 계획 변경의 영향**입니다. Fine 측정 선정은 Cell별로 바뀌었으나 결과 투영 그룹은 Head+DesignX입니다. N09에서 Cell1의10µm가 Cell2의30µm와 보간돼 Cell1 끝점15µm가 됩니다. N10의 정상 Cell별 선정과 구분해서 검수해야 합니다. Cell/Head/논리X/Branch의 동일 트랙을 유지하는 결과 그룹이 필요합니다.

## R03 높음 일반 실기 Review와 자동 Review는 여전히 미연결

주로 **기존 미완료**입니다. 일반 이동 함수는 명령을 버리고 반환합니다. Auto RunReviewStep은 로그만 남깁니다. 반면 이번 새 Beam 진단은 Simulation 전용 차단을 했습니다. 새 진단 화면을 보고 일반 Review도 실기 완료로 판단하면 안 됩니다. 실기 동작 차단 범위를 통일하고 실제 주소·권한·도착·Trigger/ATF·Timeout을 연결해야 합니다.

## R04 높음 저장된 Align 보정과 현재 Tolerance의 의미

**새 데이터의 배포 주의사항**입니다. test0929의 Align 필드42,840개 중42,828개는0이 아니고 절댓값 최대0.914mm입니다. 현재 설정 Tolerance0.4mm를 넘는 성분도17,122개입니다. 코드의 초과 제외는 기존값 유지이므로 Tolerance를 낮췄다고 기존 큰 보정이 지워지지 않습니다. 이 수치만으로 잘못된 가공이 발생했다고 단정하지 않으며, 현재 포함된 예제/시험 데이터를 양산 기준으로 승인하지 말아야 한다는 뜻입니다.

보이지 않는 생성 키가 일반 Save에서 보존되는 기능은 데이터 유실을 막지만 배포/Recipe 복사/Offset Init의 관리가 필요합니다. 근거: [CAlignShotOffsetData.cs:91–101](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/e6ff3c6fd8fb706adbff3ded070cca2502000b4d/Drilling.Common/Recipe/CAlignShotOffsetData.cs#L91-L101) · [CMenuCorrection.AlignOffset.cs:11–116](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/e6ff3c6fd8fb706adbff3ded070cca2502000b4d/Drilling.UI/Menu/Menus/CMenuCorrection.AlignOffset.cs#L11-L116) · [Setting.csv:28–34](https://github.com/kjuws10-rgb/A3_LD_Process_SW_IPS/blob/e6ff3c6fd8fb706adbff3ded070cca2502000b4d/Config/Setting/Setting.csv#L28-L34).
